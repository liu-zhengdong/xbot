# v0.3.1-beta.6

详情面板新增「上下文」标签：只读地看这一轮模型实际收到了什么。

## 改了什么

以前网页上没有任何地方能看上下文。`state.json` 里只有四个整数，工具定义那一块从来没被统计过，想回答「这一轮到底收到了什么、哪块占了多少、是不是压缩出了问题」只能翻代码。

- 内核在每次请求**发出前**留一份内存快照：分层、估算用量、每条消息截到 400 字。不落盘——transcript 已有每行的持久副本，再存一份只会让两份数据有机会不一致。文本过 `RedactText`。
- 面板给总量、工作集占比、按层分段色带和六行分层（系统提示词、工具定义、记忆、摘要块、环境更新、对话历史）。点一层看该层内容。
- 「在完整视图中打开」进全宽视图：左边是本轮各次请求和分层，右边是按发送顺序的消息序列，点一行就地展开原文。
- 工具定义单独列出：它随请求发出去，却没算进工作集的统计。

## 修了什么

- 摘要块的 `to` 序号原来解析不出来，现在能正确显示覆盖的 seq 范围。
- 快照改到请求发出前：请求超时、取消或供应商报错时，这次已经发出去的上下文也留得下。
- 切 Bot 时清空快照，不会再把 A 的上下文挂在 B 名下。
- 登录失效时关闭审计浮层（它挂在 `<body>` 上，不在被隐藏的界面里）。
- 展开一行就地展开并保留滚动位置，不再整层重建跳回顶部。

## 怎么验证

接口 JSON 结构与分层合计、工具结果确实进了序列、脱敏生效、空状态、未登录拒绝各有测试；摘要范围解析、分层归类、预览截断有内核测试。四条缺陷的回归测试都反向验证过会失败。

`go test ./internal/kernel ./internal/web` 连跑三遍通过。没跑的：`TestEvalFakeCertifies`（本机没有 `unshare`）与 `internal/browser` 的三条（本机 Chrome 残留进程），主干上同样失败。
