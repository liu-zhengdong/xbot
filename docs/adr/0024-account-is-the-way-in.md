# 0024 账号是进门的方式，登录码降为调试

## 背景
过去桌面和网页都靠登录码进门：`xbot serve` 在终端打一串 token，网页粘进去；桌面版启动时铸一次性码，用户看不到登录页。手机薄入口要「登录后在手机上用自己电脑上的 Bot」，需要一个跨设备的身份；登录码只属于一台电脑，无法表达「我的设备」。政东 2026-10-26 定：桌面和手机都走同一套邮箱账号。

## 考虑过的方案
1. **手机走账号，桌面留登录码**：两套心智，桌面仍要解释登录码。
2. **把账号写进官方信箱网关（Workers / DO）或复用 `/v1/register`**：网关管的是安装公钥和信箱，混进账号会让两类凭据纠缠。
3. **独立的账号服务，serve 通过客户端调用；登录码保留但退出产品（选定）**。

## 决定
1. 产品里进门只有账号：登录 / 创建账号 / 查收邮件（魔法链接为主，验证码为辅）。登录、注册屏不放产品标和名字。
2. 账号服务独立（`internal/account`，`/account/v1/`），存储和发信是接口；本批用文件和发件箱替身，目标部署在腾讯云，不进官方信箱网关。
3. 一台电脑绑定一个账号：第一个从本机直连（或已带主人会话）登录的已验证账号绑上，之后只有它拿到主人会话。
4. 旧登录码（`/api/login`、`/app/launch`、终端 token）保留、语义不变，只作调试和回归入口（页面 `#login-code`），产品文案不再引导。
5. GitHub / Google 登录本批只占位，灰着标「即将支持」。

## 后果
- 新装的电脑要先在本机登录一次账号才能远程用；没有真发信之前，替身把信写进 `<root>/account-api/outbox/`。
- 主人会话仍是原来那一个 token，账号只是换了拿到它的方式；`require` 不变。
- [六条基本旅程](../guard/六条基本旅程.md) 第 1 步「用登录码登录」需要主人改成账号登录（守护层改动，待确认）。

## 何时重看
- 账号服务上线腾讯云、接真发信时（`BASE_URL` 必须是固定公网地址，不再用请求的 Host 拼链接）。
- 接 OAuth、或一台电脑要给多个账号用时。
