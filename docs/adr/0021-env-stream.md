# 0021 环境流：一切会变的状态只追加差异，不改前缀

## 背景
一条聊天就是一个连续的上下文：主人的话、Bot 的回复、后台任务的报告，都是同一条对话串里的普通消息。可是除了对话，还有很多会变的状态要让模型知道：现在几点、谁在说话、子任务排队还是跑完了、记忆刚被改了什么。

之前这些状态各走各的路：
- 子任务状态由 `backgroundNote` 每次在主人消息前插一段（插话 M2），M3 又加了「已转告」标记、短引用和一次不带工具的专门转告请求。为了绕开「对话就是上下文」这个前提，机制越叠越多，真实模型测试还是失败。
- 记忆快照按发送者切换（记忆 v2 批 1）：别的 Bot 或连接器一开一轮，请求的第二条消息就换掉，缓存几乎全掉；而对话串本来就是共享的，这份隔离也不彻底。
- 压缩有内核自动的，也有 Bot 自己调 `compact` 和候选里的手动按钮，每次手动都会掉一次缓存。

## 决定
1. **只用三样东西**：只追加的对话串、环境流、[ADR 0017](0017-owner-words-go-straight-into-the-turn.md) 的插话口。新需求先想能不能放进这三样，放不进再说为什么。
2. **环境流**：每次唤醒都拿当前的值，和当前有效对话里已经公布过的值比，有变化才在对话尾部追加一条环境更新，从不改写历史，也不改前缀。「已公布的值」只从对话里的环境消息回放出来，不另存第二份账。所以每条环境消息都要能回放：变了的字段直接写新值，人物和任务按编号写当前内容或者写明移除，不能只写「已更新」或者「改了几条」。放进去的东西：
   - 时间（主人本地时间精确到分钟）；
   - 当前发送者和他的 User.md（person 层）：换了人说话就追加差异；
   - 子任务状态：派出、排队第几、在跑、完成（结果见任务回报，不保证紧挨着）、中断；
   - 记忆差异（`memory_diff`），写成能回放的具体内容。Bot 自己写记忆成功后，变化随那次写记忆的工具结果一起公布，格式和环境消息一样，算进已公布的值；写失败或者回滚了就不公布。（2026-10-23 修订）
3. **前缀固定**：人设、规则、Bot 自己的记忆一份快照，不随发送者切换。
4. **结果是普通消息**：子任务结果作为普通报告消息进对话串；太长就把全文存进任务已有的目录，消息里放开头一段和路径，前台用已有的读文件工具读。没有「已转告」标记、没有短引用、没有专门的转告请求：转没转告，看对话串就知道。
5. **对话串的顺序是进入对话的顺序**：主人的话收到即追加到对话串，不推迟保存、不改旧行。组装模型请求时，一次工具调用的结果必须紧跟调用，中途入串的消息排在这批结果之后；两条组装路径用同一规则，不改原始对话串顺序。别的 Bot、连接器、定时器的消息不取消正在等的生成，在下一步接进来。
6. **压缩不设手动按钮**：内核按 [ADR 0015](0015-soft-target-hard-ceiling.md) 的软目标和硬上限自动做，保留每个任务的结论和关键数字。去掉网页上的手动压缩按钮；Bot 自己调的 `compact` 工具保留，仍走 `CompactRange` 的工具对、尾巴和重叠规则。压缩只动投影和摘要：读范围、写摘要块，必要时重读记忆刷新注入用的快照；不写记忆文件、不追加日志或 episode，压缩前也不抽事实。（2026-10-27 修订：原文写成「去掉 Bot 的 `compact` 工具和手动压缩按钮」，是写偏了，主人当时只要去掉手动按钮，按原文落地退役的模型侧 `compact` 已恢复；同日主人另定压缩不写记忆，原先压缩前抽事实、写 episode 的做法去掉。）自动压缩生效，或者一轮里面折叠了旧内容之后，已经公布的环境可能被压掉了。所以下一次发给模型之前，先在尾部追加一条重新采样的完整环境快照，之后照常只发差异。这条快照带着压缩范围的标记，靠对话本身就能看出这次压缩之后补没补过；快照不放进前缀，也不另存标志。Bot 自己的记忆仍以决定 3 的固定前缀为准，快照里只写从前缀到现在的记忆增删，没有变化就不写记忆字段。（2026-10-23 修订）

## 考虑过的方案
- (a) 每次请求前重新拼一份完整的状态快照放在前面：每次都改前缀，缓存全掉。不采用。压缩后在尾部补一次快照不算这种做法：它不是每次都发，也不改前缀。（2026-10-23 修订）
- (b) 给转告单独建一套记账（已转告标记、短引用、FIFO）：和「对话就是上下文」重复，状态有两份就会不一致（插话 M3 的教训）。不采用。
- (c) 记忆按发送者切快照：缓存代价大，隔离又不彻底。只有真正多人共用时再考虑，那时也该用另一条对话串或另一个 Bot。

## 后果
- 状态变了模型才看到一条短差异；没变什么都不发，缓存前缀一直命中。唯一的例外是压缩或折叠之后会补一条完整快照，它追加在尾部，不碰前缀。（2026-10-23 修订）
- 环境流会让对话串长得快一点，长程测试（`TestLongRunJourney`）要重跑。
- 取代：插话 M2 的 `backgroundNote`、M3 的转告机制；[ADR 0017](0017-owner-words-go-straight-into-the-turn.md)「插话进程崩了这句会丢」那条（主人的话收到即写入对话串）；atlas/memory.md「快照按人分开」那条。（2026-10-27 修订：原先还写了取代 atlas/context.md「Bot 可以自己选范围压缩」那条，随决定 6 一起改正，该条恢复。）
- 以后的设计（慢工具统一转后台、跨 Bot 协作、例程唤醒等）都要先对照这份 ADR，看能不能直接用环境流和对话串表达。
