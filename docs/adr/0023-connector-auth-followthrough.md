# 0023 连接器必须走完鉴权后续，禁止一键假成功

## 背景
连接应用商店第一批做成「目录预置、一键添加」（见 Obsidian `设计/连接应用.md`）。目录里若干条目（手测时的 Context7）把 `secret_envs` 标成空，点「添加」只把 MCP 写入配置并立刻显示「已添加」，从不弹出密钥卡。用户手测觉得是假成功：应用看起来连上了，真正调用却因缺密钥失败或行为含糊。

同一批还有：该走 OAuth 的远程 MCP（Google / Notion 类）商店可展示，但不能假装「连接」已完成。商店卡「已添加」后若不提供移除，取消连接被藏进二层列表，也加重「假状态」感（UI 另修，不改本 ADR 主题）。

## 考虑过的方案
1. **目录标「免密钥」就真免**：适合公开只读服务；一旦条目其实要 key / Bearer，UI 会撒谎。
2. **一律弹空卡**：无密钥条目也多一次确认，和「一键精选」相反，也和 [ADR 0019](0019-no-permission-cards-by-default.md)「密钥卡才是输入框」不一致。
3. **按条目声明的鉴权类型走完后续（选定）**：目录必须诚实声明；UI 按声明完成后再标已添加 / 已连接。

## 决定
1. **「已添加 / 已连接」只能表示鉴权后续已完成**（或该条目经核实确属无需凭证的公开能力）。未完成不得改按钮态、不得写入「已装可用」语义。
2. **鉴权类型由目录声明，UI 不得猜、不得跳过**：
   - **密钥（secret / env / header）**：走确认卡填人话字段（与 Telegram / 飞书、`links install` 同路）；值进保险箱或既有 secrets，不进聊天、不进 API body、不进模型提示。没填齐 → 不安装、不落「已添加」。
   - **OAuth / 浏览器登录**：走浏览器授权 + 令牌保管；未完成登录 → 保持「连接」或「即将支持」，**禁止**标已连接。本批未实现 OAuth 的条目必须灰态诚实，不得一键假成功。
   - **确无凭证**：仅当目录与实现一致、调用不依赖用户密钥时，才允许直接「添加」成功。
3. **目录是契约**：`secret_envs` / OAuth 标记与真实上游要求不一致时，改目录或改实现，禁止靠 UI 糊弄。Context7 一类要 key 的，必须按密钥型处理。
4. **与「一键」不矛盾**：「一键」指用户不填 npx/command/args；**不**等于跳过密钥或 OAuth。
5. **移除是对称动作**：商店卡在已装态须可「移除」（与「已连接 N」二层移除同效）；本条保证状态可撤销，细节见设计文档。

## 后果
- 实现与验收：无密钥却标已添加 = bug；目录漏标密钥 = 目录 bug。手测与回归按「声明 → 后续 → 再标已装」核对。
- 无密钥的真·公开 MCP 仍可一键；误伤面小。
- OAuth 未就绪的条目继续灰态，直到批 3；不引入半吊子「已连接但令牌为空」。
- 与 [ADR 0005](0005-vault-daemon-user.md)（密钥进保险箱）、[ADR 0019](0019-no-permission-cards-by-default.md)（密钥卡是输入而非许可）同向；不恢复默认权限弹窗。

## 何时重看
- 上了统一的 MCP OAuth（magpie `mcpauth` 一类）并要改「连接」态机时。
- 出现「设备码 / 配对码」等第三种鉴权，目录枚举不够用时。
- 多用户或不再只供一位用户自用，密钥归属从「用户全局」再拆时。
