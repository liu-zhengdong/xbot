# 0024 手机薄入口经网关操作设备要流畅：加密实时管道为主，信箱只管异步消息

## 背景

政东 2026-10-26 定：手机与桌面都走邮箱账号登录；手机是薄入口，经官方网关用 Mac Mini 等设备上的 Bot（见候选「使用须注册账号」、设计「设备·网关·好友」）。账号服务另挂腾讯云 `account.babelgo.cn`，与 Cloudflare 上的信箱中继 `xbot.babelgo.cn` 分开。

同一天政东 [t843u]：聊天翻阅、切换 Bot 等「经网关连到设备」的操作都要流畅，并写进 ADR。

政东 [t846u]：中心网关**所有功能都落到腾讯云**，集中部署；稍作预留以便以后负载均衡与分布式。视为认「B + 入口缓存 + D」，管道与账号同中心；不选双轨扩 CF。

### 现状（代码事实）

- [ADR 0010](0010-gateway-mailbox-relay.md) 定网关是**存储转发信箱**，明确否了「隧道式中继把对方 HTTP 端口转过来」：收件必须在线、攻击面大。
- [ADR 0011](0011-official-gateway-on-workers.md) 官方网关在 CF Workers + DO；Free 约撑 20–25 台常在线安装（每台日约 3.7k Worker / 4k DO 请求，主因是 25s 长轮询）。
- G7e 用户远端对话（`internal/remote/chat.go`、`internal/web/remotechat.go`）：信封只有 `chat` / `chatreply`；**两边各存半份**——发起方只记自己发出的与对方回的；权威 transcript、确认卡、例程、任务、设置仍在设备本机 `serve` 的 `/api/*`。
- 远端历史接口 `GET /api/remote/{device}/bots/{bot}/messages` 读的是**本机** `remote/chats/…`，不是对方电脑上的全文。远程侧栏每 5 秒拉一次摘要。e2e 经官方网关往返约 1.2s（假模型）。
- 本机对话是 SSE 流式 + 一次拉全量 transcript；私聊翻页已有 `before` 游标，远端 chat 只有 `limit`、没有「再往上翻更早」的游标契约。
- 候选「网关局域网直连」已排期（P3）；「P2P 打洞」取消/推迟。账号候选本批明确不做局域网/P2P。

### 产品缺口

手机登录账号后，要像本机一样：**切 Bot 看首屏、上滚历史、看状态/后台、确认卡、例程、设置**。继续只用信箱半份对话，手机永远没有 Mini 上的全文历史；若把每次翻页都做成信箱「请求–响应」，延迟和 CF Free 配额都会炸。

## 考虑过的方案

| | 延迟（设备在线） | CF Free / 成本 | 安全 | 代码量 | 与 0010/0011 |
|---|---|---|---|---|---|
| **A. 信箱 RPC**（加 `kind=rpc` 请求/响应） | 最差一整个长轮询窗（25s，有待回信时缩到 2s）+ 多跳；切 Bot/翻页体感差 | 每次翻页/切 Bot ≈ 数次 send+poll+ack，常在线保活已吃额度，交互再加会顶满 | 载荷可继续 E2E；网关仍只见密文与 kind | 中：复用信封路径，但要超时、配对、重放、并发窗 | 符合「只有信封」；把交互塞进异步模型，语义别扭 |
| **B. 加密实时管道**（网关 WebSocket/长连接中继，端到端加密，手机复用设备同一套 `/api`） | 一跳管道内像本机 HTTP/SSE；目标切 Bot / 翻页 &lt;1s | 长连接空闲可休眠；按字节/连接计，远好于「每翻一页两次 poll」 | 网关**不得**见明文：管道载荷用设备与入口协商的会话密钥封；账号证明「是用户」后由设备签发短时管道票，不把安装私钥交给手机 | 大：管道、票、手机客户端、与本机 API 对齐 | **表面顶 0010 否过的隧道**；见下方决定里的区分 |
| **C. 设备推摘要/最近 N 到网关缓存，更早按需拉** | 列表/最近 N 快；更早仍要等设备 | 推送周期性吃配额；缓存落哪要另算 | 明文缓存 = 信任运营方；密文缓存则冷启动仍慢 | 中：多一份权威副本 | 不推翻信箱，但引入第二事实源 |
| **D. 能直连就直连**（局域网 / Tailscale / 以后 P2P），网关只兜底 | 局域网最优 | 直连不耗中心配额 | 直连仍要配对身份与 TLS/E2E；默认关、用户开（候选已写） | 中（候选已排期） | 0010「何时重看」已点名；P2P 仍推迟 |

## 决定（Accepted）

**组合：B 为主 + 入口本地缓存 + D 优先（能直连就直连）；信箱继续只承载异步消息与离线投递，不做交互式 RPC。C 不做默认权威缓存。**

**落点（政东 [t846u]）**：管道与账号服务同属**腾讯云中心网关**（首期 shanghaigo / `account.babelgo.cn` 同机或同域反代）。CF `xbot.babelgo.cn` 信箱**暂保留过渡**（现有安装与离线代存）；新产品面（账号、管道、以后发现/设备列表等）**不扩 CF**。

1. **操作分级**
   - **必须流畅（设备在线）**：切 Bot / 会话首屏、上滚加载更早一页、流式看回复、确认卡出现与点选、侧栏状态与未读、后台任务一眼。
   - **可异步**：设备离线时仍能发话（现有 `chat` + outbox + 网关代存）；离线时**只读入口本地已缓存**的历史，不假装能拉全文。
   - **本批可不要求与本机同等**：改网关 URL、装 MCP、大段导出——可提示「请到该设备本机操作」或第二批再进管道。

2. **B：用户远程控制台管道（不是 Bot 信封隧道）**
   - 手机（或异地桌面）持**账号会话** → 中心网关账号服务证明身份 → 目标设备签发**短时管道票**（绑定安装 id、入口公钥、过期）→ 入口与设备经**腾讯云中心网关**建立**端到端加密**的双向流，上面跑与本机相同的用户 `/api`（transcript 带翻页游标、messages/SSE、approvals、status、routines 只读等）。
   - 网关只转发密文帧与票校验结果，**看不到** Bot 名与正文。
   - **与 ADR 0010 的关系**：0010 否的是「把 serve 裸暴露给对端、且作为 Bot 消息主路径」。本决定是**已认证用户**的远程 UI 通道，设备可撤销票、可关管道；Bot↔Bot 与离线代存仍走信箱（过渡期仍可走 CF）。属 0010「何时重看」触发，不静默废除信箱。

3. **本地缓存**：入口对打开过的 Bot 缓存最近页与列表摘要；切回 &lt;1s 可先上屏再后台刷新。权威仍在设备磁盘。

4. **D**：与候选「网关局域网直连」对齐——同网或 Tailscale 可达时管道**优先直连**设备 HTTP；中心网关管道只作公网兜底。**中心网关流量能省就省**（政东 2026-10-26 [t847u]）。不复活已取消的 ICE P2P，除非大文件/实时流再开题。

5. **流畅指标（可观测）**
   - 设备在线、管道已建立：切 Bot 首屏（列表+最近一页）&lt;1s；上滚再加载一页 &lt;1s；确认卡从设备创建到入口可点 &lt;2s；在线发话到「已送达/开始流式」体感 &lt;2s。
   - 管道未建或设备离线：首屏用本地缓存 &lt;300ms；无缓存则明确空态/离线说明，不转圈假加载；离线发出的话走现有信箱排队文案。
   - 中心网关：交互流量不走「每动作两次长轮询」；管道空闲心跳预算写进 gateway atlas。

6. **单机起步、预留水平扩展**（政东 [t846u]：稍作考虑负载均衡与分布式）
   - **首期**：shanghaigo 单实例即可（账号 SQLite、管道入口同机或同域反代）；不上 K8s、不做多活。
   - **契约预留**：API / 管道入口尽量**无状态**（鉴权靠票/会话令牌，不绑进程内存）；票与会话可外置（以后 Redis/独立库）；设备长连接可按**安装 id 分片**路由到实例。
   - **何时真扩**：单机 CPU/连接或磁盘顶满、或要异地多活时再拆——到时另开 ADR，不提前铺集群。

7. **非目标**：网关存记忆/全文同步；手机当家节点；把供应商 OAuth 当产品账号；管道给未配对第三方；把新产品面扩到 CF。

## 后果

- **换来**：手机薄入口按本机同一套 API 心智做 UI；翻阅与切 Bot 不再被信箱 RTT 绑死；身份、管道、以后发现等集中在腾讯云，运维一面。
- **放弃**：纯信封一种传输包打天下；「网关绝对无长连接业务」的简单性；双轨扩 CF 做管道。
- **代价**：要实现票、管道、翻页契约、入口缓存；中心网关成单点时靠 D（直连）与以后水平扩展契约缓解；攻击面扩到「偷账号会话 / 偷管道票」——票必须短时、绑定设备、可撤、只开用户 API。
- **对 G7e**：现有半份 `remote/chats` 可保留作「配对电脑↔电脑、无账号时代」与离线发送痕迹；手机主路径以设备权威 transcript 为准。
- **对 CF**：信箱过渡期仍服务旧安装；新流量（账号、管道）不往 CF 加；日后可评估是否把信箱也迁中心（另题）。

## 什么时候重新考虑

- 腾讯云单实例顶不住连接/带宽 → 按「无状态 + 票外置 + 按安装分片」水平扩，或强制更多 D。
- 绝大多数用户永远同网（只 LAN）→ 可把 B 降为可选项，D 升默认。
- 要做跨用户好友远程看 Bot → 另做授权模型，不得复用「用户管道票」。
- 入口需要设备离线仍搜全文历史 → 才回头评估 C（且须明示信任边界）。
- 要把信箱也迁出 CF → 另开 ADR，不在本篇偷换。

## 附录 C · 待定 / 穿刺

1. **管道挂哪**：**已定**——腾讯云中心网关（与账号同中心）；CF 信箱仅过渡，新产品面不扩 CF。
2. **票与账号如何绑设备**：账号「我的设备」列表如何授权某安装；撤销登录是否吊销一切票。（建议：登出撤票。）
