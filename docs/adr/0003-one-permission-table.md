# 0003 一张权限表决定所有确认，只确认四类

## 背景
确认卡曾由各工具的 `Confirm` 自行决定，范围被逐次放宽，用户多次遇到不该弹的确认卡（例行任务、Bot 之间消息、写计划）。

## 决定
内核里一张显式权限表按工具名（`http`、`shell`、`self_edit` 再看参数）决定是否确认；工具的 `Confirm` 只生成摘要。只确认对外发送、删除、带密钥或非 GET/HEAD 的 HTTP、persona/profile 自改。shell 跟机器开关：off 拒绝，ask 全确认，allow 只确认上述类别。守门测试保证每个注册工具都在表里有归类。

## 考虑过的方案
- 各工具自行确认：被取代，规则散落，越改越宽。

## 后果
加新工具必须先在表里归类，否则守门测试失败。
