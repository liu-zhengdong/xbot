# 0018 确认卡不挡主人说话：插话时挂起，决定稍后送达

## 背景
[ADR 0017](0017-owner-words-go-straight-into-the-turn.md) 让主人的话直接插进正在跑的一轮，能打断模型调用，但打断不了确认卡：卡弹出时那一步的工具调用停在「等主人决定」上，最多 30 分钟。这一步不结束，插话就接不进去。主人的话是第一优先级，任何卡都不能挡住它。

## 决定

**2026-10-21 政东改定**：两种卡默认等 30 分钟，沿用 Server.ApprovalWait 配置。没人回答时自动选推荐、权限卡自动允许；不再以“无人决定”丢掉工作。

1. **没插话时不变**：卡弹出，主人点了，这一轮照常接着走。
2. **插话一来，挂起正在等的卡**：卡不关，30 分钟内照样能点；那个调用先返回「还没跑：在等主人确认卡，主人中途说了别的，不要再调，等决定」；这一轮马上接上主人的话。同一步里还在等或接着要弹的卡一起挂起。
3. **之后的决定也是主人的话**：有一轮在跑就直接插进去，没有就投进收件箱并当场叫醒（来源 `approval`，主人的身份，transcript 里是内部行，卡片本身已经显示了决定）。
   - 允许：留下一次性放行（同一个 Bot、同一个工具、同样的参数，10 分钟内，用一次就作废），并告诉模型用相同参数再调一次，然后把原来的事做完。
   - 拒绝：告诉模型主人拒绝了，不要跑。
   - 过期没人点：按允许继续原调用；挂起的调用同样留一次性放行并当场叫醒，沿用下面的恢复路径。对话留一行灰字「30 分钟没人确认，已按允许执行」。
4. **由模型再调一次，不由内核替它跑**：挂起时那一轮的内核可能已经关了；替它跑要把工具调用连同目录、工具集一起存下来再复原。再调一次走的还是原来的权限表和守卫。
5. **提问卡也等 30 分钟**：ask_user 必须给 recommended，值为 options 中某个选项的完整字符串；网页标「推荐」。问完这一轮结束，主人选择后按主人的话续跑；到时无人选择，自动提交推荐项并叫醒，灰字留「30 分钟没人选，按推荐选了 X」。超时之后再点其他选项或直接说话，作为新消息处理，不改掉自动选择的记录。期限前主人直接说话也会结束这张提问卡的计时。子代理权限卡仍只挡该子代理，超时同样自动允许。

## 后果
- 放行在进程内存里，重启就没了；模型再调时会重新弹卡。
- 参数变了不算同一个调用，会重新弹卡。
- 终端问 y/n 时还会读走主人的输入；改成「输入别的就当插话并挂起」放在之后做。
