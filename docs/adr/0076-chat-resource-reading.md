# 0076 对话资源从当前认证设备按需读取

## 背景

用户希望点击聊天中的技能目录，并统一文件、行号、网页来源和消息引用。已认可正文轻链接与覆盖式阅读面的原型。

现有路径标签只负责显示。固定记忆与工作区接口不能读取任意已给出的路径。聊天记录没有逐资源设备或工作目录字段。

## 决定

1. 原文派生资源目标，不改 transcript，不新增持久化资源索引。绝对路径或 home 路径默认在当前对话连接的设备查找，界面显示实际查询设备。
2. 增加当前设备的 owner 认证资源读取入口。沿现有用户会话；系统打开沿同源 POST 和现有 App/OpenPath 回调。不增加模型工具、许可卡或后台任务。
3. 目录按页读取条目名，文本按行分页。每页预览原始文本最多 64KiB，最终 JSON 小于 1MiB。仅读普通文件，不把设备文件或管道作为正文读取。
4. 资源阅读控制器拥有浮层、导航及请求生命周期。它位于聊天投影之外，不挤聊天、不由轮询重建。关闭或换 Bot 后，迟到结果不能重新打开界面。
5. 普通 HTTP 链接直接打开。网页角标复用已有来源身份，不自动抓正文。消息引用沿现有窗口加载与定位，并保存返回阅读锚。
6. 不用主人输入设备或临时执行选择推断历史资源归属。没有基准的相对路径不猜。明确的设备/产物引用沿已有精确路由，不增加跨设备文件同步。

## 选择与代价

选择按需读取，不给旧消息回填资源对象。这样可直接使用现有路径，并保留原文。

接受文本页按行重新扫描的代价，避免维护文件索引和缓存。来源设备的自然语言推断、文件编辑、分享、收藏和全局资源管理不在本轮。

## 守护

认证、同源写入、真实文件分页、字节预算和 OpenPath 回调用接口用例检查。目录进入、引用定位、复制、轮询阅读状态与开合位移用真实浏览器检查。实施依据见 [实施记录](../dev/archive/chat-resources.md)。
