# 0036 例程引用已有技能，在叫醒上下文装配正文

## 背景

用户指定例程加可选 `skills: string[]`，到点按序加载已有技能，与对话读技能等价；空数组保持旧行为。不重做调度、precheck，不允许例程因此改技能库。

## 决定

1. `Routine.skills` 保存有序的技能名/id；cron 和一次性 at 共用事件构造，`Event.routine_skills` 仅携带引用，经过原收件箱投递与去重。
2. 唯一正文装配函数 `Kernel.projectRoutineSkills` 复用 `read_skill` 的读取逻辑和 Bot 停用名单，作用于当轮 user message 的请求投影。初次 Handle 和忙时 eventMessage 吸收都调用它。正文不进固定前缀、不写回 transcript，后续唤醒重新读取当前正文。遵循 ADR 0021 的对话串边界，无新的状态账本。
3. 找不到（含改名/删除）、已停用或读取失败时，跳过该项，在本次唤醒上下文明确写 `Routine skill "<name/id>" skipped: <reason>`，继续后续技能和任务。保存允许引用暂时不存在的技能；不静默宣称已加载。
4. 创建缺省/空数组为无绑定；更新省略保留、`[]` 清空。写口共用 Timer 的持久化与大小约束：最多 32 项，每项去首尾空白后 1–240 字节、单行；正文沿用每技能 16 KiB 上限。无绑定的事件正文保持原样。
5. 只读技能，不授予写库授权，不改变 `write_skill` 的提议确认规则、模型工具列表、调度、precheck、slot 提交或权限表。

## 后果

- 技能是引用，技能正文更新在下一次装配生效；事件排队期间修改例程绑定不追溯已入队引用。
- 缺失说明在唤醒上下文可见；是否通知用户仍沿用例程和既有发送工具语义。
- 工具、HTTP、CLI 和任务面板编辑同一字段，不另存 UI 状态或正文快照。
