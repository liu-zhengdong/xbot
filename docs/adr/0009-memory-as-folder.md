# 0009 每个记忆范围是一个文件夹，用普通文件工具编辑

## 背景
[ADR 0008](0008-memory-v2-dated-log-first.md) 定了"默认写日志、常驻带日期、常驻最近 8 条"，但没有动存储形状：每个范围仍是 `profile.md` 加 `log.md` 两个结构化文件。成段的资料（某个项目的来龙去脉、一份清单）要么挤进 4 KiB，要么拆成很多条日志，读起来很费劲。用户改成目录式。

## 决定
- 每个范围（person、bot）是一个文件夹，里面有：
  - `memory.md`：常驻，上限约 4 KiB，是普通 markdown，条目写成 `- (日期) 文本`（person 范围的末尾加 `via <bot>`）。`## 索引` 一节列出旁边每个文件和文件夹放的是什么。
  - `log/YYYY-MM.md`：只追加的日志，每行一条 `- YYYY-MM-DD HH:MM [source] 文本`。source 是 `对话`、`episode`、`整理` 之一，person 范围用写入它的 bot 名。没有 key 和 id，不能改也不能删，更正就追加一条新的，新的为准。最近 8 条进快照，更早的用 grep 搜或读月份文件。当月文件有大小守卫。
  - 其余自由文件和文件夹（比如 `projects/xbot.md`、`notes/`）：不注入，按需读写。
- **没有专用写记忆的工具**（2026-10-17 晚修订）。Bot 用 `write_file`、`edit_file` 编辑这些文件，内核在写入路径上把关：
  - `memory.md` 写完超过 4 KiB 就拒绝，只允许缩小；
  - `log/` 只能在当月文件末尾追加合格式的行，当月文件超过 64 KiB 就拒绝；
  - 不可信回合写这两个范围文件夹，都出确认卡。
  
  `remember` 和 `forget` 从模型工具里拿掉，内部存储接口保留给抽事实、同步和迁移用。只保留一个只读的 `recall`，在范围文件夹里检索。
- 冲突规则从代码挪进 MemoryRule：关于用户本人，日期新的为准；怎么做事，bot 的压过 person 的。
- 快照里标出索引和实际文件不一致的地方；每晚整理负责修好。
- 迁移：`profile.md` 变成 `memory.md`，`log.md` 和 `log.overflow.md` 按日期拆进 `log/`，原文件改名为 `*.bak` 保留，迁移是幂等的。

## 考虑过的方案
- 保留结构化条目和专用工具（remember、revise）：模型要多学一套 schema，还会和文件工具打架；规则放在写入路径上更可靠。
- 连 `recall` 也不要，只用 shell grep：有些机器关了 shell，而且 grep 不懂日期和"另有 N 条"。`recall` 只读、便宜，保留。
- 只加 `notes/`、不加索引：Bot 不知道里面有什么，等于没有。
- 索引由内核自动生成：省事，但写不出"这个文件放什么"。所以索引由 Bot 写，内核只负责标出不一致。

## 后果
- 4 KiB 里要匀出一点给索引。
- 自由文件不受上限约束，也没有出处标注。person 范围的自由文件，任何一个 Bot 都能改。
- `recall` 要多扫一批文件；先只扫 `.md`、`.txt`，每个文件设大小上限。
- 文件工具要认得两个范围文件夹的路径。
- 冲突规则从代码判定变成提示词规则，靠模型执行，要配评测用例。

## 什么时候重新考虑
- 索引经常对不上，或者 Bot 不翻自由文件。
- person 范围的自由文件被别的 Bot 改坏。
