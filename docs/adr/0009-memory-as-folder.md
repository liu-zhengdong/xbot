# 0009 每个记忆范围是一个文件夹：常驻 memory.md 加索引，日志按月，其余自由文件

## 背景
[ADR 0008](0008-memory-v2-dated-log-first.md) 定了"默认写日志、常驻带日期、常驻最近 8 条"，但没有动存储形状：每个范围仍是 `profile.md` 加 `log.md` 两个结构化文件。成段的资料（某个项目的来龙去脉、一份清单）要么挤进 4 KiB，要么拆成很多条日志，读起来很费劲。主人改成目录式。

## 决定
- 每个范围（person、bot）是一个文件夹，里面有：
  - `memory.md`：常驻，上限约 4 KiB，条目带日期，注入时显示用量。其中 `## 索引` 一节列出旁边每个文件和文件夹放的是什么，`## 条目` 一节沿用现有的结构化条目。
  - `log/YYYY-MM.md`：结构化日志，按月分文件。最近 8 条常驻，`recall` 和每晚整理都依赖它。
  - 其余自由文件和文件夹（比如 `projects/xbot.md`、`notes/`）：不注入，Bot 用普通文件工具按需读写。
- 注入时比对索引和实际文件，标出没登记的和已经不存在的。每晚整理负责修好索引。
- `memory.md` 和 `log/` 只能通过记忆工具写：带锁、查上限、记出处。文件工具直接写这两处会被拒绝。
- 记忆工具缩成三个：
  - `remember`：默认写日志，`to=memory` 写进常驻；
  - `revise`：按唯一子串改写，不给新文本就删除；取代 `forget`，`forget` 保留一个版本作为别名；
  - `recall`：也搜自由文件。
- 迁移：`profile.md` 变成 `memory.md`，`log.md` 和 `log.overflow.md` 按日期拆进 `log/`，原文件改名为 `*.bak` 保留，迁移是幂等的。

## 考虑过的方案
- 全部用自由 markdown，不要结构化条目：冲突规则、出处标注、上限检查和最近 8 条都没了依据。
- 只加 `notes/`、不加索引：Bot 不知道里面有什么，等于没有。
- 索引由内核自动生成：省事，但写不出"这个文件放什么"。所以索引由 Bot 写，内核只负责标出不一致。

## 后果
- 4 KiB 里要匀出一点给索引。
- 自由文件不受上限约束，也没有出处标注。person 范围的自由文件，任何一个 Bot 都能改。
- `recall` 要多扫一批文件；先只扫 `.md`、`.txt`，每个文件设大小上限。
- 文件工具要认得 `memory.md` 和 `log/` 这两个特殊路径。

## 什么时候重新考虑
- 索引经常对不上，或者 Bot 不翻自由文件。
- person 范围的自由文件被别的 Bot 改坏。
