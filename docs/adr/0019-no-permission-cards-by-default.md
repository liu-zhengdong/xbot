# 0019 默认不弹权限卡，主人自己控制

## 背景
XBot 是主人自己用的工具。[ADR 0003](0003-one-permission-table.md) 的权限表会为对外发送、删除、非 GET 的 HTTP、persona/profile 自改、未知和 MCP 工具弹确认卡；有了派活之后，子代理的这类调用也弹。每张卡都是主人没要的停顿，主人原话：「这个权限好烦……默认跟 Pi 一样吧，不设权限管控！反正是我自己用，我能控制」。

## 决定
1. **默认关掉权限表的卡**：`serve` 和 `chat` 打开的内核 `Permissive`，前台和子代理的调用都直接跑。
2. **机器开关跟着关**：`allow`/`ask`/`off` 只在权限检查打开时生效，关着时一律当 `allow`（存下的值不动，打开后照旧）。主人追加：「机器设置 ask 和 off 这个功能也关掉」。
3. **外部事件开的一轮也能改记忆**：webhook、别的 Bot 这类事件开的一轮碰记忆，不再弹卡。主人：「很多情况下外来事件比如 issue 增多、重大 BUG，凭啥不能修改记忆呢？这个围栏我觉得限制了很多情况下的可行性。」外部事件的内容仍包在 `<untrusted_event>` 里，从中抽出的记忆仍标「不可信」，只是写入不再被挡；提示里补一条 `EventMemoryRule`，让模型把和工作有关的事件记进记忆并写明来源（真实 DeepSeek 上没有这条时，它把 P0 issue 当成不可信数据、拒绝记）。
4. **还留着的卡**：
   - `links` 的卡：装连接器时主人在卡上填 key，是输入框不是许可。
   - 触到保险箱、密钥、配置文件的调用：不常碰到，碰到就是要读密钥。
5. **开关**：`xbot permissions on|off`，写在数据根的 `permissions.json`；没有这个文件就是关。
6. 权限表本身留着：新工具照旧要在表里归类（守门测试照旧），打开开关时按它确认。

## 后果
- 删除、强推、对外发消息都不再先问；出了错靠主人自己发现、撤回。
- 测试里直接构造的内核默认仍按表确认，权限表的测试照旧有效。
- 外部事件能借提示注入改记忆、跑命令：主人接受这个代价。
