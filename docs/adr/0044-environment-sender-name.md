# 0044 环境发送者使用姓名，身份关联保留 ID

## 问题与用户要求

用户指出模型环境里的 `sender = u501` 不舒服，要求使用正式姓名「刘政东」。`u501` 是 person 存储和 owner 授权的稳定键，直接把 Event.Sender 改成姓名会破坏认证和记忆关联。

## 调用方与决定

用户通过已有 web/terminal 入口说话，Event.Sender 仍是 person ID。模型收到既有环境流中的来源值：

```json
{"source":{"name":"web","sender":"刘政东","sender_id":"u501","input":123}}
```

- `source.sender` 从 person 的 `DisplayName` 现读，去首尾空白；姓名缺失或身份读取失败时回退 ID。
- `source.sender_id` 用于发送者比较、person 记忆读取以及压缩后保留当前人物资料。环境内部通过 `personID()` 取身份；旧环境没有该字段时，从旧 `sender` 取 ID。
- 接收用户输入时解析姓名；模型请求的现有采样路径再次读取，使同一个人的姓名变化也只追加环境差异。
- Event、owners、person 路径、人物环境项的键继续使用稳定 ID。身份资料仍由 person.Record 追加授权记录并折叠，不增加姓名缓存或设置入口。
- 沿用 ADR 0021 的对话串和环境流；历史 transcript 不改写，固定前缀不变。

调用位置：`receiveEnvironment` 生成来源并解析姓名；`sampleEnvironment` 更新姓名、按 ID 读记忆；两处完整快照裁剪按同一 ID 保留人物项。

## 选择过程

1. 采用：只在既有环境来源结构里分开姓名和 ID。改动局限在来源采样与消费处，不增加状态副本、持久化迁移或跨模块协议。
2. 否决：把 Event.Sender 或 person.ID 改成姓名。姓名可变且可重复，会将表示需求传播到权限、路径、远端协议及记忆迁移。
3. 否决：保留 `sender=u501`、另加 `sender_name`。虽然消费方改动少，仍让用户要求更改的 sender 保持内部编号。

接受在每次既有环境采样中读取一个小身份文件，换取姓名以身份存储为真源；接受旧环境的 sender-only 回退，换取原 transcript 保持只追加。两个小方法只负责来源的身份提取与姓名解析，不建立新身份服务。

## 对照回顾

| 依据 | 核对结果 |
| --- | --- |
| 用户本次要求 | sender 展示正式姓名 |
| atlas 身份与记忆 | person ID 跨 Bot 稳定，姓名复用现有字段 |
| atlas 上下文 | 继续只追加差异，旧环境可回放 |
| ADR 0021 | 复用来源环境项，不加机制或第二份账 |
| 六条基本旅程 | 身份信任、记忆与共享对话保持原关联 |
| 现有开发设计 | 不碰 CLI message 和实体注册桩的冲突面 |
| 候选清单 | 本次是用户直接提出的现有身份展示修正，不扩展身份管理功能 |

## 验证

定向回归覆盖模型首请求的姓名与 ID、同一人的改名、旧环境回放和记忆关联；既有环境流回归覆盖切人、重启及快照。真实二进制与 HTTP 入口使用 scripted 模型检查收到的环境值和送达结果，不调用真实模型。没有需要新增 guard 的视觉或人工判断要求。
