# 0038 聊天读取是原 transcript 的窗口，搜索沿用原 FTS

> 主列数据源与搜索已由 [ADR 0039](0039-chat-delivery-timeline.md) 取代；本文的 transcript 窗口、fork 回放和传输上限仍保留给非主列用途。

## 背景

长期Bot原文达4460条/约2.8MB时，一次GET整本超过跨设备pipe单次700KiB预算，前端还把对话读取失败误报整机离线。段文件和全文索引已经存在，缺的是读取装配缝。

## 决定

- 主列窗口仍挂同一GET transcript：无参数默认尾部窗口，before/after排他游标、around搜索定位，带连续seq范围和双向元数据。取消旧“无参数整本”默认；全本仅复用已有流式export。
- 深模块在段存储层拥有范围、快照尾seq、索引字节预算与fork回溯语义，按既有lines偏移读命中段，不让每个调用方各自Entries全读再切。
- 旧fork回溯和通知成功回包可能在窗外，增加可重建的fork_spans/tool_results关系索引；旧索引一次性重建，成功后提交版本，原段追加语义不变。全文检索依旧Bot.Search/FTS5，Web仅增加搜索出口。
- 本机和跨设备UI采用同一预算，正文包括包络小于pipe700KiB；特别大的单条显示明确预览，游标仍前进。不因Bot名称特判。
- 遮罩等待整包就绪后一次揭开；历史分页保持锚点，搜索定位后能前后翻和回最新，读取失败诚实说明对话加载失败。

## 边界

本决定补齐ADR0024的历史翻页需求，沿用ADR0029同设备UI真源与ADR0021只追加对话串。无新WS、无另一份全文索引、无压缩前置、无改旧行。模型上下文组装、权限机制不变。
