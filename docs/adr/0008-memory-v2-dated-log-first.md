# 0008 记忆 v2：默认写日志，常驻快照加差异，带最近 8 条

## 背景
- 两层范围（[ADR 0006](0006-two-memory-scopes.md)）定下之后，暴露出几个问题：
  - `remember` 默认写 profile，每个范围 4 KiB 很快写满，还会混进流水；
  - 常驻记忆不显示日期，新旧事实矛盾时模型分不清；
  - 不给 key 时，同一句话会渲染两遍；
  - 新会话不知道最近发生了什么；
  - 改一条只能按全文 forget 再重写。
- 我们对照了主人自己的 Grok Bot 数据导出（只看形状和外部可见行为）和 Hermes Agent 的公开文档，见 [记忆 v2 规格](../MEMORY-V2.md)。

## 决定
- 新的记忆默认写日志。常驻只放每次对话都要用的稳定事实。
- **快照**：会话开始时和每次压缩后，把两个范围的常驻记忆，加这个 bot 最近 8 条日志（约 1.5 KiB），拍成快照，放在系统提示后面的记忆消息里。会话中途这条消息的字节不变，前缀缓存一直能命中。注入总预算是 `2×4KiB+1.5KiB+512`。
- **差异**：每轮开头拿当前记忆和"模型已经看过的版本"比哈希。变了就追加一条只含逐行差异的 `<environment_update>`，最多约 2 KiB。Bot 自己这一轮写的改动不追加，因为它在工具结果里已经看过。别的 bot、每晚整理、主人手工改的，都会追加。压缩时快照刷新，之前的差异随被压缩的范围一起消失。
- 常驻条目带日期，每个范围显示用量。这是按时间固定注入，不是关键词自动召回。
- 每晚整理直接改，每次改动的 diff 记进日志，可以回滚，错过不补跑。
- （2026-10-17 晚修订）原来的"按唯一子串改写的专用工具"不做了：写记忆改用普通文件工具，见 [ADR 0009](0009-memory-as-folder.md)。

## 考虑过的方案
- 每条加 id：定位最稳，但要改文件格式和迁移，先不做。
- 默认仍写 profile，只靠上限逼着整理：试过，写满太快，整理压力全落在对话中途。
- 按关键词自动召回日志：费 token、扰动上下文，仍然不做（见 CANDIDATES）。
- 每轮都按最新记忆重写记忆消息（现状）：记忆一变，前缀缓存在第二条消息就断了。
- 记忆变了只提示一句"memory: updated"（现状）：模型不知道改了什么。
- 每晚整理先出提议、等主人确认：主人选择直接改，留 diff。

## 后果
- 每次唤醒固定多出约 1.5 KiB。
- 同一个事实可能在快照里是旧值、在后面的差异里是新值，规则写明以后出现的差异为准。
- state 要多存两份记忆文本：快照，和模型已经看过的版本，各约 10 KiB。
- profile 增长变慢，但新事实默认不常驻，要靠最近 8 条或 `recall` 才看得到。
- 子串定位在条目很像时会报"匹配到多条"，模型要给更长的子串。
- 每晚整理会改写模型自己写的记忆，回滚靠日志里的 diff。

## 什么时候重新考虑
- 评测显示 bot 常常漏掉 8 条以外的旧信息。
- 子串冲突经常发生。
- 每晚整理改错的次数，一周超过一次。
