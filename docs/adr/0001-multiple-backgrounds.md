# 0001 插话分叉允许多个后台并行

## 背景
主人要求 Bot 任何时候都能在几秒内回应插话，且不拖慢正在干的活。Grok Bot 的实际体验是：已有后台任务时再提一件事，它立刻开始，原后台进度不受影响。

## 决定
插话时正在跑的一轮分叉成后台；已有后台时新任务立刻开新的 `bg_` 执行器。每个 Bot 最多 3 个后台（可配置）。只有碰同一文件、仓库或工作目录的才排队。前台有硬上限（4 次工具调用、20 秒，只读）。

## 考虑过的方案
- (a) 每句插话分一个叉、不设上限：N 个分支抢文件、各占上下文和费用，前台难以管理。不采用；现方案用上限和资源冲突排队约束它。
- (b) 一个长期后台 + 短前台，第二件长活排到唯一后台之后。**曾采用，已被本条取代**：第二件互不相干的活白白排队，和 Grok Bot 体验不符。
- (c) 由模型事先判断哪些活放后台：模型不一定听，主人否掉。
- (d) 插话时暂停当前的活，答完再接着做：每句都要等当前一步跑完，达不到几秒内。

## 后果
需要资源登记和冲突检测（F3），界面每个后台一张卡（F5）。验收加一条：2 个后台并行期间插话互不影响。
