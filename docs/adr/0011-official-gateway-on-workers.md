# 0011 官方网关跑在 Cloudflare Workers 上，客户端默认连它

## 背景
[ADR 0010](0010-gateway-mailbox-relay.md) 定了跨设备靠信箱中继，代价是"需要一台公网可达的机器跑网关"。普通用户没有这台机器，装好两台 XBot 也配不上对。用户 2026-10-18 定了：我们自己部署一个官方网关，XBot 默认连它，装好就能配对；网关仍然开源，想自建的人在配置里改地址。

## 考虑过的方案
- **共享电脑上跑 Go 网关，用 Cloudflare Tunnel 暴露**：依赖这台电脑一直开着，单点。
- **Workers + Durable Objects**：不依赖任何一台机器，TLS 和全球接入由 Cloudflare 负责，Free 计划够个人用量起步。
- **只给 Go 网关，不做官方部署**：自建门槛留给每个用户，配对体验差。

## 决定
- 官方网关是 `gateway-worker/` 里的 Worker，部署在 `https://xbot.babelgo.cn`。每个收件安装一个信箱 Durable Object，全局一个目录 Durable Object 记安装和配额。
- Go 的 `xbot gateway serve` 保留，作为自建方案。两份实现说同一套 HTTP 协议，必须都通过 `internal/gateway/conformance_test.go`（`XBOT_GATEWAY_URL` 指向被测地址）。协议以 Go 为准。
- 客户端没配网关时用官方地址；配了就用配置里的。默认地址不写进配置。
- 隐私约束：没有配对设备、也没有未用且未过期的邀请时，客户端不联系官方网关，不注册、不轮询，只在本地检查。自建网关的口令（`XBOT_GATEWAY_TOKEN`）只发给显式配置的网关，官方网关不收口令。这两条都要有测试守着。
- 端到端加密不变：网关看得到安装 id、客户端 IP、信封种类（`pair`/`box`/`bounce`/`dir`）、时间、大小，以及密文。仍然不同步文件，每台安装只管自己的数据。
- 官方网关和 Go 协议的有意差异：注册默认开放（Go 不给 `--open` 就要口令）；每个客户端 IP 每个 UTC 日最多 30 个新安装，超了回 429（Go 没有）；IP 只按当天随机密钥做 HMAC 后计数，密钥和计数第二天删掉；安装上限 1000（Go 固定 64）；"最近见到"由信箱每小时最多写一次，Go 每个通过验签的请求都刷新，所以淘汰时间略有不同。

## 后果
- 换来：装好就能跨设备配对，不需要自己的公网机器。
- 代价：Free 计划每天各 10 万次 Worker 请求和 Durable Object 请求、10 万行写入。一台已配对、一直在线的安装每天长轮询约 3,456 次；每个配对对端再加约 96 次目录推送和相应的确认，合计约 3,750 次 Worker 请求、4,000 次 DO 请求和 700 行写入。所以大约撑 20–25 台，对端多了更少。用户多了要换付费计划或改成更省请求的等待方式。
- 注册开放，没通过验签的请求也算 Worker 请求，一个人就能刷完每天的额度，让官方网关对所有人停摆。需要时加 Cloudflare WAF 或限速规则。
- 官方网关是用户运营的服务，安装 id 和通信时间会经过它。

## 什么时候重新考虑
- 用量接近 Free 计划上限，或遭到刷请求，或 Cloudflare 的条款、价格变了。
- 需要不依赖单一云厂商的官方网关。
