# 0029 公网登录后 UI 单源：通过 pipe 读取当前配对设备的静态壳

## 背景

公网账号入口曾把 `internal/web/static` 拷成账号仓的 `public/app`，再经 `sync-app-from-xbot` 和 `sync-public` 发布。设备与云上两份业务壳会漂移，主人看到的菜单与本机 tip 不一致。主人纠正双源，主管确定通过 ADR 0024 的现有 pipe 读取设备壳；设计师的完成标准已对齐。

## 决定

- 登录薄页、账号 API、最小连接引导与大字体仍在账号服务；登录后的 index、脚本、样式、图标等业务资源以**当前选中的配对设备正在运行的二进制**为权威。
- 设备提供 `GET /api/ui/static/<path>`，只读内嵌 `staticFS` 中合法相对路径、允许类型的真实文件；不读工作区，也不使用开发静态目录覆盖。复用 owner 认证、原静态响应的 MIME / ETag / no-cache 语义，带 `X-Xbot-Tip`。未注入构建版本的 `dev` 用内嵌资源摘要区分，不永远返回裸 `dev`。
- 请求仍走现有 pipe 的 `Do` / owner mux / `AuthorizeOwner`；pipe 只允许相对 `/api/` 路径。响应新增 tip、ETag、Cache-Control 白名单字段，请求可带 If-None-Match；不透传任意头或 cookie。
- 700 KiB 正文预算不变，出口在读取前检查文件大小，超限回 413。大字体在云上缓存；JS/CSS 不作为云上缓存例外。
- 账号仓 `/app/` 仅保留 boot、bridge 和资源 worker。worker 仅控制 `/app/` 的文档，把浏览器原生脚本、CSS、图片请求交回其所属页面的现有 pipe；它不建立第二条网络传输，不存业务壳缓存。设备 HTML 内联初始化作为同源临时资源执行，保留 `script-src 'self'`。
- 优先用明确选择的设备；未选择时取在线设备。明确选择的设备离线时不偷偷换到另一台。账号菜单可切设备，切换关闭旧 pipe 并整页重载。无设备、离线、不支持静态出口或资源失败都显示中文说明和重试，不回落旧业务壳。
- `sync-app-from-xbot` 废弃并停止覆盖引导目录；`sync-public` 不再是业务 UI 发版或验收路径，只能用于登录入口、引导和字体的部署维护。设备 UI 更新不需要运行它们。

## 为什么不反代 8788

8788 是设备本机的 HTTP 服务，整站反代会把端口暴露、认证与 URL 改写引入主路径，也不符合只开放 owner `/api/` 的既有边界。直接在内嵌 FS 上提供受限 API 能复用加密传输与 owner 身份，不需要设备公网自托管。账号库与官方网关继续分离。

## 后果与验证边界

设备须运行包含新出口的构建。仅修改磁盘开发静态目录并不改变内嵌资源，需重新构建并重启设备进程。本批不改发版脚本。

浏览器需支持 Web Crypto X25519 和 Service Worker；不支持时显示明确错误。无设备时不会展示业务主界面；pipe 中断不自动重放写请求。公网网络启动时延与主人日用另验，本地浏览器使用真实 Go 账号 / hub / owner handlers 和 scripted 模型。
