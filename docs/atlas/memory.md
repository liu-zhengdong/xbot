# 身份与记忆

> **30 秒版**：人是跨 Bot 的全局身份；记忆分人和 Bot 两层，以 Markdown 加索引存放。

## 边界
负责：人的身份映射、两层记忆、冲突规则，以及启动时把旧的 Bot 与人目录并进 Bot 记忆。不负责：跨设备同步的传输（见 [机器与设备](machines.md)）。

## 怎么运转
- **人**是跨 Bot 的全局身份。各个 Link 负责把外部账号映射到同一个人。
- **记忆分两层**（[ADR 0006](../adr/0006-two-memory-scopes.md)）：
  - **人（person）**：所有 Bot 共享。只放每个 Bot 都需要的、关于主人本人的事实：时区、语言、日常作息、他是谁。每条注明是哪个 Bot、什么时间写的。写入必须显式带 `scope=person`。
  - **Bot（bot）**：这个 Bot 自己的记忆：角色、和主人约定的规则、项目决定。`remember` 省略 scope、自动抽事实、不可信回合里的自动写入，默认都进这一层。不可信回合写进哪一层都标成 untrusted。工作规则和项目决定不进 person。Bot 记忆对每个发送者都可见。
- **不再有 Bot 与人这一层。** 单主人系统里三选一没有默认，一个开发 Bot 把 19 条开发规则写进了共享范围。以后只有真的要多人使用时，才加回按人分开的范围。
- **冲突规则**：关于人本身的事实，以最新的为准；关于怎么做事，以 Bot 自己的记忆为准，压过 person。
- **存储方式**：可以直接编辑的 Markdown 加索引；分常驻层（每次都进上下文，有大小上限）和日志层（需要时检索）。
- **常驻上限**：每个范围的 profile 约 4 KiB；两份一起注入，预算是 `2×4KiB+512`。写超了就报错，要求合并事实、忘掉过时的、或把细节挪到日志层，不静默截断。只拦会让文件变大的写：已经超限的文件（上限之前写的，或同步合并进来的）照样能 forget，一条一条整理；日志层同样只拦变大的写。同步合并不受 profile 上限挡，免得整次合并卡死。注入只有越界才裁，并注明该整理。
- **旧数据**：每个数据根只迁一次（进程内 `sync.Once`，干净跑完写 `.memory-migrated`）。启动和第一次读写都会触发。某个目录读失败就记日志、跳过、留在原地，不让 Remember、Recall、Forget 或启动失败。只合并该 Bot `owners` 里的人，因为 Bot 记忆每个发送者都看得见；其他人的目录改名为 `memory.bak`，不并进去。合并去重，保留时间戳、来源和原来的 kind（空 kind 不改写成 work）。profile 超过 4 KiB 的事实改记日志并写一条说明。日志超过 64 KiB 时，多出来的写到 `log.overflow.md`，检索和 forget 把它和日志一起读，`log.md` 本身不超过 64 KiB。人的同步日志仍是 person 通道。
- **资料库不单独做**：Bot 直接读用户本机的文件和笔记。
