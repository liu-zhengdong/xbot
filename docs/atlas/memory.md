# 身份与记忆

> **30 秒版**：人是跨 Bot 的全局身份；记忆分人和 Bot 两层，以 Markdown 加索引存放。

## 边界
负责：人的身份映射、两层记忆、冲突规则，以及启动时把旧的 Bot 与人目录并进 Bot 记忆。不负责：多台电脑之间的配对与消息（见 [网关](gateway.md)）；记忆不在机器之间同步（[ADR 0012](../adr/0012-retire-node.md)）。

## 怎么运转
- **人**是跨 Bot 的全局身份。各个 Link 负责把外部账号映射到同一个人。
- **记忆分两层**（[ADR 0006](../adr/0006-two-memory-scopes.md)）：
  - **人（person）**：所有 Bot 共享。只放每个 Bot 都需要的、关于主人本人的事实：时区、语言、日常作息、他是谁。每条注明是哪个 Bot、什么时间写的。模型用文件工具编辑标题给出的人记忆路径。
  - **Bot（bot）**：这个 Bot 自己的记忆：角色、和主人约定的规则、项目决定。模型用 `write_file`/`edit_file` 编辑记忆文件；自动抽事实默认进这一层。不可信回合的文件写入须主人确认，自动抽取仍标成 untrusted。工作规则和项目决定不进 person。Bot 记忆对每个发送者都可见。
- **不再有 Bot 与人这一层。** 单主人系统里三选一没有默认，一个开发 Bot 把 19 条开发规则写进了共享范围。以后只有真的要多人使用时，才加回按人分开的范围。
- **冲突规则**：关于人本身的事实，以最新的为准；关于怎么做事，以 Bot 自己的记忆为准，压过 person。同一个键上，最新的那条赢；不可信出处只做标注，不改变取舍。
- **存储方式**：常驻层用可直接编辑的 memory.md（含 ## 索引和带日期的条目）加 memory.index.json，日志层用 log/YYYY-MM.md，每行 `- YYYY-MM-DD HH:MM [source] 文本`，本地时间、按时间排序，无索引 JSON。旧 log.md 与 log.overflow.md 合并到月文件，按分钟、渲染来源和完整正文逐份匹配，保留真实重复记录与出处标记，不截断迁移正文；零时间按 Unix epoch 保存，原文件及索引留作 .bak（冲突用 .bak.N）；中断可重试，未迁移时读取报错。迁移先合并并存的 profile.* 与 memory.md、恢复旧索引元数据，再将 profile.* 留作 .bak 备份；失败而仅剩 profile.md 时读取报错。手改 Markdown 按文本恢复元数据，日期只用于同文条目消歧，索引条目只匹配一次；仅 person 条目解析 via 作者，无索引时按范围补 kind 并识别出处标记。常驻层每次进上下文并有大小上限，日志层按需检索。
- **文件写入守卫**：内核对两个范围的 `write_file`/`edit_file` 持目录锁校验并在违规时恢复；`memory.md` 超过 4 KiB 只许缩小，日志只许向本地当月追加合法行且不超过 64 KiB，索引与锁文件禁止写入，自由文件不限大小。逻辑路径或真实路径落入记忆目录均受保护，拒绝记忆目录本身的文件写入及目录内（含目录自身）的符号链接。不可信回合须主人确认；仅成功的常驻与日志文件改动跳过下一轮差异，回滚失败明确提示路径可能残留被拒内容，快照标题给出文件工具路径。目录根上由存储自己管理的名字（`.lock`、`sync.jsonl`、旧布局的 `log.md`/`log.overflow.md`/`profile.md`、`*.index.json`）一律拒写；`memory.md` 只收存储能读回的三个标题、一个索引段和 `- (YYYY-MM-DD) 文本` 条目；在 macOS 和 Windows 上按大小写不敏感判定（`MEMORY.md` 就是 `memory.md`）。子代理的文件工具同样过守卫，但它的改动算外部改动，前台下一轮能看到差异。不可信回合里写到记忆目录的 `shell`（含先 `cd` 再写）也要主人确认，纯只读命令照常执行。
- **人的记忆只在本机**：人的身份和人的记忆是每台安装自己的存储（`people/<id>/identity.jsonl`、`people/<id>/memory/sync.jsonl`），不在机器之间同步；跨节点同步已于 2026-10-18 随旧的「节点」一起退役（[ADR 0012](../adr/0012-retire-node.md)）。这些日志是本机的事实记录，往模型里注入时仍然只当数据。
- **常驻上限**：每个范围的 profile 约 4 KiB；默认键事实注入为 `- text`，自定义键保留 `- key: text`，person 范围追加 ` via X`；写入和迁移按 memory.md 的实际渲染字节数加每个自定义键的 `len(Key)+2` 计量，文件格式不变。两份一起注入，预算是 `2×4KiB+512`。写超了就报错，要求合并事实、忘掉过时的、或把细节挪到日志层，不静默截断。只拦会让文件变大的写：已经超限的文件（上限之前写的，或同步合并进来的）照样能删减条目，一条一条整理；日志层同样只拦变大的写。同步合并不受 profile 上限挡，免得整次合并卡死。注入只有越界才裁，并注明该整理。
- **注入：快照加差异**（记忆 v2 批 1，已落地）：
  - 写入规则在 `<memory>` 块里紧随 `MemoryRule` 注入，不依赖已保存的 `rules.md`；渲染版本 3 使旧 Bot 下一次唤醒重新拍快照。
  - 记忆渲染版本变化时先清掉所有人的旧视图，重新拍快照，不把格式升级报成记忆差异。会话开始时和每次压缩后，把两层 profile 加 bot 最近 8 条日志（约 1.5 KiB，预算变成 `2×4KiB+1.5KiB+512`）拍成快照存进 State，作为第二条消息；会话中途不改，前缀缓存一直能命中。
  - 每轮开头把当前记忆跟"模型以为的记忆"（已看过的版本加上自己后来的改动）逐行比一遍，不管顺序。有变化就在 `<environment_update>` 里追加一个 `<memory_diff>`，每行带所在小节，如 `+ [Person] - …`，转义尖括号，上限 2 KiB，超了只写增删行数并提示用 `recall`。最近日志那一节只报新增的条目，标题行不算变化。原来那行 `memory: updated` 不再出现。
  - Bot 自己用文件工具改的行（写前写后逐行比，同一进程里串行）记在内核里，下一次唤醒时并进每个相关的快照：bot 范围的改动进所有人的快照，person 范围的只进那个人的。同一轮里别人的改动照样报；别人删掉 bot 自己加的行也会报。进程重启会丢这部分，后果只是自己的改动被当成差异报一次。
  - 快照按人分开：每个人有自己的快照，群聊、别的 bot 和连接器共用一份只含 bot 记忆的。定时器、shell 和子代理（含后台结束）的唤醒沿用当前快照，不来回切换。别的人看不到主人的 person 事实；主人再说话时恢复原来那份。最多再留 8 份，超了丢一份非主人的。限制：transcript 是共享的，主人回合里追加过的差异，之后别人的回合在历史里也看得到。
- **旧数据**：每次进程启动都重新走一遍 `bots/*/people/*/memory`，每个数据根每进程一次。没有持久化的迁移标记；迁过的目录已改名为 `memory.bak`，所以重复走是幂等的。`config.json` 缺失、读不了或不是合法 JSON 时，这个 Bot 的旧目录留在原地。`owners` 为空才算没有主人，旧事实只留在 `memory.bak`。只合并 owners 里的人，其他人的目录改名为 `memory.bak` 并记日志，读不读得动都挪走。主人的目录读失败才留在原地。不让 Remember、Recall、Forget 或启动失败。合并去重，保留时间戳、来源和原来的 kind。profile 放不下的改记日志并写一条说明；说明同样按日志身份匹配，防止中断重试重复写入。person 日志的 Forget 先折叠同步记录，只删除当前仍匹配的键，不影响同键后来更新的值。迁进日志时按月落盘，不受大小守卫限制。普通写入只在当月超过 64 KiB 且继续增长时拒绝，提示压成几条整理记录；同步折叠绕过守卫。无文本查询从最新月份读够 200 条即停，文本查询读全部月份；快照总条数单独按行计数。人的同步日志仍是 person 通道。
- **只读检索**：`recall` 用 BM25 按行检索可见的 bot/person 目录中的 `.md`、`.txt`（递归，跳过备份和符号链接，每文件最多 256 KiB，每次最多 2000 文件、合计 4 MiB，触顶标明搜索不完整），读取各范围时持 `.lock`，拒绝偏离数据根规范路径的符号链接祖先，打开后核对文件 inode；汉字按重叠双字分词。返回最多 20 条 `scope:路径:行号`，正文截到约 200 字，超出提示剩余数量；`scope` 缩小范围，`since=YYYY-MM-DD` 按条目日期筛选常驻与日志、按 mtime 筛选自由文件。
- **演进中**：[ADR 0008](../adr/0008-memory-v2-dated-log-first.md) 和 [ADR 0009](../adr/0009-memory-as-folder.md) 已定：每个范围是一个文件夹（常驻 `memory.md` 带索引，`log/YYYY-MM.md`，其余自由文件），用普通文件工具编辑，只留只读的 `recall`；快照加差异已在批 1 落地（见上）；每晚整理时核对索引。分批落地，见 [记忆 v2 规格](../MEMORY-V2.md)；上面描述的是还没落地的现状，每落地一批就改一处。
- **资料库不单独做**：Bot 直接读用户本机的文件和笔记。
