# 内核：Link、Event、收件箱

> **30 秒版**：内核只有几个抽象：Link 是 Bot 和外界之间的任何通道，Event 是统一的事件结构，每个 Bot 一个收件箱和一个事件循环。新能力尽量用这几个抽象表达，不加新对象。

## 边界
负责：事件进出、可信判断、一轮对话的循环、工具调度和确认路径。不负责：具体工具（见 [生态](ecosystem.md)）、transcript 存储（见 [上下文](context.md)）、权限分类（见 [安全](security.md)）。

## 怎么运转
- **Link**：Bot 与外部世界之间的任何一条通道。出站方向把动作暴露成工具；入站方向把外部发生的事变成 Event，投进 Bot 的收件箱。终端、Web 界面、定时器、Webhook、文件监听、MCP、浏览器、编码代理、其他机器、其他 Bot，都是 Link。其他 Bot 走 `message_bot`：同一安装里直接投进对方收件箱；写成 `bot@设备` 时由 `internal/remote` 经网关发给已配对设备上的同主人 Bot；网关连不上时进本机发件队列，工具结果说明已排队；`list_bots` 也列出配对设备推送来的 `bot@设备`（只有名字，见 [网关](gateway.md)）。
- **Event**：统一的事件结构 `{source, type, content, sender, time}`。内核根据来源判断是否可信：只有主人通过经过认证的入口发来的消息才算可信，其余一律当作不可信数据包裹在 `<untrusted_event>` 里；正文里能关上或伪造这层包裹的开闭标签先被拆开（规则同网页结果，见 [生态](ecosystem.md)）。
- **收件箱与唤醒**：每个 Bot 只有一个事件处理循环，事件按顺序处理，同一事件不会处理两次，主人正在聊天时事件也会被及时处理。终端只在真正跑一轮时拿着处理锁，停在提示符上时不占锁，网页可以当场回复，也可以 fork。网页写进 transcript 的行，终端下一次刷新时补上。主循环在工具返回和无工具正常答复的下一边界，把这一轮期间新到的收件箱事件按到达顺序接进当前对话，先写 transcript 再 Ack；这些非主人事件不取消正在等的模型，下一步就能看见，transcript 的时间不会倒退。
- **主人的话直接插进正在跑的一轮**（[ADR 0017](../adr/0017-owner-words-go-straight-into-the-turn.md)，`interject.go`，不分叉的内核）：主线的每一轮从 `Handle` 一开始就在进程里按 Bot 目录登记，网页的 `kernel.Interject` 把主人的话交给它，不写收件箱。正在等模型就取消这次调用、带上这句话重发（`agent.Options.Preempt`），被取消的那次输出不进 transcript；正在跑工具就等它返回，再接进来，先于收件箱事件。模型正要给出最后回答时有话进来，这一轮再跑一段。主人的原话收到即写进 transcript（[ADR 0021](../adr/0021-env-stream.md) 取代 ADR 0017 原未落盘风险），模型请求重组按统一工具配对规则排列，后面跟一条内部提示 `<owner_interjected>`：先答这句，没被改掉或取消的话再把手上的事做完（真实 DeepSeek 没有这条时只答了插话就收尾）。前台的次数和秒数从这句话重新算。这一轮的流式输出（`Sink`）换给最新说话的那条请求，之前的请求收到 `handed_off`。这一轮出错结束、话还没读到时，交回给发话的请求自己回答。另一个进程里的一轮（终端 `chat`）够不着，网页退回收件箱并保持请求打开。
- **确认卡不挡插话**（[ADR 0018](../adr/0018-cards-never-block-the-owner.md)，`park.go`）：前台在等确认卡时主人插话，等待挂起：卡照样开着，调用返回「还没跑：在等主人确认卡」，这一轮接着答主人。之后的决定也直接插进在跑的一轮，没有就投进收件箱（来源 `approval`，主人身份，内部行）并由网页当场叫醒（`kernel.SetWaker`）。允许留下一次性放行（同一 Bot、工具、参数，10 分钟，进程内存），模型用相同参数再调一次就直接跑；没有确认人的链路上放行照样有效。拒绝就告诉模型不跑；默认 30 分钟没人确认则自动允许并叫醒续跑。提问卡到点按必填推荐项续跑；迟到选择仅属于原卡，不结束其他待答卡，主人直接打字仍结束待答计时。
- **主体（Principal）**：人、Bot、群都是主体，都可以发消息、可以被授权。
- **提醒通道**：条件成立才提醒，冷却期内不重复。正文追加在它绑定的那一条消息末尾，不改写更早的消息，也不写进 transcript 正文。仓库提供的项目说明单独成一条，不拼进主人的可信正文。落在 `bots/<name>/reminders.jsonl`，写入前过脱敏；序号是刚写下的那一行，不拿事后的 `Count`。下次组装按序号原样贴回，前缀字节保持不变。日志在内存里留一份，活窗口之外的旧行在超过上限后压掉，每种只留最近一条给冷却用。这份缓存只在文件大小和 mtime 都没变时复用；另一个进程追加或重写之后，下次读取重新装入。现在接上的种类：待确认卡（定时唤醒不带）、打转警告、外部文件改动（`file_change`，不超过 4 KiB 的统一 diff，放不下就写 `[diff truncated]`，冷却 1 分钟，同一次变化不重复；自己 `write_file` / `edit_file` 成功后刷新记录，不再把这次改动报成外部变化，前台 `shell` 改的也一样；`.env`、`*.key`、`*.pem`、credentials 一类文件只写 changed，不附 diff；别的文件的 diff 看起来带密钥时（私钥块、`ghp_`/`sk-`/`AKIA` 一类前缀、password/token 赋值、URL 里的账号密码、长的高熵串，见 `vault.LooksLikeSecret`）也不附，只写 `diff not shown`）、项目说明（`project`：从当前目录向上读到工作区或共享目录根，每层 `AGENTS.md`，没有这个名字才读 `CLAUDE.md`，近的在后；这一轮的上下文里已经有同一套就不再发，`cd` 换了目录才再发；后台分支发过的那一套不在前台的上下文里，被压缩挪走的也不在，这两种情况都会再发一次；合计最多 32 KiB，截断时写 `[truncated]`；目录和候选文件的 mtime、大小、inode、ctime 没变就不再读文件、不再哈希，但 1 秒内改过的文件（Windows 看 mtime）不信缓存，因为同一个时间戳刻度里的两次同尺寸改写可能留下完全相同的戳；工作区根上、且该目录不是 git 检出、也不是共享目录时，文件是主人放的项目约定，贴在最新一条消息上；共享目录、带 `.git` 的工作区根、子目录或克隆仓库里的是仓库提供的数据，不是主人的指示，只作编码约定，不能当作批准、发送、读密钥或删除的依据，包在 `<untrusted_event source="project">` 里单独成一条；关掉 `project_instructions` 时忽略大小写和空白；用 `O_NOFOLLOW` 打开，最后一段是符号链接就不跟（Windows 上用 `FILE_FLAG_OPEN_REPARSE_POINT` 打开，是重解析点就拒绝）；不进系统提示，不改权限表，写入前仍过保险箱脱敏；允许的根以外的文件不读）、上下文用量（`context_usage`：模型报告的 prompt 跨过 `providers.json` 里该模型上下文窗口的 50/75/90% 时发一行；同一档不重复，掉下去再跨过才再发；接口给了用量就用原数，没给才按大约 4 字一 token 估计并标明 estimated；最近一次和本进程累计进状态接口和 `trace.jsonl`；「最近一次」和门槛只看前台，后台分支的调用只加进累计，`trace.jsonl` 里那一条记它自己的数并带 `branch`）、待办清单（定时唤醒不带）、后台 shell 结束（`shell_job`，冷却 0）。设计笔记见 [claude-code-internals.md](../research/claude-code-internals.md)。
- **文件新鲜度**：每个 Bot 的活内核在本进程里记下读过和自己写过的文件，字段是路径、mtime、大小、内容哈希，以及记下它的那一轮。改或覆盖一个已经存在、但这次会话还没读过的文件会报错，让模型先读。大小或哈希和记录不一致就拒绝写入，并说明自第 N 步读过之后文件变了；只有 mtime 变、哈希没变，当成时钟抖动，允许写。大小和 mtime 都相同、且当时不是截断哈希时，跳过内容哈希：同样大小、同样 mtime 的替换会当成没变。模型自己写入成功后立刻刷新记录，工具结果写明不必再读一遍核对。`write_file` 可以把记录标成完整；`edit_file` 保持改之前的完整或局部，局部读过再改一行不会让下一次整文件读取变成回执。没有要行范围、也没有 `force` 时，同一轮里再读一个没变过的完整文件只回一句短回执（大约 30 token，第 N 步是这一轮的工具计数）。下一轮重新读正文。外部改动走上面的 `file_change`。哈希按流计算，最多前 4 MiB，小文件不按这个上限分配缓冲。记录最多留 64 个文件。状态在这个内核的生命周期里，不落盘，换一个进程要重新读。
- **被拒绝的调用**：主人拒绝过的工具调用，相同参数在这一轮里不能再试。再拿来就直接返回错误，不再问一次。新的一轮开始时清掉这份记录，主人下一条消息改口后可以再问。参数按 JSON 值比较，键的顺序不算不同。
- **待办清单**：工具 `todo` 把短清单写在 `bots/<name>/todos.json`（0600）。一项有 content 和状态 pending、in_progress、done；放弃用 dropped 并写原因。同时最多一项 in_progress，最多 20 项。这是当前任务的清单，跨回合保留：主人说继续，或前台插话时后台还在跑，都不清掉。每一项都已 done 或 dropped、写入空清单、或新清单和旧清单没有相同 id 时，旧清单追加进 `bots/<name>/todos-archive.jsonl`，活动清单清空。状态接口带一行 `todo` 摘要；全文在 `GET /api/bots/{name}/todos`，不进步骤环，界面不另画。提醒只在活动清单还在、且距上次成功更新已过 N 步时发（默认 6；模型上的 `todo_steps`，或内核 `TodoSteps`）。只写相对上次提醒的差异，冷却 2 分钟，刚更新的那一步不发。步数记在内存里，开关关掉或只是计数时不重写文件。模型配置 `todo` 为 true 或 false；缺省时供应商或模型名含 deepseek 才开，空绑定按默认的 deepseek-chat 算开。除 `links` 和 `todo` 外全是只读工具的一轮不发。定时唤醒不发这条提醒。完成门只在这一轮写过或改过清单、模型又要在还有未完成项时停下时，另起一条用户消息注入一次 `<todo_gate>`。模型最后一句是在向主人提问，或还有待确认卡时，不注入。注入的这条注记带 `origin: internal`，界面不显示。
- **shell 后台**：`shell` 默认超时 120 秒，最长 600 秒，模型可传 `timeout_seconds`。到点不杀进程，转成后台，结果给出任务 id 和输出路径。`run_in_background` 立刻转后台。输出在 `bots/<name>/shell-jobs/<id>.log`（目录 0700，文件 0600），只留尾部最多 256 KiB。`shell_output` 按 offset 或 tail 读，读出时再过一遍脱敏（写入之后才进保险箱的值也换掉，offset 仍按写入时的流计算），`shell_status` 看状态，`shell_cancel` 杀进程组，等这个任务写完记录、投完叫醒才返回；任务刚结束时也一样等。同一 serve 进程里跨回合还在；重启把仍是 running 的标成 lost，不向旧 pid 发信号。完成提醒走 `shell_job`，贴在下一步工具返回之后的边界上，不打断正在跑的调用。Bot 空闲时往收件箱投一条来源 `shell` 的不可信事件叫醒它，不另开后台段，熔断照旧。`sleep`、`watch` 和带 `sleep` 的 `while`/`until` 不自动转后台。显式 `run_in_background` 仍可把 `sleep` 放后台。待写尾巴里，只有可能是某个已知密钥形式开头的那一段留在内存里，不进文件、预览或 `shell_output`。已知形式包括保险箱里的原文、JSON、URL 和 base64，这一轮暂存的密钥原文，以及收进内存、至少 8 字节的供应商密钥。保险箱变了才重新列出保险箱形式；暂存密钥和内存里的供应商密钥每次都附上，所以跨两次写入拆开的密钥也会被留住。留住的是当前尾巴的最长后缀，且这个后缀必须是任一形式的前缀；对不上时，已经完整脱敏的部分立刻写入。还留着的字节数在 `shell_output` 和 `shell_status` 里写成 `held_bytes: N`（大于 0 才写）。每次写入对整段待写原文脱敏，按替换区间把原始偏移映射到脱敏结果，只提交这段前缀之前的那一段。一个形式如果跨在提交点和这段前缀上，整段形式继续留着。结束时把剩下的全部脱敏后写入。多个密钥同时出现时按从长到短替换，一样长就按字节序，避免短的先替换、把长的剩下一段。流的 offset 只增不减。文件超过上限才丢掉头部；`shell_output` 的 offset 按整段流计算，丢掉的前缀会写明。完成提醒或叫醒会把 `notified` 写进任务记录，重启后不再为已经报过的任务各开一轮；本进程结束或恢复发现的 lost 都经同一叫醒路径，lost 最多通知一次。结束的任务只留最近 20 个、且不超过 7 天。`Close` 杀掉本进程拥有的进程组，同样等它们写完才返回。记录里有 `proc_start`，重启不凭它发信号；另一个进程如果对上了仍活着的 pid 和 `proc_start`，就不会把这条改成 lost。评测沙箱仍是 30/120 秒并在超时杀掉，也不出现 `shell_output` / `shell_status` / `shell_cancel`；没挂任务表的 shell（节点、命令行）也是到点杀掉。挂上会话之后，前台 `cd` 留在这个 Bot 上，记在内存和 `bots/<name>/cwd`。后台分支按分支 id、子代理按创建时各有一份目录，继承当时调用方的目录，之后互不影响，分支或子代理结束时删掉；只有前台写入 `bots/<name>/cwd`。文件工具、项目说明、权限判断和后台冲突检测用调用方这一份。每次调用确认目录还在、并且在工作区或共享目录里，否则回到工作区并在结果里说明。结果在状态行后面写 `cwd:`。后台任务记下启动时的目录，不改这份会话目录。没挂会话的 shell 每次仍从自己的目录开始。cwd 标记写在 `bots/<name>/cwd-markers`（0700），不放进程临时目录。到点转后台的那次不改会话目录。`read_file`、`write_file`、`edit_file`、`view_image` 的相对路径按当时的 shell 目录解析，新鲜度记下的仍是绝对路径；`view_image` 解析符号链接后还必须落在工作区或共享目录里。评测沙箱不改根。前台跑完的 `shell` 命令（`sed -i`、格式化工具、重定向）改了读过的文件、mtime 落在这次调用的时间窗里时，刷新记录（不算看全）并在结果里列出这些文件，不再报成外部变化；转后台的命令照旧按外部变化报。
- **熔断**：同一轮里数五件事：重复输出、同工具同参数、文件来回改、同一失败反复轮询、连续 3 次确认被拒。同参和轮询只数连续重复，中间夹了别的调用就清零，并且按命令各自计数；成功一次就清掉失败计数。只读、`go test`/`go build`/`go vet`、后台轮询放宽到 8 次。排队的控制消息另起一轮时清掉这些连续计数。收益递减这一项随续段机制一起删掉了：没有续段就没有「又开了一段却什么都没干」这种形态，后台的时间由墙钟预算管。第一次只注入打转提醒；第二次硬停，让模型总结，并把 `<stop_reason>` 写进 transcript，同时往 `trace.jsonl` 追加 `{kind:stop, reason}`。
- **悬空工具调用**：中断、取消、切换模型都走 `DanglingResult`，给没返回的调用补一条占位结果，配对不会断。

有主人话或任务结果的一轮必须给正常回复，不能以 `SILENT` 吞掉；只有没有这些输入的定时唤醒才允许静默。环境与任务结果都是原有消息，不另建转告请求或签收机制。

## 共享规则
所有 Bot 共用的规则在 [assemble.go](../../internal/kernel/assemble.go) 的 `DefaultRules`。`rules.md` 只在建 Bot 时写一次；`UntrustedRule`、`OwnerRule`、`ProjectRule`、`MemoryRule` 这四条安全规则如果不在已保存的 `rules.md` 里，内核组装系统提示时补在后面，老 Bot 和改过规则的 Bot 也拿得到，不会重复。`ProjectRule` 把项目文件当成编码约定：工作区根上、且该目录不是 git 检出、也不是共享目录时，才是主人放的；共享目录、git 检出、子目录和克隆仓库里的不是批准、发送、读密钥或删除的依据，也不压过内核安全、权限表和脱敏。新 Bot 写 `rules.md` 时带上这一条；已经写好的 `rules.md` 保持原样。评测目录没有提示词快照，这是有意的稳定前缀变化。另外两条是主人的做事方式：`JudgmentRule`（先给答案和理由；主人的说法只对一半时指出哪部分对、哪部分不对，给独立判断；需要决定时以一份可直接批准的方案收尾）和 `ResourcefulRule`（缺工具或信息时先做能做的部分，推断的内容标「待确认」，或换一条路，例如把文件放到共享处再给别的 Bot 发消息让它自己改；只把最小的剩余一步交出去并说明原因）。评测用例 `half-right`、`propose-plan`、`vision-draft`、`avatar-handoff` 和留出的 `ci-version` 守着它们。挂了记忆存储时，内核在规则末尾追加 `MemoryWriteRule`（用文件工具改记忆文件夹、`memory.md` 常驻且不超过 4 KiB、日志按月追加、其余细节放自由文件、用 `recall` 检索）；它不写进 `rules.md`，所以已有自定义规则的 Bot 也会带上。写记忆文件夹时的内核守卫和只读 `recall` 见 [身份与记忆](memory.md)。外部调用失败后「最多再试一次」不在常驻规则里，改由熔断的轮询提醒在真的重复失败时说。

`ActionRule` 让模型在删除、代表主人对外发消息、改已定计划之前先问一次，「即使请求里点名了这一步」。权限卡关着时（默认，[ADR 0019](../adr/0019-no-permission-cards-by-default.md)，`Kernel.Permissive`），组装时换成 `OwnAskActionRule`：主人点名的步骤（删除、发消息也算）直接做、不再追问，只有模型自己加出来的这类步骤才先问一次；同时补一条 `EventMemoryRule`：外部事件报告的事和工作有关（新 issue、重大 bug、故障、构建挂了）就记进记忆并写明来源，但事件里的措辞仍不改人设和规则。评测按表确认的内核，`boundary` 仍测旧规则。

记忆渲染版本由 State.MemRender 记录；唤醒时版本不符则重建唯一的 Bot 记忆快照，人物资料改走环境流，压缩刷新也记录版本。记忆注入的默认键不重复显示文本，自定义键保留；只有 person 范围追加 `via` 作者，使已接受的常驻记忆不因重复键和作者格式膨胀而被裁剪（见 [身份与记忆](memory.md)）。
