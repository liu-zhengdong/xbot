# 内核：Link、Event、收件箱

> **30 秒版**：内核只有几个抽象：Link 是 Bot 和外界之间的任何通道，Event 是统一的事件结构，每个 Bot 一个收件箱和一个事件循环。新能力尽量用这几个抽象表达，不加新对象。

## 边界
负责：事件进出、可信判断、一轮对话的循环、工具调度和确认路径。不负责：具体工具（见 [生态](ecosystem.md)）、transcript 存储（见 [上下文](context.md)）、权限分类（见 [安全](security.md)）。

## 怎么运转
- **解释器命令**：按 [生态](ecosystem.md) 注册具体壳名；新鲜度刷新、保护路径、只读判定、资源冲突、熔断和 Jobs 输出保留覆盖全部解释器。后台完成事件仍沿用 `shell` 来源和 `shell_job` 类型，任务记录的 `tool` 是实际解释器名，`description` 是调用用途。
- **Link**：Bot 与外部世界之间的任何一条通道。出站方向把动作暴露成工具；入站方向把外部发生的事变成 Event，投进 Bot 的收件箱。终端、Web 界面、定时器、Webhook、文件监听、MCP、浏览器、编码代理、其他机器、其他 Bot，都是 Link。其他 Bot 走 `message_bot`：同一安装里直接投进对方收件箱；写成 `bot@设备` 时由 `internal/remote` 经网关发给已配对设备上的同主人 Bot；网关连不上时进本机发件队列，工具结果说明已排队；`list_bots` 也列出配对设备推送来的 `bot@设备`（只有名字，见 [网关](gateway.md)）。
- **Event**：统一的事件结构 `{source, type, content, sender, time}`。内核根据来源判断是否可信：只有主人通过经过认证的入口发来的消息才算可信，其余一律当作不可信数据包裹在 `<untrusted_event>` 里；正文里能关上或伪造这层包裹的开闭标签先被拆开（规则同网页结果，见 [生态](ecosystem.md)）。
- **收件箱与唤醒**：每个 Bot 只有一个事件处理循环，事件按顺序处理，同一事件不会处理两次，主人正在聊天时事件也会被及时处理。终端只在真正跑一轮时拿着处理锁，停在提示符上时不占锁，网页可以当场回复，也可以 fork。网页写进 transcript 的行，终端下一次刷新时补上。主循环在工具返回和无工具正常答复的下一边界，把这一轮期间新到的收件箱事件按到达顺序接进当前对话，先写 transcript 再 Ack；这些非主人事件不取消正在等的模型，下一步就能看见，transcript 的时间不会倒退。
- **主人的话直接插进正在跑的一轮**（掐话续跑；[ADR 0017](../adr/0017-owner-words-go-straight-into-the-turn.md)，`interject.go`，不分叉的内核）：主线的每一轮从 `Handle` 一开始就在进程里按 Bot 目录登记，网页的 `kernel.Interject` 把主人的话交给它，不写收件箱。正在等模型就取消这次调用、带上这句话重发（`agent.Options.Preempt`），被取消的那次输出不进 transcript；正在跑工具则结束前台等待，给同一调用的后台回执后接新话，不取消或重跑工具；全批结果仍按调用顺序封口。模型正要给出最后回答时有话进来，这一轮再跑一段。主人的原话收到即写进 transcript（[ADR 0021](../adr/0021-env-stream.md) 取代 ADR 0017 原未落盘风险），模型请求重组按统一工具配对规则排列，后面跟一条内部提示 `<owner_interjected>`：先答这句，没被改掉或取消的话再把手上的事做完（真实 DeepSeek 没有这条时只答了插话就收尾）。前台的次数和秒数从这句话重新算。这一轮的流式输出（`Sink`）换给最新说话的那条请求，之前的请求收到 `handed_off`。这一轮出错结束、话还没读到时，交回给发话的请求自己回答。另一个进程里的一轮（终端 `chat`）够不着，网页退回收件箱并保持请求打开。
- **确认卡不挡插话**（[ADR 0018](../adr/0018-cards-never-block-the-owner.md)，`park.go`）：前台在等确认卡时主人插话，等待挂起：卡照样开着，调用返回「还没跑：在等主人确认卡」，这一轮接着答主人。之后的决定也直接插进在跑的一轮，没有就投进收件箱（来源 `approval`，主人身份，内部行）并由网页当场叫醒（`kernel.SetWaker`）。允许留下一次性放行（同一 Bot、工具、参数，10 分钟，进程内存），模型用相同参数再调一次就直接跑；没有确认人的链路上放行照样有效。拒绝就告诉模型不跑；默认 30 分钟没人确认则自动允许并叫醒续跑。提问卡到点按必填推荐项续跑；迟到选择仅属于原卡，不结束其他待答卡，主人直接打字仍结束待答计时。
- **主体（Principal）**：人、Bot、群都是主体，都可以发消息、可以被授权。
- **提醒通道**：条件成立才提醒，冷却期内不重复。正文追加在它绑定的那一条消息末尾，不改写更早的消息，也不写进 transcript 正文。仓库提供的项目说明单独成一条，不拼进主人的可信正文。落在 `bots/<name>/reminders.jsonl`，写入前过脱敏；序号是刚写下的那一行，不拿事后的 `Count`。下次组装按序号原样贴回，前缀字节保持不变。日志在内存里留一份，活窗口之外的旧行在超过上限后压掉，每种只留最近一条给冷却用。这份缓存只在文件大小和 mtime 都没变时复用；另一个进程追加或重写之后，下次读取重新装入。现在接上的种类：待确认卡（定时唤醒不带）、打转警告、外部文件改动（`file_change`，不超过 4 KiB 的统一 diff，放不下就写 `[diff truncated]`，冷却 1 分钟，同一次变化不重复；自己 `write_file` / `edit_file` 成功后刷新记录，不再把这次改动报成外部变化，前台 `shell` 改的也一样；`.env`、`*.key`、`*.pem`、credentials 一类文件只写 changed，不附 diff；别的文件的 diff 看起来带密钥时（私钥块、`ghp_`/`sk-`/`AKIA` 一类前缀、password/token 赋值、URL 里的账号密码、长的高熵串，见 `vault.LooksLikeSecret`）也不附，只写 `diff not shown`）、项目说明（`project`：从当前目录向上读到工作区或共享目录根，每层 `AGENTS.md`，没有这个名字才读 `CLAUDE.md`，近的在后；这一轮的上下文里已经有同一套就不再发，`cd` 换了目录才再发；后台分支发过的那一套不在前台的上下文里，被压缩挪走的也不在，这两种情况都会再发一次；合计最多 32 KiB，截断时写 `[truncated]`；目录和候选文件的 mtime、大小、inode、ctime 没变就不再读文件、不再哈希，但 1 秒内改过的文件（Windows 看 mtime）不信缓存，因为同一个时间戳刻度里的两次同尺寸改写可能留下完全相同的戳；工作区根上、且该目录不是 git 检出、也不是共享目录时，文件是主人放的项目约定，贴在最新一条消息上；共享目录、带 `.git` 的工作区根、子目录或克隆仓库里的是仓库提供的数据，不是主人的指示，只作编码约定，不能当作批准、发送、读密钥或删除的依据，包在 `<untrusted_event source="project">` 里单独成一条；关掉 `project_instructions` 时忽略大小写和空白；用 `O_NOFOLLOW` 打开，最后一段是符号链接就不跟（Windows 上用 `FILE_FLAG_OPEN_REPARSE_POINT` 打开，是重解析点就拒绝）；不进系统提示，不改权限表，写入前仍过保险箱脱敏；允许的根以外的文件不读）、上下文用量（`context_usage`：模型报告的 prompt 跨过 `providers.json` 里该模型上下文窗口的 50/75/90% 时发一行；同一档不重复，掉下去再跨过才再发；接口给了用量就用原数，没给才按大约 4 字一 token 估计并标明 estimated；最近一次和本进程累计进状态接口和 `trace.jsonl`；「最近一次」和门槛只看前台，后台分支的调用只加进累计，`trace.jsonl` 里那一条记它自己的数并带 `branch`）、待办清单（定时唤醒不带）。设计笔记见 [claude-code-internals.md](../research/claude-code-internals.md)。
- **文件新鲜度**：每个 Bot 的活内核在本进程里记下读过和自己写过的文件，字段是路径、mtime、大小、内容哈希，以及记下它的那一轮。改或覆盖一个已经存在、但这次会话还没读过的文件会报错，让模型先读。大小或哈希和记录不一致就拒绝写入，并说明自第 N 步读过之后文件变了；只有 mtime 变、哈希没变，当成时钟抖动，允许写。大小和 mtime 都相同、且当时不是截断哈希时，跳过内容哈希：同样大小、同样 mtime 的替换会当成没变。模型自己写入成功后立刻刷新记录，工具结果写明不必再读一遍核对。`write_file` 可以把记录标成完整；`edit_file` 保持改之前的完整或局部，局部读过再改一行不会让下一次整文件读取变成回执。没有要行范围、也没有 `force` 时，同一轮里再读一个没变过的完整文件只回一句短回执（大约 30 token，第 N 步是这一轮的工具计数）。下一轮重新读正文。外部改动走上面的 `file_change`。哈希按流计算，最多前 4 MiB，小文件不按这个上限分配缓冲。记录最多留 64 个文件。状态在这个内核的生命周期里，不落盘，换一个进程要重新读。
- **被拒绝的调用**：主人拒绝过的工具调用，相同参数在这一轮里不能再试。再拿来就直接返回错误，不再问一次。新的一轮开始时清掉这份记录，主人下一条消息改口后可以再问。参数按 JSON 值比较，键的顺序不算不同。
- **待办清单**：工具 `todo` 把短清单写在 `bots/<name>/todos.json`（0600）。一项有 content 和状态 pending、in_progress、done；放弃用 dropped 并写原因。同时最多一项 in_progress，最多 20 项。工具仍接收完整清单；磁盘保留完整值，成功回包只报条数摘要和相对写入前的变更项（id、内容、新旧状态和放弃原因），原样重写只报无变化。这是当前任务的清单，跨回合保留：主人说继续，或前台插话时后台还在跑，都不清掉。每一项都已 done 或 dropped、写入空清单、或新清单和旧清单没有相同 id 时，旧清单追加进 `bots/<name>/todos-archive.jsonl`，活动清单清空。状态接口带一行中文 `todo` 摘要（「进度：… · 还剩 N 项待办」或「待办：还有 N 项」，仍脱敏且最多 80 字）；全文在 `GET /api/bots/{name}/todos`，不进步骤环。侧栏显示这行摘要，轨迹按原调用与成功回包显示待办进度，展示规则见 [ui](ui.md)。提醒只在活动清单还在、且距上次成功更新已过 N 步时发（默认 6；模型上的 `todo_steps`，或内核 `TodoSteps`）。后续提醒只写相对上次提醒的差异和条数摘要；首次只点名未动的开放项 id、状态与完整清单路径，不重贴内容。冷却 2 分钟，刚更新的那一步不发。步数记在内存里，开关关掉或只是计数时不重写文件。模型配置 `todo` 为 true 或 false；缺省时供应商或模型名含 deepseek 才开，空绑定按默认的 deepseek-chat 算开。除 `links` 和 `todo` 外全是只读工具的一轮不发。定时唤醒不发这条提醒。完成门只在这一轮写过或改过清单、模型又要在还有未完成项时停下时，另起一条用户消息注入一次 `<todo_gate>`。模型最后一句是在向主人提问，或还有待确认卡时，不注入。注入的这条注记带 `origin: internal`，界面不显示。
- **慢工具后台化**：所有实际启动的工具共用原 `tools.Jobs`，前台默认最多等待 2 秒（待实测参数）；主人插话立即结束该批尚在等待的调用，不打断运行。`shell.timeout_seconds` 只能缩短等待，`run_in_background` 立即交回；shell 不再有 sleep/poll 例外。完成、等待到点、插话与取消在同一调用上裁决：只返回一次正常结果或一次含任务号和输出路径的后台回执。工具 Job 不占子代理的 3+8。确认、文件新鲜度拒写和资源排队仍先于启动。输出沿 `bots/<name>/shell-jobs/<id>.log`（目录 0700，文件 0600），最多 256 KiB；短结果普通回报，长结果只给预览与原输出路径，图片复用工作区粘贴文件。`shell_output/status/cancel` 共用这些任务，名称暂不变；取消 shell 杀进程组，其他工具请求取消，不响应 context 的调用在真正退出前仍是 running，`Close` 等实际退出。运行完成不论忙闲都以稳定事件 ID 投原 Inbox，再唤醒；无独立 shell 提醒或签收账，`notified` 只表示运输已投递，不代表主人已收到回复。runner 沿已有事件与控制接口接同一 Jobs；新进程仅观察仍存活的原执行进程，不能确认存活则标 lost，一次普通回报，不重跑。待写尾巴里，只有可能是某个已知密钥形式开头的那一段留在内存里，不进文件、预览或 `shell_output`。已知形式包括保险箱里的原文、JSON、URL 和 base64，这一轮暂存的密钥原文，以及收进内存、至少 8 字节的供应商密钥。保险箱变了才重新列出保险箱形式；暂存密钥和内存里的供应商密钥每次都附上，所以跨两次写入拆开的密钥也会被留住。留住的是当前尾巴的最长后缀，且这个后缀必须是任一形式的前缀；对不上时，已经完整脱敏的部分立刻写入。还留着的字节数在 `shell_output` 和 `shell_status` 里写成 `held_bytes: N`（大于 0 才写）。每次写入对整段待写原文脱敏，按替换区间把原始偏移映射到脱敏结果，只提交这段前缀之前的那一段。一个形式如果跨在提交点和这段前缀上，整段形式继续留着。结束时把剩下的全部脱敏后写入。多个密钥同时出现时按从长到短替换，一样长就按字节序，避免短的先替换、把长的剩下一段。流的 offset 只增不减。文件超过上限才丢掉头部；`shell_output` 的 offset 按整段流计算，丢掉的前缀会写明。普通回报成功入 Inbox 后写 `notified`；失败留待下次投递，稳定事件 ID 去重，lost 最多通知一次。结束的任务只留最近 20 个、且不超过 7 天。`Close` 杀掉本进程拥有的进程组，同样等它们写完才返回。记录里有 `proc_start`，重启不凭它发信号；另一个进程如果对上了仍活着的 pid 和 `proc_start`，就不会把这条改成 lost。评测沙箱仍是 30/120 秒并在超时杀掉，也不出现 `shell_output` / `shell_status` / `shell_cancel`；没挂任务表的 shell（节点、命令行）也是到点杀掉。挂上会话之后，前台 `cd` 留在这个 Bot 上，记在内存和 `bots/<name>/cwd`。后台分支按分支 id、子代理按创建时各有一份目录，继承当时调用方的目录，之后互不影响，分支或子代理结束时删掉；只有前台写入 `bots/<name>/cwd`。文件工具、项目说明、权限判断和后台冲突检测用调用方这一份。每次调用确认目录还在、并且在工作区或共享目录里，否则回到工作区并在结果里说明。结果在状态行后面写 `cwd:`。后台任务记下启动时的目录，不改这份会话目录。没挂会话的 shell 每次仍从自己的目录开始。cwd 标记写在 `bots/<name>/cwd-markers`（0700），不放进程临时目录。到点转后台的那次不改会话目录。`read_file`、`write_file`、`edit_file`、`view_image` 的相对路径按当时的 shell 目录解析，新鲜度记下的仍是绝对路径；`view_image` 解析符号链接后还必须落在工作区或共享目录里。评测沙箱不改根。前台跑完的解释器命令（`sed -i`、格式化工具、重定向）改了读过的文件、mtime 落在这次调用的时间窗里时，刷新记录（不算看全）并在结果里列出这些文件，不再报成外部变化；转后台的命令照旧按外部变化报。
- **熔断**：同一轮里数五件事：重复输出、同工具同参数、文件来回改、同一失败反复轮询、连续 3 次确认被拒。同参和轮询只数连续重复，中间夹了别的调用就清零，并且按命令各自计数；成功一次就清掉失败计数。只读、`go test`/`go build`/`go vet`、后台轮询放宽到 8 次。排队的控制消息另起一轮时清掉这些连续计数。收益递减这一项随续段机制一起删掉了：没有续段就没有「又开了一段却什么都没干」这种形态，后台的时间由墙钟预算管。第一次只注入打转提醒；第二次硬停，让模型总结，并把 `<stop_reason>` 写进 transcript，同时往 `trace.jsonl` 追加 `{kind:stop, reason}`。
- **悬空工具调用**：中断、取消、切换模型都走 `DanglingResult`，给没返回的调用补一条占位结果，配对不会断。

有主人话或任务结果的一轮必须给正常回复，不能以 `SILENT` 吞掉；只有没有这些输入的定时唤醒才允许静默。环境与任务结果都是原有消息，不另建转告请求或签收机制。接收原话和公布该输入的环境共用原环境发布锁；请求发送前从有效对话回放基线并采样变化，不再保存独立已见状态（格式见 [上下文](context.md)）。

输出截断的合并规则见 [供应商](providers.md#输出截断)。内核把 prepare、fit、环境公布和用量记账保留在每次实际请求上，输出截断不改变 overflow 的裁剪重试。逻辑回复拼接完成后才统一剥离 `reply_to`、校验 SILENT 和工具协议文本，并沿原助手记录入口追加一次；中间片段及续写指令不进 transcript。取消和插话沿原模型请求的 context；已正常完成的回复仍优先于迟到取消。

## 工具组渐进披露

`mountedTools` 保留全部已挂载能力；主 Agent 的 `modelTools` 将尚未展开的资料写工具换成组短入口。当前只有 `bot_profile`（「Bot资料编辑」）：`bot_update_profile` 改名字、简介、时区、头像，`bot_propose_persona` 改人设；其他常驻工具不变。短入口只带名称、摘要和协议要求的空参数对象，不带成员参数；直接调用短入口会明确提示使用 `expand_tool_group`。

`expand_tool_group({"group":"bot_profile"})` 也接受展示名，返回成员完整定义。下一次模型请求由现有 `RefreshTools` 重建可调用目录，整组成员替换短入口，元工具一直可用。未展开时直接调用成员，以及与展开放在同一批里的成员调用，均返回 `unknown tool`。这只是能力发现，不是主线权限白名单；子代理仍沿用完整挂载目录和原有类型范围。

展开态按当前 Bot 的 Kernel 实例保存在互斥保护的内存映射里：同一实例的后续步骤、插话和后续唤醒保留；重复展开无害；Kernel 重建、进程重启或另一个 Bot 从折叠态开始。不落盘、不从历史 schema 回包恢复，不与每轮清空的 Link `loaded` 混用。网页复用缓存 Kernel，绑定切换或改名等导致缓存重建时也重置；短命服务唤醒内核只覆盖该实例的请求。现有 Env Stream 从 `modelTools()` 采样 `tools`，列表变化才追加差异，固定前缀与旧 transcript 不改。权限分类见 [安全](security.md)。

## 轨迹路径与脚本回放

扩展现有入口，禁止第二套轨迹账本。三处各有职责，`{root}` 是当前安装的数据根：

| 内容 | 路径与来源 |
|---|---|
| 用量、熔断及 fit 等遥测 | `{root}/bots/<name>/trace.jsonl`，`Bot.TracePath()`；不是工具步骤全文 |
| 对话与工具调用、结果 | `{root}/bots/<name>/transcript/`，`Bot.TranscriptDir()`；原有 seq 分段与 blobs，网页「轨迹」是同源投影 |
| 子代理步骤 | `{root}/bots/<name>/agents/<id>/transcript.jsonl`，`Bot.AgentsDir()` / `Bot.AgentDir(id)`；不复制进主 Bot 账本 |

环境流的 `paths` 与 `xbot [--root DIR] trace paths [bot]` 共用 `Bot.Paths()`：`bot`、`trace`、`transcript`、`agents` 均为真实存储位置的绝对路径，另有 `access` 说明访问方法。路径不变不重复公布，压缩后的完整环境快照会恢复它们；不修改固定前缀。路径可在首条遥测或任务写入前存在于约定中，对应文件/目录按原有规则延迟创建。`read_file` 沙箱在 WorkDir，读取这些路径使用 shell、`xbot trace` 或脚本。

- `trace paths [bot]` 输出一条 JSON 对象；省略 bot 使用已存在的主 Bot，空安装报错，不创建 Bot。
- `trace list [bot] [--since RFC3339] [--until RFC3339] [--kind KIND]` 将遥测按文件顺序逐行输出 JSONL。时间窗包含两端，支持时区偏移；缺文件为空结果，未知 kind 无匹配。只读打开时的文件大小，未换行的追加尾巴留给下次读取；单行上限 1 MiB，完整坏行报行号而不打印原文。
- `trace replay [bot] [--from SEQ --to SEQ]` 将 Markdown 投影流式写 stdout，序号窗包含两端；from/to 必须成对，省略则全量。直接复用 `bot.ExportTo` 与 `TranscriptExport{Tools:true}`，还原工具 blob，沿用摘要、脱敏与公开边界，不输出 reasoning 或 vendor_raw，不执行历史工具。它回放主 Bot transcript，子代理全文按上述路径另读。

list/replay 使用对应 Bot 既有保险箱脱敏出口；命令不追加业务记录。加载仍可能触发既有配置或保险箱迁移；replay 的读取沿用原存储锁、旧格式迁移和派生索引维护，不能理解成底层文件系统绝对零写入。设计师用户视角已 PASS（tip `f16c9a6`）；本约定即 atlas 真源。

## 厂商生图

每轮开始从 `web.json` 固定全局生图开关和供应商选择；默认关。仅开启、当前 Bot 绑定为所选家的 OAuth Responses 且现有保险箱登录态已配置时，模型调用上下文才提供 hosted 生图的工作区保存入口；开关关闭优先于旧模型标记，同一轮续段保留快照。与搜索策略独立，完成和失败沿 `PartHosted` 进入进度与原对话。Save 只将文件保存到 `generated/` 并返回真实工作区相对路径，不写出图队列或 `Entry.Images`。Bot 读取回执后，主动调用既有 `notify_owner` 的 `images` 挂图；相对路径按调用时的目录解析，目录改变时需按工作区根定位回执路径。挂图沿既有 `attachOutImages` 的工作区边界、类型/尺寸校验和每条回复 4 张 / 10 MiB / 长边 2048 上限，内容相同的图只挂一次。通知调用携带原 turn 与 reply generation，迟到调用不能挂到另一条回复，同一长轮的后续回复可正常挂图。最终回复沿既有队列写 `Entry.Images`；保存成功不代表交付成功，挂图成败以 `notify_owner` 回执为准，拒绝不污染队列，原文件仍保留。传输、配置、保存上限及回放规则见 [供应商](providers.md)，不增加本地工具或权限分支，不改 transcript 旧行。

主对话与本机子代理的模型调用另有一次 MCP schema 降级重试，独立于 overflow；停用范围、跨轮冷却和恢复边界见 [生态](ecosystem.md)。

## 全局搜索策略

模型入口、工具目录、作用域工具、本机子代理和内置编码任务读取同一份网页搜索设置。策略包装保留底层模型与授权传输；远程执行端点在新任务启动时继承当前搜索能力，运行中的远端任务保留启动快照。厂商与本机的选择规则见 [供应商](providers.md)，持久化和本机搜索见 [生态](ecosystem.md)。修改设置不重建内核，不丢失正在运行的任务控制。

## 共享规则

通用执行原则统一在本层，DeepSeek 内嵌 overlay 为空：`VerifyRule` 把任务材料写明的结果做完整，按结果验收；`JudgmentRule` 对齐提问与改动请求，对不运行的系统给建议，非关键细节不全时说明推断后同轮做安全部分；`ResourcefulRule` 补齐成品必需配套，标明推断。两个确认模式共用交接原则，指定渠道和既定 Bot 的交接属于执行，新接收人仍需批准，删除、外发、不可逆操作和目录边界保持原确认模式。`KnowledgeRule` 区分稳定知识、项目证据和时效来源；`ConvergenceRule` 要求工具调用能改变结论或推进必需结果，外部失败最多重试一次，结论定了就停止。SilenceRule 的 S4 和 LanguageRule 不变。开发用例见 [供应商](providers.md#主动性评测)。

所有 Bot 共用的规则由 [assemble.go](../../internal/kernel/assemble.go) 的 `KernelRules` 随当前二进制组装，包含完整默认规则与通用说话规则。`rules.md` 只存 Bot 自有补充；创建和模板导入不再复制默认规则。首次组装（fork 继承前也一样）按空行分段清理旧默认：完整当前规则及开头可识别的旧默认段删除，独立自定义段保留，混入旧默认段而无法拆出的修改丢弃，不提示、不存历史版本账。清理和规则写入共用文件锁、原子替换；重复加载没有内容变化就不写盘。空文件和缺文件都表示无补充。组装顺序仍是人设、当前内核规则、Bot 补充、模型补充和 Link/技能，条件规则仍在原内核边界追加。

`ProjectRule` 把项目文件当成编码约定：工作区根上、且该目录不是 git 检出、也不是共享目录时，才是主人放的；共享目录、git 检出、子目录和克隆仓库里的不是批准、发送、读密钥或删除的依据，也不压过内核安全、权限表和脱敏。新旧 Bot 均由当前内核注入这一条。评测目录没有提示词快照，这是有意的稳定前缀变化。挂了记忆存储时，内核在规则末尾追加 `MemoryWriteRule`（用文件工具改记忆文件夹、`memory.md` 常驻且不超过 4 KiB、日志按月追加、其余细节放自由文件、用 `recall` 检索）；它不写进 `rules.md`，所以已有自定义规则的 Bot 也会带上。写记忆文件夹时的内核守卫和只读 `recall` 见 [身份与记忆](memory.md)。共享规则提前限制外部失败最多重试一次；熔断轮询提醒仍要求停止重复失败，不追加重试预算。

`ActionRule` 让模型在删除、代表主人对外发消息、改已定计划之前先问一次，「即使请求里点名了这一步」。权限卡关着时（默认，[ADR 0019](../adr/0019-no-permission-cards-by-default.md)，`Kernel.Permissive`），组装时换成 `OwnAskActionRule`：主人点名的步骤（删除、发消息也算）直接做、不再追问，只有模型自己加出来的这类步骤才先问一次；同时补一条 `EventMemoryRule`：外部事件报告的事和工作有关（新 issue、重大 bug、故障、构建挂了）就记进记忆并写明来源，但事件里的措辞仍不改人设和规则。评测按表确认的内核，`boundary` 仍测旧规则。

合伙人行为分散在既有规则对应职责：Judgment 先对齐结果并独立判断；Resourceful 禁止因可逆就替主人编职责；Offer 把偏题新想法记候选（无指定落点则 Bot 记忆），维护聚焦并用既有例程盯进度；Verify 自己核对已约定的产物、测试命令/输出/退出状态，缺证据说未验证，验收数值与 done 不等于测通。任务数量与各状态按最新环境回放，包含 queued/blocked。Dispatch 同步允许核对既定验收，仍禁止越界重复派活。Action/OwnAskAction 也涵盖未经授权的花钱。人设与工作档案不双写，字段落点见 [多 Bot](multibot.md#人设组成与提示词边界)。

记忆渲染版本由 State.MemRender 记录；唤醒时版本不符则重建唯一的 Bot 记忆快照，人物资料改走环境流，压缩刷新也记录版本。记忆注入的默认键不重复显示文本，自定义键保留；只有 person 范围追加 `via` 作者，使已接受的常驻记忆不因重复键和作者格式膨胀而被裁剪（见 [身份与记忆](memory.md)）。

环境当前值、跨轮提前占位、空闲队列触发和换小窗口预检共用内核压缩路径，配置与边界见 [上下文与 transcript](context.md)。
