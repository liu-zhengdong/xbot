# 网页界面

> **30 秒版**：网页和桌面版用同一套界面：左侧列出 Bot，主区顶部两层分别是身份操作和页面标签；聊天、记忆、轨迹、子代理、任务、上下文、收件箱、技能共用主区。对话里只有用户的话和 Bot 用 `send_message_to_user` 说的话，工具原文、任务与上下文分别放在对应标签里。主体是黑白灰，靠底色深浅分层、不画线；轨迹类型用蓝、绿、紫、橙作小面积标识，其他语义颜色沿既有约定。以后改界面要守的规矩在 [guard/界面.md](../guard/界面.md)。

命令行 `xbot [--root DIR] message <bot> <text...>` 向已运行的本机 serve 发送主人消息：`--http` 默认 `127.0.0.1:8788`，`--timeout` 默认 2 分钟，`--text` 或 `-`/省略正文可提供文本或读 stdin。先通过回环 `/api/session` 获取会话，再调用现有 messages SSE；只输出 `done.text`，没有可见回复、转交、错误或超时返回非零。

对话中的 Bot 往来与 CLI Event 共用可点击的来源行装配缝，按来源种类和身份合并连续事件。Bot 行打开既有往来视图；CLI 行以发送者为组合头像种子，点击展开该组原文，不把发送者登记为 Bot。`aside` 原文仍复用来源行分组。Lucide 心形对话图标位于对应 Bot 消息操作栏的复制按钮后、时间前，沿用 14px 图形与 24px 按钮；默认收起，收起时不额外占行。点击展开无底色的灰字旁注，正文与 Bot 气泡内文字对齐，采用项目字体和 14px／1.7 行高。手动开合保留阅读位置并解除自动贴底，入场只淡入。`aria-label` 与悬停提示同步查看／收起及合并条数，悬停保留全文；轮询保留节点与展开态。窗口首部未加载对应 Bot 消息时，心里话仍有独立入口。旁注不绑定回复菜单，也不进消息复制、侧栏预览或引用摘要。行为由 `TestAsideSourceBrowser` 和逐帧的 `TestAsideDisclosureStableBrowser` 守护。

主视图「记忆」由 `GET /api/bots/{name}` 的 `memory` DTO 装配：桌面与窄屏均为单栏，上方「关于本 Bot」、下方经历；不显示「关于你」，person 的存储及模型注入不变。常驻预览前两条带日期条目（手机一条），「展开全部」读取原文的完整 Markdown 投影；复用气泡渲染和打开文件入口，不经 Recall 拆卡。经历来自当前 Bot 的 `experience.sqlite`，带时间、新到旧，点开关注点与提纲；正常 user/assistant 片段按「你／Bot 名」分段、限制阅读行宽，工具完成回报与截断标记只留在默认折叠的「原始提纲」里。原始内容仍逐字可读、可选中复制并保留搜索命中，不改经历库。首屏 40 条，可加载更早内容。标题旁「搜索经历」通过 `GET /api/bots/{name}/experiences?q=…&before=…` 搜整个库的摘要、关注点、提纲；字面包含、英文忽略大小写，沿相同顺序分页，命中用中性底突出。输入法选词期间不查询，快速换词或切 Bot 丢弃旧回包；轮询保留输入、焦点与展开态，清除恢复已加载的普通列表。失败保留查询并可重试，无匹配单独提示。页脚只在本月有流水时给打开入口，不进主列表。浏览器打开只读原文件，桌面交给默认应用；不提供编辑器。守护为 `memory_panel_test.go`、`memory_panel_search_test.go` 的数据与搜索回归，`memory_panel_browser_test.go`、`memory_search_browser_test.go`、`memory_detail_browser_test.go` 的 Chrome 行为，以及真实 serve 的 `TestChatTabsJourney`。

主视图的收件箱位于上下文右侧：只读展示该 Bot 的入站叫醒事件，按时间新到旧，可展开摘要；待处理数量弱显，窄屏顶部标签横滚。数据来自 `GET /api/bots/{name}/inbox`，Webhook 和文件监听来源按前缀识别，摘要展示事件正文而非外壳，routine 只取标签内正文；与聊天和全局通知分开。

主视图「技能」位于收件箱右侧。列表从 `GET /api/bots/{name}/skills` 仅投影未停用项，沿用全局设置的 title/name/slug 名称规则；搜索覆盖名称、说明和 slug，英文忽略大小写，输入法组合期间不筛选。点击读取既有详情接口，正文复用 Markdown 渲染，折叠原文使用纯文本。宽屏列表与详情并列，主区不足时改为单页详情；返回保留查询和阅读位置。进入标签与关闭设置时重读，不增加轮询。技能设置的启停、导入和删除成功后也通知当前技能页，保存晚于关闭设置时仍能刷新。详情回包保留标题与控件的焦点，切 Bot 释放视图并忽略旧请求。管理入口复用全局技能设置，聊天 DOM、草稿和阅读位置沿原工作区保存。模块为 `bot-skills.js/css`；行为由 `bot_skills_browser_test.go`、`bot_skills_settings_browser_test.go` 和真实二进制 `TestBotSkillsJourney` 守护。

任务 Tab 的例程技能入口装配在 `routineCard` / `updateRoutineCard` 的现有 `.task-routine` 内：行头保持 36px 密度、14px 图标、34×20px 开关与 6×10px 内边距；正文起点下方一整行 12px 灰字显示有序技能引用或「添加技能」。点击展开逗号编辑，取消或 Escape 丢弃草稿并返回入口，保存仅 PATCH 现有例程接口的 `skills`；留空提交 `[]`，失败保留输入与扁平错误。轮询复用卡片和输入节点，不覆盖草稿或抢焦点。输入使用 `--x-input`，取消用次级底、保存用 primary，卡片仍透明跟页；不读技能库映射名称或增加选择器。行为守护在 `routine_skills_browser_test.go`，接口契约见 [API](../API.md)。

- 设置浮层的「模型与供应商」分成「已启用」和「添加供应商」两区。已启用集中置顶：从 `key_configured` 推导，显示官方图标、名称、接入方式副行（订阅 / API 密钥 / 自定义 API）和已配置绿点；ChatGPT 与 xAI 的已启用订阅卡在悬停或键盘焦点进入时，原位将绿点换成红色 Lucide 垃圾桶（16px 图形、36px 点击区），触控设备常显删除入口。点击后复用 OAuth 移除接口，成功回到未登录目录并保留搜索，失败保留卡片供重试；同品牌 API 密钥不受影响，xAI 详情不再提供旧退出入口。目录按订阅组（ChatGPT 与 xAI 卡作为登录入口：未登录时点击授权，等待时可再次点击重开授权窗，不重绘搜索框；成功后显示已登录绿点，再点进入详情）与「API 接入」网格分组，OAuth 条目不重复进入 API 网格（同一品牌的订阅与 API 密钥两个真实接入都保留）。供应商用两列圆角卡，只显示透明品牌标、供应商展示名和已配置绿点，名左、绿点（订阅未登录时的「登录」）贴卡右缘，配置 id 不作主标题；普通条目透明跟页，hover 与选中卡用中性底色 `--x-fill-2`，不靠外框或硬切强调；键盘焦点用中性轮廓。换绑行和网页搜索选项也用较浅的选中底，其列表容器不铺底色。搜索占内容宽度，过滤覆盖各组，无匹配时给清除入口。点卡进入详情：返回入口、厂标、厂名、弱化的协议文字和密钥状态。模型名采用 14px 正文字体，搜索、看图、窗口及「有厂商生图 / 无厂商生图」用 12px 灰阶图标与短文字展示；不画彩色能力胶囊或能力表格。普通模型行最低 40px，内容列不足 510px 时改为最低 64px 双行，能力可换行；上下文窗口提供悬停说明与无障碍名称。能力只表达支持情况，不显示“本绑定不再使用本地搜索”的策略断言。ChatGPT 的重新登录操作独立右对齐，登录进度与失败信息保留在状态区域。生图能力只读（OpenAI/xAI OAuth Responses 为有），不提供可勾策略或生图模型输入；策略只在「图片生成」设置。进入详情及重试时实时拉供应商 model list，名单与能力来源见 [供应商](providers.md)。未配密钥先提示配置，拉取失败和空名单均给出重试；返回保留搜索条件，迟到响应（含保存密钥）不会覆盖新页面。内置厂商的详情拉取走 `POST /api/providers/{brand}/sync`：把厂商真名单登记进配置（可选择、可绑定），未改动且无 Bot 绑定的占位种子随之清掉；同名但地址或密钥变量不同的自定义条目一律 409，不收密钥、不被发送。xAI 账号登录与 API 密钥互不占用，订阅详情和密钥供应商详情都可填写密钥；Bot 分别绑定账号或密钥供应商。ChatGPT 详情显示「已登录」并支持重新登录；名单失败可重试或重新登录。授权复用既有 OAuth 与 vault；OpenRouter 列表不提供登录入口，Claude 订阅不提供 OAuth。模型仍从 Bot 的模型行选择绑定。厂商搜索步骤、正文引用角标和来源列表显示在对话气泡内，不画任务卡；生图按下述普通工具轨迹展示。供应商网格在 DeepSeek / OpenAI / Anthropic / OpenRouter 之后列 13 家密钥厂商（Gemini、Vertex AI、xAI、Kimi、Kimi Code、Zhipu GLM、Z.ai、MiniMax、StepFun、Xiaomi MiMo、Baidu Qianfan、Tencent Cloud、OpenCode Go），默认值在 `internal/config/vendors.go`，`GET /api/providers` 的 `vendors` 只带品牌、短名、协议和默认模型名。未配密钥的厂商详情给密钥输入框，`PUT /api/providers/{brand}/key` 按内置默认补 providers.json 条目（不覆盖用户同名条目）并把密钥写入 env 文件；Vertex 没有纯密钥路线，只显示默认模型和「需要先登录 Google Cloud」，不可聊。已配置条目的品牌按 base_url 主机名识别。OpenCode Go 复用密钥详情，提示「订阅 Go 后到 Console 复制 API key，粘到这里。」，不进入订阅 OAuth 区。

## 聊天主列窗口与搜索

消息行保留 Tab 定位与 Shift+F10 / ContextMenu 快捷菜单。行自身获得键盘焦点时，不绘制整行矩形外框，仅改变圆角气泡底色；复制、回复和菜单按钮沿用各自的焦点提示。行为由 `TestMessageFocusBrowser` 守护。

主列打开/切Bot、分页、轮询、收工与侧栏预览只请求`GET …/chat`，搜索只请求`…/chat/search`；默认40条送达行、上限200条，不为可见条数扩大raw窗。`id`负责游标和keyed patch，`transcript_seq`保留引用回链；附件和卡片沿原渲染组件。存储/整轮不可变快照见[上下文](context.md#聊天读取窗口)，决定见[ADR 0039](../adr/0039-chat-delivery-timeline.md)，验收入口见[设计](../dev/chat-timeline.md)。轨迹打开后单独读取原transcript。

打开/切 Bot 清空旧主列，等待中仅挂页色半透明遮罩和当前Bot圆头像（复用生成/上传头像）叠随机闲话；长等待轮换、轻弹入与字偶轻抖，reduced-motion 全静态。尾窗 JSON 完整到齐后离屏拼完整消息 DOM，一次替换，遮罩约320ms散去；失败留在遮罩内显示「对话加载失败」并重试，不冒充整机离线。设计交接在用户本机 `~/agent-tools/chat-window-search/`，当前功能验收见 [dev](../dev/transcript-window.md)。

列顶居中「更早的消息」chip 与上滑入口走同一before请求，加载时只改chip，不重置已有消息；prepend保留可见泡节点和视觉锚。回复 SSE 尚未结束时也可向前翻页，分页保留实时回复、临时发送与活节点的顺序；失败保留当前内容并可重试。回复收尾优先读取持久结果，迟到的旧分页响应不覆盖对账结果。`TestHistoryEarlierStreamingBrowser` 守护持续回复中翻页、失败重试、后续送达与收尾交错。主列缓存最多800条 chat 送达行，合并统一从旧端裁，不丢打开时的最新消息；满窗后不能继续向旧端扩展时，现有提示行说明用搜索定位更早历史。分页按钮的加载态、到达最老页的提示先更新，再校正可见锚点；最老页提示不再定时消失引起二次位移。主列滚动由 `threadStick` 统一持有 stick 状态、rAF 贴底、ResizeObserver（当前 `.thread-inner` 与滚动容器）和视觉锚；打开/首次/latest 进入 stick，上翻离开 120px 阈值解除，主动下滚回底部恢复。各消息与控件更新入口先用更新前的几何读取滚动意图，再修改 DOM 并按 stick 状态跟尾。近底部的小幅上滚即使尚未收到原生 scroll 事件，也继续跟随长回复；超出阈值的上滚保留阅读位置。布局增高不解除 stick，发送状态行收缩后立即同步位置；追加、SSE、临时发送与历史控件改高都经此缝跟尾，解除后不被观察者或新尾拉回。分页和轮询的控件／失败提示变更完成后恢复可见消息的视觉锚；引用与搜索定位显式解除 stick。回复收工单独对账，不受历史轮询冻结限制，保留连续的已加载历史和阅读位置；SSE 送达时即使用正式气泡布局，避免收工补头像／名字造成正文位移。历史轮询按 stick 状态冻结，重新 stick 或回最新可读取服务器真尾，尾窗有缺口时 stick 直接换新尾窗、不拼接断层。回归为 `chat_stick_browser_test.go`（墙钟 Chrome 帧循环，避免虚拟时间跳过 ResizeObserver/rAF）。搜索由顶栏右放大镜打开白纸浮层，摘录与时间来自同Bot FTS；点命中关闭浮层、按chat ID开附近窗并短高亮，前后都能继续翻、能回到最新。搜索只命中chat FTS的可见正文，内部/工具行仍由Agent的transcript搜索负责。历史位置不被轮询抢走，尾窗变化继续走chat条件请求与按chat ID补丁；窗口有缺口时保留旧窗并提供更新入口，不静默拼断层。失败保留已有消息并可重试。接口契约见 [API](../API.md)。

## 语音交流

Composer 的 mic 在发送钮左侧：点按进入录音条，「发送」提交语音文件；持按松手发送，滑出或取消区丢弃，Esc、切 Bot 和离页释放麦克风。文字草稿、待发图片不随录音发送。录音失败用短提示；上传失败保留录音供重试，消息发送失败保留语音 id 供重试。

主列的 `userBubble`、`botBubble` 与 `optimisticMessage` 共用 `appendMessageBubbles`：连续文字合为一泡，空行在泡内形成多个段落（代码围栏与块级公式内部空行保留）；每个 audio id 各一泡；图片独立于文字和语音，单图单独展示，多图合为可换行的缩略组。短尾段明确标作版本或以「注／备注／说明：」开头时归入最后一个语音泡的 `.v-caption`，不确定的正文保留在文字泡内。文字在音频前、图片仍在末尾。簇间距 6px，Bot 左对齐、用户右对齐；各泡宽跟内容，语音独立于文字宽度。播放器横排行内居中：32px 播放钮、同高的十根竖波形、右侧时长，行内间距 8px；波形短音（≤5 秒）56px，随 metadata 时长增长到 120px，短音泡约 140–170px，窄屏仅收缩、不扩张填满文字。播放时右侧显示向上取整的剩余秒数，原生 audio 的 play／pause／ended／timeupdate 事件更新状态，按 currentTime / duration 从左到右给已播竖条加 `.is-on` 填实、未播 muted；暂停与结束回总时长和静态波形，不增加计时器。下方注释 13px 灰字；不另套灰壳，不画横进度轨。引用只放在该列第一条内容前，同一条 transcript 仍是一条，不改变存盘或 Bot 已送达消息的归组。原生音频播放器只由点击播放，同线程互斥；取 metadata 显示实际时长，未知时不画零秒。失败显示「语音加载失败 / 重试」。主列不展示 listen/tts 调用，轨迹沿用既有投影。`commitTranscript` 继续按行比较静态投影：附件改变只替换受影响行，未变播放器与播放状态保留，移除或切线程时停止播放。新投影只有进入 DOM 才载入 metadata，不因丢弃投影发媒体请求。HTTP 契约见 [API](../API.md#语音附件)，验收入口见 [语音交流](../dev/voice-chat.md)。

## 为什么这样设计
2026-10-20 用户试用后觉得旧界面太丑，用户体验设计师出了一整套「白纸」设计，用户定稿后分七步落地，2026-10-22 做完。设计稿不在仓库里（box 的 `/workspace/xbot-ui-design/step2/`），仓库里只留设计变量 `internal/web/static/tokens.css`。几条贯穿全局的取舍：

**对话只放对话。** 旧界面里，一个子代理在跑这件事会同时出现在对话里的任务卡、消息上的「后台」标签、铃铛和任务弹层里，同一件事说三遍。现在对话里只有用户和 Bot 的消息；子代理进度显示在输入框上方的一行状态；本机孩子的完整经过在独立「子代理」Tab，Routine在「任务」Tab。例程跑完没话说时，对话里什么都不留。

面板「任务」页最下面是 **Webhook** 小节（不进设置·连接应用）：空态「还没有 Webhook」+ 新建；列表行是名字、地址末段和「签名校验 / 令牌」；新建浮层填名字（客户端先按 `ValidID` 拦）和校验方式，成功后同一浮层换成「已创建」，明文给出地址和密钥，点内容复制；详情可再看地址、显示/隐藏密钥、撤掉（确认）。有公网地址时主行是公网地址、「本机」折叠在下；没有时主行是本机地址，下面一行「登录网关后可得到公网地址」进设置·设备。数据走 `/api/bots/{name}/webhooks`，打开任务页读一次，不随任务轮询重画。

**靠明度分层，不画线。** 窗口灰、卡片白、面板浅灰，再加三档填充色，区块之间靠底色和留白分开，没有描边和分隔线。页面里的卡片不加阴影，只有浮层（菜单、弹窗）有。轨迹列表普通行统一底色，以对齐、行距和文字层级分行，只在悬停与选中时给中性浅底。

**颜色省着用。** 红只给错误、失败和删除（Windows 关闭按钮悬停的系统红除外）；在线圆点用绿色。类别色用于上下文色带、子代理类型标签和轨迹类型标识。轨迹沿用户确认的 DSH 色系，输入蓝、上下文绿、模型紫、工具橙；总览色条、标签文字与浅底分别配色，主体和选中行保持中性。

**设计变量集中在一份文件。** `tokens.css` 单独加载、先于 `app.css`，组件只引用里面的变量（颜色、字号、间距、圆角、动效时长和曲线）。设计师以后改变量时整份替换，不用改组件。

前端标准唯一入口是项目根 [design.md](../../design.md)。共享角色由现有 `tokens.css` 提供，普通文字按钮与嵌套弹窗由 `app.css` 提供。业务模块继续拥有数据、请求与生命周期。结构决定见 [ADR 0074](../adr/0074-frontend-standard.md)。

普通控件 36px，单行列表最小 40px，双行列表最小 64px。工作区顶栏图标 16px、标签图标 14px，图标按钮和标签的 36px 点击区域保持独立。编辑资料与主题、搜索共用 `icon-btn` 角色，真实页面的图形尺寸、点击区域与命中由 `TestFrontendStandardHeaderActionsBrowser` 守护。正文与导航 14px，普通操作 13px，辅助文字 12px；设置操作统一 14px。文字 Button 不配图标，专用图标控件和对象标识保留。普通行不铺斑马底。减少动态效果时，公共按钮不缩放。

未保存拖宽值时，侧栏随窗口采用 256px／232px；已保存宽度优先。身份栏 56px，标签带 48px、标签按钮 36px；手机标签带 46px。记录页最大 960px，页面边距按桌面／中间宽度／手机采用 32／24／20px。聊天正文在桌面与手机均为 15px；输入框和语音保留专用尺寸。几何与弱文字操作由 `frontend_standard_browser_test.go` 检查。

## 怎么运转
### 公网登录后的设备壳

公网账号入口（`xbot-account` 云静态）只留登录 / 注册 / 查收邮件三屏；`#devices` / `#gateway` 已删，有会话一律进 `/app/`，无设备或离线用设备侧 boot 中文，不回落云设备列表。入口另保留 boot / bridge、仅控制 `/app/` 文档的资源 worker 和字体；业务 HTML、JS、CSS、图标通过当前配对设备的 `GET /api/ui/static/<path>` 读取 serve 进程实际提供的 UI。本机路由与 pipe 共用解析：开启 `XBOT_DEV_STATIC` 时同读配置目录（每次请求重读，缺文件不回落 embed），关闭时同读内嵌 `staticFS`；开发覆盖时 `X-Xbot-Tip` 为 `dev-static`。同源浏览器资源请求由 worker 交回所属页面的现有加密 pipe。账号仓 bridge 的 `/api/account/devices/` 子路径适配也走 pipe；顶层设备目录和登录仍走云账号适配。没有云上业务壳副本或持久业务资源缓存。

设备选择时会关闭原 pipe 并整页重载。未选择时取在线设备；明确选择的设备离线时显示原因和重试，不自动换设备、不回落旧壳。会话版本由设备静态响应的 `X-Xbot-Tip` 提供，纯 dev 构建用内嵌 UI 摘要区分。同步脚本不再是业务 UI 发版路径。协议、安全和体限见 [ADR 0029](../adr/0029-public-ui-single-source-via-pipe.md)、[API](../API.md#设备静态壳)。 设计师用户视角已 PASS（合入 tip `a02e3f3`）：公网 `/app/` 仅 pipe 薄引导（`boot.js` 200、`app.js` 404），业务壳经设备 `GET /api/ui/static`；本约定即 atlas 真源。登录后主壳缺会话不挡本条收口。
### 统一设置浮层

设置壳采用浅灰底板和内缩的白色主面。桌面尺寸上限 820×681，侧栏 176px，主面圆角 18px，内容边距 28px。导航和配置操作共用 14px 字号，辅助文字 12px，页标题 24px；变量集中在 `tokens.css` 的 `--settings-*`，仅在设置壳内覆盖字号与辅助灰度。各分类共用标题节奏和固定高度，长内容独立滚动。普通行保持透明，供应商模型列表没有斑马纹。浅深主题下，单色品牌标保持可见。

设置采用用户指定的 Magpie 配置格式，左侧标签、右侧控件，相邻配置行用低对比细线。通用页为头像、外观、手机推送三行，最低 64px；头像行右侧只展示头像，点击头像按钮直接打开文件选择器；支持键盘操作，不再显示用户名与独立更换按钮。清除只在有自定义图时出现。主题使用跟随系统／浅色／深色紧凑原生 radio 分段，取消大预览和中间分类标题；手机推送使用关闭／开启分段。推送提交期间禁用分段，成功后更新选择，权限拒绝或保存失败保留原选择并显示错误。键盘焦点循环按单选组的当前选中项处理。`TestSettingsGeneralBrowser` 守住主题偏好、推送成功／失败和窄屏目录返回；头像、滚动及各子页沿用对应浏览器回归。当前原型与 DPR 2 实际截图保存在 `~/.xbot-build/ui-shots/magpie-settings/`。长期 UC 来源为用户 Obsidian「设置页视觉统一」。

桌面设置壳与侧栏不随右栏内容滚动；`.setcnt` 是内缩的独立滚动区，滚动条与模态右缘、上下圆角留出间距。各页主标题行吸顶；通用、连接应用和同族长页共用规则，不按应用页特判。桌面设置不显示右上关闭按钮，点击浮层外部或按 Escape 关闭，关闭后恢复入口焦点；内部点击不关闭，有嵌套弹窗时沿原层级处理。窄屏设置占满屏幕，沿用固定顶栏、关闭入口与独立内容滚动。行为守护为 `TestSettingsGeneralBrowser`。

账号菜单的「设置」打开居中浮层，左侧依次是通用、账号、权限、保险库、网页搜索、技能、人设卡、图片生成、设备、连接应用、模型与供应商、关于，对话保留在遮罩后面。主题用跟随系统／浅色／深色紧凑分段；跟随系统会响应系统明暗变化，并保留 system 偏好。权限总开关与 CLI 共用 `permissions.json`，缺文件默认关，运行中的 Bot 也读取同一开关。设备列表嵌在浮层内；账号设备管理与旧短码配对共用原设备模块，见下文[账号设备与本次执行](#账号设备与本次执行)。连接应用是应用商店：顶栏「已连接 N 个」、搜索、分类芯片、推荐与分区卡网格，全部走不带 Bot 名的 `/api/apps`（添加、移除、自定义应用），装的是用户全局，与侧栏选中的 Bot 无关；商店卡标盒 48px、图形 30px，品牌使用品牌形标；网格同行等高，说明最多两行截断，末行单卡仍占一格，密钥范围说明完整显示。Google 三家只展示「即将支持」，文件系统、Webhook、文件监听、技能不在这一栏；电脑操作、浏览器、网页抓取是原生能力，`/api/apps` 目录本身不含它们（`StoreApps` 不列原生器官，`fetch` 目录行 `hidden`），前端不再另滤，「已连接 N 个」只数外接，分类芯片没有「本机」，推荐是 Playwright 与 Context7。要密钥的商店条目在设置内复用 nestcard 输入密钥（标签取列表的 `fields`），不关设置或代发聊天；提交失败保留输入，成功后才关闭并提示「已添加到你的应用」。所有添加都要服务端真调通才标已装，无密钥卡失败时错误留在卡上。手机推送位于「通用」，使用关闭／开启分段。关于页顶部居中展示标和「XBot」。版本与重启共用一个浅底分组，配置行左侧放标签及说明，右侧放完整版本串或重启按钮，行间使用设置细线。版本串允许换行；点击后复制完整内容并短显「已复制」。重启使用透明底、淡橙细边和暖色文字，固定 80×36px，仅在服务端允许重启时显示。等待时显示「重启中」并禁止重复提交；说明区提示正在重新打开。失败在同一说明位置显示错误，恢复「重启」并允许重试。按钮和配置行在各状态下保持位置与尺寸。通用、权限的行，技能、人设卡、已连接清单（行间无分隔线），设备「这台电脑」行，图片生成的开关行和未登录引导都透明跟页，不套 `--x-fill-1` 灰壳；商店卡和已配对设备卡保留卡面。短号来自 `/api/session.tip`。
### 账号设备与本次执行

已登录时，设备页展示真实账号设备池。点击详情标题直接改名，不重复展示名称和系统配置行。列表、详情与选择器用平台标识展示 macOS、Windows 和 Linux。通用操作使用图标按钮，并提供悬停说明与无障碍名称。确认与保存保留文字。标源与条款见 [平台素材](../../internal/web/static/vendor/platform-icons.SOURCE.md)。

添加设备引导新电脑登录同一账号并主动绑定；「检查设备」重新读取真实列表。未绑定本机保留绑定入口，旧短码配对从独立入口进入。取消解绑不改成员，失败保留改名输入；文件与 Bot 历史保留。

聊天输入旁的「本次使用」按 Bot 保存下一条消息的目标，可搜索设备，离线项禁用。发送成功受理后恢复自动；已受理任务保留原设备。单行状态和详情使用真实任务、停止与产物接口；设备不达时保留已知状态并标明待确认，列表截取时给弱提示。轮询保留草稿、焦点与打开状态。执行归属见 [机器与设备](machines.md)，完整接口见 [API](../API.md#账号设备管理与执行)。

### 本机电脑操作

「设备 → 这台电脑」下的电脑操作行透明跟页，显示 Mac 无障碍授权状态；未授权给系统设置短引导，Windows 给登录桌面与完整性限制说明。按钮「重新检查」只读 `/api/devices/desktop`，缺组件给安装方法、失败不冒充可用；离页丢弃迟到响应，不新建权限卡或系统弹窗。后端与动作共用同一个官方 CLI，合同见 [机器与设备](machines.md)。行为守护为 `desktop_browser_test.go`、`desktop_test.go`；DPR 2 实际本机浅色截图由主 Agent 自检，未独立视觉评审。

### 主人头像

设置「通用」的个人行显示头像与 `owner_name`，提供「换一张」及有自定义图时的「清除」。整机唯一图片在数据根 `owner-avatar`；`/api/session.owner_avatar_url` 和 `GET/POST/DELETE /api/owner/avatar` 共用此文件，没有 localStorage 图片副本。上传沿 Bot 现有 PNG/JPEG/GIF/WebP、1 MiB 和 multipart 范式（均不另做压缩），类型按字节嗅探、原子落盘；成功后设置预览与侧栏「我」同时使用 URL，清除回 `owner_name` 对应的组合头像。认证、同源、缓存契约见 [API](../API.md#主人头像)。接口与脚本化浏览器守护在 `owner_avatar_test.go`、`owner_avatar_browser_test.go`；真实二进制走查脚本为 `internal/web/testdata/owner-avatar.cjs`。
### 保险库设置

「保险库」（`static/vault.js` / `vault.css`）展示整机单库，所有 Bot 共用；不显示「当前 Bot」，不要求先选 Bot，切侧栏 Bot 不换列表或清草稿。左栏在权限后、网页搜索前，采用定稿 Grok 风格：全部/出站/本机计数 chip（中性 fill-2 选中）、名称与域名搜索、轻 fill-1 圆角卡。卡左钥匙/终端色块 glyph 的浅深色由专属 token 提供，名称等宽、副行域名或「本机」，右侧「管理」。没有整页灰壳或描边选中。出站是有域名，本机是空域名（包括 LOCAL_SUDO）；筛选与搜索无结果分开说明，全空给添加和本机 sudo 两按钮。

主钮纯「添加」，无箭头或下拉，直接打开 nestcard 收名称、password 值、可空域名；sudo 仅从卡内快捷条和空态次钮进入，预填 LOCAL_SUDO、域名空，并说明给 shell 提权、模型看不见。添加导语说明写入本机保险库、所有 Bot 共用。管理只读名称，可改域名，点「重新设置值」才展开空 password 输入，不读取旧值；保存不填新值时只更新域名。删除从管理进入同族 D5 确认，说明所有 Bot 都用不到、不可恢复，默认焦点取消，实心危险删除。失败保留草稿，成功/离页清空密码，切 Bot 不重挂全局页；迟到响应不能覆盖新页面，没有轮询重画。脚注说明模型只看名字及连接应用也写入这里。接口见 [API](../API.md#全局保险库)，本机 sudo 边界见 [安全](security.md)。设计与验收入口见 [设置保险库与本机 sudo](../dev/vault-settings-sudo.md)。真入口冒烟 `e2e/smoke/vault_settings_sudo_test.go` 对真实二进制、HTTP、浅深 Chrome 及脚本化 sudo 运行，不用真实模型或本机密码；截图由辅助脚本生成。
### 技能设置

「技能」是本机技能库的安静清单（`static/skills.js`、`skills.css`，同族于网页搜索）。一层：标题行只有「技能」，导语下、列表块顶外缘右对齐 `[搜索技能][导入]`，导入是唯一主按钮；每行只有主名、副行和 chevron，不显示路径、停用状态或 Bot 数。列表与详情共用展示名规则：非空 title 优先，再用旧文件的可读 name 或 slug/文件夹名，永不用 description 作主名；副行放不同于主名的 description；缺失、解析失败或块标量符号不画副行。手机标题和开关无障碍名称沿用同一主名，内容均按纯文本渲染；搜索按名称、说明和 slug 在前端过滤。导语与导入层统一写「本机 Bot 共享。是否启用，按每个 Bot 单独设。」；列表脚注只提示按 Bot 开关。库为空时隐藏搜索和工具条，空态提示「从本机导入一份技能，也可在对话里让 Bot 帮你装。」，中心放「导入」；无匹配显示「没有匹配的技能」和「清除搜索」，不再放第二个导入。二层：返回「技能」，名称和说明只读，「在这些 Bot 里启用」当前登录人有权管理的每个本机 Bot 一个开关（默认开，关只影响该 Bot，失败时开关退回）。

点「导入」先出来源层：Agent、Codex、Claude、本机文件夹四行，底栏只有取消。前三项读本机对应技能库的一级技能目录（服务端只认来源 id，不回路径），进多选清单，底栏唯一主按钮「导入所选」（没勾禁用），逐条导入，遇同名逐条问、取消只跳过那一条；空源写「这边还没有可导入的技能。」和「换个来源」。本机文件夹由浏览器选（`webkitdirectory`），只读出根下的 SKILL.md 发给 `POST /api/skills/import`，不传路径；同名先问「库里已有同名技能，要覆盖吗？」，覆盖才替换，取消不动库。多用户 Bot 同样显示开关；库共享不扩大 Bot 管理接口的访问权限。详情、导入这类异步回包只认最新一次选择：新选择、返回列表、关闭设置都会让旧的回包作废，导入文件读完后若设置已关或导入层已换也不再发送。接口见 [API](../API.md#用户技能)。详情底栏左边次要「删除技能」（照人设卡危险文），嵌层确认「从库里删除？」；有本机 Bot 开着则点明本数据根的启用总数 N（详情里的开关仍只列当前用户可管理的 Bot）；确认后删出库并清掉各 Bot 对它的开关，回列表报「已删除「…」。」。不做改正文、重命名、分组、MCP 和设置页编辑器。 设计师用户视角已 PASS（tip `a02e3f3`，祖先含 `3803f3d`）：技能 title 优先、只给你用默认开关、四源导入；本约定即 atlas 真源。
### 人设卡设置

「人设卡」是用户整个卡库（`static/persona-cards.js`、`persona-cards.css`，壳和列表复用技能设置）。一层：标题行只有「人设卡」；导语提示「内置种子已升级；你改过的不会被盖」；导语下、列表顶外缘一行左侧是选中的「全部」分段项，右侧是 `[搜索人设卡][＋][导入]`（窄屏可折行），「＋」是纯图标的新建，「导入」是唯一主按钮；空库不显示工具条；每行卡名、正文首行预览和 chevron，不显示 Bot 数或开关；搜索输入时先按卡名加正文前 1 KiB 即时过滤，再以服务端 `?q=` 的全文结果为准（旧回答迟到会丢掉）；选用层同样。选用层归资料抽屉：抽屉关闭或重开时 `closePick` 让还在加载的选用层作废，打开或加载期间再点不重复打开。库为空时隐藏搜索和工具条，空态中心放「写一张」（次）和「导入」（主），说明导入总是新建。无匹配显示「没有匹配的人设卡」和「清除搜索」。二层：返回「人设卡」，卡名可改，一整块正文，底栏左边次要「删除」、右边主「保存」；不在这里按 Bot 开关。删除在有 Bot 在用时说「N 个 Bot 还在用它」，确认后解绑再删。「导入 Markdown」嵌层选一份 .md（最多 256 KiB），同名时问「库里已有同名人设卡」，「仍然导入」新建带编号的一张，原来那张不变。卡正文进页面只用 textContent。
### 自定义供应商设置

模型与供应商的 API 网格末格为透明 ghost「添加自定义」。详情在现有扁平面内填可选展示名、Base URL 与脱敏密钥；地址失焦或保存按后端 host 表给协议芯片，「更改」展开三协议选项。HTTP 仅灰字建议 HTTPS；非法 URL 和无已存密钥时的空输入阻止保存。试态 icon 明确标为「保存并测试密钥」，先落配置再读目录，成功才显示通过；普通保存也在成功后拉模型。空/失败目录可重试或手动添加 id，模型勾选直接登记/取消；删除在底栏危险入口二次说明密钥、模型与 Bot 换绑影响。

自定义卡用通用线标、右缘配置点和中性 fill-2 选中。主标题优先用户展示名、其次 host 对应人话名、最后「自定义供应商」，不露内部配置 id。匹配内置 host 的自定义卡仍单独存在，且不吞内置格。绑定侧复用实时目录及显式手动模型，供应商标题读取同一元数据。注册与密钥规则见 [供应商](providers.md)，真入口冒烟为 `e2e/smoke/custom_provider_test.go`，辅助 `internal/web/testdata/custom-provider.cjs`；用户日用尚待验收。
### 图片生成设置

设置左栏在人设卡后、设备前显示「图片生成」。全局默认关闭，采用关闭／开启原生分段；关闭时只留开关和生效说明。开启后依次展示「生图方式」与「生图账号」。生图方式使用配置行右侧的原生下拉框：自动优先用当前模型自带的生图能力，否则代理到所选账号；「始终使用下方账号」只走代理。设置组之间和账号行之间采用用户确认的低对比细横线，值来自 `--settings-divider*` 和 `--settings-row-divider`，相关细线遵循设置配置行的统一约定。菜单、选项保持同一字号，说明随主名缩进，页脚合并为两行。

OpenAI / Grok（xAI）账号状态只读现有 OAuth 元数据；没有保存选择时优先已登录的一家，否则 OpenAI。未登录的选中行下显示扁平说明和「去模型与供应商」，在同浮层进入 ChatGPT 详情 / 订阅区 xAI 卡。只有用户点击现有登录按钮才发起 OAuth，过期或失败可重新登录。本页没有登录或密钥表单。重新打开刷新登录态；保存失败保留上次设置，离开后迟到响应不重绘。分段的选中值与两区 `hidden` 同步取保存后的 `enabled`，提交期间禁用控件。

所选账号只决定代理使用哪家，不要求与 Bot 当前绑定对上。页脚提示图片保存在工作区，由 Bot 挂到回复中；修改从下一轮对话生效。只有 Bot 调用 `send_message_to_user images` 挂到回复的图片才沿既有 gallery 展示；生图保存回执仍是普通工具轨迹。`TestImageGenSettingsBrowser` 守住开关、策略、账号、登录入口、保存失败和迟到回包。

生图使用普通工具调用呈现：运行摘要显示在侧栏 Bot 预览中（空 description 沿用本次忙碌的上一条，尚无 description 时不加文案），`image_generation` 的提示词与真实保存回执进入「轨迹」工具事件和右侧详情。协议仍是 `PartHosted`，不伪造可执行本地工具调用；对话中不再绘制独立生图步骤、提示词按钮或「查看 generated/」交付入口。只有最终回复的 `Entry.Images` 经现有 paste 路由进入 gallery，完成步骤本身不显示图片。生图回执与失败规则见 [供应商](providers.md)。

Bot 菜单「查看生成的图片」保留为可选工作区定位功能，打开现有模态框展示服务端工作区路径并可复制；桌面有真实 OpenPath 回调时才显示「打开目录」，复用 open-workdir。接口仍固定路径并校验 Bot 所有权，不分发图片、不新增产物账本。
### 资料即时刷新

普通资料、生成头像 seed、独立上传/清除与改名共用 `profile` SSE 提示；实际发生部分保存或移动时也按实际身份通知。网页并行读取原 Bot 列表与当前名字的资料接口，更新侧栏、顶栏头像和已有资料缓存，不解析 Shell 输出或旧模型工具结果，不写 Inbox。流未结束也能看到新简介或头像，读取失败不打断回复；已打开的编辑表单保留草稿，不被刷新替换。

改名提示带 `{name,previous_name}`。只有 `previous_name` 匹配当前选中 Bot 时，界面才在原 selection 对象上改名，更新 URL、顶栏、侧栏、按 Bot 的草稿及子代理状态；保留原 SSE reader/abort、已输入文字、焦点、待发附件与滚动位置，不调用重新选择 Bot 的入口来重开流。后续请求和 SSE 继续认新名，资料请求 generation 拒绝较旧响应；切到其它 Bot 后到达的旧提示不改当前视图。头像仍参与侧栏缓存签名，更新不等待流式结束。
### 网页搜索设置

「网页搜索」控制整台 XBot 的所有 Bot。启用项为左标签、右关闭／开启原生分段；策略使用行内下拉框，说明随已保存值显示。关闭时不提供本机和厂商搜索；自动模式优先模型自带搜索，没有则用本机；总用本机只用所选本机搜索。新一轮对话使用新设置；本机已有内核也会在下一次调用读取设置，不重建内核或取消任务。运行中的远端任务保留启动时的设置，新任务使用新设置。供应商详情不加搜索开关。

本机默认 DuckDuckGo。「本机用哪家」标题旁的说明在悬停或聚焦时提示默认服务、搜索失败和新设置生效时机。九家名单由 `config.SearchProviders` 提供，DeepSeek 已接入，其余七家保留入口但搜索会明确报不可用。开关行、「怎么搜」两行和本机供应商行都透明跟页（方向 A 勾选静音），选中只靠 radio 内点。DuckDuckGo 行右写「免密钥」，未选的需密钥行右侧留空；选中需密钥行仍是单行，行右是透明的脱敏密钥输入和一个状态图标：绿勾可用、叉无效（都可点再试），播放为待试。图标就是原「试一下」探测，状态写在它的 aria-label 里。空密钥时图标禁用；失焦和图标共用一次探测。成功后自动保存、清空输入并只留遮蔽占位，读取接口只给配置状态；失败保留输入。改字或离开设置时取消旧探测，迟到结果不覆盖草稿。保存选择后同步接口返回的密钥状态，保留未提交输入和已知失败状态。
### 窗口与聊天工作区
桌面版 `xbot app [--port 8787]`（[ADR 0007](../adr/0007-local-first-desktop-app.md)）在同一进程里跑 serve（不开隧道、不自动升级、不打印登录 token），只绑 127.0.0.1，用 `internal/appshell`（唯一引用 MyGo 的包）开系统 WebView 窗口。窗口打开 `/app/launch?code=…`：一次性登录码 32 字节随机、60 秒过期、用一次就作废，换成正常的会话 cookie 后跳到 `/`，所以桌面用户看不到登录页。同一个数据根只能开一个（`app.lock`）；端口被占时在改动数据之前就报错退出。安装包由 scripts/package-desktop.sh 打出（macOS .app/.dmg、Windows XBot.exe），安装和放行步骤见 [desktop-install.md](../desktop-install.md)。关窗即退出；窗口记住尺寸、位置与最大化状态，外链交给默认浏览器。页面切换外观时 `POST /api/app/theme` 让系统按钮跟随 XBot 自己的明暗主题，不跟系统（`appshell.SetTheme`）。

桌面实例通过已认证的 `/api/session.can_restart` 声明重启能力；`POST /api/app/restart` 将用户请求送入现有 `restartCh`，沿原 Drain／Relaunch 路径等待旧进程退出、再以同一可执行文件、参数和 held environment 打开新进程。202 只表示请求已接受；无能力实例返回 404，普通 serve 和当前 Windows 不装配。接口与回归见 [API](../API.md#登录)、`internal/web/app_restart_test.go` 和真实 runServe 的 `TestRunServeApp`。

窗口没有单独的标题栏，内容铺到窗口顶，每一栏顶部约 40 是拖动区，按钮不参与拖动。Mac 的红绿灯内嵌在侧栏左上，侧栏顶部让出 46，主卡片四周留 8。Windows 的最小化、最大化、关闭按钮由 MyGo 原生画在右上（46×32），主卡片贴着右边和下边、只有左上圆角，面板操作行下移到 36，避开系统按钮。版本号在设置的「关于」里。

窗口分为侧栏和主区。侧栏可拖宽、双击复位、拖窄后进入只留头像的 rail，宽度记在本机 `xbot.side`；rail 保留未读点、忙碌指示和悬停名字，隐藏预览与分区文字。原右侧信息抽屉已由顶部主视图标签替代，不再恢复旧 `xbot-panel-open` 偏好。

打开 Bot 时，`xbot-selected-bot` 同时写入窗口的 sessionStorage 与同源的 localStorage。刷新优先恢复本窗口选择；关闭窗口或退出进程后再开，从持久记录恢复上次打开的 Bot。记录中的 Bot 已不存在时，沿用主 Bot、列表首项的回退顺序；账号退出清除两处选择。就地改名同步迁移本窗口记录；同源持久值仍为旧名时才更新，保留其它窗口后来选择的 Bot。行为守护为 `selected_bot_browser_test.go`，覆盖真实页面关闭、同浏览器 profile 进程重启、多窗口刷新及两级回退；`profile_selected_browser_test.go` 覆盖实际资料改名后关闭页面、新页恢复新名与其聊天。

身份区位于主区左上，显示真实头像、名字和模型副标，资料编辑、主题、搜索与更新靠右。dev 刷新按钮采用 Lucide 官方 `rotate-cw` 路径，沿用公共图标尺寸、线宽与编译重启入口。点击身份或更多里的资料项进入 Bot 资料，群组身份进入成员；往来时身份入口禁用。主视图直接从内容开始，页面名称由顶部标签表达；各 Tab 内不再重复大标题或保留其占位，分区标题与操作照常保留。窄屏保留侧栏入口，页面标签横向滚动，更多固定可达。桌面身份栏保留拖动区，按钮和标签明确 no-drag，Windows/Linux 顶部避让系统按钮。⌘\ / Ctrl+\ 在聊天与资料间切换，Escape 先关闭菜单、搜索与弹窗。
侧栏运行摘要打开的「本轮」步骤浮层最高 420px，低窗口按可用高度收缩；窄屏上限还受 75dvh 约束。标题与关闭按钮固定，只有步骤列表独立滚动，短列表随内容收缩。步骤轮询保留阅读位置，读取后重新定位以守住窗口边缘。浏览器回归为 `TestStepsScrollBrowser`。

### 对话
主 Bot 忙碌状态和工具摘要只在侧栏 Bot 预览显示。状态接口在本轮继续时保留最近的非空 description，工具完成后的模型等待、刷新和另一端首次打开均可显示；本轮结束后清除，不跨轮继承。`tool` 与等待计时仍只按真实运行状态返回。`TestBusyDescriptionBrowser` 使用真实内核和 HTTP 快照验证新页面展示、步骤入口、两轮询节点复用与清除。聊天主列不再显示三点、重复摘要或空消息时间，也不保留空白占位。底部状态行仅在有提示时显示；发送、排队、错误与子代理状态沿既有入口展示，Bot 往来提示可按内容换行。

输入区是一条 44px 高、22px 圆角的药丸（`--composer-*` 变量，v2 原型 chat-workspace-v2 定稿）：默认一列布局「输入 + 32px 动作钮（mic、发送）」；有引用、附件或草稿超过一行（`is-multiline`）时圆角收到 18px，引用条与 48px 缩略附件行排在输入框上方，录音时整条换成录音栏。聚焦时底色加深到 `--x-fill-2`。顶栏 56px、标签条 42px（标签高 32px），选中标签下有一块跟随滑动的 `.tab-pill-indicator` 底片，只动 transform 不重排。

对话阅读宽度由 `--workspace-thread` 限制（v2 起 760px，屏幕 ≥1600px 时 820px）。用户消息靠右、深色 `--x-primary` 底白字（深浅主题各一套 `--x-user-*`，只作用于工作区自身消息流，远程对话不受牵连）；Bot 消息靠左、浅灰 `--x-bot-bubble` 底，单聊每条不再带头像和名字，保持一条左对齐阅读轴；群聊每条仍是 28px 头像加名字，同一人连续条目把正文缩到头像列之后。文字、列表、代码与独立附件沿原投影组装，语音保留紧凑播放器尺寸。复制、回复、时间收进每条消息悬停（或键盘聚焦）才浮出的 `.msg-meta-bar`；发送状态（发送中、已排队、没送到）是气泡下常驻的小字行，不进悬停条。同发送者、间隔不超过 5 分钟且没有其他消息插入时保持连续分组和较小间距，历史、分页与实时追加共用 `groupStart`。相隔 30 分钟以上或跨天时插入居中时间。群聊和 Bot 往来仍保留来源标记。内容自上向下排列，输入区固定在聊天主区底部。

右键（手机上长按）一条消息弹出菜单，有「回复」和「复制」，群聊里不显示「回复」。引用回复在临时发送气泡中立即显示原消息摘要，并可点击定位；受理、排队或落盘对账后，输入框清除本次引用并恢复普通占位，不等待 Bot 整轮结束。受理前失败保留引用和草稿；旧请求不清除用户后来选择的引用，即使仍是同一条消息。行为由 `reply_browser_test.go` 守护。菜单弹出时，被点的那条气泡先轻轻按下再回弹，菜单本身一次回弹展开；系统打开「减少动态效果」时只淡入淡出。

点击引用后，「返回阅读处」以阅读列右下角的圆形图标显示，36px 点击区内使用 16px Lucide undo。控件使用中性浅底，不画边框或阴影；悬停和键盘聚焦提供提示。控件单独位于整个输入状态区上方，右缘与输入框对齐，单行无状态时相隔 12px；多行草稿增高时自然上移，隐藏不留空行。点击返回恢复原窗口、阅读位置和引用焦点，保留草稿。`quote_return_browser_test.go` 守护桌面、手机、多行输入和返回行为。

系统行仍是文字，不画气泡。定时唤醒和错过的定时汇总是记录，不进对话：例程跑完有话对用户说时只见那条气泡，没话说（SILENT）就什么都不出；这条投影规则在 `app.js` 的 `routineRuns`。后台工具完工的 `shell` 来源事件也不进聊天主列，原事件仍保存在 transcript。收到别的 Bot 的消息、没送到、限流这类状态行也是灰字；Bot 自己调工具发出的往来不画系统行。汇报和主动唤醒都按普通 Bot 消息画，消息上没有「后台」标签。工具调用原文不进对话，在面板的「轨迹」里看。助手正文、预览和标题只在显示时隐藏内部任务编号，原始编号只在孩子的「任务信息」/记录来源或旧任务的「任务详情」里出现。

子代理在跑时，输入框上方有一行状态：一个时写「头像 名字 · 当前一步 · 第 N 步 · 用时」，多个时收成「N 个子代理在跑 · 最久 X 分」，点它打开独立「子代理」Tab，仅一个本机孩子时直接进入该孩子；旧后台/编码任务仍打开原任务页，全部做完这行就消失。前台在跑一个慢工具、用户又说了话时，消息流末尾多一行灰字说明它在等什么、等了多久；慢工具按调用 id 跟踪，并行的快调用结束不会把仍在跑的慢调用藏掉。标题栏只放头像、名字、状态，不放后台任务的小标；子代理类型标签沿现有卡片规则（类型来自 [ADR 0016](../adr/0016-foreground-dispatches-typed-subagents.md)；主线全工具、长活派子代理见 [ADR 0028](../adr/0028-no-foreground-background-split.md)）。

没有消息的 Bot 在卡片正中给 64px 头像、名字和「有什么事，直接说就行。」，下面最多 3 个开场建议，点了只把文字填进输入框，从不直接发送；v2 起这组不再带线条插画。其余空状态（记忆、轨迹、任务、服务离线、未配对设备）仍各有一张线条插画，共用页面里的 SVG 定义。

切换 Bot 时同步清空对话与详情，显示灰色骨架。旧请求只更新原 selection。加载失败显示「连不上 XBot」和「重试」。每次新发送创建普通记录，冻结正文、附件、语音、引用和时间。发送状态保存在记录中；DOM 只展示用户气泡、发送状态和失败说明。
Bot 发送只凭同一 owner 的 `chat.meta.event_id` 精确对账。对应持久行接替自己的临时气泡；窗口缺少该 ID 时继续保留状态。新提交不会删除另一条同文失败消息。已记录状态不被迟到回包降低。语音显式重试沿同一记录；群发送沿原 `status=sent` 回执结算。协议见 [API](../API.md#对话)。
**Bot 只通过工具说话**：对话里 Bot 的正文和挂图只来自 `send_message_to_user`（旧名 `notify_owner`）的 `text` / `images`，一次送达的调用一条气泡，同一轮的挂图画在这一轮最后一条气泡里；`ask_user` 仍是决策卡。裸助手正文（流式和终稿，含 SILENT）不进 bot 气泡、不进侧栏预览和引用摘要，transcript 照存给模型；有成功 say 的轮次可由 Go 整轮投影经 Record 追加一条合格短正文为 aside 来源行（「心里话」），不从前端 transcript 抠正文。服务端 SSE 不再发 `delta`；`send_message_to_user` 送达时 `result` 事件带 `text`，前端据此显示正式消息；后续空活泡仅承接 SSE，不进入可见布局；`done.text` 是本次送达的消息。主列不画工具过程行和 Bot 自己发起的往来系统行，忙态摘要只在侧栏预览显示，细节在「轨迹」。持久主列读取chat送达快照，不再由前端spokenLines/skipMessage投影raw。成功say待最终助手行与媒体归组定稿后一次写入，多say多行、媒体挂最后一条；SSE仍实时显示。回填的单一Go可见规则保留`2026-10-27 11:00 +08:00`之前无say旧轮正文，其后的裸正文不作为 bot 行入 chat，只可按心里话筛选规则入 aside。正文渲染先去掉图片 Markdown 与残缺语法，再统一渲染 Markdown；代码示例、数学公式和普通链接保留，原 transcript 不改。Bot chat 的首次装载、轮询与发送收工对账统一经 `applyTranscript(messages, who)`；主列按chat ID对齐，transcript_seq只用于引用与轨迹回链，审批卡按 card id 对齐，时间行跟随消息键。比较上一次投影的 DOM 结构，只增删或替换变化的行，不动未变行的节点、选区与展开态；首次／切 Bot 或chat ID缺失乱序时才全量装配。变化响应仍计算完整离屏投影，不是服务端增量分页。轮询复用chat尾ID与窗口参数的弱ETag，无变化 304 跳过正文解析；没有 validator 的响应在该 seam 做结构相等短路，不 stringify 整份历史。无变时不重算预览、不重画对话；打开轨迹Tab时独立读取/轮询原transcript，不依赖chat变化。回归为 `transcript_incremental_browser_test.go` 与 `transcript_conditional_test.go`。旧轮的空助手回复显示「这次没有收到回复，请再试一次。」。Responses 真正返回空回复时走现有错误提示和内核失败通知，用户的原话保留。
桌面版（`Server.App`）的旧登录码路径不提供「退出」，`/api/session` 带 `app:true`，`POST /api/logout` 回 409，因为登录码只在启动时生成一次；账号可以退出（`POST /api/account/logout`），再用账号登录回来；`POST /api/app/theme`（`{"theme":"light|dark|system"}`）只在桌面版存在，走登录和同源检查，值不对回 400，成功回 204，App 用它设置 `Server.AppTheme`。排队消息保留自身气泡，直到精确 ID 的持久记录接替；「回复出错了」在下一次发送被接受时清除。重新点击当前打开的 Bot 或群不重置对话；群消息在会话过期时同样保存草稿并在重新进入时恢复；服务端 4xx 带原因时显示「没能完成：原因」。

**文内可点文字一套皮**：输入框草稿、用户与 Bot 气泡、`.prose` 正文里的链接共用 `--x-text-link` / `--x-text-link-bg` / `--x-text-link-hover`（tokens.css，浅深两套）：蓝字、浅蓝 4px 圆角底、无下划线、不加粗；用户气泡底色与卡片相反，`.bubble` 把这组换成 `--x-user-link*`。按钮、整行、图标钮、code 不用这套。可点的 http(s) 文内链（气泡裸 URL 与 `[文字](url)`、输入框草稿链、联网来源 `.hs-cites`）在底内最左带该站自己的 `/favicon.ico`（`linkIcon`，14px，距字 4px）：加载成功前不占位，失败就去掉图片、只剩文字链；每个站点的成败在进程内记一次，草稿重绘不重复请求。不用公开图标服务，因为它们对没有图标的站回一个能正常加载的占位地球。

**输入框 URL 高亮可点**：对话输入框是纯文本 contenteditable（不是 textarea）：草稿里的 `http(s)://` 地址就地高亮成文字链（与气泡链接同款），点它用系统默认浏览器打开（网页走 `target=_blank` + `noopener`，桌面壳复用既有离域导航 → OpenExternal），点击不会触发发送；Enter 照旧发送、Shift+Enter 换行、输入法选词回车不发送。只认能解析为 http/https 的地址，尾随标点（`。，)…`）不进链接，紧贴的中文正文不吞；`javascript:`、`data:` 等其它协议不高亮不可点。纯文本上限仍 16000，规则同旧 textarea 的 maxlength：超限的编辑（输入、粘贴、拖入、整段替换）在编辑入口整体拒绝，不截尾，已有草稿一字不丢；程序化写入（发送清空、草稿恢复、失败回填）不走截断。撤销/重做由页面自己维护（每次被接受的编辑一步，⌘/Ctrl+Z、⌘/Ctrl+Shift+Z、Ctrl+Y，菜单撤销和浏览器原生 undo/redo 命令也接住：后者不经 beforeinput、作为不可取消的 historyUndo/historyRedo input 到达，丢弃原生结果、改放自己的历史），因为原生撤销栈经不住整段重渲染；程序化写入重置撤销基线，同旧 textarea 赋值。粘贴一律转纯文本，图片粘贴照走下面的流程。

**草稿 Markdown 语法高亮**：在 URL 高亮之上，输入框对草稿做语法上色（非 WYSIWYG，所有源字符照常可见可编辑）：行首 `#`/`##`/`###`（要求后跟空格，`####` 不认）、行首列表符 `- `/`* `、`` `code` ``（等宽字加底，内部不再嵌套高亮）、`**粗**`、`*斜*`（列表星不误判成斜体）、`[text](url)`（整段源文本可点，协议规则与裸 URL 一致，非 http(s) 不成链）。深浅色各用主题变量上色；光标按纯文本偏移恢复，打字不跳。数学 `$…$` 不在草稿里渲染，保持源字符。

**气泡数学公式**：消息气泡（流式与已存 transcript 同路径 `appendMarkdown`）渲染 `$…$` 行内与 `$$…$$` 块级数学，KaTeX 0.16.11 随静态资源内置于 `static/vendor/katex/`（MIT，字体 SIL OFL，仅 woff2）。TeX 源从不作为 HTML 进 DOM，唯一 innerHTML 来自 KaTeX 的转义输出；KaTeX 以 `throwOnError` 调用，缺失、抛错或真实解析失败都回退显示原文，不炸气泡，回退串保留完整源定界符（句中的 `$$…$$` 仍以 `$$` 回退，不改写成单 `$`）。块级配对按首个闭合 `$$` 切分：同一行 `$$a$$ 和 $$b$$` 是两段公式加中间正文，多行块闭合行尾再跟公式也照切。`$5 和 $6` 这类金额（闭侧是空格）不当公式；代码段里的 `$` 保护；流式期间未闭合的 `$` 先显原文，闭合后整段重渲染即正确。

**围栏公式分流**：`appendFenced` 经 `looksLikeFormula` 分流：math/latex/tex 强制公式；空/text 仅含等号及数学符号、上下标、`_`/`^` 或多行短等式时识别，其它语言仍为原代码块。`formulaBlocks` 对 Unicode 与解析失败内容逐行 trim、忽略空行，各渲一个透明 `.formula-block`；显式 TeX 解析成功时整段一个块，复用 `mathNode`/KaTeX。每条悬停/键盘聚焦独立高亮，点击或 Enter/Space 复制本条源文，成功态在右缘同槽将 copy 切为 `--x-online` 绿 check，1.6 秒后恢复，不绘制提示文字；「已复制」仅作为 aria-label。默认透明、悬停/聚焦及成功态为 fill-2；右缘 icon 仅为不接收点击的提示。正文回退只用 textContent，不高亮。守护为 `bubble_math_test.go`、`formula_blocks_browser_test.go`；草稿、普通代码皮与 `$`/`$$` 路径不变。

**气泡 Markdown 排版**：同一 `appendMarkdown` 路径还渲染三种块。围栏代码由自研 `highlight` 按语言档（go、js/ts、python、java/kotlin、c/c++、rust、shell、sql、json、yaml 及常见别名）切出关键词、字面量、字符串、注释、数字、函数名，每段用 textContent 进 span；未标语言或不认识的语言保持纯文本，单行字符串没闭合时引号按原文处理，不吞后文。颜色走 `.code-block` 上的 `--syn-*` 变量：浅底用浅色板，深底（深色主题的 Bot 气泡、浅色主题的用户气泡）用深色板。行首 `>` 连成引用块：每层剥一个 `>` 后递归回 `appendMarkdown`，所以 `>>` 嵌套、列表、行内格式、数学都照常，可见文字里不留 `>`。引用在切围栏之前先按行认出（围栏里的 `>` 行仍是代码，`$$` 块里的 `>` 行仍是 TeX），所以写在引用里的 ``` 围栏留在引用内、代码不带 `>`；表格数据行遇到引用行即结束。GFM 管道表（表头行紧跟 `|---|` 分隔行、列数一致）渲成 `div.md-table > table`，`:---:` 对齐写 text-align，单元格走 `appendInline`（链接仍只认 http(s)），`` `a|b` `` 与 `\|` 不拆格；只有表头没有分隔行时按正文显示，流式补齐后整段重绘成表。

**粘贴图片**：在输入框里粘贴、或把图片文件拖到对话区，图片先上传（`POST /api/bots/{name}/paste`）再在输入框上方排成 56px 缩略图，每张右上角一个「去掉」；撤回后可以重贴。只认 PNG、JPEG、GIF、WebP，单张上传与缩后均不超过 10 MiB；PNG、JPEG、GIF 长边超过 2048 时复用 `view_image` 等比缩到 2048 再落盘（GIF 缩后存 PNG），合规图原字节保存。超边 WebP 无法缩小，明确拒绝；超出既有解码上限（边长 4096／估算 160 MiB）的图仍拒绝，一条消息最多 4 张、合计不超过 10 MB，被拒时在缩略图下方用一句话说明原因，没有缩略图时这一行也照样显示。上传中缩略图变淡、发送按钮禁用；只有图片没有文字也能发。发送失败时图片不入输入框，提示「图片要重新贴一次」。换到别的 Bot 或群会清掉未发的图片，因为图片存在上一个 Bot 的工作区里。主列单图宽约聊天内容栏的 ⅓，保比例、最高 320px，`object-fit: contain`；多图全部展示为 84px 缩略格，按可用宽度换行。点开大图后仍可在同条消息的图片间切换。历史上这一轮的图片照常显示，刷新页面后还在：transcript 只记文件名，图片字节不进 transcript，也不进历史请求；回答这一条的那一轮请求直接带图，之后各轮只留一行「`[用户的图] paste/<文件名>`」让模型自己用 `view_image` 打开。群组对话暂不支持贴图。**Bot 出图**：Bot 用 `send_message_to_user` 的 `images`（pasted id 或工作区图片路径）挂图，图片存进同一个 `paste/`，这一轮最终回复那一行带上文件名，界面把它画在这一轮最后一条 `send_message_to_user` 气泡下方，用同一套单图自适应／多图缩略 gallery，点开是大图。发送失败时原文回到输入框（输入框已有新草稿则保留新草稿并提供「放回输入框」），不再显示「重试」。
### 删除 Bot 确认

更多菜单与侧栏右键的「删除 Bot」共用 `openDangerConfirm`，复用技能删除的 `.nestlayer` / `.nestcard` 样式。标题「删除 {展示名}？」、一句灰字说明对话一并删除且不能恢复，不另加身份行或正文灰框；右齐次要取消与实心危险删除。初始焦点在取消，Tab 留在卡内，取消或 Esc 关闭；提交中禁用按钮。主 Bot／最后一只的接口拒绝在卡内显示人话错误；成功后刷新列表并切到主 Bot。浅深浏览器行为回归在 `delete_bot_browser_test.go`，HTTP 契约不变。
### 侧栏
侧栏从置顶的 Bot 和「新建」开始，不显示问候语或运行数量汇总。「新建」用于新建 Bot 或群组。下面按分组列出 Bot 和群组，分组可以折叠、改名、删除（删除不带走 Bot），折叠状态记在本机。没有铃铛，也没有通知面板：要用户看的，就在那个 Bot 的头像右上点一个黑色未读点；未读只按消息游标判断，打开这个 Bot 的对话就算已读。在跑的 Bot 在窄条里是头像右下一个小转圈。底部是「我」，点头像开关账号菜单；菜单只留带齿轮的「设置」一行，无分隔线。设备和关于仍可在设置中访问，展开列表、设备、账号、退出登录和关于暂不在此菜单。界面里不出现「节点」这个词。

账号那一行显示 `/api/session` 的 `owner_name`（系统用户名，去掉 `域\` 前缀），不显示 person id：Windows 上那是 `u` 加账户 SID，没有名字时显示「我」。设备设置由 `devices.js` 渲染，账号设备管理见上文[账号设备与本次执行](#账号设备与本次执行)。旧短码配对保留允许、拒绝及撞名处理；只绑定账号不会把远端 Bot 加入侧栏。侧栏在 Bot 和群组下面按设备列出其他电脑上的 Bot（`#remote-roster`，`devices.js` 的 `paintSidebar`，点组头折叠）：组头是设备图标、名字和右边一行状态——在线写「● 在线」，离线只写时间「○ 昨天 18:20」、完整的「离线 · 最后联系 …」放在悬停提示里，不写 Bot 数量；网关不通时上方一条「连不上网关，其他电脑的 Bot 暂时用不了。」加重试，各组变淡、不逐台标离线；还没收到 Bot 列表的设备也列出，右边写「等它的 Bot 列表」并在下面一行灰字说明，对方解除配对的照旧隐藏。每行是本机行那样的头像、名字和最新一句（`/api/devices` 的 `chats`，对方说的原样，自己说的前面加「你：」），有没发到的消息时第二行是「◷ 排队中 · 你：…」，不标红；`unread` 大于 0 时头像右上角是未读点。离线的行变淡但照样能点，选中的行和本机行一样有灰底。点一行打开远端对话（`remotechat.js`）：面板绝对定位盖住 `.main`，app.js 不参与；标题 56 高，头像、Bot 名和副标题「在 MacBook 上 · 在线」或「离线 · 最后联系 昨天 18:20」，右边的「详情」打开信息面板（设备、`bot@name` 地址、聊天记录两台电脑各存一份、记忆只在对方电脑上、「在「设备」里查看」打开设置·设备）。对话里用户的话是右对齐浅灰气泡，Bot 的话带头像、名字和时间，正文一律按纯文本、保留换行。用户这条下面按状态写小字：还在这台电脑上是「◷ 已排队 · 还在这台电脑上」，已交给网关而设备离线是「◷ 已排队 · 等 MacBook 上线」，设备在线而网关在 `ack_timeout` 秒内没等到回执（消息带 `no_ack`）写「◷ 没收到 MacBook 的回执」和一行灰字「可以在「设备」里看看它的状态」，没发出去是「没发出去」加「重试」（原样重发），其他不写；4xx 带 `error`（如 409 已解除配对）不进「重试」，原文放回空着的输入框、输入框上方写「没能完成：<error>」，下次发出、用户改字或换成别的对话时收起。设备离线时输入框上方一行说明：消息已交给网关，对方打开 XBot 后才会收到和回复，最多等 7 天。输入框「写给 <Bot>」从不禁用，Enter 发送、Shift+Enter 换行，输入法选词时的回车不发送；先显示气泡，成功后换成服务器那条。打开时调只读接口顺带标已读；打开且页面可见时每 5 秒拉一次，页面切走不拉，回来立刻拉。点本机的 Bot、群组、置顶或手机上的返回关闭面板。远程 Bot 的头像同样是生成人像，seed 取 `/api/devices` 里那台设备的 `bot_avatars`（上传过图片、旧版本的设备没给 seed、设备列表还没到或认不出设备时一律画几何图形，从不借本机 Bot 的脸；图片不过网关）；Bot 之间往来的灰色事件行、往来视图的标题和消息里的远程 Bot 也按这条画，设备列表到了（`xbot:devices` 事件）就地换成人像，没有自建分组时直接显示 Bot，多选成员用加深底色和加粗文字标明选中。
### 聊天图片查看

气泡缩略图沿用该条消息的图片列表与 paste URL。点击哪张就打开哪张，查看层是原生模态 dialog，始终只显示当前一张完整图片；同条消息中抽出的图片与附件按原顺序合成一组。左右按钮、方向键和未放大时的横向触控滑动只在这组内切换，到头停住，不循环、不跨消息。多图显示 `i / n`，单图隐藏计数与切换按钮。

双击、触屏双击、双指捏合与滚轮可以在适应屏幕到 6 倍之间缩放，放大后拖动平移，位置限制在图片边界内；切图和窗口尺寸变化重置适应屏幕。图片载入失败保留关闭及切图入口。空白遮罩、关闭按钮和 Esc 退出，恢复触发缩略图的焦点及聊天滚动位置；背景由原生模态层隔离，Tab 在查看器按钮间循环。拖动、捏合、取消手势不会误触关闭。交互只改变图片 transform，没有缩放过渡动画。图片仍走既有鉴权与资源路径，没有新增下载、编辑、挂图或线程图库机制。
### 对话资源与引用

聊天中的绝对路径、home 路径和明确的 Windows 路径显示为轻量链接。反引号完整路径、具名本地 Markdown 链接和文件行号复用同一目标解析。具名链接保留标题，长路径沿既有宽度省略，完整地址保留在标题和阅读面。代码块、明显命令、普通文件名与缺少基准的相对路径保持原文；本应用的 HTTP 命名空间不猜成文件。

目录与文件点击后，通过认证的 [资源接口](../API.md#对话资源读取与打开) 查询当前连接设备。阅读面标出实际设备名和完整地址。目录按 40 项续页，文本按 64KiB 原始字节和完整行续页，支持 `:112`、`#L112` 与 `file:` URI 的行范围。无法预览时保留真实元信息；不存在与失败可复制和重试。真实桌面能力决定是否出现系统打开。行引用的复制保留位置，普通文件复制路径。默认设备不由主人输入来源或临时执行选择推断。

阅读控制器挂在聊天投影外。它覆盖页面，不压窄聊天，不由轮询重建。子目录返回保留目录滚动；关闭与 Escape 恢复触发焦点，点击输入框保留新焦点。分页和子导航保留键盘阅读流程，迟到回包不能在关闭或换 Bot 后重开。来源角标展示已有标题与原网址，普通网页链接直接打开。消息引用沿原窗口加载定位，再用临时阅读检查点恢复原窗口与阅读锚。

实现位于 [chat_resources.go](../../internal/web/chat_resources.go)、[resources.js](../../internal/web/static/resources.js) 和 [resources.css](../../internal/web/static/resources.css)。HTTP 行为由 [chat_resources_test.go](../../internal/web/chat_resources_test.go) 守护；实际文件、分页、焦点、轮询、行号及引用返回由 [resources_browser_test.go](../../internal/web/resources_browser_test.go) 覆盖。设备选择与边界依据 [ADR 0076](../adr/0076-chat-resource-reading.md)。

### 聊天工作区与顶部标签

布局依据 [ADR 0042](../adr/0042-chat-workspace-tabs.md) 和[已确认原型](../prototypes/chat-tabs/README.md)。顶栏先身份与资料编辑、主题、聊天搜索、更新操作，再「聊天、记忆、轨迹、任务、上下文、收件箱、更多」。聊天固定第一；更多管理其他标签显隐，偏好存在本机；间接打开任务或上下文会恢复目标标签。群组仅露聊天，身份区和更多可查看成员；往来继续只读。

主区保留一份聊天 DOM。非聊天视图隐藏聊天、冻结滚动观察并保留草稿、附件、引用、历史位置和 SSE；返回后恢复历史锚或跟尾。各内容视图用原 API 和组件，选择 Bot 回聊天并隔离迟到响应。记忆在桌面与窄屏均为单栏，上方全文预览、下方经历；任务保持编辑草稿、焦点和复制选择；上下文用量只在顶部「上下文」页查看；聊天输入框下方不再显示用量条，输入框距主工作区底边为 8px 加设备安全区，多行草稿仍向上展开。顶部资料入口承接原详情，职责、人设卡和模型换绑不变。

更多操作从左侧本机 Bot 行或置顶头像右键／触控长按进入，复用同一菜单：取消置顶 / 置顶、移到分组、复刻、复制 Bot ID、打开工作目录（只在桌面版有）、导出对话，空一格后是红字「删除 Bot」。操作绑定被点的 Bot，不切换当前对话，也不把远端同名 Bot 当成本机；滚动、取消触控不会误开，长按松手不触发普通选择。重复打开先关旧菜单及其子菜单。复制 Bot ID 用一个 3 秒消失的提示（toast）回执；toast 只用于复制、保存这类回执，不带撤销。

编辑资料抽屉是「基本」（头像、名字、简介）、「职责」（多行正文）、「人设卡」和「模型」四段，底栏保存：人设卡是原生下拉，选项是全库卡名，默认卡标「（默认）」，没有「未选用」；一改即绑定，旁边弱链「管理人设卡」去设置。模型一段是与详情同一块双行触发面，换绑即时生效（下一轮）。抽屉的保存管名字、简介和职责（职责没变不发）。没有说话方式、语言、免打扰。

用量带读最新一次请求的已用、硬上限和软目标，消息色块在前、工具定义在右，点了切到「上下文」标签；在「上下文」标签里和还没有快照时都不画，不用零值占位。上限现在按 128K 画，数字一律取接口，不在前端写死。

「轨迹」由输入／模型／工具三轨总览、类型筛选和当前范围搜索、事件列表、右侧详情组成。总览按记录序号、已加载范围内的用户轮次或模型调用分组，点击结果标记回到对应调用；时间只表示 transcript 追加时间，不推断执行耗时。桌面行高 34px、主文 13px、标题与短摘要同行；窄屏行高 44px，详情覆盖轨迹内容，关闭／Escape 保留列表位置。分类色只用于小面积标记和标签，普通行不铺斑马纹。

事件来自现有公开 transcript：用户输入、显式 internal／环境／memory 上下文、模型消息与工具调用分别可选；同 seq 多调用有独立稳定键。结果按 tool_call_id 合回调用，窗口内孤立结果保留入口，加载到调用后归并。列表隐藏环境标签外壳，公开原文仍可读。工具目的取已记录 description，没有时用工具名；hosted image_generation 仍是只读工具事件，不伪造本地执行。搜索按字面包含、英文忽略大小写，覆盖当前加载事件正文、参数及关联结果；工具事件不继承承载模型正文造成重复命中。类型和错误筛选可以清除，无匹配独立显示。

点行打开「概述／预览／原始内容／来源」四页签。概述与预览承载可读正文和参数／结果；原始内容只复制当前接口公开记录 JSON，复制完成后才回执；来源展示真实 seq、角色、追加时间、调用关联与已记录分支，不虚构技能注入来源。公开预览被截断时明确说明。思考只在模型事件详情按需展开、默认折叠，空白不画；主列不显示，导出契约不变。子代理步骤不混进主Bot轨迹；独立子代理视图复用同一事件投影与详情renderer，状态和来源由root-local adapter隔离。

轨迹初载沿有界尾窗，使用 before／after 分页与条件请求合并新记录；加载更早内容保留阅读锚点。视图根、搜索框与事件节点复用，轮询保搜索焦点、选中项、详情页签、思考展开、滚动及正文选区；选区期间延后替换详情正文。切 Bot 回聊天并清理归属，迟到响应不串入新 Bot。读取失败保留已加载列表并提供重试。行为入口由 `trace_explorer_browser_test.go`、迁移后的 thinking／todo／hosted 生图回归和真 serve 的 `TestTraceExplorerJourney` 覆盖。
### 子代理与例程入口

「子代理」是与聊天、记忆、轨迹、任务平级的 Tab。`static/subagents.js` / `subagents.css` 经真实 serve 静态路由及设备同源资源出口提供；`sa_` 孩子不再混在例程页。列表按进行中、排队中、最近结束分组，类型标签与短标题沿原投影；最近结束为紧凑可点行，运行项提供「查看对话」。孩子不是顶层 Bot，身份栏保持父 Bot，返回列表和回主 Bot 各有入口。

孩子视图显示公开用户/助手正文及紧凑工具记录，按 tool_call_id 关联结果；与主轨迹共用 `traceEvents`、`syncTraceDetail` 的概述/预览/原始内容/来源，状态与来源按 Bot+child 隔离。读取 before/limit 窗口，搜索明确限已加载范围；单行或响应裁剪标公开预览，不称完整原包，思考/vendor_raw不公开。物理 seq 与公开原文可在详情复制。可继续孩子底部有独立草稿，运行时默认补充当前任务，可切本轮结束后发送；完成/失败/停止仍能原 id 续聊。真实POST受理才清草稿，失败留原文可重试；停止显示真实 stopping/终态，不本地伪造已停，不提供无后端的单条撤回。

轮询复用根、输入、列表/详情和未变记录；输入焦点/选区、已选工具正文、搜索、详情页签与阅读位置不被刷新抢走。切 Bot/孩子后丢弃旧 generation 回包。原始编号只在任务信息/记录来源中显示并可复制；内核的「值得留意」短事实和完整对象沿既有 renderer 保留。

「任务」Tab 查看 Routine，保留未涉及的 Webhook、旧 bg_/外部编码任务入口。例程每行开关接 `PATCH /api/bots/{name}/routines/{id}`，失败弹回并同行报错；常见定时中文、其他为自定义时间，原始cron在悬停提示。例程跑次不混入孩子最近结束，旧任务卡折叠和编号选区仍守原行为。相关检查为 `continuable_subagents_acceptance_browser_test.go`、迁移的 routine_projection/task_fold/context_bar，以及真二进制/Chrome `TestContinuableSubagentBinary`；HTTP见 [API](../API.md#子代理通知群)。
### 值得留意
子代理任务结束时，内核整理一份只含四类事情的清单（`agents[].notable`，见 [API.md](../API.md)）：删除、对外部服务发消息、在 Bot 工作区以外写入、全局安装。清单只记实际发生了的事，判断不准的宁可不报；`--dry-run`、`rsync -n` 这类只预演的命令不算。界面只显示内核给的条目，一条都没有就不出现。

子代理终态对话和旧任务详情里，先是一行「值得留意」（12px 次级灰），下面每类一行（13px），行首是一个和文字同色的线条图标：删除 trash-2、外发 send、工作区外写入 file-pen、全局安装 package。顺序固定为删除、外发、工作区外写入、全局安装，越难撤回的越靠前；四类都不用红色，因为这是已经发生的事，不是报错。每行写出对象（「全局安装了 ripgrep」「写入了 ~/.zshrc」「删除了 3 个文件」），对象超过 2 个写成「A、B 等 5 个」，完整列表放进孩子的「任务信息」或旧「任务详情」；拿不到对象的写泛称，对象太多（超过 64 KiB）时标明不完整。行内不加句号。路径过长时保留开头两段和最后两段、截掉中间（「~/.config/xbot/…/日常工作/.zshrc」），还放不下就先去掉倒数第二段，文件名永远保留；气泡里的路径用同一个截断函数。

对话里，Bot 的汇报带同一件事的一句话，和任务卡对得上：一条时写「值得留意：全局安装了 ripgrep。」，多条时写「值得留意：删了 3 个文件，另有 3 项，详见任务。」。这句由内核生成（`notable.Line`），交回前台的结果里也有。

顶部的「上下文」标签：一张只读的用量卡，看这一轮模型实际收到了什么。数据来自 `GET /api/bots/{name}/context`（见 [API.md](../API.md)），来源是内核在发出请求时留下的快照：本进程有内核时用内存环形缓冲，没有或缓冲为空时回落到 `bots/<名>/context-last.json` 并把响应标成 `stale`，界面顶部加一句「最近一次唤醒留下的快照」；不读 transcript、不触发提醒重写。从上到下：标题「上下文」带下拉，选本轮最近 10 次请求，默认「最新」；一句「N% 已用」和「已用 / 硬上限」（已用含工具定义，硬上限见 [context.md](context.md) 的两条线）；一条色带，把空余也画进去，所以离满还有多远一眼可见，色带上一道细刻度标出软目标（「后台整理线」），消息排在前、工具定义排在最后，刻度对的就是消息量；图例每行是色块、名字、用量和占硬上限的比例，顺序是本轮、早先对话、摘要块、系统提示词、记忆、环境更新、工具定义、空余。下面三到四个可展开的明细：本轮（默认展开，每步一行「工具 + 对象 + 用量」，新的在上，失败的标「失败」，长绝对路径只留最后两段，点一行看结果开头 240 字）、早先对话（每轮一行，用开头那句话命名，没有就不出现）、摘要块（覆盖的 seq 和用量）、工具（每个工具的定义用量）。最后一行按状态说：消息还没到软目标时是「离后台整理还有约 N」，到了以后是「后台在整理 · 离上限还有约 N」。选较早的一次请求时，图例是那一次的，本轮只列到那一次为止的步骤；其余明细总是最新一次的。颜色只花在分段上：本轮和早先对话是同一族的两种蓝，摘要块绿，记忆橙，其余是灰；空余和工具定义用灰，深色主题各自换一套。原来的全宽审计视图删掉了：卡片已经回答「满没满、谁占的」，逐条原文看 transcript。没有快照时（这个 Bot 还没在本进程里发过请求，或由另一个进程驱动）显示一句说明而不是零值。只有前台主循环的请求会进来：子代理、记忆抽取和压缩自身的调用都不经过这里。

状态走只读接口，和别的接口同一套登录：`GET /api/bots/status` 返回 `{bots:[BotStatus]}`，含全部同一用户的 Bot，不带步骤；`GET /api/bots/{name}/steps?n=20` 返回 `{steps:[...]}`，是这个 Bot 当前这一轮的步骤环，`n` 最多 20。`GET /api/bots/{name}/todos` 返回待办清单。`BotStatus.todo` 是一行中文待办／进度摘要；流式回复期间仍每 3 秒拉取 status。运行时侧栏与主列忙态共用按 Bot 保存的 last-description，只取工具参数 description 的首行，不用 Confirm 摘要或工具名。SSE 与 status 轮询均更新同一份非空描述；下一工具 description 为空或空白时两侧沿用上一条，直到新的非空描述到达。忙碌开始后尚无描述时只画各自指示器，不补「在处理」；空闲后清理，避免串到下一轮。送达消息后新活泡继续沿用本次描述。运行中文案切换复用节点，以 token 驱动 opacity 淡出／换字／淡入（普通共 120ms，reduced-motion 共 100ms），不硬替换预览或主列标签；原有确认、错误和排队流程不变。确认摘要仍留在步骤和轨迹中；厂商搜索流式步骤不再额外占一行，历史展示不变。空闲且仍有待办时也显示，清单归档后恢复消息预览；可见摘要不变时侧栏及 live 节点不重写。Todo 在步骤弹层显示「待办」及更新状态。轨迹待办事件未全部完成时显示「待办 · 进度 n/m 项」，全部完成才写「已完成」；详情概述只按成功回包和原入参显示人话摘要、「进行中／待办／已完成／已放弃」及原因，失败和无回包不把拟写入条目当作已保存。参数、拟写入条目及回包在「预览／原始内容」保留，全部完成归档后历史轨迹仍可看；不往对话里加卡片，不额外请求或存账。 设计师用户视角已 PASS（tip `a02e3f3`，含 Todo streaming 热修）：轨迹「进度 n/m」；本约定即 atlas 真源。同一个用户的远端点由本机合并进来，`node` 写上节点名；每个节点缓存最近一次状态，最多每 10 秒刷新一次，调用超时 2 秒，端点不可达时给出缓存并把 `state` 写成 `offline`、`stale_seconds` 写成缓存年龄，所以一个死节点不会拖慢 `/api/bots/status`。远端只给状态，不给步骤。节点侧的能力是 `status`，返回那台机器上各 Bot 的状态列表，JSON 最多 16 KiB，放不下就整条整条地丢并保持 JSON 合法。
### 确认卡
只在 ADR 0019 仍会弹卡的情况下出现，要用户确认的操作在对话里给出确认卡片。确认卡片也写进 transcript：先记一张 pending，用户决定后追加一张终态（approved、declined）。服务端默认等 30 分钟（`Server.ApprovalWait` 可配置），待确认的卡带 `deadline`（RFC3339）；网页只按它倒计时，没有字段就不计时。到点没人确认，自动允许原调用并续跑，追加 `auto_approved` 和 notice 灰字；提问卡必须有推荐项，到点按推荐项作为用户选择继续。自动选择后再次点击视为新的用户消息，不改自动记录，也不结束其他待答卡。用户直接打字仍会结束待答计时。这一轮从前台转到后台时，卡片继续等，不作废。显示卡片的那次请求已经结束时，用户仍可以用 `POST /api/bots/{name}/approvals/{id}` 决定（见 [API.md](../API.md)）。进程重启时，上一个进程留下的 pending 卡一律追加 `no_decision:restart`，不留下看起来还能点的卡。同一个 id 只显示最新的一张，回复结束或刷新页面后卡片仍在，状态就是最后的决定；这些卡片行不进模型上下文，也不进记忆抽取。

对外发送确认卡从命令中提取收件主机与正文，原始命令折叠在「查看命令」下，倒计时明确说明到期照发，提交决定时显示处理中反馈，终态用文字区分允许、发送、拒绝与过期，拒绝保持灰色。任务面板把最后一张审批卡被拒绝且正常结束的分叉显示为「已拒绝」，到期没人决定的操作按允许执行。
### 名字和头像
Bot 名字保留原样的大小写（默认 Bot 叫 XBot），可以用的字符是任意文字的字母和数字，外加 _ 和 -，路径分隔符、控制字符、空白和超过 64 个字符（或 255 字节）的名字都不行，名字本身就是要落盘的目录名。

没上传图片时，浏览器按 `avatar_seed` 随机组合用户提供的小人部件。同一 seed 保持同一组合，16px 只改变裁切。现有一个人体基底，发型、上衣、表情、眼镜、头饰、胸饰和手持物分别随机；没有部件选择器。源素材中的身体与肤色变体是整图，不作为独立层。`scripts/avatar/entry.js` 唯一维护稳定目录和算法，固定种子输出由 golden 守护。

PNG 图层通过既有 `/api/ui/static/avatar-parts/…` 读取，本机与 pipe 使用同一设备静态源。真实 SVG DOM 依次叠加基底、上衣、胸饰、头部覆盖、表情、发型、眼镜、头饰、手持物；头部覆盖修复下颌与衣服遮挡。服务端只保存种子或上传图，不保存合成图片。素材来源和准备方式见 `avatar-parts/SOURCE.txt` 与 `scripts/avatar/prepare.py`。

编辑资料只显示当前头像和操作。「换一个」随机生成 seed 并立即保存，成功后同步资料、侧栏与顶栏，失败保持旧头像并可重试。上传保留 seed，清除上传恢复原组合。网页新建时先生成随机 seed，输入名字不换脸；可以重新随机，也可以上传。改名和刷新保留 seed。「我」的默认头像沿用同一组合画风，自定义图仍走主人头像接口。上传或图层加载失败、seed 为 `glyph`、脚本缺失时使用名字对应的几何图形。XBot 标志不作为默认头像。

行为守护为 `TestRandomAvatarBrowser`、`TestAvatarLayersAreServed` 和真实二进制 `TestRandomAvatarJourney`；覆盖随机、失败重试、上传清除、新建、读回、改名和进程重启。
### 字体
界面文字用 `tokens.css` 里的 `--x-font`：`"Segoe UI", "Noto Sans SC", "PingFang SC"`，Windows 用 `"Segoe UI Variable", "Segoe UI"` 打头。中文用自带的 Noto Sans SC 子集（字体名 `XBot SC`，GB2312 全部汉字，400–700 字重，约 1.9 MB，`unicode-range` 只管中文和全角符号，本机装了 Noto Sans SC 就直接用本机的），各系统看起来一样。子集用 scripts/subset-cjk-font.sh 重新生成。静态文件带 ETag，重复加载只回 304。 Mona Sans 只用在字标「XBot」（已转成路径）和头像兜底的首字上。
### 登录和会话

公网 `account.babelgo.cn:8443` 云静态只走登录 / 注册 / 查收邮件；成功或已有会话进入 `/app/`（账号仓前置 pipe bridge），手机也直接打开主界面。bridge 的账号适配走原 Bearer，用户 API 经 ADR 0024 管道 `Do`；不反代 8788。`xbot serve` 用独立安装凭据恢复待命并上报设备状态；UI 退出不解绑。凭据、迁移与撤销规则见 [安全](security.md#账号设备身份)，协议与缓冲边界见 [pipe](../pipe.md)。
本机通过回环地址直接进主壳，账号是可选增强；公网账号入口仍先登录。设置左栏「账号」复用本机账号登录、注册和邮件验证表单，登录后显示脱敏邮箱和网关状态，退出账号保留本机用户会话。`?s=account` 打开设置账号页。侧栏头像菜单只留设置。设备页使用账号共享池；未登录时保留原本机与配对入口，见[账号设备与本次执行](#账号设备与本次执行)。

账号服务在 `internal/account`：`Store`（现为一个 0600 的 `accounts.json`）和 `Mailer`（现为把信写成文件的 `OutboxMailer`）两个接口；密码 PBKDF2-SHA256 60 万次；链接 token、验证码、会话都只存哈希；注册直接建已验证账号并发会话（首期免邮，ADR 0025 第 6 条），已占用的邮箱按登录处理，密码不对回 `credentials` 并计一次失败；注册按客户端 IP 每小时 5 次限频（内存里，`X-Real-IP` 优先、不读 `X-Forwarded-For`；进程内 `Local` 调用不带 IP 时不限）；验证 15 分钟有效、只能用一次，验证码错 5 次作废，「再发一次」30 秒内不重发，密码错 10 次锁 15 分钟；已存在和不存在的邮箱回同样的话，后者不发信。同一个 `Handler` 挂在 `/account/v1/`，可以单独跑成 `xbot account-api`（环境变量 `DATA_DIR`、`BASE_URL`、`ADDR`、`MAIL_MODE`、`MAIL_OUTBOX`），部署时只要这个二进制和数据目录。`xbot serve` 设了 `XBOT_ACCOUNT_API` 就调它；没设就在进程里跑一份替身，数据在 `<root>/account-api/`，信写到 `<root>/account-api/outbox/`，邮件链接指回本机地址，本机只挂链接页的 GET/POST。

安装的账号归属与独立凭据见 [安全](security.md#账号设备身份)。登录和注册从不绑定，只认原来的绑定；还没绑定时，要由「把这台电脑绑到账号？」的「绑定这台电脑」（`POST /api/account/claim`）来绑，并且第一个验证过的账号要从本机直连（回环地址，且没有任何转发痕迹：所有 `X-Forwarded-*`、`Forwarded`、`Via`、`X-Real-Ip`、`Cf-Connecting-Ip`、`Cf-Ray`、`True-Client-Ip`、`X-Client-Ip`，有这个头就算，值空也算）或已经带着用户会话登录，才能绑上；隧道进来的不行。本机在设置设备页主动认领，不因登录阻断主壳。claim 绑上后立即向账号服务上报本机，回包的 `reported` 说明账号设备列表是否已更新；已绑别的账号回 403。账号绑定提供设备执行；侧栏中的远端 Bot 对话仍依赖旧短码配对。`/api/session` 带 `remote`（经隧道或代理进来）：底栏那行在官网入口写账号设备数，本机窗口写这台电脑的名字。绑定的账号登录时拿到原来的用户会话 cookie（`xbot_session`），其它账号拿不到。安装待命每分钟用绑定凭据上报设备元数据；账号设备列表的本机行使用本地 Bot 列表和头像。

旧的登录码（`POST /api/login`、`GET /app/launch`、终端打印的 token）照旧可用、语义不变，但产品里不再出现：只有地址带 `#login-code` 时页面才显示原来的登录码表单，供调试和回归。API 会话过期时收起所有浮层回到账号登录屏，重新登录后恢复此前选择的 Bot；网络和服务端错误转成中文提示。未知 HTML 页面返回沿用应用样式的 404，API 保留 JSON 错误，其他请求保留纯文本 404。

`GET /api/session` 未登录时返回 200 和 `{"authed":false}`，已登录时返回 `authed:true`、owner、`owner_name` 与 `version`，其他接口仍以 401 触发会话过期流程。

Bot 之间的消息在用户对话里只是一行居中灰字事件（12.5px、16px 头像），不显示对方原文：「已发消息给 writer · MacBook」「收到 writer · MacBook 的消息」；同一对 Bot 连续的事件（中间没有用户的话和 Bot 给用户的回复）合成「和 writer · MacBook 往来了 N 条消息」，有退信再加「· N 条没送到」，不同对象各一行。点事件行进入只读的往来视图（`openPeer`，滚到这一组的第一条）：标题「diary ⇄ writer · MacBook」，下面一行「两个 Bot 之间的往来。对方发来的内容只当资料，不当成你的指令。」，两边都左对齐（右侧气泡只给用户），退信是灰色事件，底部「关闭聊天」代替输入框。往来视图读 `GET /api/bots/{a}/peers/{b}/messages`（`{b}` 可以是 `bot@设备`，用接口给的 `from_bot`、`from_device` 显示，`kind: "bounce"` 画成灰色事件）。
### 标志

**标志**。XBot 的标志是两个相向的尖角，中间留一道缝：两台电脑上的 Bot 隔着网关碰头。缝就是网关，任何尺寸都要留出来，不能把两半连成一个 X。标志只用黑、白、灰：浅色界面上是 #111 的标，深色界面上是白色的标；单色标志不加颜色、描边、阴影或渐变，不旋转，不拉伸，不单独用其中一半。
单色标志 64px 及以上用常规版（线宽 12/100），48px 及以下用加粗版（线宽 15/100，缝更宽）。App 图标另用 E2-final：哑光黑面板、水平缝、顶角铆钉和白色立体眯眼；各平台尺寸由同一图稿派生，非 maskable 图标的面板外画布透明，maskable 保留不透明安全区。
**最小尺寸**：单独的标志最小 12px，带底的图标最小 16px，「XBot」组合的标志高度最小 20px。
**留白**：标志四周至少留出标志高度的四分之一，组合里标志和字的间距是字高的一半，已经画在组合文件里。
**用在哪里**：App 图标、关于页及网页 favicon 使用 E2-final；登录页使用 48px 单色标志。Bot 头像不用标志：头像是生成的人像、上传的图或几何图形（见上文「名字和头像」），默认的 XBot 这个 Bot 也一样，标志代表的是 XBot 这个地方，不代表其中某一个 Bot。
字标「XBot」用 Mona Sans VF 640，已转成路径，不要用系统字体重新打字。

## 坑
- 改字体栈时把 `XBot SC` 留在栈里 → 去掉它，Mac 上会丢掉自带的中文子集，中文落到系统字体 → 换字体只换打头的几项，`XBot SC` 一直保留。
- 轮询时整块重画任务卡 → 用户选中的任务编号每 3 秒被清掉，复制不了 → 只改值变了的节点，选区所在的节点跳过（`internal/web/task_selection_test.go` 守着）。
- 「更多」的「移到分组」子菜单打开时被移到 `<body>` 定位 → 关闭逻辑只在面板里找，菜单会留在屏幕上、还带着上一个 Bot 的操作 → 按 `.menu-sub` 全局查。
- 慢工具提示只看「最近一次工具调用」→ 并行的快调用一结束，仍在跑的慢调用提示就消失 → 按调用 id 跟踪。
- 「值得留意」把预演命令也算进去 → 用户看到并没发生的删除或外发 → 预演选项（`--dry-run`、`-n` 等）一律不报；判断不了的命令宁可不报。

模型换绑在工作锁内先经内核的新窗口预检与必要压缩，成功才保存绑定；上下文仍超新窗口时 HTTP 409 保留旧绑定，详见 [上下文](context.md)。

开发入口 `scripts/xbot-dev start/restart` 默认后台启动当前构建的 `xbot app`，使用 `~/.xbot-dev` 和 8788；显式 `--web` 才启动 serve 并打开浏览器。PID 与日志仍在 `~/.xbot-build/dev/`。安装版 `/Applications/XBot.app` 默认用 `~/.xbot`，不替代 dev 实例；关桌面窗会结束 app 进程。

桌面壳在建窗时使用内嵌的品牌 PNG：macOS 设置 Dock 图标，其他平台设置窗口图标；调用方可通过 `appshell.Options.Icon` 指定 PNG，设置失败写日志但不阻止开窗。正式 macOS 包仍带 icns。
