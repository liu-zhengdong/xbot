# 网页界面

> **30 秒版**：网页和桌面版用同一套界面：左边侧栏列出 Bot，中间是对话，右边是信息面板。对话里只有主人和 Bot 说的话，工具调用、子代理任务和上下文用量都放在面板里。整体是黑白灰，靠底色深浅分层、不画线，颜色只留给错误、在线和子代理类型。以后改界面要守的规矩在 [guard/界面.md](../guard/界面.md)。

- 详情中的模型行打开换绑定浮层，按 Completions / Responses / Messages 分组，读取运行时能力表。Messages 选项禁用；Bot 有前台、分叉后台或运行/排队子代理时换绑返回清晰错误，不取消已有任务。换绑保存后下一轮重建内核。
- 设置浮层的「模型与供应商」按 A-magpie 分成订阅和供应商两区。订阅区以 ChatGPT 卡作为唯一入口：未登录时点击授权，等待时可再次点击重开授权窗，不重绘搜索框；成功后显示已登录绿点，再点进入详情；供应商用两列圆角卡，只显示透明品牌标、短名和已配置绿点，搜索框靠右。点卡进入详情：返回入口、厂标、厂名、协议小标签、密钥状态，以及 hosted / vision / 窗口芯片行；不使用能力表格。进入详情及重试时实时拉供应商 model list，名单与能力来源见 [供应商](providers.md)。未配密钥先提示配置，拉取失败和空名单均给出重试；返回保留搜索条件，迟到响应不会覆盖新页面。ChatGPT 详情显示「已登录」并支持重新登录；名单失败可重试或重新登录。授权复用既有 OAuth 与 vault；OpenRouter 列表不提供登录入口，Claude 订阅不提供 OAuth。模型仍从 Bot 的模型行选择绑定。hosted 步骤、正文引用角标和来源列表显示在对话气泡内，不画任务卡。

## 边界
负责：网页界面（`internal/web/static`）的组成和展示规则，以及桌面窗口外壳（`internal/appshell`）。接口见 [API.md](../API.md)。「值得留意」清单由内核整理（`internal/notable`，见 [subagents.md](subagents.md)），界面只管显示。

不负责：权限审批的界面。这套界面不做审批：新组件里没有确认卡、没有「等你确认」状态，也没有相关计数。[ADR 0019](../adr/0019-no-permission-cards-by-default.md) 仍会弹的卡（连接器填 key、碰保险箱和密钥、主人打开 `xbot permissions on` 之后）沿用旧的确认卡渲染，见下文「确认卡」。

## 为什么这样设计
2026-10-20 主人试用后觉得旧界面太丑，用户体验设计师出了一整套「白纸」设计，主人定稿后分七步落地，2026-10-22 做完。设计稿不在仓库里（box 的 `/workspace/xbot-ui-design/step2/`），仓库里只留设计变量 `internal/web/static/tokens.css`。几条贯穿全局的取舍：

**对话只放对话。** 旧界面里，一个子代理在跑这件事会同时出现在对话里的任务卡、消息上的「后台」标签、铃铛和任务弹层里，同一件事说三遍。现在对话里只有主人和 Bot 的消息；谁在忙，看输入框上方的一行状态和侧栏顶部的问候句；完整经过在面板的「任务」页。例程跑完没话说时，对话里什么都不留。

**靠明度分层，不画线。** 窗口灰、卡片白、面板浅灰，再加三档填充色，区块之间靠底色和留白分开，没有描边和分隔线。页面里的卡片不加阴影，只有浮层（菜单、弹窗）有。面板里的列表用隔行底色（斑马行）代替分隔线。

**颜色省着用。** 红只给错误、失败和删除（Windows 关闭按钮悬停的系统红除外）；绿只给「在线」圆点；其余颜色只出现在上下文色带和子代理类型标签里，而且都是低饱和的。

**设计变量集中在一份文件。** `tokens.css` 单独加载、先于 `app.css`，组件只引用里面的变量（颜色、字号、间距、圆角、动效时长和曲线）。设计师以后改变量时整份替换，不用改组件。

## 怎么运转

### 统一设置浮层

账号菜单的「设置」打开居中浮层，左侧依次是通用、权限、网页搜索、技能、设备、连接应用、模型与供应商、关于，对话保留在遮罩后面。主题用浅色/深色/跟随系统下拉框；跟随系统会响应系统明暗变化。权限总开关与 CLI 共用 `permissions.json`，缺文件默认关，运行中的 Bot 也读取同一开关。设备列表嵌在浮层内，远端对话与配对完成后的「查看设备」都进入这一页；设备标题行只有「+ 配对设备」入口，页面没有加入入口和底部动作条；配对、改名等弹窗复用原设备模块。连接应用沿用所选 Bot 的 Link/MCP 接口与账号推送接口，密钥仍走聊天确认卡。关于显示服务端版本；v1 不显示数据目录。

### 技能设置

「技能」是主人整个技能库的安静清单（`static/skills.js`、`skills.css`，同族于网页搜索）。一层：标题行只有「技能」，导语下、列表块顶外缘右对齐 `[搜索技能][导入]`，导入是唯一主按钮；每行只有名称、一句说明和 chevron，不显示目录名、路径、停用状态或 Bot 数，搜索按名称加说明在前端过滤。库为空时隐藏搜索和工具条，只在空态中心放「导入」；无匹配显示「没有匹配的技能」和「清除搜索」，不再放第二个导入。二层：返回「技能」，名称和说明只读，「在这些 Bot 里启用」每个本机 Bot 一个开关（默认开，关只影响该 Bot，失败时开关退回）。

导入由浏览器选本机文件夹（`webkitdirectory`），只读出根下的 SKILL.md 发给 `POST /api/skills/import`，不传路径；同名先问「库里已有同名技能，要覆盖吗？」，覆盖才替换，取消不动库。多人共用的 Bot 不加载个人技能库，详情里只写明暂不使用、不给开关。详情、导入这类异步回包只认最新一次选择：新选择、返回列表、关闭设置都会让旧的回包作废，导入文件读完后若设置已关或导入层已换也不再发送。接口见 [API](../API.md#用户技能)。本批不做删库、改正文、重命名、分组、MCP 和设置页编辑器。

### 网页搜索设置

「网页搜索」控制整台 XBot 的所有 Bot。关闭时不提供本机和厂商搜索；自动模式优先模型自带搜索，没有则用本机；总用本机只用所选本机搜索。新一轮对话使用新设置；本机已有内核也会在下一次调用读取设置，不重建内核或取消任务。运行中的远端任务保留启动时的设置，新任务使用新设置。供应商详情不加搜索开关。

本机默认 DuckDuckGo。九家名单由 `config.SearchProviders` 提供，DeepSeek 已接入，其余七家保留入口但搜索会明确报不可用。选中用中性填充色；除 DuckDuckGo 外，选中行展开 API 密钥和「试一下」。空输入禁用；失焦和按钮共用一次探测。成功后自动保存、清空输入并只留遮蔽占位，读取接口只给配置状态；失败保留输入。改字或离开设置时取消旧探测，迟到结果不覆盖草稿。保存选择后同步接口返回的密钥状态，保留未提交输入和已知失败状态。

### 窗口和三栏
桌面版 `xbot app [--port 8787]`（[ADR 0007](../adr/0007-local-first-desktop-app.md)）在同一进程里跑 serve（不开隧道、不自动升级、不打印登录 token），只绑 127.0.0.1，用 `internal/appshell`（唯一引用 MyGo 的包）开系统 WebView 窗口。窗口打开 `/app/launch?code=…`：一次性登录码 32 字节随机、60 秒过期、用一次就作废，换成正常的会话 cookie 后跳到 `/`，所以桌面用户看不到登录页。同一个数据根只能开一个（`app.lock`）；端口被占时在改动数据之前就报错退出。安装包由 scripts/package-desktop.sh 打出（macOS .app/.dmg、Windows XBot.exe），安装和放行步骤见 [desktop-install.md](../desktop-install.md)。关窗即退出；窗口记住尺寸、位置与最大化状态，外链交给默认浏览器。页面切换外观时 `POST /api/app/theme` 让系统按钮跟随 XBot 自己的明暗主题，不跟系统（`appshell.SetTheme`）。

窗口没有单独的标题栏，内容铺到窗口顶，每一栏顶部约 40 是拖动区，按钮不参与拖动。Mac 的红绿灯内嵌在侧栏左上，侧栏顶部让出 46，主卡片四周留 8。Windows 的最小化、最大化、关闭按钮由 MyGo 原生画在右上（46×32），主卡片贴着右边和下边、只有左上圆角，面板操作行下移到 36，避开系统按钮。版本号在账号菜单的「关于 XBot」里。

三栏从左到右是侧栏、对话、信息面板。侧栏默认宽 280，右边缘可以拖，宽 240 到 360，双击边缘回到 280，宽度记在这台浏览器里（`xbot.side`）；拖到 200 以下吸成 72 宽的窄条，只剩头像，名字改成悬停提示。对话和信息面板在同一张主卡片上，面板宽 384，靠 `--x-panel` 底色和对话区分开。窗口窄于 960 时面板改成盖在上面的抽屉，带可点击关闭的遮罩。

整个界面只有一个面板开关，钉在主卡片右上角，面板打开和收起时位置都不变：打开时它是面板操作行最右边那个按钮，带浅底；收起后还在原处，没有底色。Mac 上在卡片内右上，Windows 上紧挨在系统按钮左边。Esc 收起面板（有菜单、抽屉、弹窗时先关它们），⌘\ / Ctrl+\ 切换。面板默认只在窗口至少 1440 宽时打开，手动开关后记在本机。

### 对话
对话列宽 `min(680px, 100% - 64px)`，标题栏里只有头像、名字和一个灰色状态。消息都画成气泡：主人的气泡靠右、深底白字（深色模式反过来），最宽 72%；Bot 的气泡靠左、浅灰底，最宽 86%，段落、列表和代码块都在气泡里，代码块用比气泡浅一级的底色。单聊不放头像和名字，时间只在悬停时出现在气泡旁边。同一个发送者 5 分钟内、中间没夹别的东西的几条算一串，串内间距小，串与串之间间距大；分组由 `groupStart` 这个纯函数决定，历史、翻页和实时追加都走它。和上一条相隔 30 分钟以上或跨天时，中间出现一行居中的时间（「昨天 11:38」）。群聊和 Bot 之间的往来视图里，每串第一条保留头像、名字和时间。消息少时对话贴着底部排。

右键（手机上长按）一条消息弹出菜单，有「回复」和「复制」，群聊里不显示「回复」。菜单弹出时，被点的那条气泡先轻轻按下再回弹，菜单本身一次回弹展开；系统打开「减少动态效果」时只淡入淡出。

系统行仍是文字，不画气泡：定时唤醒和错过的定时汇总是居中的灰色时钟行，写成「定时 · 早报 · 昨天 08:00」，点开看提示词和来源；Bot 之间的往来事件、没送到、限流这类状态行也是灰字。汇报和主动唤醒都按普通 Bot 消息画，消息上没有「后台」标签。工具调用原文不进对话，在面板的「轨迹」里看。助手正文、预览和标题只在显示时隐藏内部任务编号，原始编号只在「任务」页的「任务详情」里出现。

子代理在跑时，输入框上方有一行状态：一个时写「头像 名字 · 当前一步 · 第 N 步 · 用时」，多个时收成「N 个子代理在跑 · 最久 X 分」，点它打开面板的「任务」页，全部做完这行就消失。前台在跑一个慢工具、主人又说了话时，消息流末尾多一行灰字说明它在等什么、等了多久；慢工具按调用 id 跟踪，并行的快调用结束不会把仍在跑的慢调用藏掉。标题栏只放头像、名字、状态，不放后台任务的小标；以后子代理的提示方式按 [ADR 0016](../adr/0016-foreground-dispatches-typed-subagents.md) 的子代理卡片来做。

没有消息的 Bot 在卡片正中给头像、名字和「有什么事，直接说就行。」，下面最多 3 个开场建议，点了只把文字填进输入框，从不直接发送。空状态（新 Bot、记忆、轨迹、任务、服务离线、未配对设备）各有一张线条插画，共用页面里的 SVG 定义。

切换 Bot 时同步清空对话与详情，显示灰色骨架；线程、详情与流式回复只更新发起请求时选中的对象，旧请求不覆盖新 Bot。加载失败在对话中央显示「连不上 XBot」和次级「重试」。发送先显示用户气泡与「发送中」，三个灰点等到首个文字片段才消失；减少动态效果时灰点静止。成功后原文记录替换临时气泡，失败时在原气泡旁说明（细则见下文），后续同一原文发送成功时移除对应的失败气泡，不把服务器错误放进标题。
发送已接受后流中断时仍保留标为「没送到」的原文气泡并恢复草稿，排队事件继续显示「已排队」，直到新增的主人原文记录接替气泡；任务状态和错误使用中文，原始错误可展开「详情」，任务结束时间取终态元数据的写入时间。
流式结束后从原文记录重绘，当前 Bot 保持选中。历史上的空助手回复显示「这次没有收到回复，请再试一次。」，不隐藏整条回复；工具调用和定时静默不加此提示。Responses 真正返回空回复时走现有错误提示和内核失败通知，主人的原话保留。
桌面版（`Server.App`）不提供「退出」，`/api/session` 带 `app:true`，`POST /api/logout` 回 409，因为登录码只在启动时生成一次；`POST /api/app/theme`（`{"theme":"light|dark|system"}`）只在桌面版存在，走登录和同源检查，值不对回 400，成功回 204，App 用它设置 `Server.AppTheme`。再次发送同一原文时先移除旧的失败行；返回 202 排队的消息保留气泡并标「已排队」，直到对话记录里出现同样的文字；「回复出错了」在下一次发送被接受时清除。重新点击当前打开的 Bot 或群不重置对话；群消息在会话过期时同样保存草稿并在重新进入时恢复；服务端 4xx 带原因时显示「没能完成：原因」。

**粘贴图片**：在输入框里粘贴、或把图片文件拖到对话区，图片先上传（`POST /api/bots/{name}/paste`）再在输入框上方排成 56px 缩略图，每张右上角一个「去掉」；撤回后可以重贴。只认 PNG、JPEG、GIF、WebP，单张不超过 10 MB、长边不超过 2048（超过就整张退回，不缩），一条消息最多 4 张、合计不超过 10 MB，被拒时在缩略图下方用一句话说明原因，没有缩略图时这一行也照样显示。上传中缩略图变淡、发送按钮禁用；只有图片没有文字也能发。发送失败时图片不入输入框，提示「图片要重新贴一次」。换到别的 Bot 或群会清掉未发的图片，因为图片存在上一个 Bot 的工作区里。对话里的图片按 84px 缩略图排，最多显示 3 张、第 3 张盖「+N」，点开是大图。历史上这一轮的图片照常显示，刷新页面后还在：transcript 只记文件名，图片字节不进 transcript，也不进历史请求；回答这一条的那一轮请求直接带图，之后各轮只留一行「`[主人的图] paste/<文件名>`」让模型自己用 `view_image` 打开。群组对话暂不支持贴图。发送失败时原文回到输入框（输入框已有新草稿则保留新草稿并提供「放回输入框」），不再显示「重试」。

### 侧栏
侧栏顶部是问候句，说谁在忙、什么刚做完、还没看（窗口窄于 960 时隐藏）。下面是置顶的 Bot 和「新建」（新建 Bot 或群组），再下面按分组列出 Bot 和群组，分组可以折叠、改名、删除（删除不带走 Bot），折叠状态记在本机。没有铃铛，也没有通知面板：要主人看的，就在那个 Bot 的头像右上点一个黑色未读点；未读只按消息游标判断，打开这个 Bot 的对话就算已读。在跑的 Bot 在窄条里是头像右下一个小转圈。底部是「我」，点开是账号菜单（设置、收起列表、关于 XBot，浏览器里还有退出）。界面里不出现「节点」这个词。

账号那一行显示 `/api/session` 的 `owner_name`（系统用户名，去掉 `域\` 前缀），不显示 person id：Windows 上那是 `u` 加账户 SID，没有名字时显示「我」。账号菜单的「设置」打开居中浮层，设备分组由 `devices.js` 渲染：从上到下是一句说明（配对后在本机就能和另一台的 Bot 聊天，两边的 Bot ### 信息面板
面板顶部从上到下是：操作行、身份行、上下文用量带、标签栏，操作行、身份和标签栏吸顶。操作行只有「编辑资料」和「更多」两个按钮（加上右边的面板开关）；「更多」菜单依次是取消置顶 / 置顶、移到分组、复刻、复制 Bot ID、打开工作目录（只在桌面版有）、导出对话，空一格后是红字「删除 Bot」。复制 Bot ID 用一个 3 秒消失的提示（toast）回执；toast 只用于复制、保存这类回执，不带撤销。身份行是 48 头像左对齐，人设和模型在「详情」标签里。

用量带读最新一次请求的已用、硬上限和软目标，消息色块在前、工具定义在右，点了切到「上下文」标签；在「上下文」标签里和还没有快照时都不画，不用零值占位。上限现在按 128K 画，数字一律取接口，不在前端写死。

标签依次是详情、记忆、任务、轨迹、上下文。「轨迹」一轮一行，写时间、用过的工具和耗时，点开看每次调用的参数和输出，输出默认截断；轨迹不画时间轴分轨，也还不嵌子代理的步骤。

### 任务页
「任务」页分四段，顺序是进行中、排队中、最近结束、例程。一个子代理一项，状态原地更新；名字后面紧跟一个低饱和的类型标签（开发、调研、通用、自定义四色），名字本身就是类型名时不重复。卡片标题用任务的短标题，没有短标题时退回类型名，不显示内部编号。进度文字和标题重复时（去掉开头的「在」后和标题相同，或以标题开头）只显示「第 N 步 · 用时」。每项下面有可展开的「任务详情」（带向右的箭头，展开时转向下），里面是原始请求和任务编号，编号放在这里就是为了让人能复制。

面板每 3 秒轮询一次。值没变的节点不重写，选区落在某个节点里时跳过这个节点，所以主人选中任务编号后，刷新不会清掉选区。

例程每行一个开关，接 `PATCH /api/bots/{name}/routines/{id}`；请求失败时开关弹回，在这一行报错。例程以中文显示常见定时规则，其他规则显示「自定义时间」，原始 cron 放在行的悬停提示里。例程跑完没话说时，只在「最近结束」里记一条「没什么要说的」。

### 值得留意
子代理任务结束时，内核整理一份只含四类事情的清单（`agents[].notable`，见 [API.md](../API.md)）：删除、对外部服务发消息、在 Bot 工作区以外写入、全局安装。清单只记实际发生了的事，判断不准的宁可不报；`--dry-run`、`rsync -n` 这类只预演的命令不算。界面只显示内核给的条目，一条都没有就不出现。

任务页里，结果摘要下面先是一行「值得留意」（12px 次级灰），下面每类一行（13px），行首是一个和文字同色的线条图标：删除 trash-2、外发 send、工作区外写入 file-pen、全局安装 package。顺序固定为删除、外发、工作区外写入、全局安装，越难撤回的越靠前；四类都不用红色，因为这是已经发生的事，不是报错。每行写出对象（「全局安装了 ripgrep」「写入了 ~/.zshrc」「删除了 3 个文件」），对象超过 2 个写成「A、B 等 5 个」，完整列表放进「任务详情」；拿不到对象的写泛称，对象太多（超过 64 KiB）时标明不完整。行内不加句号。路径过长时保留开头两段和最后两段、截掉中间（「~/.config/xbot/…/日常工作/.zshrc」），还放不下就先去掉倒数第二段，文件名永远保留；气泡里的路径用同一个截断函数。

对话里，Bot 的汇报带同一件事的一句话，和任务卡对得上：一条时写「值得留意：全局安装了 ripgrep。」，多条时写「值得留意：删了 3 个文件，另有 3 项，详见任务。」。这句由内核生成（`notable.Line`），交回前台的结果里也有。

信息面板的第五个标签是「上下文」：一张只读的用量卡，看这一轮模型实际收到了什么。数据来自 `GET /api/bots/{name}/context`（见 [API.md](../API.md)），来源是内核在发出请求时留下的内存快照，不落盘、不读 transcript、不触发提醒重写。从上到下：标题「上下文」带下拉，选本轮最近 10 次请求，默认「最新」；一句「N% 已用」和「已用 / 硬上限」（已用含工具定义，硬上限见 [context.md](context.md) 的两条线）；一条色带，把空余也画进去，所以离满还有多远一眼可见，色带上一道细刻度标出软目标（「后台整理线」），消息排在前、工具定义排在最后，刻度对的就是消息量；图例每行是色块、名字、用量和占硬上限的比例，顺序是本轮、早先对话、摘要块、系统提示词、记忆、环境更新、工具定义、空余。下面三到四个可展开的明细：本轮（默认展开，每步一行「工具 + 对象 + 用量」，新的在上，失败的标「失败」，长绝对路径只留最后两段，点一行看结果开头 240 字）、早先对话（每轮一行，用开头那句话命名，没有就不出现）、摘要块（覆盖的 seq 和用量）、工具（每个工具的定义用量）。最后一行按状态说：消息还没到软目标时是「离后台整理还有约 N」，到了以后是「后台在整理 · 离上限还有约 N」。选较早的一次请求时，图例是那一次的，本轮只列到那一次为止的步骤；其余明细总是最新一次的。颜色只花在分段上：本轮和早先对话是同一族的两种蓝，摘要块绿，记忆橙，其余是灰；空余和工具定义用灰，深色主题各自换一套。原来的全宽审计视图删掉了：卡片已经回答「满没满、谁占的」，逐条原文看 transcript。没有快照时（这个 Bot 还没在本进程里发过请求，或由另一个进程驱动）显示一句说明而不是零值。只有前台主循环的请求会进来：子代理、记忆抽取和压缩自身的调用都不经过这里。

状态走只读接口，和别的接口同一套登录：`GET /api/bots/status` 返回 `{bots:[BotStatus]}`，含全部同一主人的 Bot，不带步骤；`GET /api/bots/{name}/steps?n=20` 返回 `{steps:[...]}`，是这个 Bot 当前这一轮的步骤环，`n` 最多 20。`GET /api/bots/{name}/todos` 返回待办清单。`BotStatus.todo` 是一行摘要，侧边栏和步骤弹层还没画它。同一个主人的远端点由本机合并进来，`node` 写上节点名；每个节点缓存最近一次状态，最多每 10 秒刷新一次，调用超时 2 秒，端点不可达时给出缓存并把 `state` 写成 `offline`、`stale_seconds` 写成缓存年龄，所以一个死节点不会拖慢 `/api/bots/status`。远端只给状态，不给步骤。节点侧的能力是 `status`，返回那台机器上各 Bot 的状态列表，JSON 最多 16 KiB，放不下就整条整条地丢并保持 JSON 合法。

### 确认卡
只在 ADR 0019 仍会弹卡的情况下出现，要主人确认的操作在对话里给出确认卡片。确认卡片也写进 transcript：先记一张 pending，主人决定后追加一张终态（approved、declined）。服务端默认等 30 分钟（`Server.ApprovalWait` 可配置），待确认的卡带 `deadline`（RFC3339）；网页只按它倒计时，没有字段就不计时。到点没人确认，自动允许原调用并续跑，追加 `auto_approved` 和 notice 灰字；提问卡必须有推荐项，到点按推荐项作为主人选择继续。自动选择后再次点击视为新的主人消息，不改自动记录，也不结束其他待答卡。主人直接打字仍会结束待答计时。这一轮从前台转到后台时，卡片继续等，不作废。显示卡片的那次请求已经结束时，主人仍可以用 `POST /api/bots/{name}/approvals/{id}` 决定（见 [API.md](../API.md)）。进程重启时，上一个进程留下的 pending 卡一律追加 `no_decision:restart`，不留下看起来还能点的卡。同一个 id 只显示最新的一张，回复结束或刷新页面后卡片仍在，状态就是最后的决定；这些卡片行不进模型上下文，也不进记忆抽取。

对外发送确认卡从命令中提取收件主机与正文，原始命令折叠在「查看命令」下，倒计时明确说明到期照发，提交决定时显示处理中反馈，终态用文字区分允许、发送、拒绝与过期，拒绝保持灰色。任务面板把最后一张审批卡被拒绝且正常结束的分叉显示为「已拒绝」，到期没人决定的操作按允许执行。

### 名字和头像
Bot 名字保留原样的大小写（默认 Bot 叫 XBot），可以用的字符是任意文字的字母和数字，外加 _ 和 -，路径分隔符、控制字符、空白和超过 64 个字符（或 255 字节）的名字都不行，名字本身就是要落盘的目录名。没上传图片时，头像是浏览器按 `avatar_seed` 现画的 Notionists 线条人像，只用冻结的白名单（只有平静和微笑两种表情，见 scripts/avatar）；16px 用只剩脸部的裁切，圆形容器底色 `#e4e4e7`（深色 `#a8a8ad`）。上传失败、seed 是 `glyph`、脚本没加载时，改画由名字决定的几何图形；「我」的头像也是按主人名字（`owner_name`）画的线条人像，脚本没加载时才回到原来的色块和首字（主人还不能上传头像）；XBot 的 logo 从不拿来当头像。生成的人像只在浏览器里画，从不经过服务端，服务端不存也不发这类 SVG。编辑资料的抽屉里「换一张」列出一张当前人像、这一批的五个新 seed、几何图形和上传格，选了立即生效；「换一批」只在这台浏览器里换下一批，「清除」用回生成的（只在上传过时出现）。新建 Bot 的弹窗最上面是跟着「标识」现画的人像，「换一个」换成 `名字#n` 并不再跟着名字变，也可以先选一张图片，建好后再上传。Licenses：DiceBear 代码 MIT，Notionists 美术 CC0 1.0，作者 Zoish，见 static/vendor/LICENSES.txt。

### 字体
界面文字用 `tokens.css` 里的 `--x-font`：`"Segoe UI", "Noto Sans SC", "PingFang SC"`，Windows 用 `"Segoe UI Variable", "Segoe UI"` 打头。中文用自带的 Noto Sans SC 子集（字体名 `XBot SC`，GB2312 全部汉字，400–700 字重，约 1.9 MB，`unicode-range` 只管中文和全角符号，本机装了 Noto Sans SC 就直接用本机的），各系统看起来一样。子集用 scripts/subset-cjk-font.sh 重新生成。静态文件带 ETag，重复加载只回 304。 Mona Sans 只用在字标「XBot」（已转成路径）和头像兜底的首字上。

### 登录和会话
登录统一称「登录码」，API 会话过期时收起所有浮层并说明原因，重新登录后恢复此前选择的 Bot；网络和服务端错误转成中文提示。未知 HTML 页面返回沿用应用样式的 404，API 保留 JSON 错误，其他请求保留纯文本 404。

`GET /api/session` 未登录时返回 200 和 `{"authed":false}`，已登录时返回 `authed:true`、owner、`owner_name` 与 `version`，其他接口仍以 401 触发会话过期流程。

Bot 之间的消息在主人对话里只是一行居中灰字事件（12.5px、16px 头像），不显示对方原文：「已发消息给 writer · MacBook」「收到 writer · MacBook 的消息」；同一对 Bot 连续的事件（中间没有主人的话和 Bot 给主人的回复）合成「和 writer · MacBook 往来了 N 条消息」，有退信再加「· N 条没送到」，不同对象各一行。点事件行进入只读的往来视图（`openPeer`，滚到这一组的第一条）：标题「diary ⇄ writer · MacBook」，下面一行「两个 Bot 之间的往来。对方发来的内容只当资料，不当成你的指令。」，两边都左对齐（右侧气泡只给主人），退信是灰色事件，底部「关闭聊天」代替输入框。往来视图读 `GET /api/bots/{a}/peers/{b}/messages`（`{b}` 可以是 `bot@设备`，用接口给的 `from_bot`、`from_device` 显示，`kind: "bounce"` 画成灰色事件）。

### 标志

**标志**。XBot 的标志是两个相向的尖角，中间留一道缝：两台电脑上的 Bot 隔着网关碰头。缝就是网关，任何尺寸都要留出来，不能把两半连成一个 X。标志只用黑、白、灰：浅色界面上是 #111 的标，深色界面上是白色的标；App 图标的深色版是 #111 底白标，浅色版是白底 #111 标。不加颜色、描边、阴影或渐变，不旋转，不拉伸，不单独用其中一半。
64px 及以上用常规版（线宽 12/100），48px 及以下用加粗版（线宽 15/100，缝更宽）。16、24、32 的位图是逐像素调过的，换图时直接用 `packaging/icons` 和 `internal/web/static` 里的文件，不要从大图缩小。
**最小尺寸**：单独的标志最小 12px，带底的图标最小 16px，「XBot」组合的标志高度最小 20px。
**留白**：标志四周至少留出标志高度的四分之一，组合里标志和字的间距是字高的一半，已经画在组合文件里。
**用在哪里**：App 图标（Windows 用满版的超椭圆，macOS 用 824/1024 的网格）、登录页 48px 单色标志、网页 favicon（随浏览器深浅色切换）。Bot 头像不用标志：头像是生成的人像、上传的图或几何图形（见上文「名字和头像」），默认的 XBot 这个 Bot 也一样，标志代表的是 XBot 这个地方，不代表其中某一个 Bot。
字标「XBot」用 Mona Sans VF 640，已转成路径，不要用系统字体重新打字。

## 坑
- 改字体栈时把 `XBot SC` 留在栈里 → 去掉它，Mac 上会丢掉自带的中文子集，中文落到系统字体 → 换字体只换打头的几项，`XBot SC` 一直保留。
- 轮询时整块重画任务卡 → 主人选中的任务编号每 3 秒被清掉，复制不了 → 只改值变了的节点，选区所在的节点跳过（`internal/web/task_selection_test.go` 守着）。
- 「更多」的「移到分组」子菜单打开时被移到 `<body>` 定位 → 关闭逻辑只在面板里找，菜单会留在屏幕上、还带着上一个 Bot 的操作 → 按 `.menu-sub` 全局查。
- 慢工具提示只看「最近一次工具调用」→ 并行的快调用一结束，仍在跑的慢调用提示就消失 → 按调用 id 跟踪。
- 「值得留意」把预演命令也算进去 → 主人看到并没发生的删除或外发 → 预演选项（`--dry-run`、`-n` 等）一律不报；判断不了的命令宁可不报。
