# 网页界面

> **30 秒版**：网页和桌面版用同一套界面：左边侧栏列出 Bot，中间是对话，右边是信息面板。对话里只有用户的话和 Bot 用 `send_message_to_user` 说的话，工具调用、子代理任务和上下文用量都放在面板里。整体是黑白灰，靠底色深浅分层、不画线，颜色只留给错误、在线和子代理类型。以后改界面要守的规矩在 [guard/界面.md](../guard/界面.md)。

命令行 `xbot [--root DIR] message <bot> <text...>` 向已运行的本机 serve 发送主人消息：`--http` 默认 `127.0.0.1:8788`，`--timeout` 默认 2 分钟，`--text` 或 `-`/省略正文可提供文本或读 stdin。先通过回环 `/api/session` 获取会话，再调用现有 messages SSE；只输出 `done.text`，没有可见回复、转交、错误或超时返回非零。

对话中的 Bot 往来与 CLI Event 共用可点击的来源行装配缝，按来源种类和身份合并连续事件。Bot 行打开既有往来视图；CLI 行以发送者为 Notionists 头像种子，点击展开该组原文，不把发送者登记为 Bot。

Bot 信息面板「记忆」由 `GET /api/bots/{name}` 的 `memory` DTO 装配：常驻竖叠「关于你」「关于本 Bot」，直接展示各自 `memory.md` 整篇原文，复用气泡 Markdown 渲染和打开文件入口；主数据不经 Recall 拆卡。经历来自当前 Bot 的 `experience.sqlite`，带时间、按记录时间新到旧，点开关注点与提纲；首屏 40 条，`GET /api/bots/{name}/experiences?before=…` 加载更早内容。流水只在页脚给「打开本月流水」入口或空状态，不进主列表。浏览器打开只读原文件，桌面交给默认应用；不提供面板编辑器。守护为 `memory_panel_test.go` 的整篇与带时间数据装配回归、`memory_panel_browser_test.go` 的浏览器行为。

Bot 信息面板的收件箱位于上下文右侧：只读展示该 Bot 的入站叫醒事件，按时间新到旧，可展开摘要；待处理数量弱显，窄面板标签横滚。数据来自 `GET /api/bots/{name}/inbox`，Webhook 和文件监听来源按前缀识别，摘要展示事件正文而非外壳，routine 只取标签内正文；与聊天和全局通知分开。

任务 Tab 的例程技能入口装配在 `routineCard` / `updateRoutineCard` 的现有 `.task-routine` 内：行头保持 36px 密度、14px 图标、34×20px 开关与 6×10px 内边距；正文起点下方一整行 12px 灰字显示有序技能引用或「添加技能」。点击展开逗号编辑，取消或 Escape 丢弃草稿并返回入口，保存仅 PATCH 现有例程接口的 `skills`；留空提交 `[]`，失败保留输入与扁平错误。轮询复用卡片和输入节点，不覆盖草稿或抢焦点。输入使用 `--x-input`，取消用次级底、保存用 primary，卡片仍透明跟页；不读技能库映射名称或增加选择器。行为守护在 `routine_skills_browser_test.go`，接口契约见 [API](../API.md)。

- 详情与编辑资料共用一块模型触发面（`XBotProviders.trigger`）：整栏可点双行，主行模型 id、辅行「供应商展示名 · 协议」（厂商搜索模型再加「厂商搜索」；展示名取 `/api/models` 的 brand/oauth，未知品牌退回供应商名），右侧 chevron。点开「更换模型」浮层（`XBotProviders.open`，沿用 `.binding-dialog` 壳）：副标「Bot名 · 当前 供应商展示名 · 模型id」，顶栏右侧查找模型（按模型 id 或展示名过滤）与 ✕；按 `/api/providers` 分组，每家有密钥的再逐个读运行时名单 `/api/providers/models`（不用本地登记表充当名单；选中尚未登记的模型时换绑接口先核对实时名单再登记），组头「展示名 · 协议短标」，可点行横铺整宽，左侧模型 id（mono），右侧看图、搜索的 outline 图标及短数字窗口（图标的 title 和无障碍名称区分可看图/不看图、本机/厂商搜索），选中中性底加右缘 ✓；空间不足时文字截断。点行只是待选，搜索路变化时列表下一行灰字说明下一轮改用本机或厂商搜索；「使用此模型」才提交，待选等于当前时禁用；取消、Esc、✕、点遮罩丢弃待选。底栏左「管理供应商…」关浮层开设置「模型与供应商」。加载中、没有供应商、没配密钥（组内一行可点去管理）、名单拉取失败（读供应商表失败为整面重试；某家实时名单失败只在该组显示并只重拉该家）、无匹配都是扁平面短句。确认后两处触发面就地重画。浮层内 Escape 只关浮层，不连带关抽屉或面板。厂头副标只读显示模型 id。不可用的模型行禁用并写「暂时用不了」；Bot 有前台、分叉后台或运行/排队子代理时换绑返回清晰错误，不取消已有任务。换绑保存后下一轮重建内核。
- 设置浮层的「模型与供应商」按 A-magpie 分成订阅和供应商两区。订阅区以 ChatGPT 和 xAI 卡作为登录入口：未登录时点击授权，等待时可再次点击重开授权窗，不重绘搜索框；成功后显示已登录绿点，再点进入详情；供应商用两列圆角卡，只显示透明品牌标、供应商展示名和已配置绿点，名左、绿点（订阅未登录时的「登录」）贴卡右缘，配置 id 不作主标题；选中卡用中性底色 `--x-fill-2`，网格容器透明，未选卡为 `--x-fill-1`，不靠外框或硬切强调；键盘焦点用中性轮廓。换绑行和网页搜索选项也用较浅的选中底，其列表容器不铺底色。搜索框靠右。点卡进入详情：返回入口、厂标、厂名、协议小标签、密钥状态，以及「厂商搜索」「看图」/ 窗口芯片行（用户用语，不露工程词）；不使用能力表格。模型行显示只读「有厂商生图 / 无厂商生图」能力芯片（OpenAI/xAI OAuth Responses 为有），不再提供可勾策略或生图模型输入；策略只在「图片生成」设置。进入详情及重试时实时拉供应商 model list，名单与能力来源见 [供应商](providers.md)。未配密钥先提示配置，拉取失败和空名单均给出重试；返回保留搜索条件，迟到响应（含保存密钥）不会覆盖新页面。内置厂商的详情拉取走 `POST /api/providers/{brand}/sync`：把厂商真名单登记进配置（可选择、可绑定），未改动且无 Bot 绑定的占位种子随之清掉；同名但地址或密钥变量不同的自定义条目一律 409，不收密钥、不被发送。xAI 账号登录与 API 密钥互不占用，订阅详情和密钥供应商详情都可填写密钥；Bot 分别绑定账号或密钥供应商。ChatGPT 详情显示「已登录」并支持重新登录；名单失败可重试或重新登录。授权复用既有 OAuth 与 vault；OpenRouter 列表不提供登录入口，Claude 订阅不提供 OAuth。模型仍从 Bot 的模型行选择绑定。厂商搜索步骤、正文引用角标和来源列表显示在对话气泡内，不画任务卡；生图按下述普通工具轨迹展示。供应商网格在 DeepSeek / OpenAI / Anthropic / OpenRouter 之后列 13 家密钥厂商（Gemini、Vertex AI、xAI、Kimi、Kimi Code、Zhipu GLM、Z.ai、MiniMax、StepFun、Xiaomi MiMo、Baidu Qianfan、Tencent Cloud、OpenCode Go），默认值在 `internal/config/vendors.go`，`GET /api/providers` 的 `vendors` 只带品牌、短名、协议和默认模型名。未配密钥的厂商详情给密钥输入框，`PUT /api/providers/{brand}/key` 按内置默认补 providers.json 条目（不覆盖用户同名条目）并把密钥写入 env 文件；Vertex 没有纯密钥路线，只显示默认模型和「需要先登录 Google Cloud」，不可聊。已配置条目的品牌按 base_url 主机名识别。OpenCode Go 复用密钥详情，提示「订阅 Go 后到 Console 复制 API key，粘到这里。」，不进入订阅 OAuth 区。

## 聊天主列窗口与搜索

主列打开/切Bot、分页、轮询、收工与侧栏预览只请求`GET …/chat`，搜索只请求`…/chat/search`；默认40条送达行、上限200条，不为可见条数扩大raw窗。`id`负责游标和keyed patch，`transcript_seq`保留引用回链；附件和卡片沿原渲染组件。存储/整轮不可变快照见[上下文](context.md#聊天读取窗口)，决定见[ADR 0039](../adr/0039-chat-delivery-timeline.md)，验收入口见[设计](../dev/chat-timeline.md)。轨迹打开后单独读取原transcript。

打开/切 Bot 清空旧主列，等待中仅挂页色半透明遮罩和当前Bot圆头像（复用生成/上传头像）叠随机闲话；长等待轮换、轻弹入与字偶轻抖，reduced-motion 全静态。尾窗 JSON 完整到齐后离屏拼完整消息 DOM，一次替换，遮罩约320ms散去；失败留在遮罩内显示「对话加载失败」并重试，不冒充整机离线。设计交接在用户本机 `~/agent-tools/chat-window-search/`，当前功能验收见 [dev](../dev/transcript-window.md)。

列顶居中「更早的消息」chip 与上滑入口走同一before请求，加载时只改chip，不重置已有消息；prepend保留可见泡节点和视觉锚。主列缓存最多800条 chat 送达行，合并统一从旧端裁，不丢打开时的最新消息；满窗后不能继续向旧端扩展时，现有提示行说明用搜索定位更早历史。分页按钮的加载态、到达最老页的提示先更新，再校正可见锚点；最老页提示不再定时消失引起二次位移。主列滚动由 `threadStick` 统一持有 stick 状态、rAF 贴底、ResizeObserver（当前 `.thread-inner` 与滚动容器）和视觉锚；打开/首次/latest 进入 stick，上翻离开 120px 阈值解除，主动下滚回底部恢复。布局增高不解除 stick，追加、SSE、临时发送与历史控件改高都经此缝跟尾；解除后不被观察者或新尾拉回。分页先完成控件状态再校锚，搜索定位显式解除 stick；历史轮询按 stick 状态冻结，重新 stick 或回最新可读取服务器真尾，尾窗有缺口时 stick 直接换新尾窗、不拼接断层。回归为 `chat_stick_browser_test.go`（墙钟 Chrome 帧循环，避免虚拟时间跳过 ResizeObserver/rAF）。搜索由顶栏右放大镜打开白纸浮层，摘录与时间来自同Bot FTS；点命中关闭浮层、按chat ID开附近窗并短高亮，前后都能继续翻、能回到最新。搜索只命中chat FTS的可见正文，内部/工具行仍由Agent的transcript搜索负责。历史位置不被轮询抢走，尾窗变化继续走chat条件请求与按chat ID补丁；窗口有缺口时保留旧窗并提供更新入口，不静默拼断层。失败保留已有消息并可重试。接口契约见 [API](../API.md)。

## 语音交流

Composer 的 mic 在发送钮左侧：点按进入录音条，「发送」提交语音文件；持按松手发送，滑出或取消区丢弃，Esc、切 Bot 和离页释放麦克风。文字草稿、待发图片不随录音发送。录音失败用短提示；上传失败保留录音供重试，消息发送失败保留语音 id 供重试。

主列的 `userBubble`、`botBubble` 与 `optimisticMessage` 共用 `appendMessageBubbles`：连续文字合为一泡，空行在泡内形成多个段落（代码围栏与块级公式内部空行保留）；每个 audio id 与每张图各一泡。短尾段明确标作版本或以「注／备注／说明：」开头时归入最后一个语音泡的 `.v-caption`，不确定的正文保留在文字泡内。文字在音频前、图片仍在末尾。簇间距 6px，Bot 左对齐、用户右对齐；各泡宽跟内容，语音独立于文字宽度。播放器横排行内居中：32px 播放钮、同高的十根竖波形、右侧时长，行内间距 8px；波形短音（≤5 秒）56px，随 metadata 时长增长到 120px，短音泡约 140–170px，窄屏仅收缩、不扩张填满文字。播放时右侧显示向上取整的剩余秒数，原生 audio 的 play／pause／ended／timeupdate 事件更新状态，按 currentTime / duration 从左到右给已播竖条加 `.is-on` 填实、未播 muted；暂停与结束回总时长和静态波形，不增加计时器。下方注释 13px 灰字；不另套灰壳，不画横进度轨。引用只放在该列第一条内容前，同一条 transcript 仍是一条，不改变存盘或 Bot 已送达消息的归组。原生音频播放器只由点击播放，同线程互斥；取 metadata 显示实际时长，未知时不画零秒。失败显示「语音加载失败 / 重试」。主列不展示 listen/tts 调用，轨迹沿用既有投影。`commitTranscript` 继续按行比较静态投影：附件改变只替换受影响行，未变播放器与播放状态保留，移除或切线程时停止播放。新投影只有进入 DOM 才载入 metadata，不因丢弃投影发媒体请求。HTTP 契约见 [API](../API.md#语音附件)，验收入口见 [语音交流](../dev/voice-chat.md)。

## 为什么这样设计
2026-10-20 用户试用后觉得旧界面太丑，用户体验设计师出了一整套「白纸」设计，用户定稿后分七步落地，2026-10-22 做完。设计稿不在仓库里（box 的 `/workspace/xbot-ui-design/step2/`），仓库里只留设计变量 `internal/web/static/tokens.css`。几条贯穿全局的取舍：

**对话只放对话。** 旧界面里，一个子代理在跑这件事会同时出现在对话里的任务卡、消息上的「后台」标签、铃铛和任务弹层里，同一件事说三遍。现在对话里只有用户和 Bot 的消息；谁在忙，看输入框上方的一行状态和侧栏顶部的问候句；完整经过在面板的「任务」页。例程跑完没话说时，对话里什么都不留。

面板「任务」页最下面是 **Webhook** 小节（不进设置·连接应用）：空态「还没有 Webhook」+ 新建；列表行是名字、地址末段和「签名校验 / 令牌」；新建浮层填名字（客户端先按 `ValidID` 拦）和校验方式，成功后同一浮层换成「已创建」，明文给出地址和密钥，点内容复制；详情可再看地址、显示/隐藏密钥、撤掉（确认）。有公网地址时主行是公网地址、「本机」折叠在下；没有时主行是本机地址，下面一行「登录网关后可得到公网地址」进设置·设备。数据走 `/api/bots/{name}/webhooks`，打开任务页读一次，不随任务轮询重画。

**靠明度分层，不画线。** 窗口灰、卡片白、面板浅灰，再加三档填充色，区块之间靠底色和留白分开，没有描边和分隔线。页面里的卡片不加阴影，只有浮层（菜单、弹窗）有。面板里的列表用隔行底色（斑马行）代替分隔线。

**颜色省着用。** 红只给错误、失败和删除（Windows 关闭按钮悬停的系统红除外）；绿只给「在线」圆点；其余颜色只出现在上下文色带和子代理类型标签里，而且都是低饱和的。

**设计变量集中在一份文件。** `tokens.css` 单独加载、先于 `app.css`，组件只引用里面的变量（颜色、字号、间距、圆角、动效时长和曲线）。设计师以后改变量时整份替换，不用改组件。

## 怎么运转

### 公网登录后的设备壳

公网账号入口（`xbot-account` 云静态）只留登录 / 注册 / 查收邮件三屏；`#devices` / `#gateway` 已删，有会话一律进 `/app/`，无设备或离线用设备侧 boot 中文，不回落云设备列表。入口另保留 boot / bridge、仅控制 `/app/` 文档的资源 worker 和字体；业务 HTML、JS、CSS、图标通过当前配对设备的 `GET /api/ui/static/<path>` 读取 serve 进程实际提供的 UI。本机路由与 pipe 共用解析：开启 `XBOT_DEV_STATIC` 时同读配置目录（每次请求重读，缺文件不回落 embed），关闭时同读内嵌 `staticFS`；开发覆盖时 `X-Xbot-Tip` 为 `dev-static`。同源浏览器资源请求由 worker 交回所属页面的现有加密 pipe，账号 API 继续在云上。没有云上业务壳副本或持久业务资源缓存。

设备选择时会关闭原 pipe 并整页重载。未选择时取在线设备；明确选择的设备离线时显示原因和重试，不自动换设备、不回落旧壳。会话版本由设备静态响应的 `X-Xbot-Tip` 提供，纯 dev 构建用内嵌 UI 摘要区分。同步脚本不再是业务 UI 发版路径。协议、安全和体限见 [ADR 0029](../adr/0029-public-ui-single-source-via-pipe.md)、[API](../API.md#设备静态壳)。 设计师用户视角已 PASS（合入 tip `a02e3f3`）：公网 `/app/` 仅 pipe 薄引导（`boot.js` 200、`app.js` 404），业务壳经设备 `GET /api/ui/static`；本约定即 atlas 真源。登录后主壳缺会话不挡本条收口。

### 统一设置浮层

账号菜单的「设置」打开居中浮层，左侧依次是通用、账号、权限、网页搜索、技能、人设卡、图片生成、设备、连接应用、模型与供应商、关于，对话保留在遮罩后面。主题用浅色/深色/跟随系统下拉框；跟随系统会响应系统明暗变化。权限总开关与 CLI 共用 `permissions.json`，缺文件默认关，运行中的 Bot 也读取同一开关。设备列表嵌在浮层内，远端对话与配对完成后的「查看设备」都进入这一页；设备标题行只有「+ 添加设备」入口，页面没有加入入口和底部动作条；配对、改名等弹窗复用原设备模块。连接应用是应用商店：顶栏「已连接 N 个」、搜索、分类芯片、推荐与分区卡网格，全部走不带 Bot 名的 `/api/apps`（添加、移除、自定义应用），装的是用户全局，与侧栏选中的 Bot 无关；商店卡标盒 48px、图形 30px，品牌使用品牌形标；网格同行等高，说明最多两行截断，末行单卡仍占一格，密钥范围说明完整显示。Google 三家只展示「即将支持」，文件系统、Webhook、文件监听、技能不在这一栏；电脑操作、浏览器、网页抓取是原生能力，`/api/apps` 目录本身不含它们（`StoreApps` 不列原生器官，`fetch` 目录行 `hidden`），前端不再另滤，「已连接 N 个」只数外接，分类芯片没有「本机」，推荐是 Playwright 与 Context7。要密钥的商店条目在设置内复用 nestcard 输入密钥（标签取列表的 `fields`），不关设置或代发聊天；提交失败保留输入，成功后才关闭并提示「已添加到你的应用」。所有添加都要服务端真调通才标已装，无密钥卡失败时错误留在卡上。手机推送开关挪到「通用」。关于的版本行左侧是标签、右侧是服务端版本与构建短号；点击版本串复制完整展示内容并短显「已复制」，头区只有标和「XBot」，不复读短号。通用、权限、关于的行，技能、人设卡、已连接清单（行间无分隔线），设备「这台电脑」行，图片生成的开关行和未登录引导都透明跟页，不套 `--x-fill-1` 灰壳；商店卡和已配对设备卡保留卡面。短号来自 `/api/session.tip`。

### 技能设置

「技能」是本机技能库的安静清单（`static/skills.js`、`skills.css`，同族于网页搜索）。一层：标题行只有「技能」，导语下、列表块顶外缘右对齐 `[搜索技能][导入]`，导入是唯一主按钮；每行只有主名、副行和 chevron，不显示路径、停用状态或 Bot 数。列表与详情共用展示名规则：非空 title 优先，再用旧文件的可读 name 或 slug/文件夹名，永不用 description 作主名；副行放不同于主名的 description；缺失、解析失败或块标量符号不画副行。手机标题和开关无障碍名称沿用同一主名，内容均按纯文本渲染；搜索按名称、说明和 slug 在前端过滤。导语与导入层统一写「本机 Bot 共享。是否启用，按每个 Bot 单独设。」；列表脚注只提示按 Bot 开关。库为空时隐藏搜索和工具条，空态提示「从本机导入一份技能，也可在对话里让 Bot 帮你装。」，中心放「导入」；无匹配显示「没有匹配的技能」和「清除搜索」，不再放第二个导入。二层：返回「技能」，名称和说明只读，「在这些 Bot 里启用」当前登录人有权管理的每个本机 Bot 一个开关（默认开，关只影响该 Bot，失败时开关退回）。

点「导入」先出来源层：Agent、Codex、Claude、本机文件夹四行，底栏只有取消。前三项读本机对应技能库的一级技能目录（服务端只认来源 id，不回路径），进多选清单，底栏唯一主按钮「导入所选」（没勾禁用），逐条导入，遇同名逐条问、取消只跳过那一条；空源写「这边还没有可导入的技能。」和「换个来源」。本机文件夹由浏览器选（`webkitdirectory`），只读出根下的 SKILL.md 发给 `POST /api/skills/import`，不传路径；同名先问「库里已有同名技能，要覆盖吗？」，覆盖才替换，取消不动库。多用户 Bot 同样显示开关；库共享不扩大 Bot 管理接口的访问权限。详情、导入这类异步回包只认最新一次选择：新选择、返回列表、关闭设置都会让旧的回包作废，导入文件读完后若设置已关或导入层已换也不再发送。接口见 [API](../API.md#用户技能)。详情底栏左边次要「删除技能」（照人设卡危险文），嵌层确认「从库里删除？」；有本机 Bot 开着则点明本数据根的启用总数 N（详情里的开关仍只列当前用户可管理的 Bot）；确认后删出库并清掉各 Bot 对它的开关，回列表报「已删除「…」。」。不做改正文、重命名、分组、MCP 和设置页编辑器。 设计师用户视角已 PASS（tip `a02e3f3`，祖先含 `3803f3d`）：技能 title 优先、只给你用默认开关、四源导入；本约定即 atlas 真源。

### 人设卡设置

「人设卡」是用户整个卡库（`static/persona-cards.js`、`persona-cards.css`，壳和列表复用技能设置）。一层：标题行只有「人设卡」；导语提示「内置种子已升级；你改过的不会被盖」；导语下、列表顶外缘一行左侧是选中的「全部」分段项，右侧是 `[搜索人设卡][＋][导入]`（窄屏可折行），「＋」是纯图标的新建，「导入」是唯一主按钮；空库不显示工具条；每行卡名、正文首行预览和 chevron，不显示 Bot 数或开关；搜索输入时先按卡名加正文前 1 KiB 即时过滤，再以服务端 `?q=` 的全文结果为准（旧回答迟到会丢掉）；选用层同样。选用层归资料抽屉：抽屉关闭或重开时 `closePick` 让还在加载的选用层作废，打开或加载期间再点不重复打开。库为空时隐藏搜索和工具条，空态中心放「写一张」（次）和「导入」（主），说明导入总是新建。无匹配显示「没有匹配的人设卡」和「清除搜索」。二层：返回「人设卡」，卡名可改，一整块正文，底栏左边次要「删除」、右边主「保存」；不在这里按 Bot 开关。删除在有 Bot 在用时说「N 个 Bot 还在用它」，确认后解绑再删。「导入 Markdown」嵌层选一份 .md（最多 256 KiB），同名时问「库里已有同名人设卡」，「仍然导入」新建带编号的一张，原来那张不变。卡正文进页面只用 textContent。

### 自定义供应商设置

模型与供应商的 API 网格末格为透明 ghost「添加自定义」。详情在现有扁平面内填可选展示名、Base URL 与脱敏密钥；地址失焦或保存按后端 host 表给协议芯片，「更改」展开三协议选项。HTTP 仅灰字建议 HTTPS；非法 URL 和无已存密钥时的空输入阻止保存。试态 icon 明确标为「保存并测试密钥」，先落配置再读目录，成功才显示通过；普通保存也在成功后拉模型。空/失败目录可重试或手动添加 id，模型勾选直接登记/取消；删除在底栏危险入口二次说明密钥、模型与 Bot 换绑影响。

自定义卡用通用线标、右缘配置点和中性 fill-2 选中。主标题优先用户展示名、其次 host 对应人话名、最后「自定义供应商」，不露内部配置 id。匹配内置 host 的自定义卡仍单独存在，且不吞内置格。绑定侧复用实时目录及显式手动模型，供应商标题读取同一元数据。注册与密钥规则见 [供应商](providers.md)，真入口冒烟为 `e2e/smoke/custom_provider_test.go`，辅助 `internal/web/testdata/custom-provider.cjs`；用户日用尚待验收。

### 图片生成设置

设置左栏在人设卡后、设备前显示「图片生成」。全局默认关闭，关时仅显示开关和生效说明；开时先显示与网页搜索同皮的「怎么画」：自动（默认，当前模型有 hosted 则厂商，否则代理到所选账号）/ 总用设置里的家（只走代理）；再显示 OpenAI / Grok（xAI）单选及工作区产物说明。关时两区都隐藏。xAI 未登录时详情引导回订阅区，过期或登录失败时可重新登录。账号状态只读现有 OAuth 元数据；没有保存选择时优先已登录的一家，否则 OpenAI。未登录的选中行下显示扁平说明和「去模型与供应商」，在同浮层进入 ChatGPT 详情 / 订阅区 xAI 卡，只有用户点击现有登录按钮才发起 OAuth。此页没有登录或密钥表单。重新打开刷新登录态；保存失败保留上次设置，离开后迟到响应不重绘。开关的 `.on`、`aria-checked` 与选择区 `hidden` 同步取保存后的 `enabled`；保存失败保持旧状态。所选账号只决定代理使用哪家，不要求与 Bot 当前绑定对上；产物脚注为「画好的图保存在工作区，由 Bot 主动挂到回复中。」新一轮使用新设置，只有 Bot 调用 `send_message_to_user images` 挂到回复的图片才沿既有 gallery 展示；生图保存回执仍是普通工具轨迹。

生图使用普通工具调用呈现：运行中复用普通工具的三点忙态（空 description 沿用本次忙碌的上一条，尚无 description 时不加文案），`image_generation` 的提示词与真实保存回执进入现有「轨迹」调用行和展开正文。协议仍是 `PartHosted`，不伪造可执行本地工具调用；对话中不再绘制独立生图步骤、提示词按钮或「查看 generated/」交付入口。只有最终回复的 `Entry.Images` 经现有 paste 路由进入 gallery，完成步骤本身不显示图片。生图回执与失败规则见 [供应商](providers.md)。

Bot 菜单「查看生成的图片」保留为可选工作区定位功能，打开现有模态框展示服务端工作区路径并可复制；桌面有真实 OpenPath 回调时才显示「打开目录」，复用 open-workdir。接口仍固定路径并校验 Bot 所有权，不分发图片、不新增产物账本。

### 资料即时刷新

`bot_update_profile` 的工具结果到达后异步刷新 Bot 列表，头像字段参与侧栏缓存签名；当前仍选中原 Bot 且不在往来视图时同步重绘顶栏。刷新不等待流式结束，慢请求不阻塞正文；切换 Bot 后迟到请求不恢复旧顶栏，读取失败不打断回复。

### 网页搜索设置

「网页搜索」控制整台 XBot 的所有 Bot。关闭时不提供本机和厂商搜索；自动模式优先模型自带搜索，没有则用本机；总用本机只用所选本机搜索。新一轮对话使用新设置；本机已有内核也会在下一次调用读取设置，不重建内核或取消任务。运行中的远端任务保留启动时的设置，新任务使用新设置。供应商详情不加搜索开关。

本机默认 DuckDuckGo。「本机用哪家」标题旁的说明在悬停或聚焦时提示默认服务、搜索失败和新设置生效时机。九家名单由 `config.SearchProviders` 提供，DeepSeek 已接入，其余七家保留入口但搜索会明确报不可用。开关行、「怎么搜」两行和本机供应商行都透明跟页（方向 A 勾选静音），选中只靠 radio 内点。DuckDuckGo 行右写「免密钥」，未选的需密钥行右侧留空；选中需密钥行仍是单行，行右是透明的脱敏密钥输入和一个状态图标：绿勾可用、叉无效（都可点再试），播放为待试。图标就是原「试一下」探测，状态写在它的 aria-label 里。空密钥时图标禁用；失焦和图标共用一次探测。成功后自动保存、清空输入并只留遮蔽占位，读取接口只给配置状态；失败保留输入。改字或离开设置时取消旧探测，迟到结果不覆盖草稿。保存选择后同步接口返回的密钥状态，保留未提交输入和已知失败状态。

### 窗口和三栏
桌面版 `xbot app [--port 8787]`（[ADR 0007](../adr/0007-local-first-desktop-app.md)）在同一进程里跑 serve（不开隧道、不自动升级、不打印登录 token），只绑 127.0.0.1，用 `internal/appshell`（唯一引用 MyGo 的包）开系统 WebView 窗口。窗口打开 `/app/launch?code=…`：一次性登录码 32 字节随机、60 秒过期、用一次就作废，换成正常的会话 cookie 后跳到 `/`，所以桌面用户看不到登录页。同一个数据根只能开一个（`app.lock`）；端口被占时在改动数据之前就报错退出。安装包由 scripts/package-desktop.sh 打出（macOS .app/.dmg、Windows XBot.exe），安装和放行步骤见 [desktop-install.md](../desktop-install.md)。关窗即退出；窗口记住尺寸、位置与最大化状态，外链交给默认浏览器。页面切换外观时 `POST /api/app/theme` 让系统按钮跟随 XBot 自己的明暗主题，不跟系统（`appshell.SetTheme`）。

窗口没有单独的标题栏，内容铺到窗口顶，每一栏顶部约 40 是拖动区，按钮不参与拖动。Mac 的红绿灯内嵌在侧栏左上，侧栏顶部让出 46，主卡片四周留 8。Windows 的最小化、最大化、关闭按钮由 MyGo 原生画在右上（46×32），主卡片贴着右边和下边、只有左上圆角，面板操作行下移到 36，避开系统按钮。版本号在设置的「关于」里。

三栏从左到右是侧栏、对话、信息面板。侧栏默认宽 280，右边缘可以拖，宽 240 到 360，双击边缘回到 280，宽度记在这台浏览器里（`xbot.side`）；拖到 200 以下吸成 72 宽的窄条，只剩头像，名字改成悬停提示。信息面板在所有宽度下都是盖在对话上方的右侧抽屉：桌面宽 384，中宽 340，窄于 768 时为全高、宽 `min(90%, 400px)`，自己承担上下安全区。进出统一用 translateX，开关不改变抽屉宽度、不重排对话；点击露出的对话遮罩关闭。减少动态效果时取消滑动。72px rail 只显示置顶头像、Bot/群头像、底部加号和自己头像；分区头与设备头只留 10px 透明空隙，无背景、圆角或残留按钮。问候、预览、网关提示整段隐藏，名字通过悬停提示显示，未读点和在跑转圈保留。

对话顶栏透明，身份卡悬浮在对话上方：各宽度均只显示 28px 头像与名字的紧凑横排；状态和 Bot 往来提示在对话底部，简介不显示在卡上。面板依对话区宽度避开身份卡，空间不足时从顶栏下方打开。面板开关是对话顶栏中间的身份芯片 `#head-chip`（头像 + 展示名，整块是按钮），点一下开、再点收起；开态浅底并 `aria-expanded=true`；没有单独的详情钮，也不属于面板厂头。群组同样可点；两个 Bot 的往来视图没有面板，芯片禁用。窄屏左边是打开 Bot 列表的汉堡，芯片在汉堡与右缘之间居中，右边留空。窄屏顶栏高度为 `52px + safe-area-inset-top`，内容带固定 52px、左右内边距 16px；热区 32×32，图标约 20px。Esc 收起面板（有菜单、资料抽屉、弹窗时先关它们），⌘\ / Ctrl+\ 切换。面板默认关闭，只恢复本机明确保存的打开选择。Windows/Linux 桌面顶栏为系统按钮让出顶部空间。

### 对话
底部状态行预留一行高度，不再显示重复的「正在回复」文案，回复中保留主列三点 typing 指示；排队、错误与进程状态逻辑不变，Bot 往来提示可按内容换行。

对话列宽 `min(680px, 100% - 64px)`。消息都画成气泡：用户的气泡靠右、深底白字（深色模式反过来），最宽 72%；Bot 的气泡靠左、浅灰底，最宽 86%，段落、列表和代码块都在气泡里，代码块用比气泡浅一级的底色。单聊不放头像和名字，时间只在悬停时出现在气泡旁边。同一个发送者 5 分钟内、中间没夹别的东西的几条算一串，串内间距小，串与串之间间距大；分组由 `groupStart` 这个纯函数决定，历史、翻页和实时追加都走它。和上一条相隔 30 分钟以上或跨天时，中间出现一行居中的时间（「昨天 11:38」）。群聊和 Bot 之间的往来视图里，每串第一条保留头像、名字和时间。消息少时对话贴着底部排。

系统行仍是文字，不画气泡。定时唤醒和错过的定时汇总是记录，不进对话：例程跑完有话对用户说时只见那条气泡，没话说（SILENT）就什么都不出；这条投影规则在 `app.js` 的 `routineRuns`。后台工具完工的 `shell` 来源事件也不进聊天主列，原事件仍保存在 transcript。收到别的 Bot 的消息、没送到、限流这类状态行也是灰字；Bot 自己调工具发出的往来不画系统行。汇报和主动唤醒都按普通 Bot 消息画，消息上没有「后台」标签。工具调用原文不进对话，在面板的「轨迹」里看。助手正文、预览和标题只在显示时隐藏内部任务编号，原始编号只在「任务」页的「任务详情」里出现。

子代理在跑时，输入框上方有一行状态：一个时写「头像 名字 · 当前一步 · 第 N 步 · 用时」，多个时收成「N 个子代理在跑 · 最久 X 分」，点它打开面板的「任务」页，全部做完这行就消失。前台在跑一个慢工具、用户又说了话时，消息流末尾多一行灰字说明它在等什么、等了多久；慢工具按调用 id 跟踪，并行的快调用结束不会把仍在跑的慢调用藏掉。标题栏只放头像、名字、状态，不放后台任务的小标；以后子代理的提示方式按子代理卡片来做（类型来自 [ADR 0016](../adr/0016-foreground-dispatches-typed-subagents.md)；主线全工具、长活派子代理见 [ADR 0028](../adr/0028-no-foreground-background-split.md)）。

没有消息的 Bot 在卡片正中给头像、名字和「有什么事，直接说就行。」，下面最多 3 个开场建议，点了只把文字填进输入框，从不直接发送。空状态（新 Bot、记忆、轨迹、任务、服务离线、未配对设备）各有一张线条插画，共用页面里的 SVG 定义。

发送已接受后流中断时仍保留标为「没送到」的原文气泡并恢复草稿，排队事件继续显示「已排队」，直到新增的用户原文记录接替气泡；任务状态和错误使用中文，原始错误可展开「详情」，任务结束时间取终态元数据的写入时间。

桌面版（`Server.App`）的旧登录码路径不提供「退出」，`/api/session` 带 `app:true`，`POST /api/logout` 回 409，因为登录码只在启动时生成一次；账号可以退出（`POST /api/account/logout`），再用账号登录回来；`POST /api/app/theme`（`{"theme":"light|dark|system"}`）只在桌面版存在，走登录和同源检查，值不对回 400，成功回 204，App 用它设置 `Server.AppTheme`。再次发送同一原文时先移除旧的失败行；返回 202 排队的消息保留气泡并标「已排队」，直到对话记录里出现同样的文字；「回复出错了」在下一次发送被接受时清除。重新点击当前打开的 Bot 或群不重置对话；群消息在会话过期时同样保存草稿并在重新进入时恢复；服务端 4xx 带原因时显示「没能完成：原因」。

**文内可点文字一套皮**：输入框草稿、用户与 Bot 气泡、`.prose` 正文里的链接共用 `--x-text-link` / `--x-text-link-bg` / `--x-text-link-hover`（tokens.css，浅深两套）：蓝字、浅蓝 4px 圆角底、无下划线、不加粗；用户气泡底色与卡片相反，`.bubble` 把这组换成 `--x-user-link*`。按钮、整行、图标钮、code 不用这套。可点的 http(s) 文内链（气泡裸 URL 与 `[文字](url)`、输入框草稿链、联网来源 `.hs-cites`）在底内最左带该站自己的 `/favicon.ico`（`linkIcon`，14px，距字 4px）：加载成功前不占位，失败就去掉图片、只剩文字链；每个站点的成败在进程内记一次，草稿重绘不重复请求。不用公开图标服务，因为它们对没有图标的站回一个能正常加载的占位地球。

**输入框 URL 高亮可点**：对话输入框是纯文本 contenteditable（不是 textarea）：草稿里的 `http(s)://` 地址就地高亮成文字链（与气泡链接同款），点它用系统默认浏览器打开（网页走 `target=_blank` + `noopener`，桌面壳复用既有离域导航 → OpenExternal），点击不会触发发送；Enter 照旧发送、Shift+Enter 换行、输入法选词回车不发送。只认能解析为 http/https 的地址，尾随标点（`。，)…`）不进链接，紧贴的中文正文不吞；`javascript:`、`data:` 等其它协议不高亮不可点。纯文本上限仍 16000，规则同旧 textarea 的 maxlength：超限的编辑（输入、粘贴、拖入、整段替换）在编辑入口整体拒绝，不截尾，已有草稿一字不丢；程序化写入（发送清空、草稿恢复、失败回填）不走截断。撤销/重做由页面自己维护（每次被接受的编辑一步，⌘/Ctrl+Z、⌘/Ctrl+Shift+Z、Ctrl+Y，菜单撤销和浏览器原生 undo/redo 命令也接住：后者不经 beforeinput、作为不可取消的 historyUndo/historyRedo input 到达，丢弃原生结果、改放自己的历史），因为原生撤销栈经不住整段重渲染；程序化写入重置撤销基线，同旧 textarea 赋值。粘贴一律转纯文本，图片粘贴照走下面的流程。

**草稿 Markdown 语法高亮**：在 URL 高亮之上，输入框对草稿做语法上色（非 WYSIWYG，所有源字符照常可见可编辑）：行首 `#`/`##`/`###`（要求后跟空格，`####` 不认）、行首列表符 `- `/`* `、`` `code` ``（等宽字加底，内部不再嵌套高亮）、`**粗**`、`*斜*`（列表星不误判成斜体）、`[text](url)`（整段源文本可点，协议规则与裸 URL 一致，非 http(s) 不成链）。深浅色各用主题变量上色；光标按纯文本偏移恢复，打字不跳。数学 `$…$` 不在草稿里渲染，保持源字符。

**气泡数学公式**：消息气泡（流式与已存 transcript 同路径 `appendMarkdown`）渲染 `$…$` 行内与 `$$…$$` 块级数学，KaTeX 0.16.11 随静态资源内置于 `static/vendor/katex/`（MIT，字体 SIL OFL，仅 woff2）。TeX 源从不作为 HTML 进 DOM，唯一 innerHTML 来自 KaTeX 的转义输出；KaTeX 以 `throwOnError` 调用，缺失、抛错或真实解析失败都回退显示原文，不炸气泡，回退串保留完整源定界符（句中的 `$$…$$` 仍以 `$$` 回退，不改写成单 `$`）。块级配对按首个闭合 `$$` 切分：同一行 `$$a$$ 和 $$b$$` 是两段公式加中间正文，多行块闭合行尾再跟公式也照切。`$5 和 $6` 这类金额（闭侧是空格）不当公式；代码段里的 `$` 保护；流式期间未闭合的 `$` 先显原文，闭合后整段重渲染即正确。

**气泡 Markdown 排版**：同一 `appendMarkdown` 路径还渲染三种块。围栏代码由自研 `highlight` 按语言档（go、js/ts、python、java/kotlin、c/c++、rust、shell、sql、json、yaml 及常见别名）切出关键词、字面量、字符串、注释、数字、函数名，每段用 textContent 进 span；未标语言或不认识的语言保持纯文本，单行字符串没闭合时引号按原文处理，不吞后文。颜色走 `.code-block` 上的 `--syn-*` 变量：浅底用浅色板，深底（深色主题的 Bot 气泡、浅色主题的用户气泡）用深色板。行首 `>` 连成引用块：每层剥一个 `>` 后递归回 `appendMarkdown`，所以 `>>` 嵌套、列表、行内格式、数学都照常，可见文字里不留 `>`。引用在切围栏之前先按行认出（围栏里的 `>` 行仍是代码，`$$` 块里的 `>` 行仍是 TeX），所以写在引用里的 ``` 围栏留在引用内、代码不带 `>`；表格数据行遇到引用行即结束。GFM 管道表（表头行紧跟 `|---|` 分隔行、列数一致）渲成 `div.md-table > table`，`:---:` 对齐写 text-align，单元格走 `appendInline`（链接仍只认 http(s)），`` `a|b` `` 与 `\|` 不拆格；只有表头没有分隔行时按正文显示，流式补齐后整段重绘成表。

**粘贴图片**：在输入框里粘贴、或把图片文件拖到对话区，图片先上传（`POST /api/bots/{name}/paste`）再在输入框上方排成 56px 缩略图，每张右上角一个「去掉」；撤回后可以重贴。只认 PNG、JPEG、GIF、WebP，单张不超过 10 MB、长边不超过 2048（超过就整张退回，不缩），一条消息最多 4 张、合计不超过 10 MB，被拒时在缩略图下方用一句话说明原因，没有缩略图时这一行也照样显示。上传中缩略图变淡、发送按钮禁用；只有图片没有文字也能发。发送失败时图片不入输入框，提示「图片要重新贴一次」。换到别的 Bot 或群会清掉未发的图片，因为图片存在上一个 Bot 的工作区里。主列每张图片单独显示一个 84px 缩略图泡，全部展示；点开大图后仍可在同条消息的图片间切换。历史上这一轮的图片照常显示，刷新页面后还在：transcript 只记文件名，图片字节不进 transcript，也不进历史请求；回答这一条的那一轮请求直接带图，之后各轮只留一行「`[用户的图] paste/<文件名>`」让模型自己用 `view_image` 打开。群组对话暂不支持贴图。**Bot 出图**：Bot 用 `send_message_to_user` 的 `images`（pasted id 或工作区图片路径）挂图，图片存进同一个 `paste/`，这一轮最终回复那一行带上文件名，界面把它画在这一轮最后一条 `send_message_to_user` 气泡下方，用同一套 84px gallery、点开是大图。发送失败时原文回到输入框（输入框已有新草稿则保留新草稿并提供「放回输入框」），不再显示「重试」。

在线」或「离线 · 最后联系 昨天 18:20」，右边的「详情」打开信息面板（设备、`bot@name` 地址、聊天记录两台电脑各存一份、记忆只在对方电脑上、「在「设备」里查看」打开设置·设备）。对话里用户的话是右对齐浅灰气泡，Bot 的话带头像、名字和时间，正文一律按纯文本、保留换行。用户这条下面按状态写小字：还在这台电脑上是「◷ 已排队 · 还在这台电脑上」，已交给网关而设备离线是「◷ 已排队 ### 聊天图片查看

气泡缩略图沿用该条消息的图片列表与 paste URL。点击哪张就打开哪张，查看层是原生模态 dialog，始终只显示当前一张完整图片；同条消息中抽出的图片与附件按原顺序合成一组。左右按钮、方向键和未放大时的横向触控滑动只在这组内切换，到头停住，不循环、不跨消息。多图显示 `i / n`，单图隐藏计数与切换按钮。

双击、触屏双击、双指捏合与滚轮可以在适应屏幕到 6 倍之间缩放，放大后拖动平移，位置限制在图片边界内；切图和窗口尺寸变化重置适应屏幕。图片载入失败保留关闭及切图入口。空白遮罩、关闭按钮和 Esc 退出，恢复触发缩略图的焦点及聊天滚动位置；背景由原生模态层隔离，Tab 在查看器按钮间循环。拖动、捏合、取消手势不会误触关闭。交互只改变图片 transform，没有缩放过渡动画。图片仍走既有鉴权与资源路径，没有新增下载、编辑、挂图或线程图库机制。

### 信息面板
面板顶部从上到下是：满宽厂头、上下文用量带、标签栏，只有正文滚动。厂头左侧是 48px 头像、名字和副标，右侧仅「编辑资料」铅笔；不显示更多按钮或假在线/忙碌状态。详情先是「职责」（满宽标题加职责正文），下面另起「人设卡」只显示卡名和一行弱预览，不放卡全文、不放下拉，改绑只在编辑资料；模型为整栏双行触发面（见上文），点击沿用换绑浮层；有上下文快照时在触发面右侧显示真实窗口与后台整理线。

更多操作从左侧本机 Bot 行或置顶头像右键／触控长按进入，复用同一菜单：取消置顶 / 置顶、移到分组、复刻、复制 Bot ID、打开工作目录（只在桌面版有）、导出对话，空一格后是红字「删除 Bot」。操作绑定被点的 Bot，不切换当前对话，也不把远端同名 Bot 当成本机；滚动、取消触控不会误开，长按松手不触发普通选择。重复打开先关旧菜单及其子菜单。复制 Bot ID 用一个 3 秒消失的提示（toast）回执；toast 只用于复制、保存这类回执，不带撤销。

编辑资料抽屉是「基本」（头像、名字、简介）、「职责」（多行正文）、「人设卡」和「模型」四段，底栏保存：人设卡是原生下拉，选项是全库卡名，默认卡标「（默认）」，没有「未选用」；一改即绑定，旁边弱链「管理人设卡」去设置。模型一段是与详情同一块双行触发面，换绑即时生效（下一轮）。抽屉的保存管名字、简介和职责（职责没变不发）。没有说话方式、语言、免打扰。

用量带读最新一次请求的已用、硬上限和软目标，消息色块在前、工具定义在右，点了切到「上下文」标签；在「上下文」标签里和还没有快照时都不画，不用零值占位。上限现在按 128K 画，数字一律取接口，不在前端写死。

标签依次是详情、记忆、任务、轨迹、上下文。「轨迹」一轮一行，写时间、用过的工具和耗时，点开看每次调用的参数和输出，输出默认截断；该轮有可读思考时，展开体最上方多一个默认收起的「思考」折叠块，空白则不画，气泡、主列和导出都不带思考；轨迹不画时间轴分轨，也还不嵌子代理的步骤。

### 任务页
「任务」页分四段，顺序是进行中、排队中、最近结束、例程。一个子代理一项，状态原地更新；名字后面紧跟一个低饱和的类型标签（开发、调研、通用、自定义四色），名字本身就是类型名时不重复。卡片标题用任务的短标题，没有短标题时退回类型名，不显示内部编号。进度文字和标题重复时（去掉开头的「在」后和标题相同，或以标题开头）只显示「第 N 步 · 用时」。每项下面有可展开的「任务详情」（带向右的箭头，展开时转向下），里面是原始请求和任务编号，编号放在这里就是为了让人能复制。

最近结束的运行记录以紧凑行显示；点同一行展开或收起下方结果，标题、图标和行密度保持不变。进行中的任务仍显示展开卡片。

面板每 3 秒轮询一次。值没变的节点不重写，选区落在某个节点里时跳过这个节点，所以用户选中任务编号后，刷新不会清掉选区。

例程每行一个开关，接 `PATCH /api/bots/{name}/routines/{id}`；请求失败时开关弹回，在这一行报错。例程以中文显示常见定时规则，其他规则显示「自定义时间」，原始 cron 放在行的悬停提示里。例程的跑次不进「最近结束」，那里只有子代理的结束记录。

### 值得留意
子代理任务结束时，内核整理一份只含四类事情的清单（`agents[].notable`，见 [API.md](../API.md)）：删除、对外部服务发消息、在 Bot 工作区以外写入、全局安装。清单只记实际发生了的事，判断不准的宁可不报；`--dry-run`、`rsync -n` 这类只预演的命令不算。界面只显示内核给的条目，一条都没有就不出现。

任务页里，结果摘要下面先是一行「值得留意」（12px 次级灰），下面每类一行（13px），行首是一个和文字同色的线条图标：删除 trash-2、外发 send、工作区外写入 file-pen、全局安装 package。顺序固定为删除、外发、工作区外写入、全局安装，越难撤回的越靠前；四类都不用红色，因为这是已经发生的事，不是报错。每行写出对象（「全局安装了 ripgrep」「写入了 ~/.zshrc」「删除了 3 个文件」），对象超过 2 个写成「A、B 等 5 个」，完整列表放进「任务详情」；拿不到对象的写泛称，对象太多（超过 64 KiB）时标明不完整。行内不加句号。路径过长时保留开头两段和最后两段、截掉中间（「~/.config/xbot/…/日常工作/.zshrc」），还放不下就先去掉倒数第二段，文件名永远保留；气泡里的路径用同一个截断函数。

对话里，Bot 的汇报带同一件事的一句话，和任务卡对得上：一条时写「值得留意：全局安装了 ripgrep。」，多条时写「值得留意：删了 3 个文件，另有 3 项，详见任务。」。这句由内核生成（`notable.Line`），交回前台的结果里也有。

信息面板的第五个标签是「上下文」：一张只读的用量卡，看这一轮模型实际收到了什么。数据来自 `GET /api/bots/{name}/context`（见 [API.md](../API.md)），来源是内核在发出请求时留下的内存快照，不落盘、不读 transcript、不触发提醒重写。从上到下：标题「上下文」带下拉，选本轮最近 10 次请求，默认「最新」；一句「N% 已用」和「已用 / 硬上限」（已用含工具定义，硬上限见 [context.md](context.md) 的两条线）；一条色带，把空余也画进去，所以离满还有多远一眼可见，色带上一道细刻度标出软目标（「后台整理线」），消息排在前、工具定义排在最后，刻度对的就是消息量；图例每行是色块、名字、用量和占硬上限的比例，顺序是本轮、早先对话、摘要块、系统提示词、记忆、环境更新、工具定义、空余。下面三到四个可展开的明细：本轮（默认展开，每步一行「工具 + 对象 + 用量」，新的在上，失败的标「失败」，长绝对路径只留最后两段，点一行看结果开头 240 字）、早先对话（每轮一行，用开头那句话命名，没有就不出现）、摘要块（覆盖的 seq 和用量）、工具（每个工具的定义用量）。最后一行按状态说：消息还没到软目标时是「离后台整理还有约 N」，到了以后是「后台在整理 · 离上限还有约 N」。选较早的一次请求时，图例是那一次的，本轮只列到那一次为止的步骤；其余明细总是最新一次的。颜色只花在分段上：本轮和早先对话是同一族的两种蓝，摘要块绿，记忆橙，其余是灰；空余和工具定义用灰，深色主题各自换一套。原来的全宽审计视图删掉了：卡片已经回答「满没满、谁占的」，逐条原文看 transcript。没有快照时（这个 Bot 还没在本进程里发过请求，或由另一个进程驱动）显示一句说明而不是零值。只有前台主循环的请求会进来：子代理、记忆抽取和压缩自身的调用都不经过这里。

状态走只读接口，和别的接口同一套登录：`GET /api/bots/status` 返回 `{bots:[BotStatus]}`，含全部同一用户的 Bot，不带步骤；`GET /api/bots/{name}/steps?n=20` 返回 `{steps:[...]}`，是这个 Bot 当前这一轮的步骤环，`n` 最多 20。`GET /api/bots/{name}/todos` 返回待办清单。`BotStatus.todo` 是一行中文待办／进度摘要；流式回复期间仍每 3 秒拉取 status。运行时侧栏与主列忙态共用按 Bot 保存的 last-description，只取工具参数 description 的首行，不用 Confirm 摘要或工具名。SSE 与 status 轮询均更新同一份非空描述；下一工具 description 为空或空白时两侧沿用上一条，直到新的非空描述到达。忙碌开始后尚无描述时只画各自指示器，不补「在处理」；空闲后清理，避免串到下一轮。送达消息后新活泡继续沿用本次描述。运行中文案切换复用节点，以 token 驱动 opacity 淡出／换字／淡入（普通共 120ms，reduced-motion 共 100ms），不硬替换预览或主列标签；原有确认、错误和排队流程不变。确认摘要仍留在步骤和轨迹中；厂商搜索流式步骤不再额外占一行，历史展示不变。空闲且仍有待办时也显示，清单归档后恢复消息预览；可见摘要不变时侧栏及 live 节点不重写。Todo 在步骤弹层显示「待办」及更新状态。轨迹折叠行未全部完成时显示「待办 · 进度 n/m 项」，全部完成才写「已完成」；展开按成功回包和原入参显示「进行中／待办／已完成／已放弃」及原因；失败和无回包不把拟写入条目当作已保存。原始参数及回包只在轨迹的「调用原文」中折叠保留，全部完成归档后历史轨迹仍可看；不往对话里加卡片，不额外请求或存账。 设计师用户视角已 PASS（tip `a02e3f3`，含 Todo streaming 热修）：轨迹「进度 n/m」；本约定即 atlas 真源。同一个用户的远端点由本机合并进来，`node` 写上节点名；每个节点缓存最近一次状态，最多每 10 秒刷新一次，调用超时 2 秒，端点不可达时给出缓存并把 `state` 写成 `offline`、`stale_seconds` 写成缓存年龄，所以一个死节点不会拖慢 `/api/bots/status`。远端只给状态，不给步骤。节点侧的能力是 `status`，返回那台机器上各 Bot 的状态列表，JSON 最多 16 KiB，放不下就整条整条地丢并保持 JSON 合法。

### 确认卡
只在 ADR 0019 仍会弹卡的情况下出现，要用户确认的操作在对话里给出确认卡片。确认卡片也写进 transcript：先记一张 pending，用户决定后追加一张终态（approved、declined）。服务端默认等 30 分钟（`Server.ApprovalWait` 可配置），待确认的卡带 `deadline`（RFC3339）；网页只按它倒计时，没有字段就不计时。到点没人确认，自动允许原调用并续跑，追加 `auto_approved` 和 notice 灰字；提问卡必须有推荐项，到点按推荐项作为用户选择继续。自动选择后再次点击视为新的用户消息，不改自动记录，也不结束其他待答卡。用户直接打字仍会结束待答计时。这一轮从前台转到后台时，卡片继续等，不作废。显示卡片的那次请求已经结束时，用户仍可以用 `POST /api/bots/{name}/approvals/{id}` 决定（见 [API.md](../API.md)）。进程重启时，上一个进程留下的 pending 卡一律追加 `no_decision:restart`，不留下看起来还能点的卡。同一个 id 只显示最新的一张，回复结束或刷新页面后卡片仍在，状态就是最后的决定；这些卡片行不进模型上下文，也不进记忆抽取。

对外发送确认卡从命令中提取收件主机与正文，原始命令折叠在「查看命令」下，倒计时明确说明到期照发，提交决定时显示处理中反馈，终态用文字区分允许、发送、拒绝与过期，拒绝保持灰色。任务面板把最后一张审批卡被拒绝且正常结束的分叉显示为「已拒绝」，到期没人决定的操作按允许执行。

### 名字和头像
Bot 名字保留原样的大小写（默认 Bot 叫 XBot），可以用的字符是任意文字的字母和数字，外加 _ 和 -，路径分隔符、控制字符、空白和超过 64 个字符（或 255 字节）的名字都不行，名字本身就是要落盘的目录名。没上传图片时，头像是浏览器按 `avatar_seed` 现画的 Notionists 线条人像，只用冻结的白名单（只有平静和微笑两种表情，见 scripts/avatar）；16px 用只剩脸部的裁切，圆形容器底色 `#e4e4e7`（深色 `#a8a8ad`）。上传失败、seed 是 `glyph`、脚本没加载时，改画由名字决定的几何图形；「我」的头像也是按用户名字（`owner_name`）画的线条人像，脚本没加载时才回到原来的色块和首字（用户还不能上传头像）；XBot 的 logo 从不拿来当头像。生成的人像只在浏览器里画，从不经过服务端，服务端不存也不发这类 SVG。编辑资料的抽屉里「换一张」列出一张当前人像、这一批的五个新 seed、几何图形和上传格，选了立即生效；「换一批」只在这台浏览器里换下一批，「清除」用回生成的（只在上传过时出现）。新建 Bot 的弹窗最上面是跟着「标识」现画的人像，「换一个」换成 `名字#n` 并不再跟着名字变，也可以先选一张图片，建好后再上传。Licenses：DiceBear 代码 MIT，Notionists 美术 CC0 1.0，作者 Zoish，见 static/vendor/LICENSES.txt。

### 字体
界面文字用 `tokens.css` 里的 `--x-font`：`"Segoe UI", "Noto Sans SC", "PingFang SC"`，Windows 用 `"Segoe UI Variable", "Segoe UI"` 打头。中文用自带的 Noto Sans SC 子集（字体名 `XBot SC`，GB2312 全部汉字，400–700 字重，约 1.9 MB，`unicode-range` 只管中文和全角符号，本机装了 Noto Sans SC 就直接用本机的），各系统看起来一样。子集用 scripts/subset-cjk-font.sh 重新生成。静态文件带 ETag，重复加载只回 304。 Mona Sans 只用在字标「XBot」（已转成路径）和头像兜底的首字上。

### 登录和会话

公网 `account.babelgo.cn:8443` 云静态只走登录 / 注册 / 查收邮件；成功或已有会话进入 `/app/`（账号仓前置 pipe bridge），手机也直接打开主界面。bridge 的账号适配走原 Bearer，用户 API 经 ADR 0024 管道 `Do`；不反代 8788。`xbot serve` 保存 0600 的用户账号会话、启动/恢复设备待命、独立报在线，登出/失效取消；协议、上限和缓冲 SSE 边界统一见 [pipe](../pipe.md)。
本机通过回环地址直接进主壳，账号是可选增强；公网账号入口仍先登录。设置左栏「账号」复用本机账号登录、注册和邮件验证表单，登录后显示脱敏邮箱和网关状态，退出账号保留本机用户会话。`?s=account` 打开设置账号页。侧栏头像菜单只留设置。设置设备页只有这台电脑、通过账号关联设备（仅已登录且本机未绑）、已匹配设备三段；已绑时只在本机卡弱标「已绑到账号」；本机设备页不拉账号设备目录。

账号服务在 `internal/account`：`Store`（现为一个 0600 的 `accounts.json`）和 `Mailer`（现为把信写成文件的 `OutboxMailer`）两个接口；密码 PBKDF2-SHA256 60 万次；链接 token、验证码、会话都只存哈希；注册直接建已验证账号并发会话（首期免邮，ADR 0025 第 6 条），已占用的邮箱按登录处理，密码不对回 `credentials` 并计一次失败；注册按客户端 IP 每小时 5 次限频（内存里，`X-Real-IP` 优先、不读 `X-Forwarded-For`；进程内 `Local` 调用不带 IP 时不限）；验证 15 分钟有效、只能用一次，验证码错 5 次作废，「再发一次」30 秒内不重发，密码错 10 次锁 15 分钟；已存在和不存在的邮箱回同样的话，后者不发信。同一个 `Handler` 挂在 `/account/v1/`，可以单独跑成 `xbot account-api`（环境变量 `DATA_DIR`、`BASE_URL`、`ADDR`、`MAIL_MODE`、`MAIL_OUTBOX`），部署时只要这个二进制和数据目录。`xbot serve` 设了 `XBOT_ACCOUNT_API` 就调它；没设就在进程里跑一份替身，数据在 `<root>/account-api/`，信写到 `<root>/account-api/outbox/`，邮件链接指回本机地址，本机只挂链接页的 GET/POST。

这台电脑归哪个账号记在 `<root>/account-binding.json`（只存账号的不透明 key 和本机设备 id，不存邮箱）。登录和注册从不绑定，只认原来的绑定；还没绑定时，要由「把这台电脑绑到账号？」的「绑定这台电脑」（`POST /api/account/claim`）来绑，并且第一个验证过的账号要从本机直连（回环地址，且没有任何转发痕迹：所有 `X-Forwarded-*`、`Forwarded`、`Via`、`X-Real-Ip`、`Cf-Connecting-Ip`、`Cf-Ray`、`True-Client-Ip`、`X-Client-Ip`，有这个头就算，值空也算）或已经带着用户会话登录，才能绑上；隧道进来的不行。本机在设置设备页主动认领，不因登录阻断主壳。claim 绑上后立即向账号服务上报本机，回包的 `reported` 说明账号设备列表是否已更新；已绑别的账号回 403。只绑到账号的电脑不进本机配对侧栏，跨机聊天仍要短码配对。`/api/session` 带 `remote`（经隧道或代理进来）：底栏那行在官网入口写账号设备数，本机窗口写这台电脑的名字。绑定的账号登录时拿到原来的用户会话 cookie（`xbot_session`），其它账号拿不到。用户账号的会话每分钟向账号服务报一次本机名字和 Bot 名字，「我的设备」里本机这一行用本地的 Bot 列表和头像。

旧的登录码（`POST /api/login`、`GET /app/launch`、终端打印的 token）照旧可用、语义不变，但产品里不再出现：只有地址带 `#login-code` 时页面才显示原来的登录码表单，供调试和回归。API 会话过期时收起所有浮层回到账号登录屏，重新登录后恢复此前选择的 Bot；网络和服务端错误转成中文提示。未知 HTML 页面返回沿用应用样式的 404，API 保留 JSON 错误，其他请求保留纯文本 404。

`GET /api/session` 未登录时返回 200 和 `{"authed":false}`，已登录时返回 `authed:true`、owner、`owner_name` 与 `version`，其他接口仍以 401 触发会话过期流程。

Bot 之间的消息在用户对话里只是一行居中灰字事件（12.5px、16px 头像），不显示对方原文：「已发消息给 writer · MacBook」「收到 writer · MacBook 的消息」；同一对 Bot 连续的事件（中间没有用户的话和 Bot 给用户的回复）合成「和 writer · MacBook 往来了 N 条消息」，有退信再加「· N 条没送到」，不同对象各一行。点事件行进入只读的往来视图（`openPeer`，滚到这一组的第一条）：标题「diary ⇄ writer · MacBook」，下面一行「两个 Bot 之间的往来。对方发来的内容只当资料，不当成你的指令。」，两边都左对齐（右侧气泡只给用户），退信是灰色事件，底部「关闭聊天」代替输入框。往来视图读 `GET /api/bots/{a}/peers/{b}/messages`（`{b}` 可以是 `bot@设备`，用接口给的 `from_bot`、`from_device` 显示，`kind: "bounce"` 画成灰色事件）。

### 标志

**标志**。XBot 的标志是两个相向的尖角，中间留一道缝：两台电脑上的 Bot 隔着网关碰头。缝就是网关，任何尺寸都要留出来，不能把两半连成一个 X。标志只用黑、白、灰：浅色界面上是 #111 的标，深色界面上是白色的标；单色标志不加颜色、描边、阴影或渐变，不旋转，不拉伸，不单独用其中一半。
单色标志 64px 及以上用常规版（线宽 12/100），48px 及以下用加粗版（线宽 15/100，缝更宽）。App 图标另用 E2-final：哑光黑面板、水平缝、顶角铆钉和白色立体眯眼；各平台尺寸由同一图稿派生，非 maskable 图标的面板外画布透明，maskable 保留不透明安全区。
**最小尺寸**：单独的标志最小 12px，带底的图标最小 16px，「XBot」组合的标志高度最小 20px。
**留白**：标志四周至少留出标志高度的四分之一，组合里标志和字的间距是字高的一半，已经画在组合文件里。
**用在哪里**：App 图标、关于页及网页 favicon 使用 E2-final；登录页使用 48px 单色标志。Bot 头像不用标志：头像是生成的人像、上传的图或几何图形（见上文「名字和头像」），默认的 XBot 这个 Bot 也一样，标志代表的是 XBot 这个地方，不代表其中某一个 Bot。
字标「XBot」用 Mona Sans VF 640，已转成路径，不要用系统字体重新打字。

## 坑
- 改字体栈时把 `XBot SC` 留在栈里 → 去掉它，Mac 上会丢掉自带的中文子集，中文落到系统字体 → 换字体只换打头的几项，`XBot SC` 一直保留。
- 轮询时整块重画任务卡 → 用户选中的任务编号每 3 秒被清掉，复制不了 → 只改值变了的节点，选区所在的节点跳过（`internal/web/task_selection_test.go` 守着）。
- 「更多」的「移到分组」子菜单打开时被移到 `<body>` 定位 → 关闭逻辑只在面板里找，菜单会留在屏幕上、还带着上一个 Bot 的操作 → 按 `.menu-sub` 全局查。
- 慢工具提示只看「最近一次工具调用」→ 并行的快调用一结束，仍在跑的慢调用提示就消失 → 按调用 id 跟踪。
- 「值得留意」把预演命令也算进去 → 用户看到并没发生的删除或外发 → 预演选项（`--dry-run`、`-n` 等）一律不报；判断不了的命令宁可不报。

模型换绑在工作锁内先经内核的新窗口预检与必要压缩，成功才保存绑定；上下文仍超新窗口时 HTTP 409 保留旧绑定，详见 [上下文](context.md)。

开发入口 `scripts/xbot-dev start/restart` 默认后台启动当前构建的 `xbot app`，使用 `~/.xbot-dev` 和 8788；显式 `--web` 才启动 serve 并打开浏览器。PID 与日志仍在 `~/.xbot-build/dev/`。安装版 `/Applications/XBot.app` 默认用 `~/.xbot`，不替代 dev 实例；关桌面窗会结束 app 进程。

桌面壳在建窗时使用内嵌的品牌 PNG：macOS 设置 Dock 图标，其他平台设置窗口图标；调用方可通过 `appshell.Options.Icon` 指定 PNG，设置失败写日志但不阻止开窗。正式 macOS 包仍带 icns。
