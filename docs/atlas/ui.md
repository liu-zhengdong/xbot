# 网页界面

> **30 秒版**：对话里只放对话，工具调用进信息面板的轨迹；确认卡写进 transcript；侧边栏按分组。

## 边界
负责：网页界面的展示规则。接口见 [API.md](../API.md)。UI 先由审美顾问出原型，主人定稿再实现。

## 怎么运转
桌面版 `xbot app [--port 8787]`（[ADR 0007](../adr/0007-local-first-desktop-app.md)）在同一进程里跑 serve（不开隧道、不自动升级、不打印登录 token），只绑 127.0.0.1，用 `internal/appshell`（唯一引用 MyGo 的包）开系统 WebView 窗口。窗口打开 `/app/launch?code=…`：一次性登录码 32 字节随机、60 秒过期、用一次就作废，换成正常的会话 cookie 后跳到 `/`，所以桌面用户看不到登录页。同一个数据根只能开一个（`app.lock`）；端口被占时在改动数据之前就报错退出。安装包由 scripts/package-desktop.sh 在 Linux 上打出（macOS .app/.dmg、Windows XBot.exe），安装和放行步骤见 [desktop-install.md](../desktop-install.md)。关窗即退出；桌面窗口记住尺寸、位置与最大化状态，外链交给默认浏览器。桌面窗口顶部是一条 40px 的顶条（`#appbar`，`html.in-app` 时显示）：整条拖动窗口、底色是窗口灰，右侧按 `--mygo-titlebar-inset-right` 留出系统按钮的位置（系统按钮由 MyGo 原生绘制，页面不画）；Windows 左侧是 X 标、「XBot」和版本号，铃铛紧挨系统按钮左边，macOS 红绿灯在头像栏上方、字标从卡片左内边距开始。铃铛和通知弹层在桌面版由 JS 移进顶条。卡片（`.main`）从顶条下面开始，右边和下边各留 8 像素，圆角 12。版本号来自 `/api/session` 的 `version`（去掉开头的 v 和 + 之后的内容）。页面切换外观时 `POST /api/app/theme` 让系统按钮跟随 XBot 自己的明暗主题，不跟系统（`appshell.SetTheme`）。

卡片标题栏高 56，内容与消息、输入框同列（`min(720px, 100% - 64px)` 居中），所以标题头像、Bot 消息头像和输入框左缘在一条线上；头像 28px 圆形，与列表一样一个字或照片，后面是名字 15px、字重 620。右边只有一个「详情」按钮（32×32、图标 20px，tooltip「详情」）开关信息面板；原「···」菜单取消，它的操作（编辑资料、复刻、置顶、移到分组、导出对话、删除）变成面板顶部的一行按钮（`#panel-actions`），只有 Bot 才有。浏览器里铃铛仍在标题栏、在「详情」左边，桌面版铃铛在顶条。

对话里只放对话。工具调用不进消息流，改到信息面板的「轨迹」：一轮一行，写上时间、用过的工具和耗时；点开一行再看每次调用的参数和输出。输出默认截断，需要时再展开。要主人确认的操作仍在对话里给出确认卡片。确认卡片也写进 transcript：先记一张 pending，主人决定后追加一张终态（approved、declined）。服务端默认等 24 小时，待确认的卡带 `deadline`（RFC3339）。网页倒计时读这个时间；旧卡没有该字段时，从卡片写入时间起算 24 小时。剩余时间长就按「23 小时」显示，不按秒。决定接口返回 410 时，这张卡显示为已过期。到时仍没人答，追加 `no_decision:expired`，模型看到的是「过期、没有决定」，不是主人拒绝。这一轮从前台转到后台时，卡片继续等，不作废。显示卡片的那次请求已经结束时，主人仍可以用 `POST /api/bots/{name}/approvals/{id}` 决定（见 [API.md](../API.md)）。进程重启时，上一个进程留下的 pending 卡一律追加 `no_decision:restart`，不留下看起来还能点的卡。同一个 id 只显示最新的一张，回复结束或刷新页面后卡片仍在，状态就是最后的决定；这些卡片行不进模型上下文，也不进记忆抽取。Bot 名字保留原样的大小写（默认 Bot 叫 XBot），可以用的字符是任意文字的字母和数字，外加 _ 和 -，路径分隔符、控制字符、空白和超过 64 个字符（或 255 字节）的名字都不行，名字本身就是要落盘的目录名。Bot 还在跑的时候，对话里只留一个轻的进行中提示。轨迹不画时间轴分轨，也不拆上下文占比。点开「发给另一个 Bot」那一行，就在当前对话里看他们俩的往来，只读，可以返回。标题是叠在一起的两个头像，后面是两边的名字，中间一个小圆点。没上传照片时，头像是随明暗主题变化的灰阶软边圆斑（不再用服务端给的 avatar_bg/avatar_ink 色相），明暗主题各用统一灰度，轮廓由名字决定，不是正圆笑脸。侧边栏按分组收起展开，数量写在标题上，折叠记在这台浏览器里。Bot 的更多菜单里可以移到分组。分组标题上可以改名或删除，删除不带走 Bot。界面自带可变字体 Mona Sans VF。中文用自带的 Noto Sans SC 子集（GB2312 全部汉字，400–700 字重，约 1.9 MB，`unicode-range` 只管中文和全角符号，本机装了 Noto Sans SC 就直接用本机的），各系统看起来一样；子集外的字再落到苹方、思源黑体。子集用 scripts/subset-cjk-font.sh 重新生成。静态文件带 ETag，重复加载只回 304。

状态走只读接口，和别的接口同一套登录：`GET /api/bots/status` 返回 `{bots:[BotStatus]}`，含全部同一主人的 Bot，不带步骤；`GET /api/bots/{name}/steps?n=20` 返回 `{steps:[...]}`，是这个 Bot 当前这一轮的步骤环，`n` 最多 20。`GET /api/bots/{name}/todos` 返回待办清单。`BotStatus.todo` 是一行摘要，侧边栏和步骤弹层还没画它。同一个主人的远端点由本机合并进来，`node` 写上节点名；每个节点缓存最近一次状态，最多每 10 秒刷新一次，调用超时 2 秒，端点不可达时给出缓存并把 `state` 写成 `offline`、`stale_seconds` 写成缓存年龄，所以一个死节点不会拖慢 `/api/bots/status`。远端只给状态，不给步骤。节点侧的能力是 `status`，返回那台机器上各 Bot 的状态列表，JSON 最多 16 KiB，放不下就整条整条地丢并保持 JSON 合法。

切换 Bot 时同步清空对话与详情，显示灰色骨架；线程、详情与流式回复只更新发起请求时选中的对象，旧请求不覆盖新 Bot。加载失败在对话中央显示「连不上 XBot」和次级「重试」。发送先显示用户气泡与「发送中」，Bot 头像旁的三个灰点等到首个文字片段才消失；减少动态效果时灰点静止。成功后原文记录替换临时气泡，失败时在原气泡旁说明（细则见下文），后续同一原文发送成功时移除对应的失败气泡，不把服务器错误放进标题。
定时唤醒和错过的定时汇总显示为居中灰色时钟行，点击展开提示词和「来源：定时」，静默回复折入定时行，侧栏跳过 SILENT 并保留上一条真实消息。
「任务」先显示例程，再显示带文字状态和引导、停止次级按钮的进行中任务；已完成和失败任务收进「最近结束」折叠行，按 Bot 仅在内存记住展开状态，展开为可通过鼠标或键盘逐项查看结果摘要的列表，同时最多展开一项，失败摘要用红色显示，没有摘要时以灰字说明（最多 2000 字，记录没有结束时间时不显示时间）。服务端摘要和前端任务标题均按字符截断，避免切坏中文或表情。

详情标签使用「记忆」「任务」，人设称呼统一；通知日期不换行，群成员支持整行选择与键盘操作，详情工具栏和标签栏均以不透明面板背景吸顶，头像和名称可随内容滚走；例程时间使用正文字体和等宽数字，行内垂直居中。例程以中文展示常见定时规则，其他规则显示「自定义时间」，原始 cron 保留在行标题提示中。

登录统一称「登录码」，API 会话过期时收起所有浮层并说明原因，重新登录后恢复此前选择的 Bot；网络和服务端错误转成中文提示。未知 HTML 页面返回沿用应用样式的 404，API 保留 JSON 错误，其他请求保留纯文本 404。
侧栏底部的「我」打开账号菜单；编辑资料使用全高右侧抽屉，宽 420 像素，低于 768 像素时占满宽度；表单按基本、说话方式、免打扰和人设分组并独立滚动，底栏保留取消、黑色保存与低权重模板操作。点击遮罩、按 Escape 或登录过期时关闭，打开时聚焦表单，关闭后返回入口。768～1100 像素默认收成头像栏，可手动展开；详情默认仅在至少 1440 像素时打开，手动选择记入本机，浮层从顶栏下方开始并带可点击关闭的遮罩。
主 Bot 在侧栏用带「主 Bot」提示的图钉图标、在详情标题旁写「主 Bot」（那里已有置顶图钉），头像圆点只表示未读；菜单分组用留白，清除头像和删除分组用次级按钮。

头像栏隐藏重复的置顶头像，保留新建 Bot 和群组入口，头像提示在右侧，账号菜单可切换外观，第一项「设备」打开 440px 的右侧抽屉（`devices.js`，v2 原型）：从上到下是一句说明（配对后在本机就能和另一台的 Bot 聊天，两边的 Bot 能互发消息，记忆和文件各留各的）、网关不通时的一条灰色横幅和重试、这台电脑（系统 · N 个 Bot，铅笔改名字，只对以后配对的设备生效）、已配对 · N 和每台一张卡（在线 · 3 分钟前联系过／离线 · 最后联系 昨天 18:20，Bot 药丸，`名字@设备` 地址和添加日期，以及按设备的「Bot 互发消息」开关，`PATCH /api/devices/{id}` 的 `bot_messaging`，失败时开关弹回并在卡里报错；对方解除配对时只留「已解除配对 · 对方解除的」和「移除」）、解释「在线」是 16 分钟内收到过对方 Bot 列表的小字、连接（灰掉的局域网直连、网关 X 改，就地改，先在编辑行里检查地址，连不上时保留旧地址并在下面报错，不解除配对；已有配对设备时先弹确认，列出这些设备并说明要重新配对），底部是加入另一台设备和添加设备；网关不通时不给每台标离线；配对弹窗在 `pairing.js`：A「添加设备」显示 4-4-4 的 12 位码、倒计时、复制和换一个（过期后叫重新生成），没网关时先问地址（保存并生成配对码）；B「加入另一台设备」可粘贴整句，输满自动查找，校验位不对当场提示、不连网关，已设网关折成「网关 X　改」，404/410/连不上各有一句话（连不上时码不标红，给重试、取消、改网关地址）；B 看到对方名字、系统和 Bot 后点连接，A 弹「X 想连到这台电脑」，2 分钟不点自动拒绝，撞名时给拒绝（左）、作为新设备添加、替换旧的 X（主按钮）。侧栏在 Bot 和群组下面按设备列出其他电脑上的 Bot（`#remote-roster`，`devices.js` 的 `paintSidebar`，点组头折叠）：组头是设备图标、名字和右边一行状态——在线写「● 在线」，离线只写时间「○ 昨天 18:20」、完整的「离线 · 最后联系 …」放在悬停提示里，不写 Bot 数量；网关不通时上方一条「连不上网关，其他电脑的 Bot 暂时用不了。」加重试，各组变淡、不逐台标离线；还没收到 Bot 列表的设备也列出，右边写「等它的 Bot 列表」并在下面一行灰字说明，对方解除配对的照旧隐藏。每行是本机行那样的头像、名字和最新一句（`/api/devices` 的 `chats`，对方说的原样，自己说的前面加「你：」），有没发到的消息时第二行是「◷ 排队中 · 你：…」，不标红；`unread` 大于 0 时头像右上角是未读点。离线的行变淡但照样能点，选中的行和本机行一样有灰底。点一行打开远端对话（`remotechat.js`）：面板绝对定位盖住 `.main`，app.js 不参与；标题 56 高，头像、Bot 名和副标题「在 MacBook 上 · 在线」或「离线 · 最后联系 昨天 18:20」，右边的「详情」打开信息面板（设备、`bot@name` 地址、聊天记录两台电脑各存一份、记忆只在对方电脑上、「在「设备」里查看」打开抽屉）。对话里主人的话是右对齐浅灰气泡，Bot 的话带头像、名字和时间，正文一律按纯文本、保留换行。主人这条下面按状态写小字：还在这台电脑上是「◷ 已排队 · 还在这台电脑上」，已交给网关而设备离线是「◷ 已排队 · 等 MacBook 上线」，设备在线而网关在 `ack_timeout` 秒内没等到回执（消息带 `no_ack`）写「◷ 没收到 MacBook 的回执」和一行灰字「可以在「设备」里看看它的状态」，没发出去是「没发出去」加「重试」（原样重发），其他不写；4xx 带 `error`（如 409 已解除配对）不进「重试」，原文放回空着的输入框、输入框上方写「没能完成：<error>」，下次发出、主人改字或换成别的对话时收起。设备离线时输入框上方一行说明：消息已交给网关，对方打开 XBot 后才会收到和回复，最多等 7 天。输入框「写给 <Bot>」从不禁用，Enter 发送、Shift+Enter 换行，输入法选词时的回车不发送；先显示气泡，成功后换成服务器那条。打开时调只读接口顺带标已读；打开且页面可见时每 5 秒拉一次，页面切走不拉，回来立刻拉。点本机的 Bot、群组、置顶或手机上的返回关闭面板。拉丁名字头像显示首两字母，中文显示单字，没有自建分组时直接显示 Bot，多选成员用加深底色和加粗文字标明选中。

侧栏未读点只按消息游标判断，打开 Bot 对话会将该 Bot 的未读通知标为已读；通知弹层提供「全部已读」，侧栏预览和通知正文去掉 Markdown 标记后按纯文本显示。`GET /api/session` 未登录时返回 200 和 `{"authed":false}`，已登录时返回 `authed:true`、owner 与 `version`，其他接口仍以 401 触发会话过期流程。

标题、消息和输入框共用一条居中的列，宽 `min(720px, 100% - 64px)`。Bot 的回复不画气泡，直接写在卡片上，15px、行高 1.7；上面一行是名字 13px 字重 620 和时间 12px #9a9aa0。主人的消息保留浅灰气泡（浅色 #f0f0f2，深色 #2a2a2e），圆角 18，内边距 9/15，最宽 72%。同一个人连续发、间隔不到 5 分钟算一组：只有第一条写名字和时间，后面的时间悬停才出现，组内间距 6，不同人之间 22；分组由 `groupStart(prev, cur, prevKey, key)` 这个纯函数决定，历史、翻页和实时追加都走它。消息少时对话贴着底部排（`justify-content: flex-end`，首行 `margin-top: auto`），滚动到底和加载更早的往来不受影响。输入框同一列宽，浅色 #f3f3f5、深色 #252528，圆角 24，最小高度 52，左内边距 20，离底部 16，占位字用最浅的灰。发送按钮是 36px 的圆，18px 箭头 2 线宽：可用时 #111 底白箭头（深色 #f2f2f2 底 #111 箭头），禁用时 #e2e2e6 底 #a6a6ac 箭头（深色 rgba(255,255,255,.08) 底 #6f6f75）。

登录报错时隐藏灰色说明；输入为空时发送按钮禁用并呈灰色，不展示未实现的附件和语音入口，按钮打开浮层期间隐藏其工具提示。发送失败时原文回到输入框（输入框已有新草稿则保留新草稿并提供「放回输入框」），不再显示「重试」。

桌面版（`Server.App`）不提供「退出」，`/api/session` 带 `app:true`，`POST /api/logout` 回 409，因为登录码只在启动时生成一次；`POST /api/app/theme`（`{"theme":"light|dark|system"}`）只在桌面版存在，走登录和同源检查，值不对回 400，成功回 204，App 用它设置 `Server.AppTheme`。再次发送同一原文时先移除旧的失败行；返回 202 排队的消息保留气泡并标「已排队」，直到对话记录里出现同样的文字；「回复出错了」在下一次发送被接受时清除。重新点击当前打开的 Bot 或群不重置对话；群消息在会话过期时同样保存草稿并在重新进入时恢复；服务端 4xx 带原因时显示「没能完成：原因」。

发送已接受后流中断时仍保留标为「没送到」的原文气泡并恢复草稿，排队事件继续显示「已排队」，直到新增的主人原文记录接替气泡；任务状态和错误使用中文，原始错误可展开「详情」，任务结束时间取终态元数据的写入时间。

对外发送确认卡从命令中提取收件主机与正文，原始命令折叠在「查看命令」下，倒计时明确说明到期自动取消、不会发送，提交决定时显示处理中反馈，终态用文字区分允许、发送、拒绝与过期，拒绝保持灰色。任务面板把最后一张审批卡被拒绝且正常结束的分叉显示为「已拒绝」，到期无决定的操作不执行。

子任务和其他外部事件以左对齐灰色系统行显示，按钮展开原文，子任务超时显示中文原因；助手正文、预览和任务标题仅在显示时隐藏内部任务编号。后台结果与主线相同的转述只保留带「后台」标记的回复。

任务与后台弹层按确认卡所属分支显示「等你确认」，隐藏引导和转圈，点击后定位确认卡并聚焦主按钮；停止须在三秒内再点一次，普通任务卡不重复显示「进行中」。头像栏和置顶头像以灰阶状态点区分在跑与待确认，群组入口使用独立图标，「我」的头像取主人名字首字（拉丁名最多两字母），无名字时显示人形。

禁用的主按钮用灰底、浅色文字和默认光标；输入框里输入的文字用正文色，只有占位提示是浅灰。群组对话里其他 Bot 仍画气泡，自己的回复同样直接写在卡片上。
