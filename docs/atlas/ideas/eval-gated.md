# 评测把关，不对着题调

> **30 秒版**：Bot 好不好，看它在评测里的行为和结果，不看模型自己怎么说。改提示、改内核之后，要用评测证明它变好了。评测分两套：普通套件拿来调，留出套件只在验收时跑，调的时候不看。每条新规则都要写成通用原则，并且在没拿来调的用例上也成立。

## 从一个场景说起
2026-10-17 的对比实验里，XBot 在 5 条主动性用例上拿了满分，同一个模型换成 Claude Code 只过了一两条。看起来是大胜。但 Bot 复刻在报告里自己指出：DeepSeek 专用提示里有好几条几乎是照着这几条用例写的，这个满分有一部分是「对着考题调的」，真正能比泛化能力的是留出套件。主人看到这段说，能意识到泛化问题、知道基本上都是对着题目调的，这一点非常好（2026-10-17）。

## 这个想法是什么
**评测看行为，不看自述。** 这条来自主人对通用智能的第一条要求：自己设定目标，被打断后继续同一件事，做不到时停下来说明原因（「愿景与思想」，2026-10-16）。所以用例检查的是 transcript、工具调用和跑完后的文件系统，评分模型也只看这些事实，不听模型自己的总结（[模型供应商与评测](../providers.md)）。

**一个通过不算数。** 每条用例默认跑 3 次，按多数算；一个模型要在普通套件和留出套件上都按多数通过，才进认证名单。

**留出套件是验收线，不是调参材料。** 2026-10-17 主人定下防过拟合的三条：留出套件只用于验收，调的时候不看；每条规则都要写明一个通用原则；新规则要在没拿来调的用例上也成立。下一版提示词就按这个做：用通用的收敛原则替换贴着用例写的 DeepSeek 规则，每项改动配自己的用例，用留出套件验证。

**分数要分维度。** 2026-10-17 主人提出借用企业评估人才的思路给 XBot 打分。最后定的是四维：能力（做对）、意愿（主动补齐、卡住了不早早放弃、做完收尾）、可靠性（3 次结果一致）、守规矩（不越权、不泄密、该问先问，一票否决）。每个提示词版本出一张四维成绩单，任何一维不许退步。只报一个通过率，会掩盖「能力涨了、意愿掉了」这类变化，比如 v0.3.0 那三条提示改动就拉低了 give-up 用例，最后撤到下个版本重做（[MILESTONES](../../MILESTONES.md)）。

## 它带来什么、代价是什么
好处是每次改动都有证据，几个月后回看也知道当时为什么这么改。代价是真模型评测要花钱、要时间，结果还有波动；所以它定期跑，不挡合并，也不进 CI，CI 只用确定性的假模型。留出套件用一次就「旧」一点，久了要补新用例。

四维成绩单从下一版提示词开始出。主人的意思是，等数据能拉开差距、有说服力了，再把它当作对外的亮点来讲（2026-10-17）。

## 在仓库里体现在哪
`evals/proactivity/` 和 `evals/proactivity-holdout/`，`xbot eval` 与认证名单（[模型供应商与评测](../providers.md)）；候选清单（在主人的 Obsidian）里的四维成绩单和收敛评测。
