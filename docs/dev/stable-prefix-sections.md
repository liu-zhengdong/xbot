# StablePrefix 分段系统提示与可读环境人设

## 动机与范围

用户已在候选「StablePrefix-分段系统提示」及本次编码任务中确认：系统提示用命名分段和固定槽说明，环境的人设身份要能读懂。本设计直接落仓实施这份要求，只借鉴外在结构，不复制 Claude Code / Claude.ai 正文。

## 骨架与前缀缓存边界

保留 Assemble 的连续 system 消息边界，固定顺序为：

- S0：人设 → 内核规矩 → 可选模型补丁。
- S1：能力框（排序后的 Link blurbs；空目录省略）。
- S2：现有 installed 说明与技能目录（空目录省略）。

候选四槽示意里能力框在模型补丁之前；本次明确要求保留 S0/S1，因此实际消息顺序以以上边界为准。StablePrefix 的合并调用同样按人设、规则、模型补丁、能力框排列。

各槽使用固定标题与说明，下一行放正文：

```text
### 人设
这段定义你是谁、口吻和关系分寸；下面是正文，照着演，不要复述本说明。
<ComposedPersona>

### 内核规矩
XBot 硬规矩，与人设无关；冲突时本段优先。
<rules / KernelRules()>

### 模型补丁
仅针对当前模型的额外约束。
<overlay>
```

S1：

```text
### 能力框
当前授权的连接/可发现能力；细节按需 load，别假装有未列出的。
<Links blurbs>
```

空 overlay（含纯空白）整槽省略；空人设和规则分别回落 DefaultPersona 与 KernelRules。说明与段序不随配置变。配置变化只改变对应正文，但服务商的最长公共前缀缓存会在首个差异处停止，不能跳过变化复用后段；连接/技能变化必须保住 S0，技能变化保住 S0/S1。

## 环境可读身份与复用

复用 Bot 的 PersonaText 读取路径：抽出共用的 PersonaSource 返回当前正文与可读来源，PersonaText 仍由它取得正文。一次 personacard.Get 同时取得 Name 和 Body；沿用磁盘绑定、唯一用户检查及失效卡回落。无卡时用稳定标签 persona.md，默认正文用「默认人设」。环境公布「标签 + 空格 + 12 位内容指纹」，不公布人设全文；资料继续使用独立 profile 字段。

保持 `<environment_update>` JSON 信封、set 字段、diff、压缩快照及 replay 规则。改名即身份变化，正文相同仍可更新标签；重复采样不重复公布。旧历史的纯哈希照常可回放，下一次采样自然追加新短值，不改旧行，不建迁移账或身份缓存。本批不加可选 product/where 字段。

## 怎样算对

按用户本次要求：StablePrefix 槽标题、固定说明、默认值与空 overlay 行为正确；links 为能力框风格；环境 persona 为卡名/稳定标签加指纹且无正文；可解码、回放、压缩补快照；link/skill 变更不废弃 S0。用现有 kernel 定向测试和补充回归验证，新增回归先在旧实现上失败。真实新会话自述卡名/口吻要点留待用户日用验证，假模型通过不等于模型自述质量通过。

## 非目标

不改权限、工具、UI、模板数据格式或环境信封；不扩充人设正文；不复制第三方提示正文；不加入机制手册全文；不合 main、不推送、不重启 8788、不改 Agent 指令/发版/lock。

## 还没做的
