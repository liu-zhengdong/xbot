# 上下文去重：overlay · todo · fork_end

> **结论先行**：不新开机制。四类重复都压进已有三样——固定前缀、环境流（[ADR 0021](../adr/0021-env-stream.md)）、普通消息。环境里只公布**能回放的短值**（版本/哈希/指针）；全文只在它该在的那一层出现一次。编码等 `feature/multi-provider-b1` 合本地 main 后再开，避免和批 1 抢同一批 kernel/provider/transcript 文件。

## 问题

长对话里模型反复看到**没变的大段文本**。Bot 自查按影响排序：

1. **model overlay**：正文已在固定前缀 `## Model`；环境更新却把同一段再塞进 `<model_overlay>`（现状：`env_replay` 对 overlay **例外存全文**，persona/rules 等只存短哈希）。换绑或压缩补快照时更容易再出一份。
2. **todo 工具结果/提醒**：每次更新几乎整表回显，多数时候只改了若干条状态。
3. **create_bot 角色描述**：调用参数里一份，随后环境/返回里再一份；删 Bot 后陈旧描述仍可能躺在历史里（生命周期另述，本设计只去**同轮双份**）。
4. **fork_end 完成事件**：子代理/分支最后一条回复已经在对话或 `result.txt`；完成事件再贴一整份结论，和前台转告叠成三份。

## 目标形态（怎样算对）

|---|---|---|---|

## 设计要点（非菜谱）

### 1. Overlay：前缀持正文，环境只持版本

- **正文唯一入口**：继续只经 `StablePrefix` / 组装前缀的 `## Model`（已有）。
- **环境公布值**：与 persona、rules 对齐——存 **provider/model 键 + 内容短哈希**（或 `none`）。比较与回放都基于对话里已公布的短值；当前正文仍由 `modelOverlay()` 现场读取，**不必**把正文写进环境消息才能回放。
- **压缩后全量快照**：同样只带键+哈希；不把 overlay 正文当作「环境状态」再采样进尾部。
- **atlas**：改 `providers.md`「模型提示」与 `context.md` 中任何「环境里带 overlay 正文」的句子，与实现一致。

### 2. Todo：结果按变更报，清单仍落盘完整

- 磁盘上的任务清单仍是完整真源（现有 `todo` 文件）。
- 写入工具的**返回给模型的那一截**改为：变更项（id/内容/新旧状态）+ 列表版本或条数摘要；避免「只改状态却回整表」。
- 提醒/`todo_reminder`：未变冷却期内本就不该刷；若刷，载荷与工具结果同一纪律（点名未动项，不整表粘贴）。
- 不把 todo 整表塞进环境流重复一份（任务类状态已有环境 `task:`；Bot 自用清单与子任务状态区分清楚）。

### 3. create_bot 角色：参数一份，环境不复述全文

- 创建时人设进 Bot 档案/前缀即可。
- 紧随的环境更新对人设只报哈希/短指纹（与现有 persona 字段纪律一致），工具成功回执不回显整段角色描述。
- **删 Bot 后历史里的陈旧描述**：属 transcript 生命周期/压缩，不在本条实现范围；备注进候选即可。

### 4. fork_end / 完成事件：摘要与指针

- 沿用 fork.md：短结果可整段；超长已有 `result.txt`。
- **收紧**：完成事件默认带 `status`、步数、分支 id，以及「结论指针」（transcript seq，或 `result.txt` 路径 + 短开头）。**不要**再把已在分支末条 assistant 上的全文复制进事件体。
- 前台转告仍是普通消息，由模型决定说什么；内核不为「已转告」另记账（0021）。

## 非目标

- 不改 ADR 0021 的三件套分工，不恢复手动压缩。
- 不在本条做「状态取代」声明文案的全局重写（留给「环境更新只发当前值」）。
- 不改多 Provider 协议/能力表/UI；若批 1 改动了 overlay 加载路径，本条实现以合入后的 main 为准做一次对接。

## 建议落地顺序（编码阶段，本文件不开工）

1. Overlay 环境短值 + 测例改写（影响面最清晰，收益最大）。
2. fork_end/完成事件瘦身（与结果文件路径规则对齐）。
3. todo 工具回包与提醒载荷。
4. create_bot 回包去重。
5. atlas 与本文件勾对；可选真机长对话抽样。

**启动时机**：`feature/multi-provider-b1` 经复审合入本地 `main` 之后，再开 `feature/context-dedup` worktree（可从当时 main HEAD 拉）。在此之前只合本文档。
