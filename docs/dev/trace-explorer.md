## 用户旅程与怎样算对

沿现有 Bot 顶部「轨迹」入口，扫读经过，点击事件后在右侧阅读概述／预览／原始内容／来源；总览、列表、详情联动。以下将已确认原型落到正式数据上：

1. 用户输入、内核上下文、模型消息和工具调用按 transcript 记录顺序展示；结果按 tool_call_id 归到调用，一条消息内多个调用各自可选，孤立结果仍有入口，不丢记录。
2. 类型、错误和正文搜索筛选有效，工具结果正文也参与搜索。搜索范围如实为当前已加载记录；沿现有 before/after 窗口加载历史，不冒充全本、不取消体积预算。不新增搜索索引或存储。
3. 点事件／总览标记打开同一条详情，结果标记定位关联调用。概述、预览、原始内容、来源可切换；复制复制当前公开记录原文，真实执行复制后再提示成功。返回／Escape 保留列表位置。
4. 思考只在轨迹详情按需展开，默认折叠，不进入聊天；待办保留回执驱动的人话摘要及调用原文；hosted image_generation 保留普通工具轨迹入口及已记录状态。
5. 真实追加和轮询不重置搜索输入、焦点、选中事件、详情页签、思考开关及正在选择的正文；切 Bot 清空归属状态，迟到回包不得串到新 Bot。列表和详情各自滚动。
6. 390px 窄屏详情覆盖轨迹内容，能关闭并回到列表；不覆盖身份／页面标签。桌面、窄屏、深浅主题可读，无横向溢出。颜色语义一致，动画仅 opacity/transform，尊重 reduced-motion。
7. 记录时间只表示追加时间；总览不虚构模型／工具执行耗时、token 用量、系统提示来源或技能注入来源。截断记录明确是公开预览，不称供应商原始包或完整输出。

## 实现边界与结构选择

只改现有 `internal/web` 轨迹投影及静态资源，复用 transcript 接口、页面装配、消息文本渲染与 DOM 更新约定，不碰内核、账本、协议和权限。比较过：继续把模型调用组逐行折叠，无法形成用户要求的独立事件与主从阅读；改为 transcript 的只读事件投影，可复用真实 seq 和调用关联，采用后者。视图状态归属于当前 Bot，保持精简，不另造全局状态管理器。

`traceView` 是正式入口；可按现有 JS 组织就近拆分必要投影／详情渲染，不为单次用途引入框架或提前抽象。重点防止现有 `paintPanel` 全量替换导致焦点、滚动和选区丢失。颜色、尺寸、间距等可复用变量从 `tokens.css` 来，原型尺寸与配色按现有前端规范适配。
