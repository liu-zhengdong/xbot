# 人设卡（一批）

> **结论先行**：设置侧栏「人设卡」管全局卡库（搜/编/新建/导入 Markdown=新建）；Bot「编辑资料」只负责单选一张卡；卡详情是卡名 + 一整块正文，不在此按 Bot 开关。密度对齐技能/网页搜索设置浮层。设计真源：`/workspace/xbot-ui-design/persona-cards/`（handoff · ia · hifi）。

## 怎样算对（= handoff 验收要点 1–12）

1. 侧栏有「人设卡」，顺序：`通用 → 权限 → 网页搜索 → 技能 → 人设卡 → 设备 → …`；选中 `--x-fill-3`。
2. 标题行只留左「人设卡」大标题；浮层 ✕ 仍在右上角。不要把搜索/＋/导入塞进标题行。
3. 列表工具条：导语下、列表顶外缘右对齐；`[搜索][＋新建 icon][导入]`；导入文字主 CTA（`.btn.pri`），新建纯 icon「＋」。与 ✕ 垂直错开。
4. 空态：无列表时隐藏搜索与工具条；中心「写一张」（次）+「导入」（主）；说明导入=新建、不覆盖。
5. 无匹配：工具条仍在；「没有匹配的人设卡」+ 清除搜索；不要再塞第二个「导入」。
6. 列表安静：卡名 + 正文首行预览 + chevron；无工程词、无「N 个 Bot 在用」行内开关。
7. 二层：返回「人设卡」；卡名可改；一大块正文 textarea；底栏次要删除 · 主保存。不在此按 Bot 开关。
8. 导入：人话「导入 Markdown」；导入=新建一张；同名确认后仍新建并「 (2)」后缀；禁 slug/路径/CLI。
9. 编辑资料：420 抽屉＝**基本（名字·简介）→「人设卡」选用行 → 底栏保存**。选用行：当前卡名（或「未选用」）+ chevron → 选用嵌层；嵌层确认即绑定，抽屉保存只管其它字段。原大块「人设」textarea 拿掉（改卡去设置·人设卡）。**整功能删除（硬约束，[t314u]/[t315u] 更正）**：删除「说话方式」与「免打扰」——前后端、配置字段、文案、死代码入口一并去掉，不是藏 UI。含：编辑资料相关 section；`quiet_start`/`quiet_end`（及免打扰攒通知逻辑若仅服务该功能）；档案/API/UI 中的「说话方式」与其下语言等入口（口吻改由人设卡正文承载）。不要留隐藏开关。若某条通知链路删免打扰后需改行为，改为始终按非免打扰路径投递，并在提交说明里写清。
10. 选用嵌层：搜索 + 单选列表（含「未选用」）+「管理卡库」链到设置·人设卡；选中色中性 `--x-fill-3` / 近黑 radio。
11. 密度与技能/网页搜索设置浮层同族；禁止紫强调、禁止灰框首稿。
12. **本批不做**：课程记忆、知识库分层、Bot 自改告知流水、多卡叠加、商店、窄屏专稿、卡详情 Bot 开关矩阵。（「说话方式」「免打扰」**不在不做列**——本批必须整功能删掉。）

文案禁词：system prompt · persona.md · 路径 · slug · CLI · 职责矩阵 / 零件表。

## 产品行为（实现须对齐）

| 动作 | 结果 |
|---|---|
| 搜索 | 按卡名 + 正文前端过滤 |
| 导入 .md | 新建一张；不覆盖；同名确认后仍新建并「 (2)」 |
| ＋ / 写一张 | 进空详情编辑后保存即入库 |
| 保存正文 | 下一轮**已选用该卡**的 Bot 说话对得上（引用，非快照） |
| 编辑资料·选用 | 嵌层确认即绑定该 Bot；换卡即换；「未选用」解除绑定 |
| 删除 | 有绑定时先提示「N 个 Bot 还在用」；确认后解绑并删卡 |

## 数据与复用

- **卡库**：本机一份，扁平 `persona-cards/<id>/card.md`，不按主人分子目录；`id` 仅内部/路径用，**界面永不展示**。
- **卡内容**：`name`（可改）+ `body`（整块 Markdown/纯文本）。导入：文件名或首行非空作卡名，全文作正文；大小/条数上限对齐技能导入量级（参考 `skills.js` `MAX_FILE`、skill `maxBody`），防路径穿越。
- **Bot 绑定**：档案/config 增加可选 `persona_card`（卡 id；空=未选用）。**未选用**时继续走现有 `persona.md` / `ReadPersona`（创建时角色正文）。**已选用**时固定前缀/ComposedPersona 用卡正文（保存卡后绑定 Bot 下一轮即见，勿另拷一份会过期的快照当唯一真源）。
- **写锁/权限**：复用 `fsutil.WriteAtomic`、现有 owner 鉴权（`require`/`owned`）、技能库同类路径校验；勿另起一套锁或权限。
- **XSS**：卡正文进 UI 一律 `textContent` / 受控渲染，勿把 Markdown 当 HTML 塞进 DOM。

## API 面（建议，可微调命名但语义固定）

- `GET /api/persona-cards` → 列表（id 可返回给客户端绑选用，界面不展示；含 name + 预览用正文截断）
- `GET /api/persona-cards/{id}` → 详情
- `POST /api/persona-cards` → 新建（name+body）
- `PUT/PATCH /api/persona-cards/{id}` → 改名/改正文
- `DELETE /api/persona-cards/{id}` → 删（可选 `?force=` 或 body 确认有绑定时）
- `POST /api/persona-cards/import` → 上传 Markdown 新建（同名策略见上）
- `PUT /api/bots/{name}/persona-card` → `{id:""|"…"}` 绑定/解绑（嵌层确认即调；或 PATCH bot 增字段，二选一，优先独立短接口以免和抽屉保存缠在一起）
- Bot GET/资料 JSON 带当前选用卡的展示名（或 `persona_card` + 解析出的 name），供编辑资料行显示

静态：`persona-cards.js` / `persona-cards.css`（类名可 `pc-*`，壳复用 `sethd`/`setlead`/`sktoolbar` 同族）；`index.html` 侧栏插入 + pane；`app.js` 设置 mount / 编辑资料改动 / 选用嵌层。
