用户希望点击小鲸回复里的技能目录，并统一对话中的文件、行号、网页来源和消息引用。用户于本轮回复“可以哎”，认可已交付原型。

UC-资源-01：从对话点击目录或文件，读取正确目标，复制完整地址，按真实能力打开。关闭后继续原处的对话。自动识别绝对路径、home 路径、明确的文件行号和具名本地链接。普通文件名、命令与代码块不猜目标；相对路径缺少明确基准时保留原文。

UC-资源-02：网页角标显示已有来源身份；普通网页保持直接打开。消息引用定位原消息，并返回原阅读处。不发送消息，不改草稿和聊天历史。

## 调用方用法

正文沿现有 Markdown 装配，路径标签保存原值和宽度省略。点击交给一个资源阅读控制器。来源角标把已有 title/url 交给同一控制器，不重新抓网页。

```js
resources.open({path: '/Users/owner/.xbot-dev/skills/', line: 1}, trigger);
resources.source({title: '来源标题', url: 'https://example.org/'}, trigger);
// 读取目标仅在用户点击后发生。
const page = await api('/api/resources?path=' + encodeURIComponent(path) + '&line=112');
await api('/api/resources/open', {method:'POST', body:{path:page.path}});
```

## 结构选择

A：给每条聊天新增持久化资源对象与索引，再按资源 ID 打开。它需要回填旧记录，且现有纯路径仍要另走解析。不选。

B：从原文派生明确目标，界面控制器按需调用当前设备的认证资源接口。文件系统类型和能力以真实读取为准。选用。

数据流最多三处：现有正文/引用装配 → 一个资源阅读控制器 → 当前实例资源 HTTP 入口。控制器拥有浮层、导航和请求生命周期；正文不保存第二份资源状态。目录和文本分页由服务端负责。不改 transcript，不增加模型工具、权限卡、来源账或跨设备文件同步。

接受文本分页重新扫描行的代价，以避免额外文件索引和缓存。当前请求设备就是缺省路径查询设备；显示实际设备名。有明确资源设备标识时沿现有精确路由。不能用 from_device 或临时执行选择重解释旧路径。

## 接口契约

- `GET /api/resources?path=…&offset=0&line=1`：沿现有 `require` owner 会话认证。path 只接绝对路径或当前服务用户的 `~/`。拒绝空目标、NUL、相对路径和当前平台不支持的路径。
- 回包含 `path,name,kind,device,platform,can_open`。platform 来自服务主机，不用浏览器系统推断原生动作。kind 为 `directory|file|unsupported`。
- 目录返回 `entries:[{name,kind}]` 与可选 `next_offset`。每页最多 40 项，用当前目录项顺序，不读取或排序整个目录；后续请求用 offset 接续。链接项可以保留 link 类型，点击后按真实目标读取。
- 文本返回 `text,start_line` 与可选 `next_line`。每页正文原始字节最多 64KiB；按行分页，指定 line 可定位。非法 UTF-8、二进制或单行超过预览上限时，保留元信息并返回 `preview_error`。不读取设备文件、管道或目录为正文。
- 返回 JSON 小于 1MiB。目录只回条目名，避免重复长父路径。请求取消后停止扫描。
- `POST /api/resources/open`：JSON `{path}`，复用 owner 认证、同源写入与既有 App/OpenPath 回调。只打开真实文件或目录。没有能力则不显示操作；错误沿回调返回。GET 不启动系统应用，不执行文件。
- 不提供写文件、删除、任意命令或全局目录搜索。

## 界面装配

正文路径继承蓝字无底和悬停淡底。具名文件链接保留标题，文件行号进入定位字段。HTTP 链接保留现有浏览器行为；file URL 只能解析为文件目标，不当浏览器导航。

阅读面沿已定原型：桌面 480px、最高 560px，手机两侧 12px；变量进入 tokens。目录行 40px，手机 44px。普通行不描边。完整地址可选中、复制，目录/文件类型来自接口。

浮层挂在正文投影外，不改变聊天列宽或 thread 高度。轮询不重建浮层和内容。请求序号与关闭/换 Bot 生命周期共同防止迟到结果覆盖当前阅读。Escape/关闭按钮恢复触发焦点；点输入框关闭时保留用户新焦点。

引用返回保存原阅读锚。已有消息加载与定位仍走现行窗口接口，避免重建第二份聊天数据。所有新动效只淡入，并遵守减少动态效果。
