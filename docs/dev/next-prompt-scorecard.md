# 下一版提示词与配套用例

候选真源：用户 Obsidian `正在干什么/06-XBot/候选/下一版提示词与配套用例.md`。规格真源：`docs/SCORECARD.md` §5（D1–D5 / S1–S4 替换表）与 §2「计划新增」。Codex Astra 在 feature/next-prompt-scorecard 实现；提交后由复审侧完成真实模型及留出验收。

## 目标

把 DeepSeek 贴用例专用规则换成通用原则；共享规则里与 D 重复的并入/删例子；为每条规则配开发套件专门用例；改前改后对照四维成绩单，任一维不低于基线，守规矩违例=0。

## 验收

| 项 | 怎样算对 |
|---|---|
| D1–D5 | `prompts/models/deepseek/*.md` 按 SCORECARD §5「通用原则」替换；尽量清空或只留模型特有格式项；原则里**禁止**写用例文件名/端点/夹具措辞（如 root-cause、site.css） |
| S1–S3 | `assemble.go` 里与 D 重复的括号/末句/例子并入对应通用原则或删掉，勿叠三份打架段 |
| S4 | **已落地，勿重做**（SilenceRule + routine-fallback） |
| 计划新增用例 | 开发套件补：knowledge-public / knowledge-project / knowledge-fresh（能力，需 `no_tool_calls` 检查若尚无则加）、模糊任务同轮开工（意愿）、「给这个工具做个桌面端」主动补齐（意愿）；中文不加英文开场若规格仍要则一并（LanguageRule 已有原则，配专门用例） |
| 成绩单 | 改前改后各跑开发套件 `xbot eval <provider/model> --suite proactivity`（或现有等价），出成绩单；四维不低于基线；守规矩违例=0。**调参时不读留出套件**；留出只在最终验收看总分（本切片编码交付后由父代理/复审侧处理） |
| 防过拟合 | 每条规则写成通用原则；新规则在没用来调它的开发套件用例上也要成立 |

## 底线

- 真源：SCORECARD + 候选「怎样算对」；**合伙人角色定位不进**本清单
- 不抄外部产品提示词正文；只按外在行为验收
- 未 push；勿开局域网直连 / 跨设备询问 / 环境实体 / 未排期轻不爽
- 纯提示/评测无 UI：不喊设计师
- 历史教训（MILESTONES「撤下的提示类改动」）：知识三档与模糊任务规则曾拉低 give-up；重做时原则必须与「目标已写明则直接执行、外部失败最多重试一次」相容，改后 give-up 与全套成绩单不得掉基线
