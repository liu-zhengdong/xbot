> **结论先行**：首次空库（主人尚无人设卡）自动种入设计稿示意三张——**碎嘴群友 / 值班运维 / 周末搭子**；真入库，可搜、可选用、可编辑。已有任意卡的库不重复灌、不覆盖。产品面 IA 不动；一批人设卡（`docs/dev/persona-cards.md`）已合入，本条只补种子。真源：persona-cards；正文对齐 `/workspace/xbot-ui-design/persona-cards/hifi/index.html` 的 `CARDS`。

## 要干啥

1. 主人打开人设卡库（或首次 `List` / 等价入口）时，若该主人库里**一张卡都没有**，自动写入上述三张。
2. 三张卡走现有卡库路径（`persona-cards/<owner>/<id>/card.md`），与手工新建/导入同一套 CRUD、搜索、选用、编辑。
3. 库里已有 ≥1 张卡时：不灌、不补缺同名、不覆盖用户改过的正文。
4. 正文与 hifi `CARDS` 一致（可微调空白/换行）；群友感短口吻；假列表 / 仅 UI 硬编码不算过。

## 怎样算对

1. 全新空库 → 打开设置·人设卡 → 列表出现三张，名字为「碎嘴群友」「值班运维」「周末搭子」。
2. 点开任一张，正文与下方「正文真源」一致（空白可微调）。
3. 搜索「群友」等能命中对应卡；编辑资料选用嵌层也能选到。
4. 改过某张正文后重启 / 再进设置：仍是用户改过的内容，不被种子覆盖。
5. 库里本来就有卡（哪怕一张、名字不同）时升级本批：不再自动插入三张。
6. 合入本地 main（不 push）→ Mini 8788 手测。

## 正文真源（hifi CARDS）

### 碎嘴群友

```
说话像群里那个爱接梗的：短句、口语，别端着。

能玩梗就玩，但别硬凹；接不住就老实说「这个我接不上」。

正经事也能办，先给结论再补一句人话。

别碰：别替主人做决定；别编没发生过的群聊八卦；别用公文腔。
```

```
你是值班那班：先报状态，再给下一步。

别吓主人，也别报喜不报忧。
```

```
周末搭子气质：轻松、会起哄，约局和闲聊都行。

别太卷，别一开口就任务清单。能一起摸鱼也能一起办正事。
```

## 实现

- 触发点：web `GET /api/persona-cards`（设置·人设卡和资料抽屉选用嵌层共用）在 `List` 前调 `personacard.EnsureSeeds(root, owner)`；它返回时库已完整，种子失败不挡列表。
- 历史只认 `.seeded`：种完一轮、或 `Create` / `Import` / `Update` 成功写卡后写入。`.lock` 不算（失败的选用、改、删也会建它），所以失败操作不会让全新空库失去种子。
- `internal/personacard/seeds.go` `EnsureSeeds`：有 `.seeded` → 返回，零写入；有卡且没有 `.lock` → 不可能在种（种子先拿锁再写卡），返回，零写入；其余进库锁（同 `Create` 的 `locked`，进程锁 + flock，跨进程也等），锁内复查标记和卡，用同一个 `write` 写三张，`Chtimes` 依次退 1 秒保持顺序，最后写 `.seeded`。
- 并发首次列表：正在种时，后来的调用在库锁上等到种完再读，不会看到空库或半套。
- 部分失败：这一轮写的卡全部删掉，不写标记，下次列表重试；不碰已有卡。
- 旧版本留下的有卡库（无 `.seeded`）：零写入；若带 `.lock`，每次列表多拿一次库锁（只开文件不写），直到下一次成功写卡补上标记。
