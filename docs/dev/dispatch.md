# 前台派活与预制子代理

2026-10-20 起草，挂在 FOCUS 的「长程运行」上：主线上下文只留对话、意图、计划和记忆，干活的工具输出留在子代理那边。决定和取舍见 [ADR 0016](../adr/0016-foreground-dispatches-typed-subagents.md)。这是开发态的设计；落地后提炼进 atlas 的 [fork.md](../atlas/fork.md)、[subagents.md](../atlas/subagents.md)，再删掉本文。

## 30 秒版

主人说一件事，前台用两三步理解意图、需要时查一下记忆或读一两个文件，然后选一种预制子代理、写好任务说明派出去，回一句「已派 w1 去做」。子代理带完整工具干活，可以跑很久，有自己的记录。做完交回固定格式的结果，前台转告主人、顺手整理记忆。主人随时插话，前台都空着，几秒内回答；要改正在做的活，就对子代理补充、排队、打断或取消。

```
主人："把测试全修了"
  前台：recall / 读一两个文件 → dispatch(dev, "修 ./... 里失败的测试，…") → 「已派 w1」
  w1（开发）：读、改、跑测试……
主人："今天几号？"
  前台：直接回答
w1 结束 → 完成事件 → 前台：「w1 修好了 3 个，还剩 1 个是……」，更新记忆
```

## 前台

- **工具在代码里限死**：只读快速工具（读文件、列目录、只读 shell、搜索、看图）、记忆、`dispatch` 和管子代理的工具（补充、排队、打断、取消、查看）。没有写文件、写类 shell、对外发送、编码代理。
- **前台上限照旧**：工作角色给的次数和秒数（`chat` 4 次、20 秒）。到上限内核收尾这一轮，提示模型把剩下的派出去；不再自动分叉。
- **前台的提示**讲清楚它的职责：先弄清意图，不清楚就问；能两三步答的直接答；要动手的派出去；派之前想好类型和任务说明；结果回来后转告，并判断要不要记进记忆。

## 子代理类型

一个类型是一份小文件，字段：

| 字段 | 意思 |
|---|---|
| `name`、`when` | 类型名，和一句「什么时候用我」（给前台挑） |
| `tools` | 工具白名单，空集报错；子代理工具集里永远没有 `dispatch`（防递归） |
| `prompt` | 拼在共享规则后面的提示片段 |
| `budget` | 墙钟预算 |
| `report` | 交回格式：结束时必须给出的几段 |
| `model` | 可选，不写跟 Bot 的绑定 |

内置三种，打进二进制；Bot 目录下 `agents/types/<name>.md` 有同名文件时盖过内置，没有的名字就是新增：

| | 调研 `research` | 开发 `dev` | 通用 `general` |
|---|---|---|---|
| 工具 | 搜索、读网页、读文件、只读 shell、看图 | 读写文件、shell、git、编码代理 | 除 `dispatch` 外全部 |
| 提示要点 | 多方查证、注明来源、分开事实和推测 | 先读再改、改完跑测试、不越出任务 | — |
| 预算 | 20 分钟 | 2 小时 | 45 分钟 |
| 交回 | 结论、来源、没查到的 | 改了什么、测试结果、没做完的 | 做了什么、结果、没做完的 |

数字是起点，用真实任务调。

## 上下文

- **子代理起步**：空白上下文 + 任务说明 + 派它的那个人的记忆快照 + 当时的工作目录。任务说明里要用到对话里的东西，前台写进去；不够时子代理可以 `expand` 主线的序号（同一个 Bot，不跨 owner）。
- **主线 transcript** 只记两行：派出（类型、任务说明、子代理 id）和结果（交回的那几段，按上限截断）。中间过程在 `agents/<id>/transcript.jsonl`，主线要看用 `read_subagent` / `expand_subagent`。
- **子代理自己的上下文**按两条线和轮内守线管（[atlas/context.md](../atlas/context.md)），不再是「涨满就失败」。

## 不变的

补充、排队、打断、取消；后台确认卡走 `BackgroundApprove`；最多 3 个子代理同时跑；开发类子代理之间按 `review.ResourceOf` 的资源排队，调研类不写东西、随便并行；崩溃后补写中断、不自动续跑。

## 迁移

- 旧 transcript 里的 `branch`、`fork`、`fork_end` 行照旧能读、能导出、界面照旧收成卡；新代码不再写。
- 网页的后台角标和弹层改读子代理列表；子代理卡的样子先出原型。

## 验收

- [x] 主人发一个要 10 分钟的开发任务，前台 3 步以内派出并回话；期间连发 5 句，p95 3 秒内回复（假模型）。`TestDispatchKeepsTheForegroundFree`：2 步派出，5 句 p95 14 毫秒。
- [x] 前台在任何一轮里都调不到写类工具（守门测试）。`TestForegroundNeverOffersWorkTools`，按类别限死。
- [x] 同时派一个调研、一个开发，互不影响；两个碰同一仓库的开发排队。`TestDevSubagentsOnOneDirectoryQueue`、`TestSameResourceQueues`。
- [x] 子代理做完，前台主动转告；主线 transcript 只多两行。`TestDispatchProgressStaysOffTheMainLine`；转告靠做完时当场叫醒（同上那条网页测试，结果只报一次）。
- [x] 真实 DeepSeek：在 eval 里加几条「该派哪种、任务说明写没写全」的用例，认证通过。`evals/dispatch` 4 条，deepseek-flash 3 次全过（2026-10-20）。
