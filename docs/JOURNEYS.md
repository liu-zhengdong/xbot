# XBot 核心旅程

> 主人每天真的会做的几件事。XBot 先把这几件事做好，别的都排在后面。做法见技能 `core-journeys`。

## 规则
- 最多 7 条，现在 6 条。满额之后要加新的，先合并或退掉一条，并写明理由。
- 旅程和「怎样算对」由主人定。Agent 可以起草、提修改，但主人确认后才算数；Agent 不能自己改「怎样算对」。
- 同一时间只推进一个功能点，而且它必须挂在某一条旅程上。挂不上的进 [候选清单](CANDIDATES.md)，不当场开工。
- 完成分三级：**已合入**（测试全绿进了 main）、**端到端通过**（对着真二进制和真网页把挂靠的旅程跑通，其他旅程没有退化）、**主人日用通过**（主人实际用了几天，没有新的阻塞问题）。汇报时说清是哪一级。只有「已合入」时不说「做完了」。
- 每条旅程配一条端到端冒烟用例：真的 `xbot serve`、真的网页（浏览器驱动），只有模型换成脚本化的假模型。冒烟用例按下面的「怎样算对」来写，写实现的一方不改它的期望。
- 日用中碰到的问题，挡住了哪条旅程就最先修，修完补一条用例；不挡旅程的攒成一批处理。

## 1. 网页对话
**入口**：浏览器打开 `xbot serve` 的地址。

1. 用启动时打出的登录码登录，看到 Bot 列表。
2. 选一个 Bot，发一句话。
3. 回复以流式出现。
4. 刷新页面；再在终端用 `xbot chat` 打开同一个 Bot。

**怎样算对**
- 回复的第一个字 3 秒内出现。
- 刷新后，刚才的一问一答都在，顺序不变，没有重复或丢失。
- 终端里看到的是同一条对话，从终端接着说的话，网页上也能看到。

## 2. 记住事情
**入口**：网页对话。

1. 告诉 Bot 一件关于自己的事，例如「我对花生过敏」。
2. 重启 `xbot serve`。
3. 问同一个 Bot「我有什么忌口」；再去问另一个 Bot。
4. 更正：「其实我不过敏了」，然后再问。

**怎样算对**
- 重启之后，同一个 Bot 答得出来。
- 关于主人本人的事，另一个 Bot 也答得出来。
- 详情的「记忆」里能看到这一条。
- 更正之后，回答以最新的说法为准。

## 3. 动手做事
**入口**：网页对话，Bot 有本机的 shell 和文件权限。

1. 让 Bot 在它的工作目录里做一件具体的事，例如「把这个目录里的文件列出来，写一份 summary.txt」。
2. Bot 调用 shell、读写文件。
3. Bot 回复说明做了什么。

**怎样算对**
- 磁盘上真的出现了这个文件，内容和要求一致。
- 回复说清做了什么、文件在哪；对话里不夹工具调用的原文。
- 详情的「轨迹」里能看到这一轮用了哪些工具。

## 4. 忙时插话
**入口**：网页对话，Bot 正在跑一个要好几分钟的任务。

1. 让 Bot 开始一个长任务。
2. 任务还在跑时，再发一句不相干的话。
3. Bot 先回答这句话。
4. 长任务跑完后，Bot 报告结果。

**怎样算对**
- 插话的回复 3 秒内开始出现。
- 长任务没有被打断，也没有重跑；「任务」面板显示它在后台进行中。
- 长任务的结果报告在对话里只出现一次。

## 5. 主动唤醒
**入口**：例程（主人在对话里让 Bot 定时做某件事）或 webhook，主人不在场。

1. 到点了，或者 webhook 到了。
2. Bot 醒来，判断有没有值得说的事。
3. 有就说，没有就保持安静。

**怎样算对**
- 到点后 1 分钟内醒来，对话里出现一行灰色时钟。
- 有值得说的事时，铃铛里出现一条通知；没有时，回复是 `SILENT`，不产生通知。
- 免打扰时段不推送。
- 重启后，已经跑过的不重跑；停机期间错过的只汇总报一次。

## 6. Bot 之间协作
**入口**：网页对话，本机有两个 Bot。

1. 对 Bot A 说「问问 B 怎么看」。
2. A 给 B 发消息，B 回复。
3. A 把 B 的意见带进给主人的回答里。

**怎样算对**
- 主人的对话里只出现一行灰色事件，点开能看到两边的往来。
- A 的最终回答里包含 B 的意见。
- 两个 Bot 不会无限来回，到上限会停。
- B 发来的内容只当资料，不当成给 A 的指令。
