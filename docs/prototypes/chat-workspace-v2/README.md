# 聊天工作区重设计原型（v2 · 紧凑输入框与视觉层级精修）

## 1. 设计背景与问题诊断

对照用户提供的现状截图与 `visual-design` 规范，现行聊天页存在四个突出的视觉与编排缺陷：

1. **输入框（Composer）过度膨胀，纵向空洞**：
   - 现行代码将 `.workspace .composer` 设为上下两行 Grid（`"input input" "plus actions"`），且 `.composer-input` 硬写了 `min-height: 60px`、外层大内边距 `16px 12px 10px`、按钮 `42px`。结果哪怕只写两三个字或空置，底部也永远横着一块高达 **~126px** 的深灰大盒子，文字孤零零挂在左上角，右下角挂着麦克风和发送钮，中间整片空白，既笨重又抢走对话主区的呼吸感。
2. **对话流主次颠倒，单聊视觉噪音多**：
   - 现行 `.workspace` 把用户气泡（`.bubble`）改成了与卡片极接近的浅灰 `--x-fill-1`，而 Bot 正文直接透明铺在背景上，但每条 Bot 消息上方都重复画一遍 `24px 头像 + 小鲸` 标题行，下方又常驻一个孤立的 `复制` 图标（`.chat-copy`）。
   - 按照 `visual-design/references/composition.md` 已定的「对话（参照 Grok Bot）」范式：**一对一单聊不放头像、也不常驻名字**（顶栏已经交代了在和谁聊）；对方的消息是靠左的浅灰气泡，自己的消息是靠右的深色气泡（深色模式反过来：白底深字），圆角 `18px`，宽度随内容走，分辨谁在说话靠左右与明暗对比。
3. **顶部两层高度偏松，挤压首屏对话视口**：
   - 现行 `--workspace-head: 88px` 加 `--workspace-tabs: 60px` 共占去 **148px** 净高，导致大屏上半截空旷、底部又被高输入框顶住，中间真正看消息的视口显得局促。
4. **辅助元素缺乏收束**：
   - 「查看心里话」纯灰字悬在半空缺乏轻量可点线索；消息下方的复制图标每一轮都常驻占位，打断对话节奏。

## 2. 核心设计决策（我是谁 → 说什么 → 怎么说 → 怎么摆）

### 2.1 输入框收小（Compact Single-Line Pill Composer）
- **默认单行高度 `44px`**（较现行 `~126px` 缩减约 **65%**）：
  - 采用单行双列 Grid（`grid-template-columns: minmax(0, 1fr) auto`，`grid-template-areas: "input actions"`），外层 `padding: 6px 6px 6px 16px`，圆角 `22px`（多行/引用/贴图展开时平滑过渡至 `18px`）。
  - 输入区 `.composer-input` 单行净高 `32px`（`line-height: 22px`、`padding: 5px 0`），与右侧 `32×32px` 的麦克风和发送圆钮严格水平同轴对齐。
- **按需向上生长**：
  - 输入多行文字（最高 `132px` 后内部滚动）、插入「引用回复」横条（`.quote-row`）或粘贴待发图片（`.attach-row`）时，容器自然向上扩展，右侧操作簇始终锚定在右下角（`align-self: end`）。
  - 点击麦克风进入录音态时，隐藏文本与普通操作簇，原地切换为等高 `44px` 的录音条（呼吸红点 + 计时 + 取消/发送胶囊）。

### 2.2 对话流编排重构（Grok Bot 单聊范式）
- **去冗余身份头**：一对一单聊不再在每条 Bot 回复上方重复渲染头像与名字；左边缘与顶部身份区、底部输入框左缘严格对齐在同一条阅读轴线上。
- **恢复气泡正反对比**：
  - 浅色主题：Bot 消息为左侧 `--x-bot-bubble`（`#f5f5f7`）圆角 `18px` 气泡；用户消息为右侧 `--x-primary`（`#18181b`）深底白字气泡。
  - 深色主题：Bot 消息为左侧 `--x-bot-bubble`（`#222226`）圆角 `18px` 气泡；用户消息为右侧 `--x-primary`（`#f2f2f2`）亮底深字气泡。
- **群聊 / 多 Bot 才恢复身份行**：同屏超过一个 Bot 时必须分清谁在说——`?state=group` 里每条 bot 行带 `28px` 头像 + `.who`（名字+时间），同一 Bot 连续发言（`.cont`）不重复头像和名字，正文缩进 `38px` 与上文文字对齐；`[action]` 工具调用、Bot 之间往来是纯灰字居中系统行，不画气泡。
- **语音泡与文字泡同簇对齐**：连续文字与独立语音播放器共用 `.bubble-col`，簇间距 `6px`，语音泡宽度随音频时长自适应，不强行撑满文字宽度。
- **操作收纳至悬停条**：复制、引用回复与发送时间收进 `.msg-meta-bar`，悬停/键盘聚焦时浮现，彻底消除每条消息下方常驻孤立图标的噪音；窄屏同样不常驻。
- **发送状态独立成行**：`已排队`、`没送到` 不是操作而是消息本身的属性，常驻 `.msg-status` 一行（失败态气泡降为 `--x-fill-2` 浅灰底，「重试」为可点文字），与悬停操作簇分开。
- **心里话轻量胶囊**：「查看心里话」加右向细 chevron，悬停浮现 `--x-fill-1` 胶囊底，点击原地展开圆角抽屉，旋转箭头指示开合状态。
- **空 Bot 开场**：无消息时居中头像 `64px` + Bot 名 + 「有什么事，直接说就行。」+ 最多 3 个 `--x-input` 开场建议，点击填入输入框不直接发送。

### 2.3 顶栏与侧栏密度平衡
- **顶栏减薄 34%**：身份行从 `88px` 收至 `56px`（头像 `32px`，Bot 名与模型 ID 同行基线对齐），标签栏从 `60px` 收至 `42px`（标签高 `32px`），合计 `98px`，把宝贵的纵向空间还给对话流。
- **标签滑动指示块**：顶部标签切换采用共享底板滑块（`.tab-pill-indicator`），切换时平滑过渡位置与宽度。
- **侧栏干净分层**：侧栏保持在 `--x-win` 底板上，主工作区为内缩 `8px`、圆角 `12px` 的 `--x-card` 岛；列表项补齐最新消息时间，选中态使用贴近未选的中性底色，无任何描边或分隔线。

## 3. 预览与状态参数

直接用浏览器打开本目录 `index.html`，或在仓库根目录启动本地静态服务：

```bash
python3 -m http.server 8766 --bind 127.0.0.1
```

支持通过 URL 参数直接打开任意状态（供审查与自动化取证）：
- `?state=idle`：浅色默认单行输入框（44px）
- `?state=dark`：深色默认单行输入框（对应原截图场景）
- `?state=multiline`：多行草稿（含行内代码与 URL 语法高亮）自适应增高
- `?state=quoting`：带引用回复条的输入框
- `?state=attach`：带粘贴图片缩略图的输入框
- `?state=recording`：正在录音状态条
- `?state=aside`：「查看心里话」展开态
- `?state=win`：Windows 桌面壳右上角系统按钮避让态
- `?state=group`：群聊/多 Bot——头像+名字区分发言者，cont 行缩进对齐，action 灰字系统行，peer 往来胶囊
- `?state=empty`：空 Bot 开场（头像+名字+一句引导+最多 3 个开场建议）
- `?state=failed`：发送失败气泡（浅灰底 + 「× 没送到 重试」常驻状态行）
- `?state=queued`：排队中气泡（「已排队」常驻状态行）
- `?state=rail`：72px 侧栏 Rail 态
- `?state=memory` / `?state=trace` / `?tab=context`：记忆、轨迹、上下文标签页
- 快捷键 `Shift + D`（或 `?demo=1`）：呼出右下角状态快速切换器
