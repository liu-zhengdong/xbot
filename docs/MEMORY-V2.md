# 记忆 v2 规格

2026-10-17 主人批准。2026-10-17 晚些时候，主人把记忆布局改成了目录式。决策见 [ADR 0008](adr/0008-memory-v2-dated-log-first.md) 和 [ADR 0009](adr/0009-memory-as-folder.md)；现行设计见 [atlas/memory.md](atlas/memory.md)。本规格每落地一批，atlas 就更新一批。本文是过程快照，定下来就冻结。

## 结论
- 两层范围（person 和 bot，[ADR 0006](adr/0006-two-memory-scopes.md)）不变。**每个范围是一个文件夹**：
  - `memory.md`：常驻，上限约 4 KiB，每条带日期，带用量；里面有一节索引，列出旁边每个文件和文件夹放的是什么。
  - `log/YYYY-MM.md`：按月的结构化日志。最近 8 条常驻，`recall` 和每晚整理都要用它。
  - 其他自由文件和文件夹，比如 `projects/xbot.md`、`notes/`：不注入，Bot 需要时用普通文件工具读写。
- 记忆专用工具从四个缩成三个：`remember`、`revise`、`recall`。`recall` 也会搜旁边的自由文件。
- 共 8 批，每批不超过约 500 行。

## 1. 参照：对照了什么
我们对照了两样东西：主人自己的 Grok Bot 数据导出的形状，以及那个产品的外部可见行为；另外看了 Hermes Agent 的公开文档。下表右两列都是**观察或公开资料**，不代表任何一方的内部实现。

| | Grok Bot（导出形状与可见行为） | Hermes Agent（[公开文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)） | XBot（本规格之前） |
|---|---|---|---|
| 常驻 | 每个 bot 的 profile | `MEMORY.md`（2,200 字符）加 `USER.md`（1,375 字符），会话开始时注入 | person 和 bot 的 profile，各 4 KiB |
| 跨 bot 共享 | 有一个关于主人的共享层，条数远少于各 bot 自己的记忆 | 每个 profile 各有一份，不共享 | person 层共享 |
| 流水 | journal，按查询召回，有条数上限，长条目截断，并提示"另有 N 条未展示" | 没有 journal，用 `session_search` 检索原始会话 | log 和 `recall_history`；`recall` 前 20 条，不提示有没有漏 |
| 日期 | 每条带日期；可以看到改写过的条目保留了首次写入的日期 | 不带日期 | 存了时间，但常驻和检索都不显示 |
| 改写 | 可以看到条目被原地改写 | `patch`/`remove` 按唯一子串定位 | 只能按全文 forget，再重写 |
| 写满 | — | 报错；提示头显示用量百分比 | 报错，提示整理 |
| 自动写 | 有"经过摘要"类条目 | 每轮结束后后台复盘 | 压缩前抽事实 |
| 坏味道 | 过时事实靠"（已过时）"注记；profile 里混进单日流水；记忆被拿来当去重状态表 | — | 不给 key 时 key 就是正文前 80 字节，于是每条渲染成"同一句: 同一句" |

## 2. 布局
```
people/<pid>/memory/            bots/<name>/memory/
├── memory.md      常驻，≤4 KiB：索引一节，加带日期的条目
├── log/2026-10.md 结构化日志，按月；每个文件 ≤64 KiB
├── projects/xbot.md   自由文件（举例）
└── notes/             自由文件夹（举例）
```
- `memory.md` 分两节：
  - `## 索引`：每行写一个旁边的文件或文件夹，加一句它放什么。Bot 自己维护。
  - `## 条目`：沿用现在的结构化条目（key、kind、by、at 和出处），这样冲突规则、出处标注和上限检查都照旧。
  - 上限按整个文件算。
- 注入时，渲染时才去比对索引和磁盘上的实际文件。索引里没写的文件，加一行"未登记：notes/x.md"。索引里写了、但磁盘上已经没有的，加一行"索引里有但不存在：…"。不扫子目录的内容，只看一层。
- 旁边的自由文件用 `read_file`、`write_file`、`edit_file` 读写，不受 4 KiB 限制，也不进注入。`memory.md` 和 `log/` 不让文件工具直接写，必须走记忆工具：带锁、查上限、记出处。文件工具碰到这两处就报错，并指向该用的工具。
- 迁移：`profile.md` 变成 `memory.md`，索引一节先是空的；`log.md` 和 `log.overflow.md` 按日期拆进 `log/`。原文件改名为 `*.bak` 保留。迁移是幂等的，沿用现有 `memory.bak` 的做法。
- person 范围同样可以有自由文件，但只放关于主人本人的资料；工作规则仍然放 bot 范围。

## 3. 工具（最小集合）
| 工具 | 作用 |
|---|---|
| `remember(text, scope?, to?)` | 追加一条带日期的条目。`to` 省略时写 `log`，`to=memory` 写进常驻。返回写进了哪里 |
| `revise(match, text?, scope?)` | `match` 是 `memory.md` 或日志里某一条的唯一子串。给了 `text` 就原地改写：保留首次写入的日期，记录更新时间。不给 `text` 就删除这一条。匹配到多条时报错，要求给更长的子串。它取代原来的 `forget`；`forget` 保留一个版本作为别名 |
| `recall(query, scope?, since?)` | 搜 `memory.md`、`log/` 和旁边的自由文件。条目显示 `(日期) [scope/位置] 文本`，自由文件显示 `路径:行号` 加那一段文字。最多显示 20 条，末尾写"另有 N 条未显示" |

不另做 `update` 和 `memory_write` 工具：自由文件交给普通文件工具，结构化条目交给上面这三个。

## 4. 能力清单
| 能力 | 状态 |
|---|---|
| 常驻每条带日期、按时间倒序；key 与正文重复时只出正文；每个范围显示用量，如 `Bot（2.7/4 KiB，67%）`；`recall` 带日期，并提示"另有 N 条" | 设计内（批 1） |
| 目录式布局和迁移（`memory.md`、`log/YYYY-MM.md`、备份） | 设计内（批 2） |
| 索引一节：注入时渲染索引，标出未登记和已不存在的文件；文件工具不能直接写 `memory.md` 和 `log/` | 设计内（批 3） |
| `remember` 默认写日志；常驻最近 8 条日志（约 1.5 KiB，单条截到约 200 字，末尾写"日志共 M 条"），不注入 person 的日志 | 设计内（批 4） |
| `revise`（按唯一子串改写或删除），`forget` 留作别名 | 设计内（批 5） |
| `recall` 搜旁边的自由文件，支持 `since=` | 设计内（批 6） |
| 压缩时多写一条经过摘要：一句话，不超过 300 字，用主人的语言，同一天去重 | 设计内（批 7） |
| 每晚整理：把常驻里的流水降回日志，合并重复，改写被取代的条目；把常驻改写成固定几段的工作档案，大块细节挪进旁边的自由文件；**核对索引和实际文件是否一致，并修好**。直接改，diff 记进日志，可以回滚；本地时间运行，错过不补跑，当天没有新写入就不跑；person 层只降级、去重和核对索引 | 设计内（批 8，可拆成两批） |
| `xbot memory import <导出.md>`、`xbot backup`（不带保险箱、`secrets.json`、`web-token.json`，聊天记录可选） | 设计内（批 9） |
| 自带技能目录；`read_skill` 能读 `references/` | 设计内（桌面端 B 阶段） |
| 项目范围、按写入者分目录、改写成第三人称英文 | 不做。项目资料可以放进 bot 范围下的自由文件，比如 `projects/xbot.md`，但不新增范围 |
| 关键词自动召回 | 不做（见 CANDIDATES）。最近 8 条是按时间固定注入，不算自动召回 |
| 拿记忆当去重状态表、单日流水进记忆 | 不做。这类状态写进 Bot 的工作文件，或者旁边的自由文件；MemoryRule 写明这条规则，并配一个评测用例 |

## 5. 关键决策
- **目录式（ADR 0009）**：只有常驻和日志是结构化的；成段的资料放进自由文件，不再硬塞进 4 KiB。索引让 Bot 知道有什么可以翻，渲染时比对磁盘，让漏登记的文件一眼可见。
- **默认写日志，常驻最近 8 条（ADR 0008）**：常驻只留稳定事实，近期上下文靠最近 8 条。注入预算从 `2×4KiB+512` 变成 `2×4KiB+1.5KiB+512`；索引算在 `memory.md` 的 4 KiB 里。
- **按唯一子串定位**：不加 id，也不改条目格式。
- **矛盾的事实靠日期解决**：冲突规则不变。
- **每晚整理直接改，留 diff**。

## 6. 实现批次（dsh 写，zcode 独立审查；每个修复都配一个在旧代码上会失败的回归测试）
| 批 | 内容 | 通过条件 |
|---|---|---|
| 1 | 常驻带日期、倒序、去重 key、显示用量；`recall` 带日期并提示"另有 N 条" | 渲染测试；`memory-scope` 评测不退步 |
| 2 | 目录布局和迁移 | 迁移跑两次结果一致；拿线上数据副本迁移，条数不丢，备份都在 |
| 3 | 索引渲染和不一致提示；文件工具不能直接写 `memory.md` 和 `log/` | 未登记、已不存在两种提示都有测试；直接写被拒并指向记忆工具 |
| 4 | 默认写日志，常驻最近 8 条 | 评测：全新会话问"昨天定了什么"，不调 `recall` 也答对 |
| 5 | `revise`，`forget` 作为别名 | 子串唯一、多条、零条三种情况都有测试；评测"把目标从 80 改成 78"不产生重复条目 |
| 6 | `recall` 搜自由文件 | 评测：答案只在 `projects/x.md` 里时，`recall` 能找到并给出路径 |
| 7 | 经过摘要 | 压缩后 `recall` 能找到当天的摘要，且不重复写 |
| 8 | 每晚整理（含索引核对） | 常驻不超过 4 KiB；索引与实际文件一致；diff 已记进日志并能回滚；工作档案评测 |
| 9 | 导入和备份 | 导入一个真实导出后条数和日期都对；备份包里没有密钥文件 |

排期：批 1–4 放在晚上的时段做，批 5–8 在 11/30 迁第一个真实 Bot 之前完成，自带技能目录放在桌面端 B 阶段。
