# 记忆 v2 规格

2026-10-17 用户批准，当晚又修订了两次：先改成目录式布局，再去掉专用记忆工具，改成"快照加差异"的注入方式。决策见 [ADR 0008](adr/0008-memory-v2-dated-log-first.md) 和 [ADR 0009](adr/0009-memory-as-folder.md)；现行设计见 [atlas/memory.md](atlas/memory.md)。本规格每落地一批，atlas 就更新一批。本文是过程快照，定下来就冻结；2026-10-27 用户定「压缩不写记忆」，下面凡是挂在压缩上的自动写记忆都已改掉，就地标了修订。

## 结论
- 两层范围（person 和 bot，[ADR 0006](adr/0006-two-memory-scopes.md)）不变，每个范围是一个文件夹：
  - `memory.md`：常驻，上限约 4 KiB，条目带日期，带一节索引；
  - `log/YYYY-MM.md`：只追加的日志，格式见第 3 节；
  - 其余是自由文件。
- person 范围按安装各一份：每台 XBot 有自己的 person 记忆，不在设备之间做文件同步；不同电脑上的 Bot 通过 link 协议互相询问（2026-10-18 用户决定，见候选清单里"跨设备"一行，清单在用户的 Obsidian）。
- **没有专用写记忆的工具**：Bot 用普通文件工具编辑这些文件，内核在写入路径上把关（上限、格式、不可信回合）。只保留一个只读的 `recall`，在范围文件夹里检索。
- **为了不打断前缀缓存**，会话开始时和每次压缩后，把两个范围的 `memory.md` 加 bot 最近 8 条日志拍成快照，放在稳定前缀里，会话中途不改。会话中途记忆文件变了，就在下一轮开头追加一条只含差异的环境更新。Bot 自己这一轮的改动不追加，因为它在工具结果里已经看过了。
- 共 7 批，每批不超过约 500 行。

## 1. 参照：对照了什么
我们对照了两样东西：用户自己的 Grok Bot 数据导出的形状，以及那个产品的外部可见行为；另外看了 Hermes Agent 的公开文档。下表右两列都是**观察或公开资料**，不代表任何一方的内部实现。

| | Grok Bot（导出形状与可见行为） | Hermes Agent（[公开文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)） | XBot（本规格之前） |
|---|---|---|---|
| 常驻 | 每个 bot 的 profile | `MEMORY.md`（2,200 字符）加 `USER.md`（1,375 字符），会话开始时注入 | person 和 bot 的 profile，各 4 KiB |
| 跨 bot 共享 | 有一个关于用户的共享层，条数远少于各 bot 自己的记忆 | 每个 profile 各有一份，不共享 | person 层共享 |
| 流水 | journal，按查询召回，有条数上限，长条目截断，并提示"另有 N 条未展示" | 没有 journal，用 `session_search` 检索原始会话 | log 和 `recall_history`；`recall` 前 20 条，不提示有没有漏 |
| 日期 | 每条带日期；可以看到改写过的条目保留了首次写入的日期 | 不带日期 | 存了时间，但常驻和检索都不显示 |
| 改写 | 可以看到条目被原地改写 | `patch`/`remove` 按唯一子串定位 | 只能按全文 forget，再重写 |
| 写满 | — | 报错；提示头显示用量百分比 | 报错，提示整理 |
| 自动写 | 有"经过摘要"类条目 | 每轮结束后后台复盘 | 压缩前抽事实 |
| 坏味道 | 过时事实靠"（已过时）"注记；profile 里混进单日流水；记忆被拿来当去重状态表 | — | 不给 key 时 key 就是正文前 80 字节，于是每条渲染成"同一句: 同一句" |

## 2. 布局
```
people/<pid>/memory/            bots/<name>/memory/
├── memory.md      常驻，≤4 KiB：## 索引 加带日期的条目
├── log/2026-10.md 只追加的日志：每行一条 "- 2026-10-17 21:30 [对话] 文本"
├── projects/xbot.md   自由文件（举例）
└── notes/             自由文件夹（举例）
```
- `memory.md` 是普通 markdown，分两节：
  - `## 索引`：每行写一个旁边的文件或文件夹，加一句它放什么；
  - 条目：每条 `- (2026-10-17) 文本`。person 范围的条目末尾写上 `via <bot>`。
- 冲突规则从代码挪进 MemoryRule：关于用户本人的事实，日期新的为准；怎么做事，bot 的 `memory.md` 压过 person 的。
- 迁移：`profile.md` 变成 `memory.md`，结构化条目渲染成带日期的行；旧的 `log.md` 和 `log.overflow.md` 按日期拆进各月文件，每条转成第 3 节的格式。没有 source 的条目，bot 范围记成 `[对话]`，person 范围记成写入它的 bot 名。原文件改名为 `*.bak` 保留，迁移是幂等的。

## 3. 日志（2026-10-17 用户批准）
- **位置**：每个范围一个 `log/YYYY-MM.md`，**只追加**。没有 key，没有 id，不能改也不能删。
- **格式**：每行一条，`- YYYY-MM-DD HH:MM [source] 文本`，用本机当地时间。source 只取下面几种：
  - `对话`：Bot 在对话里自己记的；
  - `episode`：自动写的经过摘要（原定压缩时写，已撤回，见下）；
  - `整理`：每晚整理写的；
  - person 范围用写入它的 bot 名。
- **谁来写**：
  - Bot 自己，用文件工具追加，记的是"以后可能用得上、但不是每次都要"的东西；
  - ~~压缩时自动写一条 episode 经过摘要~~ 撤回，压缩不写记忆；以后若要自动写，另定时机，不挂在压缩上（2026-10-27 修订：压缩不写记忆，见 [ADR 0021](adr/0021-env-stream.md) 决定 6。）
  - 每晚整理把 `memory.md` 里过时的、只关某一天的内容挪出来，并记一条它改了什么。
- **更正**：再追加一条新的，新的为准。旧的那条留着不动。
- **读取**：
  - 最近 8 条（约 1.5 KiB）进会话快照；
  - 更早的用 grep 搜，或者直接读月份文件。批 4 的只读 `recall` 也能搜到。
- **大小守卫**：当月文件超过 64 KiB 就拒绝追加，并提示整理：把这个月的流水压成几条 `整理` 记录，写进新的一行，原文件改名留作备份。只看当月文件，过去的月份文件只读。
- **迁移**：旧的 `log.md`（和 `log.overflow.md`）按日期拆进各月文件。

## 4. 写入：普通文件工具，内核在写入路径上把关
- `write_file` 和 `edit_file` 写 `memory.md` 时：写完超过 4 KiB 的一律拒绝（文件本来就超限时，只允许把它缩小），并提示整理：合并、删掉过时的、把细节挪到日志或自由文件。
- 写 `log/` 时：只允许在当月文件末尾追加、符合第 3 节格式的行。改动已有的行、删行、写过去的月份文件，都拒绝。当月文件超过 64 KiB 也拒绝。
- 不可信回合写这两个范围文件夹里的任何文件，都出确认卡，复用现有的受保护路径机制。
- 自由文件不设上限，但 `recall` 只读 `.md` 和 `.txt`，每个文件只读前 256 KiB。
- ~~压缩前自动抽出的事实写进 `log/`，source 记成 `episode`。~~ 撤回：压缩前不再抽事实（2026-10-27 修订：压缩不写记忆，见 [ADR 0021](adr/0021-env-stream.md) 决定 6。）
- `remember` 和 `forget` 不再给模型用，从工具列表里拿掉（批 3）。内部的存储接口保留，给同步和迁移用。

## 5. 读取：快照加差异，不打断前缀缓存
- **快照**（批 1 实现）：
  - 内容：两个范围的常驻记忆，加 bot 最近 8 条日志（约 1.5 KiB，单条截到约 200 字，末尾写"日志共 M 条，更早的用 recall"）。每个范围标出用量。
  - 什么时候拍：会话开始时（state 里还没有快照时）拍一次，每次压缩后重拍。存进 bot 的 state，进程重启后照用。
  - 放在哪：系统提示后面那条记忆消息里。会话中途它的字节一个都不变。
- **差异**（批 1 实现）：
  - 每轮开头，算一遍当前记忆渲染出来的文本，跟"模型已经看过的版本"比哈希。不一样就在 transcript 里追加一条 `<environment_update>`，只含 `memory:` 下面逐行的 `+`/`-` 差异，最多约 2 KiB，超了只写增删行数和"请读文件"。差异的每一行都按记忆数据处理（转义尖括号、保留出处标注）。
  - 追加之后，"已经看过的版本"更新为当前文本。
- **跳过自己的改动**：Bot 这一轮用记忆工具（批 3 之后改成文件工具写记忆路径）改了记忆，工具执行完，"已经看过的版本"就更新到写完之后的文本，下一轮就不会再追加这部分。别的 bot 改的 person 记忆、每晚整理的改动、用户手工编辑，都会追加。
- **压缩时**：快照刷新，"已经看过的版本"重置为新快照。之前追加的差异已经在被压缩的范围里，自然消失。
- 环境更新里原来那行 `memory: updated` 改成上面的差异块。

## 7. 关键决策
- **快照加差异**：常驻记忆只在会话开始和压缩后变，中途的变化以差异的形式追加在末尾，前缀缓存一直能命中。代价是同一个事实可能在快照里是旧值、在后面的差异里是新值；规则写明以后出现的差异为准。
- **不要专用工具**：模型本来就会用文件工具。专用工具要额外的提示和 schema，还会和文件工具打架。规则放在内核的写入路径上，不靠模型自觉。
- **日志只追加**：不能改也不能删，靠追加更新的一条来更正。这样每晚整理和差异检测都简单，历史也不会被悄悄改掉。代价是错的那条一直留着，所以读的时候规则是"新的为准"。
- **默认写日志，常驻最近 8 条**（ADR 0008），**目录式**（ADR 0009），**每晚整理直接改、留 diff**。
