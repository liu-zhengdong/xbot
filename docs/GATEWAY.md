# 开源网关与跨设备 Link 规格

2026-10-18 起草。主人的决定：每台 XBot 只管自己的数据和自己对主人的理解，不做文件同步；不同电脑上的 Bot 通过 link 协议对话；网关必须开源（见 [CANDIDATES](CANDIDATES.md) 里"跨设备"一行）。取舍见 [ADR 0010](adr/0010-gateway-mailbox-relay.md)，落地后的现行设计在 [atlas/gateway.md](atlas/gateway.md)。本文是过程快照，定下来就冻结。

## 目标与能力清单
主人在 Mac 和 Windows 上各装一个 XBot。Mac 上的 `dev` 要问 Windows 上的 `health` 一件事，`health` 回答，两台电脑都在 NAT 后面，都不开入站端口。

| 能力 | 状态 |
|---|---|
| 网关：存储转发的信箱中继。安装只向外连网关，发信、长轮询收信、确认删除 | 设计内（G1） |
| 每个安装一对 Ed25519 密钥，安装 id 是公钥指纹；网关请求逐个签名 | 设计内（G1） |
| `message_bot` 认 `bot@设备` 地址，消息进对方 Bot 的收件箱，对方照常用 `message_bot` 回复 | 设计内（G2） |
| 配对：一台出邀请码，另一台输入，两边各记下对方的名字和公钥 | 设计内（G2 手动交换公钥，G3 邀请码） |
| 信封端到端签名，网关伪造不了发信人 | 设计内（G2） |
| 载荷端到端加密（每封一把临时 X25519 密钥，AES-GCM） | 设计内（G4） |
| 离线排队：收件安装离线时网关代存；网关连不上时发件安装本地重试 | 网关侧 G1，发件侧 G5 |
| 自建：网关就是 `xbot gateway serve`，同一个二进制，一个数据目录 | 设计内（G1） |
| `list_bots`、`bot_status` 看得到另一台设备上的 Bot | 设计内（G6） |
| 桌面端设置页里配对 | 设计内（G7，等桌面端 B2） |
| P2P 直连、内网直连 | 不做（先有中继兜底；直连只省延迟，个人用量下不值得先做） |
| 跨用户通信、Bot 模板分享 | 不做（这一版只连同一个主人的设备，跨用户要另一套授权） |
| Cloudflare Workers 部署 | 不做（先只有 Go 二进制；协议简单，以后可移植） |
| 网关存记忆、同步文件 | 不做（主人决定） |

## 关键决策与理由
- **信箱中继，不是隧道。** 网关只存待取的信封，取走并确认就删。两台设备不必同时在线，NAT 后面只需要能出站 HTTPS。代价是每条消息多一跳、长轮询有几十毫秒到一秒的延迟，Bot 之间对话本来就按秒计，可以接受。
- **一个信封一条消息，复用现有 link 语义。** 跨设备消息落到对方那里，就是一条和本机 `message_bot` 一样的不可信 Bot 事件：来源 `bot:<bot>@<设备>`，带 `chain` 和 `hops`，跳数上限（3）和每对 Bot 每分钟 8 条的限流照旧。内核不加新概念，Bot 回信就是再发一次 `message_bot`。
- **身份是公钥，不是账号。** 安装首次需要时在数据根生成 `remote/install.key`（0600，Ed25519 种子）。安装 id 是公钥 SHA-256 前 16 字节的十六进制。网关不认人，只认公钥；配对关系只记在两台设备上，网关不知道谁和谁配了对。
- **网关准入用一个加入口令。** 自建网关用环境变量 `XBOT_GATEWAY_TOKEN` 设口令，安装第一次注册时带上它（同名环境变量）。注册之后的请求只靠签名。没有口令时网关拒绝注册，除非显式 `--open`。
- **请求签名防冒用，不做防重放表。** 每个请求带 `X-Xbot-Key`、`X-Xbot-Time`、`X-Xbot-Sig`，签名覆盖方法、路径、时间和正文哈希，时间偏差超过 5 分钟拒绝。重放不造成伤害：发信按信封 id 幂等，取信只是再取一遍，确认删除也是幂等的。
- **信封另签一次。** 信封里的签名用发件安装的私钥，收件安装用配对时记下的公钥核对，所以网关和别的注册者都伪造不了发件人。没配对的发件人、签名不对的信封直接确认丢弃，日志只写信封 id。
- **加密排在签名之后。** G2 的正文是明文 JSON，网关能看到 Bot 名和消息内容；G4 加上每封一把临时 X25519 密钥、HKDF、AES-GCM（只用标准库）。分两步是为了第一个 PR 能先跑通端到端，加密单独审查。G4 之前只建议用自建网关。
- **单人安装假设。** 一个安装属于一个主人，配对的设备都是这个主人的，所以对方设备可以给本机任何 Bot 发信。内容照样当不可信数据，和本机 Bot 之间一样。跨用户另开设计。
- **现有 `node` 不动。** `node` 是 tailnet 内直连的远程 shell 和状态查询，靠 bearer token；网关是 Bot 之间的消息。两者并存。

## 对外契约
网关接口（全部 JSON，正文上限 64 KiB）：

| 方法与路径 | 用途 |
|---|---|
| `POST /v1/register` | 带 `Authorization: Bearer <口令>` 和签名，登记公钥；重复登记幂等 |
| `POST /v1/send` | 正文是一个信封；`from` 必须是调用者，`to` 必须已登记 |
| `GET /v1/poll?wait=25` | 取最多 32 封；没有信时最多挂 30 秒 |
| `POST /v1/ack` | `{"ids":[...]}`，删除已取的信封 |
| `GET /healthz` | 存活检查，不需要签名 |

信封：
```json
{"v":1,"id":"<16 字节十六进制>","from":"<安装 id>","to":"<安装 id>","time":"2026-10-18T01:00:00Z",
 "kind":"msg","body":"<base64>","sig":"<base64>"}
```
`sig` 覆盖 `v|id|from|to|time|kind|sha256(body)`。`kind=msg` 的正文（G4 之前是明文）：`{"from_bot":"dev","to_bot":"health","text":"…","chain":"ch_…","hops":1}`。认不出的 `v` 或 `kind` 确认后丢弃，不报错给对方。

## 失败模式
- **收件设备离线**：信封留在网关，每个收件安装最多 512 封、8 MiB，超过就拒收新的（发件方拿到 507）。超过 7 天没取的删掉。
- **网关连不上**：G2 里 `message_bot` 直接把错误还给发件 Bot；G5 起写进本机 `remote/outbox/`，按退避重试 24 小时，放弃时给发件 Bot 一条通知。
- **重复投递**：网关至少投一次。收件安装记最近 1024 个信封 id，重复的确认后跳过。
- **收件 Bot 不存在**：确认丢弃。G5 起回一封 `kind=bounce` 让发件 Bot 知道。
- **时钟不准**：签名时间偏差超过 5 分钟拒绝，错误信息写明网关时间，方便排查。

## 待定项与穿刺项
- 现有的 `nodesync` 会在 `xbot node add` 登记过的节点之间同步人的身份和人的记忆，和"不做文件同步"冲突。要不要退役它，等主人定；在那之前它只对登记过节点的安装生效，本规格不碰它。
- 网关前面要不要直接内置 TLS（`--tls-cert`），还是只建议放在反向代理或 Cloudflare Tunnel 后面：G1 先只支持后者，`--addr` 默认回环。
- 穿刺：Windows 上长轮询穿过系统代理是否稳定。通过条件：Windows 真机上 1 小时内不丢信。

## 实现批次
每批不超过约 500 行（含测试），合并后若影响 `serve` 就升级线上。

| 批 | 内容 | 通过条件 |
|---|---|---|
| G1 | `internal/gateway`：注册、发信、长轮询、确认、磁盘队列与配额、请求签名；`remote` 身份密钥；`xbot gateway serve` | 单元测试：未签名、过期签名、冒充 `from`、超配额都被拒；离线投递后上线能取到 |
| G2 | `internal/remote`：设备表、`xbot remote id/gateway/add/list/remove`、serve 里的收信循环、`message_bot` 的 `bot@设备` 路由、信封签名核对；端到端脚本 | 盒子上一个网关、两个 serve（两个数据根、两个端口）：A 上的 Bot 给 B 上的 Bot 发信并收到回复 |
| G3 | 邀请码配对：`xbot remote invite` 出一次性码（含网关地址、公钥、一次性密钥，10 分钟过期），`xbot remote join <码>` 完成双向登记 | 两台只靠一个码配好；用过的码、过期的码、网关篡改的配对请求都失败 |
| G4 | 载荷端到端加密 | 网关数据目录里搜不到消息原文和 Bot 名；改一字节解密失败并丢弃 |
| G5 | 发件侧离线队列、退信、通知 | 网关停 1 分钟再启动，消息照到；收件 Bot 不存在时发件 Bot 收到退信 |
| G6 | `list_bots`、`bot_status` 带上配对设备的 Bot（按需拉取，缓存 1 分钟） | 模型看得到 `health@win` 并能直接发信 |
| G7 | 桌面端设置页：生成和输入邀请码、设备列表 | 主人在两台电脑上点几下完成配对（先出原型） |
