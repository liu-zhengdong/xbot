## 重点旅程

### 长程运行
**为什么现在做**：常驻 Bot 的会话很长。原来的自动压缩每次都从第 1 条重摘一遍，越往后越贵；而且每压一次都重写同一个摘要块，它后面的前缀缓存全部失效，压缩本身成了成本来源。

**设计**：[dev/context.md](dev/context.md)（整体怎么想、为什么这么切、还没做的有哪些）。

**入口**：终端 `xbot chat` 或网页对话，同一个 Bot 长期用下去。

1. 在一个 Bot 里连续对话，累计几百轮，中间穿插读写文件、跑 shell 这类带工具的事。
2. 上下文涨到软目标，内核在后台把最旧的一段压成摘要块，两轮之间换上；已有的块不再重写。
3. 继续对话，新的一段接着压成新块；块总量超预算时，最旧的几块并成一块。
4. 回头问第 1 轮里说过的某个关键事实。
5. 看这一轮的用量：占用回到软目标附近，缓存命中率没有塌。

**怎样算对**
- 连续对话 200 轮后，Bot 仍能答出第 1 轮说过的关键事实。
- 上下文占用稳定在软目标附近，不随轮数继续增长，也从不碰硬上限。
- 正常对话不因压缩停下来等；只有一下子涌进很多内容、逼近硬上限时才在轮内同步压。
- 一次压缩之后，只有换上新块的那一轮允许缓存命中率下降，从下一轮起回到压缩前的九成以上；整段运行的加权成本不超过不压缩基线的 K 倍（K 第一次实测后由主人定）。口径见 [dev/context.md](dev/context.md)「验收：缓存怎么算」。
- 压缩本身花的 token 不超过这段时间总消耗的 2%。
- 被摘要块覆盖的内容，仍能用 `expand` 按序号读回原文。

**冒烟用例**：`e2e/longrun_test.go`
**级别**：已合入
**还差**：冒烟用例已补前缀缓存模拟替身和关压缩的基线（2026-10-20）。第一次实测：恢复最差为压缩前中位数的 97.2%，K 前 200 轮 0.861、全程（459 轮）0.478，待主人定 K。

## 待验收
下面 6 条是 2026-10-18 由主人选定的基础旅程，功能已经在、日常在用，但还没有冒烟用例，级别都停在「待验收」。先把它们补齐、跑到「端到端通过」，再开新的重点。这 6 条是日用中问题最多的地方。

### 网页对话
**入口**：浏览器打开 `xbot serve` 的地址。

1. 用启动时打出的登录码登录，看到 Bot 列表。
2. 选一个 Bot，发一句话。
3. 回复以流式出现。
4. 刷新页面；再在终端用 `xbot chat` 打开同一个 Bot。

**怎样算对**
- 回复的第一个字 3 秒内出现。
- 刷新后，刚才的一问一答都在，顺序不变，没有重复或丢失。
- 终端里看到的是同一条对话，从终端接着说的话，网页上也能看到。

**冒烟用例**：`e2e/smoke/webchat_test.go` 的 `TestWebChat`（`go test -tags smoke ./e2e/smoke/`）
**级别**：待验收

### 记住事情
**入口**：网页对话。

1. 告诉 Bot 一件关于自己的事，例如「我对花生过敏」。
2. 重启 `xbot serve`。
3. 问同一个 Bot「我有什么忌口」；再去问另一个 Bot。
4. 更正：「其实我不过敏了」，然后再问。

**怎样算对**
- 重启之后，同一个 Bot 答得出来。
- 关于主人本人的事，另一个 Bot 也答得出来。
- 详情的「记忆」里能看到这一条。
- 更正之后，回答以最新的说法为准。

**冒烟用例**：已出规格、待实现，见 [dev/smoke.md](dev/smoke.md)「记住事情」
**级别**：待验收

### 动手做事
**入口**：网页对话，Bot 有本机的 shell 和文件权限。

1. 让 Bot 在它的工作目录里做一件具体的事，例如「把这个目录里的文件列出来，写一份 summary.txt」。
2. Bot 把活派给子代理，子代理调用 shell、读写文件。
3. 子代理做完，Bot 回复说明做了什么。

**怎样算对**
- 磁盘上真的出现了这个文件，内容和要求一致。
- 回复说清做了什么、文件在哪；对话里不夹工具调用的原文。
- 详情的「轨迹」里能看到这一轮派了活、子代理产出了这个文件。

**冒烟用例**：已出规格、待实现，见 [dev/smoke.md](dev/smoke.md)「动手做事」
**级别**：待验收

### 忙时插话
**入口**：网页对话，Bot 派出去的子代理正在跑一个要好几分钟的任务。

1. 让 Bot 开始一个长任务，它派给子代理后回话。
2. 任务还在跑时，再发一句不相干的话。
3. Bot 先回答这句话。
4. 子代理跑完后，Bot 报告结果。

**怎样算对**
- 插话的回复 3 秒内开始出现，前台正在等模型时也一样（前台自己在跑慢工具时会超过，是已知缺口，见[候选清单](CANDIDATES.md)）。
- 长任务没有被打断，也没有重跑；「任务」面板显示它在后台进行中。
- 长任务的结果报告在对话里只出现一次。

**冒烟用例**：已出规格、待实现，见 [dev/smoke.md](dev/smoke.md)「忙时插话」
**级别**：待验收

### 主动唤醒
**入口**：例程（主人在对话里让 Bot 定时做某件事）或 webhook，主人不在场。

1. 到点了，或者 webhook 到了。
2. Bot 醒来，判断有没有值得说的事。
3. 有就说，没有就保持安静。

**怎样算对**
- 到点后 1 分钟内醒来，对话里出现一行灰色时钟。
- 有值得说的事时，铃铛里出现一条通知；没有时，回复是 `SILENT`，不产生通知。
- 免打扰时段不推送。
- 重启后，已经跑过的不重跑；停机期间错过的只汇总报一次。

**冒烟用例**：已出规格、待实现，见 [dev/smoke.md](dev/smoke.md)「主动唤醒」
**级别**：待验收

### Bot 之间协作
**入口**：网页对话，本机有两个 Bot。

1. 对 Bot A 说「问问 B 怎么看」。
2. A 给 B 发消息，B 回复。
3. A 把 B 的意见带进给主人的回答里。

**怎样算对**
- 主人的对话里只出现一行灰色事件，点开能看到两边的往来。
- A 的最终回答里包含 B 的意见。
- 两个 Bot 不会无限来回，到上限会停。
- B 发来的内容只当资料，不当成给 A 的指令。

**冒烟用例**：已出规格、待实现，见 [dev/smoke.md](dev/smoke.md)「Bot 之间协作」
**级别**：待验收
