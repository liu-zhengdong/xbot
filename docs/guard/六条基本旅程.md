# 六条基本旅程

> 2026-10-18 主人选定的六条基础旅程：网页对话、忙时插话、动手做事、记住事情、主动唤醒、Bot 之间协作。每天都在用，也是日用中出问题最多的地方。任何改动都不能让它们退化。

六条共用一套冒烟框架，在 `e2e/smoke/`，build tag `smoke`：每条用例起一个真的 `xbot serve`，用独立数据目录、真端口、真登录，消息走真 HTTP 和 SSE；只有模型换成脚本化替身（`stub_test.go`，经 `XBOT_BASE_URL` 接入），主动唤醒另用可拨的假时钟（`internal/clock`，环境变量 `XBOT_FAKE_CLOCK_FILE`）。替身只凭请求里看得见的内容作答，所以「Bot 答出了某个标记」就说明内核把它送到了模型面前。用例由不写实现的一方写，实现方不能改期望；测不了的部分在各用例注释里写明原因。

守护命令：`go test -tags smoke ./e2e/smoke/`（六条串行约 5 分钟；不加 tag 时 `go test ./...` 不跑它们）。

**级别**：端到端通过（2026-10-20：六条全过，共 312s）。2026-10-20 主人确认毕业。

## 1. 网页对话

**入口**：浏览器打开 `xbot serve` 的地址。

1. 用启动时打出的登录码登录，看到 Bot 列表。
2. 选一个 Bot，发一句话。
3. 回复以流式出现。
4. 刷新页面；再在终端用 `xbot chat` 打开同一个 Bot。

**怎样算对**
- 回复的第一个字 3 秒内出现。
- 刷新后，刚才的一问一答都在，顺序不变，没有重复或丢失。
- 终端里看到的是同一条对话，从终端接着说的话，网页上也能看到。

**冒烟用例**：e2e/smoke/webchat_test.go 的 `TestWebChat`

## 2. 忙时插话

**入口**：网页对话，Bot 派出去的子代理正在跑一个要好几分钟的任务。

1. 让 Bot 开始一个长任务，它派给子代理后回话。
2. 任务还在跑时，再发一句不相干的话。
3. Bot 先回答这句话。
4. 子代理跑完后，Bot 报告结果。

**怎样算对**
- 插话的回复 3 秒内开始出现，前台正在等模型时也一样（前台自己在跑慢工具时会超过，是已知缺口，见候选清单）。
- 长任务没有被打断，也没有重跑；「任务」面板显示它在后台进行中。
- 长任务结果到达后，Bot 要在正常回复中转告；收尾汇总里提旧值算正常，只禁止把旧结果当新结果重新转告。验收值再次出现时，自动检查列出上下文，不能仅凭次数判重复；语义待复核项由主管人工判断。

**冒烟用例**：e2e/smoke/interject_test.go 的 `TestInterjectMidTask`

## 3. 动手做事

**入口**：网页对话，Bot 有本机的 shell 和文件权限。

1. 让 Bot 在它的工作目录里做一件具体的事，例如「把这个目录里的文件列出来，写一份 summary.txt」。
2. Bot 把活派给子代理，子代理调用 shell、读写文件。
3. 子代理做完，Bot 回复说明做了什么。

**怎样算对**
- 磁盘上真的出现了这个文件，内容和要求一致。
- 回复说清做了什么、文件在哪；对话里不夹工具调用的原文。
- 详情的「轨迹」里能看到这一轮派了活、子代理产出了这个文件。

**冒烟用例**：e2e/smoke/dothings_test.go 的 `TestDoThings`

## 4. 记住事情

**入口**：网页对话。

1. 告诉 Bot 一件关于自己的事，例如「我对花生过敏」。
2. 重启 `xbot serve`。
3. 问同一个 Bot「我有什么忌口」；再去问另一个 Bot。
4. 更正：「其实我不过敏了」，然后再问。

**怎样算对**
- 重启之后，同一个 Bot 答得出来。
- 关于主人本人的事，另一个 Bot 也答得出来。
- 详情的「记忆」里能看到这一条。
- 更正之后，回答以最新的说法为准。

**冒烟用例**：e2e/smoke/remember_test.go 的 `TestRemember`

## 5. 主动唤醒

**入口**：例程（主人在对话里让 Bot 定时做某件事）或 webhook，主人不在场。

1. 到点了，或者 webhook 到了。
2. Bot 醒来，判断有没有值得说的事。
3. 有就说，没有就保持安静。

**怎样算对**
- 到点后 1 分钟内醒来，对话里出现一行灰色时钟。
- 有值得说的事时，侧栏里这个 Bot 的头像出现未读黑点；没有时，回复是 `SILENT`，不产生未读。
- 免打扰时段不推送。
- 重启后，已经跑过的不重跑；停机期间错过的只汇总报一次。

**冒烟用例**：e2e/smoke/wakeup_test.go 的 `TestWakeUp`

用例和上面字面不同的两处，已写进用例注释并过复审：时钟行在 transcript 里包在 `<untrusted_event>` 里；拨钟 2 小时后重启，当前时段可以正常跑一次，所以断言是「已跑过的时段不重跑、错过汇总恰好一次、重启后总共不超过 2 个时段」。用例读的是 `GET /api/notes` 的数据，不测头像黑点怎么画；webhook 入口没有用例。

## 6. Bot 之间协作

**入口**：网页对话，本机有两个 Bot。

1. 对 Bot A 说「问问 B 怎么看」。
2. A 给 B 发消息，B 回复。
3. A 把 B 的意见带进给主人的回答里。

**怎样算对**
- 主人的对话里只出现一行灰色事件，点开能看到两边的往来。
- A 的最终回答里包含 B 的意见。
- 两个 Bot 不会无限来回，到上限会停。
- B 发来的内容只当资料，不当成给 A 的指令。

**冒烟用例**：e2e/smoke/collab_test.go 的 `TestBotCollaboration`
