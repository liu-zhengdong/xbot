# 界面

> 2026-10-22 整套界面重做完成后定下的规矩，以后改网页界面和桌面窗口都要守。界面现在由什么组成、为什么这样设计，见 [atlas/ui.md](../atlas/ui.md)。「UI 改动先出原型、用户定稿再实现」和 60fps、动画只动 transform/opacity、动画时长上限、轮询不引起重排这几条全局要求在 [AGENTS.md](../../AGENTS.md)，这里不重复。

这些规则由用户和用户体验设计师定，Agent 不能自己改；觉得哪条不合适，先问用户。

## 规则

1. **视觉值只从 `tokens.css` 来。** 颜色、字号、间距、圆角、阴影、动效时长和曲线，组件里一律引用 `internal/web/static/tokens.css` 的变量，不写死数值。`tokens.css` 是单独一个文件、先于 `app.css` 加载，设计师改变量时整份替换。照着原型做时，照抄的是变量、尺寸和文案，原型的 DOM 结构不用照抄。

2. **不画线。** 不加描边、分隔线、发光和渐变；区块之间靠留白和底色分开；列表普通行统一底色，靠对齐、行距和文字层级分行，不默认用斑马纹，浅底只给悬停、选中等状态。页面里的卡片不加阴影，阴影只用 `--x-shadow-pop`，只给浮层（菜单、弹窗、抽屉）。

3. **颜色只用在规定的地方。** 页面主体是黑白灰。红色只给错误、失败、删除和校验错误（外加 Windows 关闭按钮悬停的系统红）；「在线」圆点用绿色；类别颜色只出现在上下文色带、子代理类型标签，以及轨迹的类型图标／标签／总览标记里，均从 `tokens.css` 取值并控制彩色面积。轨迹采用用户确认的 DSH 配色：输入蓝、上下文绿、模型紫、工具橙，色条、文字和标签浅底分别配色；普通行及选中背景仍用中性底，失败仍用红色。「值得留意」里的删除也不用红，那是已经发生的事，不是报错。

4. **图标和字体。** 图标一律用 Lucide 内联 SVG，线宽 1.8，不用文字箭头，也不用 emoji 当图标。界面文字用 `--x-font`，栈里一直保留自带的中文子集 `XBot SC`；Mona Sans 只用于字标「XBot」（已转成路径）和头像兜底的首字。

5. **标点和文案。** 用全角标点；中文和英文、数字之间空一格；中间点写成「 · 」，两边各一个空格（例如「定时 · 早报 · 昨天 08:00」）；全角句号后面不加半角空格。卡片里一行一项的列表不加句号；对话气泡里的完整句子带句号。

6. **动效用 token，尊重减少动态效果。** 弹出、按压、回弹只用 `tokens.css` 里的动效变量（`--ease-spring`、`--dur-pop`、`--dur-pop-close`、`--dur-press`、气泡按压和回弹的几个变量），不自己另写时长和曲线。普通过渡不超过 200ms，弹性动画最长 300ms：弹出用 `--dur-pop` 220ms，气泡回弹 300ms（和 AGENTS.md「全局要求」一致）。系统打开「减少动态效果」（`prefers-reduced-motion`）时，只做 `--dur-motion-reduced` 的淡入淡出，不缩放、不回弹。

7. **对话里只放对话。** 对话里只有用户和 Bot 的消息，外加时间分隔、定时时钟行、Bot 往来事件和发送状态这几种灰字行。不往对话里加任务卡、状态标签（例如「后台」）或「没什么要说的」这类占位行；进度放输入框上方那一行状态；按用户 2026-11-01 的入口决定，本机孩子完整经过放独立「子代理」Tab，「任务」Tab 查看 Routine。主 Bot 工具原文进「轨迹」，孩子工具原文在其子代理记录里看。

8. **界面上不露原始编号。** 子代理编号、任务编号、工具名原文、内部标记不出现在对话、预览、状态行和任务卡上：任务卡用短标题，没有就用类型名。原始编号只放在可展开的孩子「任务信息」/记录来源或旧「任务详情」里，而且必须能选中复制：轮询时值没变的节点不重写，选区所在的节点跳过（`internal/web/task_selection_test.go` 守着）。

9. **没有数据就不画。** 某一块的数据还没有（例如还没有上下文快照、内核没给「值得留意」条目、接口还没做的功能）时，整块不出现，不显示零值或空进度条。

10. **不做权限审批界面。** 新组件里不放确认卡、「等你确认」状态和相关计数，也不引用旧的 `.approval-line`、`.gate-card`。ADR 0019 仍会弹的卡沿用旧渲染，不重画。

11. **「值得留意」的写法。** 清单只有内核定义的四类，界面不自己判断、不加类别：
    - 卡片：先一行「值得留意」，下面每类一行，行首是和文字同色的 Lucide 线条图标（删除 trash-2、外发 send、工作区外写入 file-pen、全局安装 package）；顺序固定为删除、外发、工作区外写入、全局安装。
    - 每行写出对象，例如「全局安装了 ripgrep」「写入了 ~/.zshrc」；对象超过 2 个写成「A、B 等 5 个」，完整列表放进孩子的「任务信息」或旧「任务详情」；内核拿不到对象时保留泛称。
    - 路径太长时保留开头两段和最后两段、截掉中间，还放不下先去掉倒数第二段，文件名永远保留；卡片和气泡用同一个截断函数。
    - 对话气泡里只写一句话、不分行，带「值得留意：」前缀和句号：一条时「值得留意：全局安装了 ripgrep。」，多条时「值得留意：删了 3 个文件，另有 3 项，详见任务。」。气泡和卡片说的必须是同一批条目。

12. **截图验证受影响的稳定场景。** 局部改动默认检查一个代表视口；主题、响应式或桌面壳受到影响时再补对应维度。整体 UI 改版在功能收敛后留受影响页面的浅深色和代表宽度证据，不逐个微小编辑重复完整矩阵。默认、悬停、打开等状态按风险选取，交互或外观未变的页面复用已有证据。截图用独立数据目录，不用用户的 `~/.xbot`；文件保存在 `~/.xbot-build/ui-shots/<特性>/`，整体改版保留 DPR 2 证据。评审针对稳定版本和实质变化，对照已确认原型；不每一步逐张重新回签。验证与重跑条件统一见 [测试约定](../TESTING.md)。

## 怎么守

**怎样算对**
- 受影响场景有足够的实际浏览器证据；涉及的主题、断点或壳已覆盖，稳定版本与确认原型一致，上面 12 条没有被违反。
- 按影响选择相关的[基本旅程](六条基本旅程.md)冒烟；无关局部 UI 改动不跑全部旅程，旅程要求不变。
- 用户选中任务编号后，等两个轮询周期，选区还在。

**冒烟用例**：internal/web/task_selection_test.go

**级别**：设计师验收通过（2026-10-22：M1–M7 逐步通过，最终提交 74edd0b）。2026-10-22 用户确认整套界面做完。

`internal/web` 中按改动选择接口、数据和行为用例；影响全包共享行为时才跑整包一次。除第 8 条的选区外，其余规则靠截图评审守，不为它们写查类名、文案、颜色值的静态测试（见 AGENTS.md「验证」）。
