# 长程运行

> 常驻 Bot 的会话很长，一个 Bot 连续用几个月不换会话。上下文要稳在软目标附近，压缩不挡对话、不越压越贵，第 1 轮说过的事还答得出来。现行实现见 [atlas/context.md](../atlas/context.md)。

**入口**：终端 `xbot chat` 或网页对话，同一个 Bot 长期用下去。

1. 在一个 Bot 里连续对话，累计几百轮，中间穿插读写文件、跑 shell 这类带工具的事。
2. 上下文涨到软目标，内核在后台把最旧的一段压成摘要块，两轮之间换上；已有的块不再重写。
3. 继续对话，新的一段接着压成新块；块总量超预算时，最旧的几块并成一块。
4. 回头问第 1 轮里说过的某个关键事实。
5. 看这一轮的用量：占用回到软目标附近，缓存命中率没有塌。

**怎样算对**
- 连续对话 200 轮后，Bot 仍能答出第 1 轮说过的关键事实。
- 上下文占用稳定在软目标附近，不随轮数继续增长，也从不碰硬上限。
- 正常对话不因压缩停下来等；只有一下子涌进很多内容、逼近硬上限时才在轮内同步压。
- 一次压缩之后，只有换上新块的那一轮允许缓存命中率下降，从下一轮起回到压缩前的九成以上；整段运行的加权成本不超过不压缩基线的 K 倍，K = 1.0。口径见 [atlas/context.md](../atlas/context.md)「缓存怎么验收」。
- 压缩本身花的 token（摘要加事实抽取）不超过这段时间总消耗的 2%。
- 被摘要块覆盖的内容，仍能用 `expand` 按序号读回原文。

**冒烟用例**：e2e/longrun_test.go
**级别**：端到端通过（2026-10-20：459 轮、3 次压缩，恢复最差 97.2%，K = 0.512，压缩占 1.766%）。2026-10-20 主人确认毕业，K = 1.0 由主人认定。

守护测试是 `e2e/longrun_test.go` 的 `TestLongRunJourney`（`go test ./e2e/ -run TestLongRunJourney`）。
